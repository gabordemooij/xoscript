欢迎使用 XOScript
XOScript 项目旨在打造一种简单且可审计的脚本语言。
简单并不一定意味着容易。
一门熟悉的编程语言可能比 XOScript 更容易上手。
这里的简单指的是另一回事：
能够对这门语言及其行为形成完整的心智模型。

XOScript 的设计目标是让你能把它完整地装进脑子里。
它的语法和概念数量都刻意保持精简。
没有类；对象可以直接扩展。
对象按引用传递，复制必须显式进行，
并且函数只有一个出口。

其中一些选择与主流语言有很大不同。
例如，XOScript 没有类型系统，并且使用动态作用域。
无法处理的消息会被忽略，而不会产生异常。
这些选择会带来相应的后果，其目的并不是消除错误。
它们的目的是让语言的底层模型保持精简和一致。

XOScript 还可以本地化，因此可以用自然语言表达业务规则，
并有可能与非技术背景的相关人员共享这些规则。

可审计性意味着在实现上贯彻同样的理念。
运行时用 C 编写，包含一个小型的手写词法分析器、语法分析器和树遍历解释器。
标准库和运行时在很大程度上与语言本身的结构相对应，
使得 XOScript 代码与其实现之间的关系相对直接。

测试也与文档紧密相连。
每个方法都应有一个对应的测试，并且可以纳入本手册，
这有助于保持文档与实现同步。

XOScript 并不打算在功能或熟悉程度上与主流语言竞争。
它探索的是另一个目标：
一个开发者能够整体理解的编程环境。

我们希望，一门小型语言加上一个小型实现，
能够让人切实地理解软件——
从字节到对象，从语法到运行时——并且满怀信心地编写代码，
因为你既了解脚本中发生了什么，

## 在 Linux 上安装

下载 apache2 和 mariadb：


```
sudo apt-get install apache2 mariadb-server
sudo a2enmod cgi
```

下载 xoscript。
请将 X 替换为正确的版本号！

```
wget https://xoscript.com/downloads/xoserver-linux-1_5_X.tar.gz
tar xvf xoserver*.tar.gz
```

将文件复制到网站根目录和 /bin：


```
sudo cp bin/xo /bin/xo
sudo cp -R bin/mods /var/www/html/
sudo cp *.xo /var/www/html/
```

编辑 apache2 配置：

```
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

将 Virtualhost 替换为：

```
<VirtualHost *:80>
    <Directory /var/www/html>
        Options +ExecCGI
        AllowOverride All
        AddHandler cgi-script .xo
        Require all granted
    </Directory>
    DocumentRoot /var/www/html
</VirtualHost>
```

创建一个测试页面：

```
sudo nano /var/www/html/test.xo
```

并编写一个小测试程序：

```
#!/bin/xo
Server 初始化.
程序 使用: ['webtools.xo'].
>> 网页 := 网页文档 新建.
网页 输出: ['Hello World'].
```

允许 apache2 通过 CGI 执行你的程序：

```
sudo chmod uog+x /var/www/html/test.xo
```

重启 apache2：

```
sudo systemctl restart apache2
```

在浏览器中打开你的测试页面：

```
http://localhost/test.xo
```

你应该会看到：

```
Hello World
```

## 语法

XOScript 是一门*纯*的*面向对象*编程语言。这意味着
xoscript 把一切都视为对象，因此不存在
其他*数据类型*。用 XOScript 编写的程序基本上只有三种
基本操作：*赋值*、*发送消息*
和*应答*。对象之间交换消息是 XOScript
程序的核心。下面分别说明这三种
基本操作：


操作            | 示例
--------------- | --------
赋值            |  \>\> x := 1. 
一元消息        | x 偶数?.
二元消息        | 1 + 2.
关键字消息      | x 从: 0 长度: 10.
应答            | <- answer.  


本章将让你对 XOScript 语言有一个总体印象，
并介绍它的基本原理。XOScript 是一门小型语言，
建立在三种操作之上（见图示），这些操作对应
大约六条语法规则。掌握这门语言只需要
这么多。

如果有些内容一时没看明白也不用担心：所有构建
要素都会在下一章（第 3 章）中详细探讨，基本规则也会
再次重复。而本章主要是对这门语言的
总体介绍。我们将简要解释基本原理，
并用几个相关示例加以说明。缺少的
细节将在后面介绍。

XOScript 中的注释以 \# 符号开头。因此下面这一行
会被忽略：

```
# 这只是一条注释
```

## 变量

要给变量赋值，
需要使用变量声明符号：>>。变量名可以包含
除以下符号之外的所有字符：<-、:=、空白字符、
句点、逗号、冒号、引号 [' '] 和圆括号 ()。
此外，变量名不能跨越多行。请注意，
变量名不能以数字或减号开头。

下面是合法变量的示例：

```
>> password := ['Secret'].
>> ♡♡♡ := 3.
>> $ := ['美元'].
>> +plus := 是.
>> 用户密码 := ['嘘！'].
```

不合法的变量例如：


```
>> -123 := ['负数'].
>> password of 用户 := ['机密'].
>> password.of:用户 := ['机密'].
>> ,x := 10.
```

{{note}}
只要不会给词法分析器造成歧义，
字符串字面量中的任何字符
（包括单引号、双引号、字符串
边界符）都无需
转义。
{{/note}}

变量声明之后就可以自由使用了。这意味着
只有在第一次使用该变量（即声明）时，
才需要使用声明符号。

更具体地说，你不能随意直接给变量
赋值 *(x := 2)*，而必须先声明该变量 *(\>\>
x := 2)*。不过，一旦声明之后，就可以修改它的值，
而无需再使用声明符号 *(\>\> x := 2. x := 3.)*。

请注意，声明变量时必须同时给它赋值。
与其他编程语言不同，你不能声明一个
没有值的变量。每个变量都必须显式地绑定
一个初始值。不过，你可以随意用 **空** 对象来初始化
变量。在这种情况下，可以认为该变量
是空的 *(\>\> x := 空.)*。简而言之，不允许声明
没有初始值的变量。所以，

```
>> x.
```

是不合法的，并会产生一条错误消息。

{{note}}
xoscript 对变量使用动态作用域，
详情请参阅"函数"一章。
{{/note}}


## 字面量

XOScript 把一切都视为对象，也就是说，所有数字、字符串
和代码片段都是对象。数字，例如 1、2、100、-999 和 1,234，都是
数值 对象。单引号之间的所有文本都是 文本
对象。花括号 {...} 中的所有代码片段都是
函数 对象。

字面量          | 根对象       | 示例
--------------- | ------------ | ----------
数字            | 数值         | 1,2,3... 
字符串          | 文本         | \['hello'\]
函数            | 函数         | { 1 + 2. }.
                
     
数字和字符串之类的对象总是源自某个根
对象。例如，所有数字都派生自对象 **数值**。所有
字符串都派生自 **文本**，所有代码片段都派生自 **函数**。
而这些对象又都源自 **对象**，它实际上是
所有对象的根对象。


## 消息

用 XOScript 编程基本上就是
向对象发送消息。向对象发送消息的
一般写法如下：

```
<object> <message>
```

例如，要判断数字 **2** 是否为偶数，就向
对象 **2** 发送消息 **偶数?**：

```
2 偶数?
```

答案将是 **是**（同样也是一个对象）。对象通常会
忽略未知消息，因此不会出现错误。有些对象（例如
数字或字符串）会以预定义的方式响应未知消息
（稍后会详细介绍）。

对象可以接收三种消息。

类型            | 参数个数
--------------- | -------------------
一元            | 0      
二元            | 1     
关键字          | 1+    


首先是**一元
消息**，见上面的示例，它们没有参数。其次是
**关键字消息**，它们有一个或多个参数，
例如：

```
>> x := 数值 在: 1 和: 10.
```

在这个例子中，消息 **在:和:** 被发送给 **数值**，
它是所有数字的根对象。结果将是 1 到 10 之间的
一个随机数。最后是**二元消息**，它们
只有一个字符和一个参数：

```
2 + 3
```

这看起来像是一个数学算式，但实际上它只是另一条消息。
消息 **+** 被发送给 **2**，参数为 **3**，返回的
答案是 **5**。二元消息可以不带冒号书写。

二元消息可以链式调用：

```
>> x := 3 + 2 - 1.
```

在这个片段中，**+ 2** 首先被发送给 **数值** 对象 **3**，
得到 数值 对象 **5**，然后再把 **-1** 发送给这个
数。细心的读者会正确地注意到，这一协议
与常规数学运算符优先级之间存在差异。
XOScript 为了消息系统的一致性而忽略了
数学运算顺序。因此，下面的算式：

```
2 + 3 * 5 = 25
```

而不是 17。

这是有意为之的。可以使用圆括号来改变运算顺序：

```
2 + (3 * 5) = 17
```

大多数对象在响应某条消息时会返回自身作为结果。
这很有用，因为它便于继续与该对象
对话，向它发送后续消息：

```
输出 写入:
[' 你好呀 '] 修剪 大写.
```

```
你好呀
```

这里向 **文本** 对象发送了两条消息：先是 **修剪**，
然后是 **大写**。

在下面的片段中，必须使用逗号来表示
接下来是一条新消息。否则，XOScript 会产生混淆。

```
输出 写入: ['Hello!'], 停止.
```

首先，消息 **写入:** 被发送给铅笔符号，接着是
**停止**。如果没有逗号，XOScript 会以为你想把
**停止** 发送给 **字符串** **Hello!**，这毫无意义。

消息的处理顺序如下：从左到右；
先处理圆括号中的消息，然后是一元消息。接着是
二元消息，最后是关键字消息。请看下面的
示例：

```
输出 写入: 0.5 四舍五入 + (2 - 1), 停止.
```

XOScript 总是从左到右阅读：首先，消息 **写入:**
被发送给 输出，随后是 **停止** 消息。在
参数内部，XOScript 同样从左到右阅读，所以先 **0.5 四舍五入**，
再 **+**。

{{note}}
停止 消息会在字符串末尾添加一个换行符。
这条消息的名称来源于电报系统。
电报系统中的消息
常用 STOP 一词来标记句子的结束
（因为标点符号不可靠或代价高昂）。
{{/note}}

此外，**四舍五入** 优先于 **+**，因为它是一条
**一元消息**。由于有圆括号，**2 - 1** 会被
首先计算，然后把 **1** 加到 **0.5 四舍五入** 的结果（1）上。

整个过程将得到结果 **2**，这也是写出的
答案。逗号之后是 停止 消息，它把光标
移到新的一行。当然，要完全理解 XOScript 程序的
执行顺序，最好的方法就是多加练习。

值得注意的是，与许多其他编程语言不同，
在 XOScript 中空白字符是其语法的基本组成部分。
尤其是在二元消息方面，空白字符可能会造成一些
混淆。二元消息之后一定要加一个空格。你不能
把数字直接紧贴在消息后面，例如：

```
3 + 2
```

不同于

```
3 +2
```

第一个示例（**3 + 2**）把
消息 **+** 发送给数字 **3**，参数为数字 **2**。
在这种情况下，结果将是 **5**。在第二个示例（**3 +2**）中，
一元消息 **+2** 被发送给数字 **3**。根据
上下文的不同，这可能会产生截然不同的结果。

## 不存在的方法

向对象发送消息会调用以该消息名
附加到该对象上的函数。如果你发送了一条
对象无法理解的消息，接收对象会忽略你的消息，
并返回对自身的引用，以便继续通信。
这称为容错消息传递。

示例：

```
输出 写入: 对象 blah, 停止.
```

这不会产生错误。它只会打印文本 **对象**。


## 控制流

在 XOScript 中，*循环*和
*条件判断*不需要单独的语法规则。if 语句只是向
**是** 对象或 **否** 对象发送一条简单的 **是:** 或 **否:**
消息：

```
2 偶数? 是: {
	输出 写入: ['二是偶数'], 停止.
}.
```
在上一个示例中，消息 **是:** 被发送给 **是**（即
问题"2 是偶数吗？"的答案）。另外还把一段
代码作为参数一并发送：一个 **函数** 对象。这个函数在
屏幕上写出 2 确实是偶数。

*循环*同样不需要单独的书写规则。要
把一段代码执行三次，只需向该 **函数** 发送 **\***，
参数为 **3**：

@test5

在这个代码片段中，**i** 是索引。所以函数第一次
执行时，**i** 等于 0，下一次执行时 **i** = 1，
依此类推。

我们再来看一个例子。假设需要打印一张
从 *kJ*（千焦）到 *kcal*（千卡）、以 100 为步长的换算表，

# 布尔值

{{messages}}

与撰写本文时大多数流行的编程语言不同，
XOScript 只提供唯一的一个 是 对象和唯一的一个 否
对象。具体来说，每次你写 **是** 时，并不意味着
创建了一个新对象。你使用的始终是一个引用。这
意味着当你写下：

\>\> x := 是.

**x** 引用的是 **是** 对象。条件代码和循环也
检验这个引用。在 XOScript 中，**是** 和 **否** 的含义
并不是固定的。事实上，像下面这样的语句会让
XOScript 程序陷入一片混乱：

是 := 否.

这类操作的结果是未定义的，但它仍然是一个合法的
操作，因此在形式上是允许的。此外，还有一个 布尔
对象，它是 **是** 和 **否** 的根对象，因为两者
都派生自该根对象。不过，布尔 对象本身
没有任何实际用途。

## 陷阱

使用 **且:** 和 **或:** 时要小心

```
输出 写入: (否 or: 是 or: 是), 停止.
输出 写入: (否 或: 是, 或: 是), 停止.
```

得到

```
否
是
```
因为消息 **或:** 只接受 1 个参数。第一行代码
向 否 发送 **或:或:**，而这条消息并不存在，因此该对象忽略
这条消息并返回自身（否）。而第二行
则先发送 **或:**，再发送另一个 **或:**（使用链接符号，即逗号：,）。

# 函数

{{messages}}

你可以把代码放在 { 和 } 之间，这样它就成为一个函数。
在 xoscript 中，我们有时也使用"任务"一词，或者直接称之为
代码块。

你可以通过发送消息 *运行* 来执行一个函数。


```
{ 输出 写入: 123, 停止. } 运行.
```

如果你的函数接受参数，请使用 **应用:**。

```
{ :a 输出 写入: a, 停止. } 应用: a.
```

另请参阅下面的示例。
由于体系结构极为简单，一个函数只能有
一个返回点。为了避免条件判断带来的开销或过深的嵌套，
你可以使用 过程（这与使用
参数为 1 的乘号相同）：

```
{
  (a = 1) 是: { x := 1. }, 中断.
  (a = 2) 是: { x := 2. }, 中断.
} 过程.
```

这样，当 a = 1 时就不会再计算 (a = 2)。
而且，这样也不需要嵌套的 是 消息。
每当你发现自己在嵌套条件时，不妨想想
过程 消息。它可能会让你的代码
更易于阅读。


这里有一个重要的陷阱：

```
{
	否 否: {
		输出 写入: ['结束循环。'].
	}, 中断.
	
	输出 写入: ['别显示我。'].

} 过程.

```

在这种情况下，文本 'Dont show me' 会被显示出来。
因为 **中断** 被发送给了 否。如果你想执行
中断，就必须把它作为消息发送给 **是**。
 

```
{
	否 取反 是: {
		输出 写入: ['结束循环。'].
	}, 中断.
	
	输出 写入: ['别显示我。'].

} 过程.

```

这样就会按预期工作。

想声明一个空任务，可以使用 空 对象：

```

```

所以，没有必要使用空任务。得益于编程语言 XOScript
优雅的设计，你只需为此使用 空
对象即可。

# 列表

{{messages}}

XOScript 有两种集合：*列表*和*字典*。
**列表**是按*固定顺序*排列的对象序列。字典没有
顺序，而是类似于一张图例，由键（或词条）及其
对应的值组成。列表相当于其他编程语言中的数组（PHP、Java、C）
和列表（Python）。字典相当于关联数组（PHP）或
字典（Python）。要创建
一个新的 数组对象，请这样写：

```
>> 斐波那契 := 数组对象 新建.
```

可以使用 **追加:** 来填充这个空列表：

```
斐波那契 追加: 0.
斐波那契 追加: 1.
斐波那契 追加: 1.
斐波那契 追加: 2.
斐波那契 追加: 3.
斐波那契 追加: 5.
斐波那契 追加: 8.
斐波那契 追加: 13.
```

如果把这个列表写到屏幕上：

```
输出 写入: 斐波那契, 停止.
```

我们会看到：

```
数组对象 ← 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13
```

除了 追加，你还可以使用 ; 向列表中添加元素：


```
>> 斐波那契 := 数组对象 新建 ; 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13.
```

这些分号（;）都是二元消息，它们把
一个值放入列表中。

## 链式调用

假设你有这样一个列表：

```
>> x := 数组对象 新建 ; 1 ; 2 ; 3.
```

如果你想删除第一个和最后一个元素，那么你的
消息会是：

```
x 左移 弹出.
```

遗憾的是，上面的写法无法正确工作。
消息 **左移** 返回列表的第一个元素，而这个元素
又会成为消息 **弹出** 的接收者。因此，
消息 **弹出** 并没有被发送给 **x**，而是被发送给了 2。一种
可能的解决办法是写成两个单独的
语句，例如：

```
x 左移.
x 弹出.
```

不过这样相当不实用，尤其是当你需要
删除两个以上的元素时。因此，XOScript 为这类情况
提供了另一种消息结构。在
**替代**消息结构中，对象的应答会被忽略，
你每次得到的答案都是接收对象本身。
通过向对象发送消息 **执行** 来开始一个**替代**消息结构，
并通过发送消息 **完成** 来结束该**替代**消息
结构。在上面的示例中，可以这样应用：

```
>> x := 数组对象 新建 ; 1 ; 2 ; 3.
x 执行 左移 弹出 完成.
```

# 字典

{{messages}}

**数组对象 和 映射对象 都是集合。然而，与列表不同，
字典**没有**顺序。两者的另一个区别
在于字典由对象对组成。其中一个对象充当词条（或
关键字），用于查找另一个对象。一个很好的
列表示例是价目表，例如：


```
>> 菜单 := 映射对象 新建
	放: ['£5'] 在: ['苹果派'],
	放: ['£6'] 在: ['胡萝卜蛋糕'],
	放: ['£3'] 在: ['fudge'].
```

与列表类似，消息 放:在:
用于向列表中添加对象。不同之处在于，与列表不同，
这里是把两个对象关联起来。第一个对象与列表中一样，
是你要存放到列表中的对象。第二个
对象不是它在集合中的位置，而是**词条**，
借助它以后可以取回前一个对象。简而言之，
字典的工作方式有点像词典：通过关键字
可以查到其含义。例如，要从
上面的列表中取出软糖的价格：

```
>> price := 菜单 在: ['fudge'].
```

你也可以使用简洁写法：

```
>> price := 菜单 ? ['fudge'].
```

如果用来存放对象的词条不含空格
（并且不与其他预定义消息冲突），
还可以使用下面的写法：

```
>> 菜单 := 映射对象 新建
	pie:   ['£5'],
	cake:  ['£6'],
	fudge: ['£3'].
```

毫无疑问，上面的写法读起来更自然一些。
要查询软糖的价格，
可以使用下面的简化写法：

```
>> price := 菜单 fudge.
```

## 会话

为了实现持久化，你可以在会话对象中存储和获取数据。
首先创建一个新的 **网页文档**。网页文档 对象把
请求、头部、HTML 和会话联系在一起。这是因为，每当你
用浏览器访问一个网站时，你只能看到 HTML。但
整个网页文档还包括**头部**。例如，
大多数 HTTP 响应都包含类似 Content-type:text/html 这样的头部，
告诉浏览器后面的数据应当作为 HTML 渲染
（而不是例如像文件一样被下载）。会话是一种
在请求之间存储用户数据的方式。为了跟踪这些数据，我们需要
设置一个 cookie，而这个 cookie 也是通过头部设置的。这就是为什么
一切都汇集在 网页文档 中（因为它是包含头部以及 HTML 或其他数据的
完整文档）。


```
# 首先创建一个新的 网页文档 实例
>> 网页 := 网页文档 新建.

# 现在启动会话，这会为 cookie 生成一个头部，并
# 创建一个文件来存储你的数据，与该 cookie 关联
>> 会话值 := 网页 开始会话.

# 现在可以像 映射对象 一样使用 会话值
会话值 userid: 123.
```

销毁会话（在注销时）：

```
网页 销毁会话.
```

## 模板

默认的模板系统非常简单。你不必学习
新的模板语法。此外，模板引擎确保了表现层与
业务逻辑之间的真正分离。

从文件创建模板：

```
>> tpl := 网页 模板: ['templates/ux.tpl'].
```

模板系统使用标记。
标记有三种类型：剪切标记、粘贴标记和
插槽标记。基本思路非常简单：你剪下
由剪切标记标识的区域，然后可以把它们粘贴到
由粘贴标记标识的区域。你可以把字符串注入到
插槽标记中。

例如，给定下面的模板，我们把
宝石放进珠宝盒，并加上价签。

```
<!-- cut:gem -->
<img src="gem.gif">
<b>$<!-- slot:price --></b>
<!-- /cut:gem -->

<div id="box">
<!-- paste:jewels -->
</div>
```

可以这样做：

```
>> gem := tpl 剪切: ['gem'], 复制.
gem price: 99.
tpl 粘贴: gem 在: ['jewels'].
网页 输出: tpl 清理标记.
```

最后一行只是把模板作为字符串，连同所需的 HTTP 头部
一起输出给客户端。

结果：

```
<div id="box">
<img src="gem.gif">
<b>$99</b>
</div>
```


## 透传

要安全地提供用户上传的文件，可以依靠透传：

```
>> 已上传 := ['smile.gif'].

程序 结束.
```

这会以适当的 mime 类型提供用户上传的内容。
只支持白名单中的 mime 类型：
GIF、JPG、PNG、WEBP、MP4、WEBM、MP3、ZIP、GZIP、PDF 和 SVG。
SVG、ZIP 和 GZIP 文件以下载方式发送，因为 SVG
可能包含脚本，否则这些脚本会在你的域名下运行。
这种方法可以防止 TOCTOU 攻击、路径遍历、
恶意代码执行（注入）、符号链接攻击、
DDoS 攻击（文件上限 = 50MB）、嗅探攻击以及
其他各种安全问题。

## 格式化

一个格式只能包含一个转换说明符，并且必须与值相匹配，

- `应用:` 用于字符串：`%s`

来自请求的值都是字符串。要把它格式化为数字，
需要先进行转换：

```
fmt 应用: (http请求 搜索词: ['amount']) 转数值.
```

# ffi

{{messages}}

FFI 是按平台/插件提供的，因为它
与底层系统体系结构紧密相关，而这是
核心不应该做的事情。
服务器插件提供了一个符合规范的 ffi/blob 实现。
默认情况下，核心通过 stdin/stdout、有限的文件 i/o 服务
和 shell（程序 系统命令:）与目标平台连接。
额外的集成则由 ffi/blob 通过以应用为中心的插件
（例如服务器插件）来提供。

FFI 是 Foreign Function Interface（外部函数接口）的缩写。它让你可以使用他人用
其他编程语言编写、并通过 DLL 文件、SO 文件或 Dylib 文件提供的功能。这些功能
可以是各种各样的函数，通过这种方式可以使用的功能极其丰富。
我们从一个示例开始：

```
Server 链接: (
 数组对象 新建 ;
 ['/usr/lib/x86_64-linux-gnu/libc.so.6'] ;
 ['printf'] ;
 ( 数组对象 新建 ; ['pointer'] ; ['int'] ) ;
 ['void'] ;
 ['Printf'] ;
 ['template:number:']
).
>> s := 二进制 可读的: ['FFI has %d letters.\n'].
Printf template: s number: 3.
s 释放.
```

这段代码的结果是，你会在命令行上看到以下内容：
FFI has 3 letters.
现在，你可能在想："这么简单的事情，代码可真多。"
确实，难道我们不能直接用一个 Gui show 命令来解决吗？答案是肯定的！
但这只是一个说明性的示例。
FFI 通常用于更复杂的任务，但那些任务不适合作为
示例，所以我选择了一个简单的例子。

链接方法的参数：

- 参数 #1：你要使用的 DLL 或 SO 文件。
- 参数 #2：你要链接的该文件中的函数。
- 参数 #3：一个列表，包含该函数各参数的数据类型名称。
- 参数 #4：该函数返回类型的名称。
- 参数 #5：你要把该函数链接到的对象的名称（如果该对象不存在，将会
自动创建）。
- 参数 #6：该函数应链接到的消息。

在上面的示例中，我们要链接 libc.so 中的 printf 函数。你可以在
所链接软件的文档中找到数据类型名称。可用的类型有：
void、pointer、float、double、int、uint、char、uchar、intX 和 uintX，
其中 X 可以是 8、16、32 或 64。

这些类型指的是存储数据所需的字节数。对于 printf，我们把它链接到
一个名为 Printf 的新对象和消息 template:number:。在使用外部
函数之前，你要先把它翻译成 XOScript 的表达方式。消息 template:number: 期望
第一个参数是一个包含模板文本的缓冲区。我们使用 二进制 对象创建这个缓冲区，
它允许你手动分配内存。之后，你有责任
使用 释放 消息来释放这块内存。

你可以用多种方式填充内存 blob。在我们的示例中，我们用文本来填充它，因此使用
可读的: 消息（UTF-8 是一种把文本转换为字节的编码）。你也可以用
字节: 来填充 blob，并传入一个字节值列表。要读取 blob 的内容，请使用 从:长度:。
你会以列表的形式取回这些字节。你甚至可以使用
结构: 消息，并传入一串 C 类型，用 二进制 来创建一个 C 结构体。当调用外部软件库中
期望接收结构体指针的 C 函数时，可能需要这样做。

{warning}
你需要自己释放 blob。
垃圾回收器不会清理 blob。
{/warning}

由于 blob 可以与库中的外部函数交换，它们
无法被自动垃圾回收（它们可能仍在被外部函数使用，
或者这些外部函数可能希望自己释放它们）。
因此，必要时你需要自己释放 blob。

释放 blob：

```
我的blob 释放.
```

释放结构体：

```
我的结构体 结构释放 释放.
```

因此，对于结构体，你需要发送两条消息：结构释放 和 释放，
才能释放该内存块。
