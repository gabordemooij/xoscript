ברוכים הבאים ל-XOScript
מטרת פרויקט XOScript היא ליצור שפת סקריפטים פשוטה וניתנת לביקורת.
פשוטה אין פירושה בהכרח קלה.
ייתכן ששפת תכנות מוכרת תהיה קלה יותר לשימוש מאשר XOScript.
כאן, פשטות פירושה דבר אחר:
היכולת לבנות מודל מחשבתי שלם של השפה ושל התנהגותה.

XOScript תוכננה כך שתוכלו להחזיק אותה כולה בראש.
הדקדוק שלה ומספר המושגים בה קטנים בכוונה.
אין בה מחלקות; ניתן להרחיב אובייקטים ישירות.
אובייקטים מועברים לפי הפניה, העתקה נעשית במפורש,
ולפונקציות יש נקודת יציאה אחת בלבד.

חלק מהבחירות הללו שונות מאוד מהמקובל בשפות הנפוצות.
ל-XOScript, למשל, אין מערכת טיפוסים, והיא משתמשת בתחום הגדרה דינמי.
הודעות שלא ניתן לטפל בהן מתעלמים מהן, במקום לזרוק חריגה.
לבחירות הללו יש השלכות, והן אינן נועדו למנוע שגיאות.
הן נועדו לשמור על המודל הבסיסי של השפה קטן ועקבי.

ניתן גם לבצע לוקליזציה של XOScript, וכך אפשר לנסח כללים עסקיים
בשפה טבעית ואף לשתף אותם עם בעלי עניין שאינם טכניים.

ביקורתיות פירושה החלת אותה פילוסופיה גם על המימוש.
סביבת הריצה כתובה ב-C, עם מנתח לקסיקלי, מנתח תחבירי ומהלך עץ קטנים שנכתבו ביד.
הספרייה הסטנדרטית וסביבת הריצה משקפות במידה רבה את מבנה השפה,
וכך הקשר בין קוד XOScript לבין המימוש שלו ישיר יחסית.

גם הבדיקות קשורות קשר הדוק לתיעוד.
לכל מתודה אמורה להיות בדיקה משויכת שניתן לשלב במדריך,
וכך התיעוד נשאר מתואם עם המימוש.

XOScript אינה מתיימרת להתחרות בשפות הנפוצות
בתכונות או במוכרות. היא חוקרת מטרה אחרת:
סביבת תכנות שמפתח יכול להבין כמכלול.

התקווה היא ששפה קטנה ומימוש קטן
יאפשרו בפועל להבין תוכנה
מהבית ועד האובייקט, מהתחביר ועד סביבת הריצה, ולכתוב קוד
בביטחון, משום שאתם מבינים גם מה קורה
בסקריפט וגם מה קורה מתחת למכסה המנוע.

הארכיטקטורה של התקנת שרת xoscript
פשוטה, ועם זאת גמישה.

{{architecture.png}}

כדי להשתמש ב-xoscript כשפת שרת, עליכם להתקין את
תוסף השרת בתיקייה בשם /mods/server. 

הסיבה לכך היא שאנו מעדיפים
להפריד את ליבת השפה מפונקציונליות ייחודית לשרת,
בניגוד, למשל, ל-PHP או ל-Python. אחרת היינו נאלצים לשלוח לכולם
את כל הכיור והמטבח ללא כל צורך, וזה פשוט מגוחך.
ניתן להתקין גם מודולים אחרים אם תרצו. המערכת
גמישה מאוד.

בנוסף, חלק מהפונקציות עדיף לממש בשפת הסקריפטים
עצמה, כמו תבניות וניהול הפעלות, ולכן אנו מצרפים
גם את הספריות template.xo ו-webtools.xo לנוחותכם.
הסיבה לכל זה היא שאיננו יודעים כיצד תרצו
להשתמש ב-xoscript. ניתן להשתמש בה כשפת סקריפטים בצד השרת,
אך גם לממשקים גרפיים, למכשירים משובצים או סתם לעיבוד אצוות.
גם אם אתם משתמשים בה כשפת סקריפטים בצד השרת (שהוא
כיום אחד משימושיה העיקריים), ייתכן שעדיין תרצו
להשתמש במנוע תבניות אחר או במנהל הפעלות אחר.
מי אנחנו שנחליט שעליכם להשתמש בשלנו?

אחד היתרונות בשימוש במנוע התבניות שלנו הוא
שאין צורך ללמוד תחביר נוסף כדי ליצור תבניות.
מנוע התבניות המגיע כברירת מחדל עם xoscript מקיים הפרדה של 100%
בין התצוגה ללוגיקה. במקום תחביר תבניות
מיוחד, הוא פשוט משתמש במערכת גמישה מאוד של סמני משבצות.
למידע נוסף, ראו את הפרק שרת.

שימו לב: אם אינכם רוצים להשתמש במנוע התבניות המוגדר כברירת מחדל או
בכלי הרשת המוגדרים כברירת מחדל, ברור מאליו שעליכם לספק
מימוש משלכם.

אם שרת האינטרנט שלכם רץ בתוך chroot, jail או ארגז חול מסוג אחר,
עליכם להתקין גם את התלויות של xo באותה סביבה. ניתן
לראות אילו ספריות דרושות באמצעות ldd (ראו את דף ה-man של Linux או BSD).
אם ברצונכם להשתמש בפקודות מעטפת בסקריפטי ה-xo שלכם, העתיקו גם מעטפת
(כמו bash או ksh) לסביבה זו.

עוד ברצוננו לציין שאנו מתייחסים לתאימות לאחור ברצינות רבה.
קיימת אף תכונת תאימות לאחור מיוחדת בשם
'version'. באופן כללי, אנו שואפים שהקוד שלכם ירוץ לנצח. כך
לעולם לא תצטרכו לעדכן את הקוד שלכם כדי לשמור על תאימות לגרסאות חדשות יותר
של xoscript. המטרה שלנו: לכתוב פעם אחת, להריץ לנצח.

שאר המדריך מוקדש להסבר מפורט של שפת התכנות
xoscript. כתיבת סקריפטים לשרת נדונה בפרק
שרת. אם אתם מפתחי תוכנה מנוסים, ייתכן שתרצו
לדלג על כמה פרקים, משום שחלקם מפורטים מעט יתר על המידה או
דומים מאוד לנוהגי תכנות כלליים. לכן, מי שכבר
יש לו ניסיון בכמה שפות תכנות אחרות,
מוטב שיתייחס למדריך זה כמדריך עיון.

## התקנה ב-Linux

הורידו את apache2 ואת mariadb:


```
sudo apt-get install apache2 mariadb-server
sudo a2enmod cgi
```

הורידו את xoscript.
החליפו את X במספר הגרסה הנכון!

```
wget https://xoscript.com/downloads/xoserver-linux-1_5_X.tar.gz
tar xvf xoserver*.tar.gz
```

העתיקו את הקבצים לתיקיית שורש האתר ול-/bin:


```
sudo cp bin/xo /bin/xo
sudo cp -R bin/mods /var/www/html/
sudo cp *.xo /var/www/html/
```

ערכו את קובץ התצורה של apache2:

```
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

החליפו את Virtualhost ב:

```
<VirtualHost *:80>
    <Directory /var/www/html>
        Options +ExecCGI
        AllowOverride All
        AddHandler cgi-script .xo
        Require all granted
    </Directory>
    DocumentRoot /var/www/html
</VirtualHost>
```

צרו דף בדיקה:

```
sudo nano /var/www/html/test.xo
```

וכתבו תוכנית בדיקה קטנה:

```
#!/bin/xo
Server אתחל.
תוכנית השתמש: ⌝'webtools.xo'⌜.
>> web := מסמך-רשת חדש.
web פלוט: ⌝'Hello World'⌜.
```

אפשרו ל-apache2 להריץ את התוכנית שלכם דרך CGI:

```
sudo chmod uog+x /var/www/html/test.xo
```

הפעילו מחדש את apache2:

```
sudo systemctl restart apache2
```

גשו לדף הבדיקה שלכם בדפדפן:

```
http://localhost/test.xo
```

אתם אמורים לראות:

```
Hello World
```


## התקנה ב-OpenBSD

ערכו את /etc/httpd.conf, והוסיפו:


```
server "mydomain.com" {
    listen on * port 80
    root "/htdocs/mydomain/"

    location "*.xo" {
        fastcgi
        fastcgi socket "/run/slowcgi.sock"   # inside chroot
    }
}
```

אם ברצונכם להשתמש ב-SSL:

```
listen on * tls port 443
tls {
	certificate "/etc/ssl/mycert.crt"
	key "/etc/ssl/private/mykey.key"
}
```

כדי להגן על החלפת המפתחות מפני מחשבים קוונטיים,
בחרו בצופן mlkem:

```
tls {
 ... 
 ecdhe "X25519MLKEM768"
 ...
}
```

הוסיפו את קובץ ההרצה xo ואת ה-mods, וכן את כל התלויות, לתוך
ה-chroot (בררו אותן בעזרת ldd).

## הרצת דוגמאות


כדי להריץ אחת מתוכניות הדוגמה שבחבילה:

```
./example.sh <name> <Linux/OBSD> [clean]
```

לדוגמה, כדי להריץ את דוגמת FizzBuzz ב-Linux:

```
./example.sh fizzbuzz Linux
```

כדי להריץ את אותה דוגמה ב-OpenBSD:

```
./example.sh fizzbuzz OBSD
```

כדי להריץ את הדוגמה עם בנייה נקייה:

```
./example.sh fizzbuzz OBSD clean
```

## בדיקות יחידה

כדי להריץ את בדיקות היחידה:

```
./runtests.sh
```

כדי להריץ את בדיקות היחידה ללא בנייה (בדיקה בלבד):

```
./runtests.sh nobuild
```

## בנייה

כדי לבנות מקוד המקור ב-Linux:

```
make clean
ISO="en" make
```

ב-OpenBSD:

```
make -f makefile.obsd clean
ISO="en" make -f makefile.obsd
```

כדי לבנות את תוסף השרת ב-Linux:

```
PACKAGE="server" NAME="server.so" make plugin-clean
ISO="en" PACKAGE="server" NAME="server.so" make plugin
```

כדי לבנות את תוסף השרת ב-OpenBSD:

```
PACKAGE="server" NAME="server.so" make -f makefile.obsd plugin-clean
ISO="en" PACKAGE="server" NAME="server.so" make -f makefile.obsd plugin
```

## שלום עולם

לאחר שהקובץ הועבר למחשב שלכם, תוכלו לחלץ אותו
ולהפעיל את xo באמצעות הפקודה הבאה:

```
xo
```

כדי להריץ XOScript, שמרו את התוכנית כקובץ עם הסיומת
-xo (אופציונלי). בנוסף, הוסיפו את שם הקובץ של התוכנית שלכם
אחרי הפקודה של XOScript:

```
xo myprogram.xo
```

כאשר אתם מריצים פקודת XOScript ומעבירים את קובץ התוכנית שלכם
כפרמטר, xo תקרא ותריץ את קובץ התוכנית.

{{note}}
ניתן גם להפעיל את התוכנית על ידי גרירתה אל הסמל של xo.
{{/note}}

{{warning}}
במערכות מסוימות יש לתת ל-xo מראש הרשאה לטעון ספריות
דינמיות.
{{/warning}}

המסורת מכתיבה שהתוכנית הראשונה בכל שפת תכנות
חדשה תהיה מעין ברכה לעולם. ב-XOScript, תוכנית
**שלום עולם** כזו נראית כך:

@test598

כאשר הטקסט נשמר לקובץ, למשל hello.xo, ניתן להריץ אותו
כך: .

xo hello.xo

Hello world


את פלט התוכנית ניתן לראות בחלון השחור שלמעלה.
לאורך המדריך ישמש אותו אופן הצגה כדי להראות
את הפלט.

{{note}}
פלט נכתב באות גדולה בתחילתו (באנגלית: Out עם O גדולה).
באופן כללי שמות אובייקטים מתחילים באות גדולה,
אלא אם האובייקט משמש כמופע (אין לו מתודות
משלו, רק נתונים). הדבר משקף את המוסכמה של מחלקה מול מופע
בשפות תכנות אחרות.
{{/note}}


## תחביר 

XOScript היא שפת תכנות *מונחית עצמים* *טהורה*. משמעות הדבר
ש-xoscript רואה בכל דבר אובייקט, ולכן אין
*טיפוסי נתונים* אחרים. ביסודו של דבר יש שלוש פעולות שגרתיות בסיסיות
בתוכנית שנכתבה ב-XOScript: *השמה*, *שליחת הודעות*
ו*מענה*. החלפת הודעות בין אובייקטים היא החלק המרכזי של
תוכנית XOScript. שלוש הפעולות השגרתיות מודגמות
להלן:


פעולה           | דוגמה
--------------- | --------
השמה            |  \>\> x := 1. 
הודעות אונריות  | x זוגי?.
הודעה בינארית   | 1 + 2.
הודעת מילת מפתח | x התחלה: 0 אורך: 10.
מענה            | <- answer.  


פרק זה ייתן לכם רושם כללי על שפת XOScript
ויתאר את עקרונותיה הבסיסיים. XOScript היא שפה קטנה
המבוססת על שלוש פעולות (ראו איור), המתורגמות
לכשישה כללי דקדוק. זה כל מה שנדרש כדי לשלוט
בשפה.

אל דאגה אם הדברים אינם ברורים לכם מיד: כל אבני
הבניין ייחקרו בפרק הבא (3) והכללים הבסיסיים
יחזרו על עצמם. הפרק הנוכחי, לעומת זאת, משמש בעיקר כמבוא
כללי לשפה. העקרונות הבסיסיים יוסברו בקצרה
וימחישו באמצעות כמה דוגמאות רלוונטיות. פרטים
חסרים יפורטו בהמשך.

הערות ב-XOScript מתחילות בסימן \#. לכן השורה הבאה
לא תילקח בחשבון:

```
# this is just a comment
```

## משתנים

כדי להציב
משתנה משתמשים בסימן הצהרת המשתנה: >>. שם של
משתנה יכול להכיל כל סימן מלבד: <-, :=, רווחים,
נקודות, פסיקים, נקודתיים, מירכאות ⌝' '⌜ וסוגריים ﴿﴾.
בנוסף, משתנה אינו יכול להשתרע על פני כמה שורות. שימו לב
שמשתנה אינו יכול להתחיל בספרה או בסימן מינוס.

אלה דוגמאות למשתנים תקינים:

```
>> password := ⌝'Secret'⌜.
>> ♡♡♡ := 3.
>> $ := ⌝'dollar'⌜.
>> +plus := אמת.
>> user-password := ⌝'Pssst!'⌜.
```

משתנים לא תקינים הם, למשל:


```
>> -123 := ⌝'negative number'⌜.
>> password of user := ⌝'Classified'⌜.
>> password.of:user := ⌝'Classified'⌜.
>> ,x := 10.
```

{{note}}
אין צורך לבצע escape לאף תו
(כולל גרש, מירכאות כפולות, גבולות
מחרוזת) בתוך
מחרוזת מילולית, כל עוד הדבר אינו
יוצר דו-משמעות עבור המנתח הלקסיקלי.
{{/note}}

לאחר שמשתנה הוצהר, ניתן להשתמש בו בחופשיות. כלומר,
יש להשתמש בסימן ההצהרה רק בפעם הראשונה
שבה משתמשים במשתנה (ההצהרה).

ליתר דיוק, אי אפשר פשוט להתחיל להציב ערך
במשתנה *(x := 2)*, משום שקודם יש להצהיר על המשתנה *(\>\>
x := 2)*. עם זאת, לאחר ההצהרה מותר לשנות את ערכו
בלי להשתמש בסימן ההצהרה*(\>\> x := 2. x := 3.)*.

שימו לב שחובה להציב ערך במשתנה בזמן
ההצהרה. בניגוד לשפות תכנות אחרות, אסור
להצהיר על משתנה ללא ערך. חיוני לקשור במפורש
כל משתנה לערך התחלתי. עם זאת, אתם מוזמנים לאתחל
את המשתנה עם האובייקט **כלום**. במקרה זה ניתן
לראות במשתנה ריק *(\>\> x := כלום.)*. בקיצור, אסור להצהיר על
משתנה ללא ערך התחלתי. לכן,

```
>> x.
```

אינו תקין ויגרום להודעת שגיאה.

{{note}}
xoscript משתמשת בתחום הגדרה דינמי של משתנים;
לפרטים עיינו בפרק פונקציות.
{{/note}}


## ליטרלים

XOScript רואה בכל דבר אובייקט; כלומר, כל המספרים, המחרוזות
וקטעי הקוד. מספרים, כגון 1, 2, 100, -999 ו-1,234, הם
אובייקטים מסוג מספר. כל טקסט שבין מירכאות בודדות הוא אובייקט
מחרוזת. כל קטעי הקוד המקובצים בין סוגריים מסולסלים ⎬...⎨ הם
אובייקטים מסוג פונקציה.

ליטרל           | אובייקט שורש | דוגמה
--------------- | ------------ | ----------
מספרים          | מספר         | 1,2,3... 
מחרוזות         | מחרוזת       | ⌝'hello'⌜
פונקציה         | פונקציה      | ⎬ 1 + 2. ⎨.
                
     
מקורם של אובייקטים כגון מספרים ומחרוזות הוא תמיד באובייקט
שורש. לדוגמה, כל המספרים נגזרים מהאובייקט **מספר**. כל
המחרוזות נגזרות מ-**מחרוזת** וכל קטעי הקוד מ-**פונקציה**.
בתורם, כל האובייקטים הללו נובעים מ-**אובייקט**, שהוא למעשה
אובייקט השורש של כל האובייקטים.


## הודעות

תכנות ב-XOScript פירושו ביסודו
שליחת הודעות לאובייקטים. הכתיב הכללי לשליחת הודעה
לאובייקט הוא כדלקמן:

```
<object> <message>
```

כדי לברר, למשל, אם המספר **2** הוא מספר זוגי,
נשלחת ההודעה **זוגי?** לאובייקט **2**:

```
2 זוגי?
```

התשובה תהיה **אמת** (שוב, אובייקט). אובייקטים בדרך כלל
מתעלמים מהודעות לא מוכרות; לכן לא תתרחש שגיאה. אובייקטים מסוימים (למשל,
מספרים או מחרוזות) מגיבים להודעה לא מוכרת באופן מוגדר מראש
(על כך בהמשך).

אובייקט יכול לקבל שלושה סוגים של הודעות. 

סוג             | מספר ארגומנטים
--------------- | -------------------
אונרית          | 0      
בינארית         | 1     
מילת מפתח       | 1+    


ראשית, יש **הודעות
אונריות**, ראו את הדוגמה שלמעלה, שאין להן ארגומנטים. שנית,
יש **הודעות מילת מפתח**, שיש להן ארגומנט אחד או יותר,
לדוגמה:

```
>> x := מספר בין: 1 לבין: 10.
```

במקרה זה ההודעה **בין:לבין:** נשלחת ל-**מספר**, שהוא
אובייקט השורש של כל המספרים. התוצאה תהיה מספר אקראי
בין 1 ל-10. לבסוף, יש **הודעות בינאריות**, שיש להן
תו אחד בלבד וארגומנט אחד:

```
2 + 3
```

זה נראה כמו תרגיל חשבון, אך למעשה זו פשוט הודעה נוספת.
ההודעה **+** נשלחת ל-**2**, עם הארגומנט **3**, והיא תחזיר
את התשובה **5**. מותר לכתוב הודעות בינאריות ללא נקודתיים.

ניתן לשרשר הודעות בינאריות:

```
>> x := 3 + 2 - 1.
```

בקטע זה, **+ 2** נשלח תחילה לאובייקט ה**מספר** **3**, מה
שמניב את אובייקט המספר **5**, ולאחר מכן **-1** נשלח למספר
זה. קוראים חדי עין צודקים כשהם מבחינים בפער שמראה
פרוטוקול זה ביחס לסדר הפעולות המתמטי המקובל של
אופרטורים. XOScript מתעלמת מסדר הפעולות המתמטי לטובת
עקביות במערכת ההודעות שלה. כתוצאה מכך, התרגיל:

```
2 + 3 * 5 = 25
```

ולא 17.

זה מכוון. ניתן להשתמש בסוגריים כדי לשנות את הסדר:

```
2 + ﴿3 * 5﴾ = 17
```

רוב האובייקטים מחזירים את עצמם כתוצאה בתגובה להודעה
מסוימת. הדבר מועיל, משום שהוא מעודד המשך דיאלוג עם
האובייקט באמצעות שליחת הודעת המשך:

```
פלט כתוב:
⌝' hello '⌜ קיצוץ-רווחים אותיות-גדולות.
```

```
HELLO
```

כאן נשלחות שתי הודעות לאובייקט ה**מחרוזת**: **קיצוץ-רווחים**, ואחריה
**אותיות-גדולות**.

בקטע הבא יש צורך בפסיק כדי לציין
שמגיעה הודעה חדשה. אחרת XOScript תתבלבל.

```
פלט כתוב: ⌝'Hello!'⌜, שורה-חדשה.
```

תחילה נשלחת ההודעה **כתוב:** לסמל העיפרון, ואחריה
**שורה-חדשה**. ללא הפסיק, XOScript הייתה חושבת שברצונכם לשלוח
את **שורה-חדשה** ל**מחרוזת** **Hello!**, תרגיל חסר תועלת.

סדר העיבוד של הודעות הוא כדלקמן: משמאל לימין;
מתחילים בהודעות שבתוך סוגריים, ואחריהן הודעות אונריות. לאחר מכן
הודעות בינאריות, ולבסוף הודעות מילת מפתח. ראו את הדוגמה
שלהלן:

```
פלט כתוב: 0.5 עיגול + ﴿2 - 1﴾, שורה-חדשה.
```

XOScript תמיד קוראת משמאל לימין: תחילה נשלחת ההודעה **כתוב:**
ל-פלט, ואחריה ההודעה **שורה-חדשה**. בתוך
הארגומנט עצמו, XOScript קוראת משמאל לימין, ולכן תחילה **0.5 עיגול**
ואחר כך **+**.

{{note}}
ההודעה שורה-חדשה מוסיפה תו שורה חדשה למחרוזת.
השם האנגלי של הודעה זו (stop) שואב השראה ממערכות טלגרף.
בהודעות במערכות טלגרף
נהגו להשתמש לעתים קרובות במילה STOP לציון סוף משפט
(משום שסימני פיסוק היו לא אמינים או יקרים).
{{/note}}

יתרה מזו, **עיגול** קודמת ל-**+**, משום שהיא
**הודעה אונרית**. בשל הסוגריים, **2 - 1** מחושב
ראשון, ולאחר מכן **1** מתווסף לתוצאה של **0.5 עיגול** (1).

התהליך כולו ייתן את התוצאה **2**, שהיא גם התשובה
הנכתבת. אחרי הפסיק באה ההודעה שורה-חדשה, המעבירה את הסמן
לשורה חדשה. כמובן, הדרך הטובה ביותר להבין לעומק את סדר
הביצוע של תוכניות XOScript היא באמצעות תרגול.

ראוי לציין שב-XOScript, בניגוד לשפות תכנות רבות
אחרות, רווחים הם חלק יסודי מהתחביר. בפרט
כשמדובר בהודעות בינאריות, רווחים עלולים לגרום
לבלבול. השתמשו תמיד ברווח אחרי הודעה בינארית. אי אפשר
להצמיד מספר ישירות להודעה, לדוגמה: 

```
3 + 2
```

שונה מ- 

```
3 +2
```

הדוגמה הראשונה (**3 + 2**) שולחת את
ההודעה **+** למספר **3**, עם הארגומנט המספר **2**.
התוצאה במקרה זה תהיה **5**. בדוגמה השנייה (**3 +2**),
ההודעה האונרית **+2** נשלחת למספר **3**. בהתאם
להקשר, הדבר עשוי להניב תוצאה שונה מאוד.

## מתודות שאינן קיימות

שליחת הודעה לאובייקט מפעילה את הפונקציה שהוצמדה
לאובייקט זה תחת שם ההודעה. אם תשלחו הודעה
שאינה מובנת, האובייקט המקבל יתעלם מההודעה
ויחזיר במקום זאת הפניה לעצמו להמשך התקשורת.
זה נקרא העברת הודעות סובלנית.

דוגמה:

```
פלט כתוב: אובייקט blah, שורה-חדשה.
```

הדבר לא יגרום לשגיאה. הוא פשוט ידפיס את הטקסט **אובייקט**.


## בקרת זרימה

ב-XOScript אין צורך בכללי דקדוק נפרדים ל*לולאות* ול*תנאים*.
משפט תנאי הוא פשוט הודעת **אם-אמת:** או **אם-שקר:**
לאובייקט **אמת** או לאובייקט **שקר**:

```
2 זוגי? אם-אמת: ⎬
	פלט כתוב: ⌝'Two is an even number'⌜, שורה-חדשה.
⎨.
```
בדוגמה הקודמת, ההודעה **אם-אמת:** נשלחת ל-**אמת** (התשובה
לשאלה: האם 2 הוא מספר זוגי?). כארגומנט נשלח יחד איתה קטע
קוד נוסף: אובייקט **פונקציה**. פונקציה זו כותבת על
המסך ש-2 הוא, אכן, מספר זוגי.

גם ל*לולאה* אין צורך בכללי כתיבה נפרדים. כדי
להריץ קטע קוד שלוש פעמים, פשוט שלחו **\*** עם הארגומנט
**3** לאותה **פונקציה**:

הלאה.

## שילוב ערכים במחרוזות

את רשימת *kJ/kcal* אפשר היה להציג בצורה
נאה יותר. רצוי שהרשימה תיראה כך:

```
100 kj ➞ 23.88 kcal

200 kj ➞ 47.76 kcal
```

כאשר ממירים את הפלט הרצוי לתבנית, הכתיב שלה
יכול להיות:

```
number1 kJ ➞ number2 kcal
```

כלומר, **number1** מייצג את ערך ה-kJ ו-**number2** את
ערך ה-kcal. כך פועל שילוב ערכים במחרוזות ב-XOScript. אין
צורך בכללי דקדוק נפרדים לשם כך ב-XOScript. פשוט שלחו
לטקסט את המילה שיש להחליף, עם טקסט התחליף
כארגומנט:

```
>> text :=

⌝'number1 kJ ➞ number2 kcal'⌜

number1: 100,

number2: 23.9.
```

התוצאה:

```
100 kj ➞ 23.9 kcal
```

כלל החלפה זה פועל לכל הודעה לא מוגדרת שמתקבלת
באובייקט **מחרוזת**. כל הודעה שאובייקט ה**מחרוזת**
אינו מזהה תפורש כך:
*החלף את טקסט ההודעה בטקסט שבארגומנט ההודעה.* ניתן להתאים את
התוכנית כך:


@test601


כדי למנוע בלבול לגבי אילו הודעות ניתן או לא ניתן להשתמש בהן
כתחליף, מוטב להכניס סמן תבנית כמו &lt; &gt;
לקטעי טקסט בתבנית
שיש להחליף.

# אובייקטים

{{messages}}

מלבד התאמה והרחבה של אובייקטים קיימים, ניתן גם ליצור
אובייקטים חדשים בעצמכם, פשוט על ידי שליחת ההודעה **חדש**. נניח
שברצונכם ליצור אובייקט חשבונית שאוכף רצף
מספור; במקרה כזה, תזדקקו תחילה לאובייקט חשבונית.

מאחר שכל אובייקט נגזר מאובייקט אחר, שבתורו
מקורו בסופו של דבר באובייקט השורש של כל האובייקטים, הנקרא אובייקט,
יש לבחור על איזה מאותם אובייקטים אחרים יתבסס
האובייקט החדש שלכם. האובייקט החדש יורש את כל התכונות של
האובייקט שעליו הוא מבוסס, כלומר, זה שאליו נשלחה
ההודעה **חדש** מלכתחילה.

בדוגמה זו עדיף אובייקט נייטרלי למדי, כזה שאין לו
יותר מדי תכונות בירושה. הבחירה כאן קלה, משום שבמקרה
זה ניתן לבסס את האובייקט החדש על אובייקט השורש עצמו, שהוא
**אובייקט**. כתיב מערכת החשבוניות המיועדת יהיה אפוא
כדלקמן:

@test604

מספר החשבונית הנוכחי נשמר באובייקט, ולכן
מוצבת לפניו מילת המפתח **שלי**. זה נקרא *תכונה*;
פרטים נוספים יבואו בהמשך.

עסקים מסוימים מעדיפים לשלב את השנה במספרי
החשבוניות. במקרה זה, ניתן ליצור אובייקט חשבונית חדש המבוסס על
אובייקט חשבונית קודם, אך המאפשר למשתמש בו
להזין שנה מסוימת:

@test605

אין צורך לכתוב שוב את המימוש של ההודעה **למספר**,
משום שהיא עוברת בירושה מ**אובייקט החשבונית** שנכתב
קודם; כך ניתן לעשות שימוש חוזר בקוד ישן. ב-XOScript אין
מושגים כמו מחלקות ומושגים קשורים אחרים. משמעות הדבר שאובייקטים
יכולים לרשת רק מאובייקטים אחרים, מה שמכונה גם *ירושה
מבוססת אב-טיפוס*.

ועכשיו, בחזרה לתכונות. ניתן לגשת לתכונות של אובייקט רק
*מתוך היררכיית האובייקט*, ולכן תכונות אלה
אינן נראות לאובייקטים אחרים.

בניגוד לשפות תכנות אחרות, כל התכונות של אובייקטים
גלויות אך ורק לאובייקט שיצר את התכונה ולאובייקטים
הנגזרים ממנו.

## אובייקטים דמויי מחלקה

אף ש-xoscript אינה מציעה מחלקות, חיקוי של התנהגות דמוית
מחלקה הוא פשוט. פשוט דרסו את ההודעה חדש.

```
>> Animal := אובייקט חדש.
Animal בקבלת: ⌝'חדש'⌜ בצע: ⎬
	<- עצמי חדש אתחל.
⎨.

Animal בקבלת: ⌝'אתחל'⌜ בצע: ⎬
	שלי sound := ⌝'?'⌜.
	שלי legs  := 4.
⎨.
```

בקטע הקוד שלמעלה אנו יוצרים אובייקט בשם Animal.
אובייקט זה משמש כ*שרטוט* לכל סוגי בעלי החיים,
כמו כלבים וחתולים. אובייקט האב Animal נכתב
עם A גדולה כדי לציין שזהו אובייקט דמוי מחלקה.
לאחר מכן אנו דורסים את ההודעה חדש על ידי כתיבת מתודת חדש משלנו.
במקרה זה היא שולחת את ההודעה חדש ל-עצמי, ואחריה את ההודעה
אתחל. מאחר ש-xoscript חוסמת רקורסיה כברירת מחדל, הדבר לא יגרום
ללולאה אינסופית. במקום זאת, היא תשלח את ההודעה חדש לאובייקט
האב (אובייקט), והתוצאה תהיה מופע חדש של Animal. כך אנו יוצרים
אובייקט חדש, המבוסס על אותו אובייקט שעבורו יצרנו את מתודת החדש שלנו.
זה תקין לחלוטין. כעת אנו שולחים גם את ההודעה אתחל, וזו מבטיחה
שלאובייקט Animal יהיו ערכי ברירת מחדל לתכונותיו. כברירת מחדל
לבעל חיים יש 4 רגליים והקול אינו ידוע (ומכאן סימן השאלה).
כדי ליצור מופע חדש של Animal שלנו, נוכל פשוט לכתוב:

```
>> a := Animal חדש.
```

כעת אנו מקבלים מופע חדש של Animal עם 4 רגליים, קול לא ידוע
ומתודת אתחל. בדיוק כמו בשפות OOP אחרות, אנו יכולים גם
להרחיב את Animal שלנו:

```
>> Dog := Animal חדש.
Dog בקבלת: ⌝'אתחל'⌜ בצע: ⎬
	עצמי אתחל.
	שלי sound := ⌝'barks'⌜.
⎨.
```

ניתן לבדוק זאת בקלות על ידי הוספת מתודת למחרוזת:

```
Animal בקבלת: ⌝'למחרוזת'⌜ בצע: ⎬
	<- שלי legs למחרוזת + שלי sound.
⎨.
```

נחבר את הכול יחד:

# האובייקט כלום

{{messages}}

האובייקט כלום
מייצג ריקות, או ליתר דיוק, היעדר מידע.
מדי פעם תקבלו אובייקט זה כתשובה להודעה,
במקרה שהתוצאה היא **כלום**. השאלה החשובה ביותר
שאפשר לשאול את האובייקט **כלום** היא: **כלום?**.
התשובה תהיה תמיד **אמת**.

```
פלט כתוב: כלום כלום?.
```

תוצאה:

```
אמת
```

כל אובייקט אחר מלבד **כלום** יענה **שקר**.
קטע הקוד שלמעלה עשוי להיראות מעט פילוסופי, אך לאובייקט **כלום**
בהחלט יש שימושים מעשיים ביותר. לדוגמה,
תקבלו את האובייקט כלום כתשובה אם תבקשו
איבר ברשימה שאינו קיים. ניתן גם להשתמש באובייקט כלום
אם ברצונכם להצהיר על משתנה, אך עדיין אינכם רוצים לציין ערך.
במקום זאת, פשוט **מציבים** בו את הערך המיוחד **כלום**.
ב-XOScript אסור להצהיר על משתנה ללא ערך, כגון:


```
>> ערך.
```

במקום זאת, עליכם לכתוב את הדברים הבאים:

```
>> ערך := כלום.
```

\>\> x := אמת.

**x** מפנה לאובייקט **אמת**. גם קוד מותנה ולולאות

אינה קבועה. למעשה, תוכנית XOScript מתערערת למדי
ממשפט כמו זה:

אמת := שקר.

התוצאה של פעולות כאלה אינה מוגדרת, אולם זו עדיין פעולה
תקינה ולכן מותרת מבחינה פורמלית. בנוסף, קיים אובייקט
בוליאני, שהוא אובייקט השורש של **אמת** ושל **שקר**, שכן שניהם
נגזרים מאובייקט השורש. לאובייקט הבוליאני עצמו, לעומת זאת,
אין שימוש מעשי.

היזהרו בשימוש ב-**וגם:** וב-**או:**

```
פלט כתוב: ﴿שקר or: אמת or: אמת﴾, שורה-חדשה.
פלט כתוב: ﴿שקר או: אמת, או: אמת﴾, שורה-חדשה.
```

מניב

```
שקר
אמת
```
משום שההודעה **או:** מקבלת ארגומנט אחד בלבד. השורה הראשונה
שולחת **או:או:** ל-שקר, הודעה שאינה קיימת, ולכן האובייקט מתעלם
מההודעה ומחזיר את עצמו (שקר). לעומת זאת, השורה השנייה
שולחת **או:** ואחריה **או:** נוספת (באמצעות סמל שרשור, כלומר פסיק: ,).

# פונקציות

{{messages}}

ניתן לקבץ קוד בין ⎬ ל-⎨, והוא הופך אז לפונקציה.
ב-xoscript אנו משתמשים לעתים גם במונח משימה, או פשוט
גוש קוד.

ניתן להריץ פונקציה על ידי שליחת ההודעה *הפעל*.


```
⎬ פלט כתוב: 123, שורה-חדשה. ⎨ הפעל.
```

אם הפונקציה שלכם מקבלת ארגומנטים, השתמשו ב-**החל:**.

```
⎬ :a פלט כתוב: a, שורה-חדשה. ⎨ החל: a.
```

ראו גם את הדוגמאות שלהלן.
בשל הארכיטקטורה הפשטנית, לפונקציה יכולה להיות רק
נקודת החזרה אחת. כדי להימנע מתקורה או מקינון מוגזם של
תנאים, ניתן להשתמש בשגרה (שזה כמו שימוש
בסימן הכפל עם הארגומנט 1):

```
⎬
  ﴿a = 1﴾ אם-אמת: ⎬ x := 1. ⎨, צא.
  ﴿a = 2﴾ אם-אמת: ⎬ x := 2. ⎨, צא.
⎨ שגרה.
```

בדרך זו, (a = 2) לא יחושב אם a = 1.
כמו כן, בדרך זו אין צורך בהודעות אם-אמת מקוננות.
בכל פעם שאתם מוצאים את עצמכם מקננים תנאים, חשבו
על ההודעה שגרה. היא עשויה להפוך את הקוד שלכם
לקריא יותר.


הנה מלכודת חשובה:

```
⎬
	שקר אם-שקר: ⎬
		פלט כתוב: ⌝'End the loop.'⌜.
	⎨, צא.
	
	פלט כתוב: ⌝'Dont show me.'⌜.

⎨ שגרה.

```

במקרה זה, הטקסט 'Dont show me' יוצג.
משום ש-**צא** נשלחת ל-שקר. אם ברצונכם לבצע
יציאה, יש לשלוח אותה כהודעה ל-**אמת**.
 

```
⎬
	שקר היפוך אם-אמת: ⎬
		פלט כתוב: ⌝'End the loop.'⌜.
	⎨, צא.
	
	פלט כתוב: ⌝'Dont show me.'⌜.

⎨ שגרה.

```

יעבוד כמצופה.

## הזרקת ערכים

XOScript מאפשרת להזריק ערכים למשימות. הביטו
במשימה שלהלן:

```
>> sending := ⎬
	Newsletter אל: שלי recipient.
⎨.
sending קבע: ⌝'recipient'⌜
ערך: ⌝'info@recipient.org'⌜.
sending הפעל.
```


איור זה מציג משימה דמיונית, השולחת ידיעון
לכתובת דואל או ל**נמען**. ניתן להזריק נמען זה
למשימה, מבחוץ ולפני שהמשימה מופעלת, על ידי שליחת
ההודעה **קבע:ערך:** למשימה. בכך ערכו של
**recipient** נקבע מראש במשימה. ניתן גם לשנות ערך זה
ולהריץ את המשימה שוב. זוהי שיטה שימושית בעבודה עם
אובייקטי משימה.

## פונקציות ריקות

משימות ריקות אינן מותרות. בתיאוריה משימה ריקה הייתה נראית
כך: **⎬⎨**, אולם XOScript רואה בזה שגיאת שפה. אם
ברצונכם להצהיר על משימה ריקה, ניתן להשתמש באובייקט כלום:

```
>> task := כלום.
```

אף שזו אינה משימה אמיתית אלא אובייקט כלום, עדיין
ניתן לשלוח לו הודעת הפעל:

```
>> answer := task הפעל.
```

למעשה זה זהה ל:

```
>> answer := כלום הפעל.
```

מאחר שהאובייקט **כלום** אינו מזהה את ההודעה **הפעל**, הוא
יחזיר את עצמו כתשובה, והתשובה תהיה שוב **כלום**.
לכן אין צורך במשימה ריקה. בזכות העיצוב
האלגנטי של שפת התכנות XOScript, ניתן פשוט להשתמש באובייקט כלום
לשם כך.

# רשימות

{{messages}}

XOScript מכירה שני סוגים של אוספים: *רשימות* ו*מילונים*.
**רשימות** הן מניות של אובייקטים ב*סדר קבוע*. למילונים
אין סדר; במקום זאת, הם דומים למקרא המורכב ממפתח (או מונח) ומהערך
התואם לו. רשימות דומות למערכים (PHP, Java, C)
ולרשימות (Python). מילונים דומים למערכים אסוציאטיביים (PHP) או
למילונים (Python) בשפות תכנות אחרות. כדי ליצור
רשימה חדשה כתבו:

```
>> fibonacci := רשימה חדש.
```

ניתן למלא רשימה ריקה זו באמצעות **הוסף-בסוף:** :

```
fibonacci הוסף-בסוף: 0.
fibonacci הוסף-בסוף: 1.
fibonacci הוסף-בסוף: 1.
fibonacci הוסף-בסוף: 2.
fibonacci הוסף-בסוף: 3.
fibonacci הוסף-בסוף: 5.
fibonacci הוסף-בסוף: 8.
fibonacci הוסף-בסוף: 13.
```

אם נכתוב את הרשימה למסך:

```
פלט כתוב: fibonacci, שורה-חדשה.
```

נראה:

```
רשימה ← 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13
```

במקום הוסף-בסוף ניתן להשתמש גם ב-; כדי להוסיף איברים לרשימה:


```
>> fibonacci := רשימה חדש ; 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13.
```

נקודה-פסיק (;) היא בכל המקרים הודעה בינארית המכניסה
ערך לרשימה.

## שרשור

נניח שיש לכם רשימה כמו:

```
>> x := רשימה חדש ; 1 ; 2 ; 3.
```

אם ברצונכם למחוק את האיבר הראשון ואת האחרון,
ההודעה שלכם תהיה:

```
x שלוף-ראשון שלוף-אחרון.
```

לרוע המזל, הכתיב הקודם לא יפעל כראוי.
ההודעה **שלוף-ראשון** מחזירה את האיבר הראשון ברשימה, שבתורו
יהפוך למקבל ההודעה **שלוף-אחרון**. כך
ההודעה **שלוף-אחרון** אינה נשלחת ל-**x**, אלא ל-2.
פתרון אפשרי לבעיה זו יהיה ליצור שני משפטים
נפרדים, כגון: 

```
x שלוף-ראשון.
x שלוף-אחרון.
```

אולם זה לא מעשי במיוחד, בפרט כאשר יש צורך
למחוק יותר משני איברים. לכן XOScript מציעה
מבנה הודעות חלופי למצבים מסוג זה. במבני
הודעות **חלופיים**, מתעלמים מהתשובות של האובייקטים
ומקבלים בחזרה את האובייקט המקבל כתשובה, שוב ושוב.
מבנה הודעות **חלופי** מתחיל על ידי שליחת
ההודעה **התחל-רצף** לאובייקט, וניתן לסיים את מבנה ההודעות
ה**חלופי** על ידי שליחת ההודעה **סיים-רצף**. בדוגמה
המודגמת, ניתן להחיל זאת כך:

```
>> x := רשימה חדש ; 1 ; 2 ; 3.
x התחל-רצף שלוף-ראשון שלוף-אחרון סיים-רצף.
```

הוא שמילון מורכב מזוגות של אובייקטים. אובייקט אחד משמש כערך (או
מילת מפתח) כדי לחפש את האובייקט האחר. דוגמה טובה
לרשימה כזו היא מחירון, כגון:


```
>> menu := מילון חדש
	שים: ⌝'£5'⌜ במפתח: ⌝'apple pie'⌜,
	שים: ⌝'£6'⌜ במפתח: ⌝'carrot cake'⌜,
	שים: ⌝'£3'⌜ במפתח: ⌝'fudge'⌜.
```

בדומה לרשימה, ההודעה שים:במפתח:
משמשת להוספת אובייקט לרשימה. ההבדל הוא שבניגוד
לרשימה, מקשרים כאן שני אובייקטים. האובייקט הראשון הוא, בדומה
לרשימה, האובייקט שתשמרו ברשימה. האובייקט השני
אינו מיקומו באוסף, אלא ה**ערך**
המאפשר לאחזר את האובייקט הקודם במועד מאוחר יותר.
בקיצור, מילון פועל קצת כמו מילון ספרותי; כלומר, באמצעות מילת המפתח
ניתן למצוא את המשמעות. למשל, כדי לאחזר מהרשימה
שלמעלה את מחירו של פאדג':

```
>> price := menu במקום: ⌝'fudge'⌜.
```

ניתן גם להשתמש בכתיב המקוצר:

```
>> price := menu ? ⌝'fudge'⌜.
```

אם הערכים שבהם אתם משתמשים לשמירת אובייקטים אינם מכילים רווחים
(ואינם מתנגשים בהודעות מוגדרות מראש אחרות),
ניתן להשתמש גם בכתיב הבא:

```
>> menu := מילון חדש
	pie:   ⌝'£5'⌜,
	cake:  ⌝'£6'⌜,
	fudge: ⌝'£3'⌜.
```

אין ספק שהכתיב שלמעלה נקרא באופן טבעי יותר.
כדי לבקש את מחירו של
פאדג', ניתן להשתמש בכתיב המפושט הבא:

```
>> price := menu fudge.
```

# תוכנית/פלט סטנדרטי

{{messages}}

אובייקט התוכנית מייצג את היישום הרץ כעת. אובייקט זה
מציע פונקציונליות להרצת פקודות מערכת, הכללת תוכניות משנה,
קריאת ארגומנטים ועוד. כל הפונקציות הקשורות למערכת.

## פלט סטנדרטי

פלט הוא אובייקט הפלט הסטנדרטי. יש לו בעצם שתי מתודות:
**כתוב:** ו-**שורה-חדשה**. ההודעה כתוב: משמשת לשליחת מחרוזת
ל-stdout, וההודעה שורה-חדשה מדפיסה תו שורה חדשה.
במקום **שורה-חדשה** ניתן להשתמש גם ב-\\n.

דוגמה:

```
פלט כתוב: ⌝'Hello World'⌜, שורה-חדשה.
```

תוצאה:

```
Hello World
```

## מודולים/תוספים

ניתן להרחיב את עולמה של XOScript באובייקטי מערכת חדשים, על ידי
התקנת מודולים. ניתן להוסיף אובייקט מערכת חדש לעולמה של
XOScript על ידי הצבת קובץ המודול (בדרך כלל קובץ עם הסיומת .so)
בתיקיית mods. 

כאשר שולחים הודעה לאובייקט שזמין דרך
מודול התוסף, XOScript תטען אותו אוטומטית.

ניתן גם לכתוב תוספים בעצמכם. תוספים נכתבים
בשפת התכנות C. תוסף לדוגמה נמצא בחבילת קוד
המקור תחת src/plugins/example.


## השתקפות

קיימות דרכים שונות לחקור את המערכת
במהלך הרצת התוכנית. ב-XOScript יש כמה מתודות
לגלות אילו אובייקטים קיימים ולאילו הודעות אובייקטים אלה
מגיבים. ראשית, ניתן לשאול כל אובייקט מהו ה**סוג** שלו,
אולם סוגים ב-XOScript ניתנים לשינוי ולכן אינם אמינים.

ניתן גם לשאול את אובייקט התוכנית אם
אובייקט נתון כבר קיים בתוכנית:

```
תוכנית Tool אם-אמת: ⎬ ... ⎨.
```

במקרה של שם אובייקט
המורכב מסמל יחיד, מוטב להשתמש
בכתיב הבא כדי למנוע בלבול:

```
תוכנית חפש: ⌝'X'⌜, אם-אמת: ⎬ ... ⎨.
```

מלבד שאלות על אובייקטים, ניתן באותה מידה לשאול את
אובייקט התוכנית על הודעות. למשל, ניתן לשאול אם
האובייקט **מספר** מכיר את ההודעה **בין:לבין:**, באופן
המודגם להלן:

```
תוכנית Number: ⌝'between:and:'⌜, שורה-חדשה.
```

# שרת

{{messages}}

תוסף השרת ב-xoscript מציע פונקציונליות ליצירת
יישומים בצד השרת. כדי לטעון את תוסף
השרת השתמשו ב:

```
Server אתחל.
```

לנוחותכם מומלץ גם לטעון את
הקבצים webtools.xo ו-template.xo.

```
תוכנית השתמש: ⌝'webtools.xo'⌜.
תוכנית השתמש: ⌝'template.xo'⌜.

```

## הגדרות שרת

ניתן לקבוע את הגדרות השרת הבאות:

```
	# default values are given
	# so if you do not set anything these
	# values are used...

	תוכנית 
	הגדרה: ⌝'max-postfields'⌜
	ערך: 40.

	תוכנית 
	הגדרה: ⌝'max-contentlength'⌜
	ערך: 2000000. # 2MB

	תוכנית 
	הגדרה: ⌝'max-time'⌜
	ערך: 5000. # 5sec

```

## שלום עולם

הנה תוכנית רשת פשוטה מאוד שניתן להשתמש בה עם
שרת CGI סטנדרטי כמו Apache2, NGINX, OpenHTTPD או כל שרת
מוכר אחר.

```
#!/bin/xo

Server אתחל.
תוכנית השתמש: ⌝'webtools.xo'⌜.

>> web-document := מסמך-רשת חדש.

web-document פלוט: ⌝'
<html>
<body>
<b>Hello World!</b>
</body>
</html>'⌜.

```

אם אינכם רוצים להשתמש באובייקט מסמך-רשת, זה בסדר, אך
אז עליכם לכתוב את כותרות ה-HTTP בעצמכם:

```
#!/bin/xo
פלט כתוב: ⌝'Content-type: text/html; charset=utf-8 \n\n'⌜, שורה-חדשה.
פלט כתוב: ⌝'hello world!'⌜, שורה-חדשה.
``` 

## בקשה

ניתן להשתמש באובייקט בקשת-HTTP כדי לקבל נתוני GET/POST/COOKIE ו-
UPLOAD:

```
>> בקשת-http  := בקשת-HTTP חדש.
>> search   := בקשת-http get: ⌝'search'⌜. # ?search=books
>> password := בקשת-http post: ⌝'password'⌜. # from form
>> selected := בקשת-http get-רשימה: ⌝'sel[]'⌜. #?sel[]=1&sel[]=2
>> selected := בקשת-http post-רשימה: ⌝'sel[]'⌜.
>> cookie   := בקשת-http cookie: ⌝'session-id'⌜.
>> upload   := בקשת-http upload: ⌝'file'⌜.
>> temppath := upload ? 1.
>> filename := upload ? 0.
```

## מגבלות post ואורך

מספר שדות ה-post המרבי כברירת מחדל הוא 40, ואורך התוכן
המרבי כברירת מחדל הוא 2MB. כדי להגדיר אחרת עבור כל סקריפט בנפרד:

```
תוכנית הגדרה: ⌝'max-contentlength'⌜ ערך: 1. 
תוכנית הגדרה: ⌝'max-postfields'⌜ ערך: 1. 
```

{{note}}
אם אורך התוכן חורג מהמרבי, התהליך
נהרג, משום שאיננו יכולים עוד להיות בטוחים
שהמטען בטוח.
{{/note}}

מגבלת maxtime קובעת את הזמן המרבי במילישניות
לקריאת stdin/נתוני post.

```
תוכנית הגדרה: ⌝'max-time'⌜ ערך: 5000. # 5sec
```

הדבר חל רק על קריאת הקלט/פלט של ה-post, ומונע
התקפות מסוג slowloris. אם ברצונכם באמת להגביל את
זמן הריצה של פעולה כלשהי, השתמשו ב-תוכנית מגבלת-זמן.

## מסד נתונים

ניתן להשתמש באובייקט מסד הנתונים כדי לתשאל MariaDB/MySQL.
כדי להתחבר למסד נתונים:

```
>> db := Maria-DB חדש מארח: ⌝'localhost'⌜,
	שם-משתמש: ⌝'xo'⌜,
	סיסמה: ⌝'pass123'⌜,
	שם-מסד: ⌝'xobase'⌜,
	התחבר.

```

כדי להוסיף רשומה השתמשו ב:

```
>> פרמטרי-חיפוש := db שאילתה: ⌝'
	INSERT INTO book (id, description, price, rating) 
	VALUES (NULL, ?, ?, ?)
'⌜, פרמטרים: ﴿ רשימה חדש ; ⌝'abc'⌜ ; 12.35 ; 6 ﴾. # parameterized queries

⎬  פרמטרי-חיפוש בצע. db אשר. ⎨
תפוס: ⎬ :e db בטל-שינויים.  ⎨, הפעל.
```

שימו לב ש-xoscript עובדת *רק* עם טרנזקציות ולעולם אינה מבצעת אישור אוטומטי (autocommit).
אם לא ניתן לבטל את ה-autocommit, תקבלו שגיאת התחברות.
השתמשו תמיד בקשירת פרמטרים בשאילתות, ולעולם אל תוסיפו קלט משתמש ישירות
ל-SQL.

קבלו את המזהה שהוכנס כך:

```
פלט כתוב: ⌝'INSERTED: '⌜ + פרמטרי-חיפוש insert-id, שורה-חדשה. # insert id
```

כדי לשלוף רשומות:

```
>> פרמטרי-חיפוש :=
db
	שאילתה: ⌝'SELECT * FROM book order by id desc limit 2'⌜, 
	שלוף: ⎬ :row 
		פלט כתוב: row id + ⌝' '⌜ + row description + ⌝': '⌜ + row price, שורה-חדשה.
	⎨. # fetching rows

```

## הפעלות

לשם התמדה ניתן לשמור ולשלוף נתונים מאובייקט הפעלה.
תחילה צרו **מסמך-רשת** חדש. האובייקט מסמך-רשת מאגד
את הבקשה, הכותרות, ה-HTML וההפעלה. הסיבה לכך היא שכאשר אתם
מבקרים באתר אינטרנט בדפדפן, אתם רואים רק את ה-HTML. אבל
מסמך-הרשת כולו מורכב גם מ**כותרות**. למשל,
רוב תגובות ה-HTTP כוללות כותרת כמו: Content-type:text/html כדי
לומר לדפדפן שיש להציג את הנתונים שאחריה כ-HTML
(ולא להוריד אותם כקובץ, למשל). הפעלות הן דרך
לשמור נתוני משתמש בין בקשות. כדי לעקוב אחר נתונים אלה עלינו
לקבוע עוגייה, ועוגייה זו נקבעת גם היא באמצעות כותרת. לכן
הכול מתכנס במסמך-רשת (משום שהוא המסמך המלא
המכיל גם כותרות וגם HTML או נתונים אחרים).


```
# First we make a new Web Document instance
>> web := מסמך-רשת חדש.

# Now we start a session, this will generate a Header for a cookie and
# create a file to store your data, associated with that cookie
>> session := web התחל-הפעלה.

# Now we can treat session like a dict
session userid: 123.
```

כדי להשמיד את ההפעלה (בעת התנתקות):

```
web השמד-הפעלה.
```

## כותרות

מסמך-רשת מאפשר גם לקבוע כותרות מוכרות אחרות.
למשל, אם ברצונכם להפנות את המשתמש לכתובת URL אחרת:

```
web עבור-אל: ⌝'/other.html'⌜.
```

מאחורי הקלעים, פקודה זו גם מייצרת את כותרת ה-HTTP שתישלח
יחד עם שאר הנתונים או ה-HTML שלכם, כדי להורות לדפדפן לנווט
לכתובת היעד שצוינה.

כדי להוסיף כותרת מותאמת אישית:

```
web כותרת: ﴿ 
	כותרת-HTTP חדש
	מפתח: ⌝'Content-Length'⌜
	ערך: 400
﴾.
```

כדי להציג דף 404:

```
web לא-נמצא: ⌝'OOps..'⌜.
```


## שבלונות

מערכת השבלונות המוגדרת כברירת מחדל פשוטה מאוד. אין צורך ללמוד
תחביר שבלונות חדש. בנוסף, מנוע השבלונות מבטיח הפרדה אמיתית
בין התצוגה ללוגיקה העסקית.

כדי ליצור שבלונה מקובץ:

```
>> tpl := web שבלונה: ⌝'templates/ux.tpl'⌜.
```

מערכת השבלונות משתמשת בסמנים. 
יש שלושה סוגי סמנים: סמני גזירה, סמני הדבקה
וסמני משבצת. הרעיון הבסיסי פשוט מאוד: גוזרים
אזורים המזוהים על ידי סמני גזירה, וניתן להדביק אותם
באזורים המזוהים על ידי סמני הדבקה. ניתן להזריק מחרוזות לתוך
סמני משבצת.

כך למשל, בהינתן השבלונה הבאה, נניח את
אבן החן בתיבת התכשיטים ונוסיף תג מחיר.

```
<!-- cut:gem -->
<img src="gem.gif">
<b>$<!-- slot:price --></b>
<!-- /cut:gem -->

<div id="box">
<!-- paste:jewels -->
</div>
```

ניתן לעשות זאת כך:

```
>> gem := tpl גזור: ⌝'gem'⌜, העתק.
gem price: 99.
tpl הדבק: gem במפתח: ⌝'jewels'⌜.
web פלוט: tpl טהר.
```

השורה האחרונה פשוט שולחת את השבלונה כמחרוזת ללקוח
יחד עם כותרות ה-HTTP הנדרשות.

תוצאה:

```
<div id="box">
<img src="gem.gif">
<b>$99</b>
</div>
```


## העברה ישירה

כדי להגיש בבטחה קבצים שהעלו משתמשים, ניתן להסתמך על passthru:

```
>> uploaded := ⌝'smile.gif'⌜.
Server העבר: uploaded קידומת: ⌝'/uploads/images/'⌜.
תוכנית סיים.
```

כך יוגש התוכן שהעלו המשתמשים עם סוג ה-mime
המתאים. נתמכים רק סוגי mime שברשימה הלבנה:
GIF, JPG, PNG, WEBP, MP4, WEBM, MP3, ZIP, GZIP, PDF ו-SVG.
קבצי SVG, ZIP ו-GZIP נשלחים כהורדה, משום ש-SVG
יכול להכיל סקריפטים שאחרת היו רצים בדומיין שלכם.
שיטה זו מונעת התקפות TOCTOU, מעבר נתיבים (path traversal),
הרצת קוד זדוני (הזרקה), התקפות קישורים סמליים,
התקפות DDoS (מגבלת קובץ = 50MB), התקפות רחרוח ו-
בעיות אבטחה שונות אחרות.

>> json := ﴿ JSON jsonify: ﴿

﴾﴾.

כדי לפענח JSON לאובייקט xoscript:

## ביטויים רגולריים

ניתן להשתמש בביטויים רגולריים על ידי יצירת דפוס.
למשל, כדי להתאים את ה-href וה-target של היפר-קישורים:

```
דפוס חדש: ⌝'href="([^"]+)" target="([^"]+)"'⌜.
```

כעת, החילו את הדפוס על מחרוזת הנושא כך:

```
pattern התאמה: נושא בצע: ⎬ :m :x .... ⎨
```

דוגמה מלאה:

```
>> נושא := ⌝'<html>
	<a href="http://link1" target="_blank">
	<a href="http://link2" target="_blank">
</html>'⌜.
>> pattern := דפוס חדש: ⌝'href="([^"]+)" target="([^"]+)"'⌜.
>> result  := pattern התאמה: נושא בצע: ⎬ :m :x
	פלט כתוב: m, שורה-חדשה.
	פלט כתוב: x, שורה-חדשה.
	<- ⌝'XXX'⌜.
⎨.
פלט כתוב: result, שורה-חדשה.
```

## עיצוב

האובייקט תבנית מאפשר לעצב נתונים, למשל ריפוד או
הוספת אפסים. הוא משתמש בתחביר של printf.

```
>> fmt := תבנית חדש: ⌝'%06.0f'⌜.
fmt החל: 56. # gives 000056
```

תבנית יכולה להכיל המרה אחת, והיא חייבת להתאים לערך,
אחרת תקבלו שגיאה:

- `החל:` עם מחרוזת: `%s`
- `החל:` עם מספר: `%f`, `%e`, `%g` או `%a`
- `החל-שלם:` עם מספר: `%d`, `%i`, `%o`, `%u`, `%x` או `%c`

ערכים מבקשה הם מחרוזות. כדי לעצב ערך כזה כמספר,
המירו אותו תחילה:

```
fmt החל: ﴿בקשת-http get: ⌝'amount'⌜﴾ למספר.
```

# ffi

{{messages}}

FFI מסופק על בסיס פלטפורמה/תוסף, משום שהוא
קשור לארכיטקטורת המערכת הבסיסית, דבר שהליבה
אינה אמורה לעשות.
תוסף השרת מציע מימוש ffi/blob תואם.
כברירת מחדל הליבה מתחברת לפלטפורמת היעד
דרך stdin/stdout, שירותי קלט/פלט מוגבלים לקבצים ומעטפת (תוכנית מערכת:).
אינטגרציה נוספת מסופקת על ידי ffi/blobs באמצעות תוספים
ממוקדי יישום, כמו תוסף השרת.

FFI הוא ראשי תיבות של Foreign Function Interface (ממשק פונקציות זרות). הוא מאפשר להשתמש בפונקציונליות שנכתבה על ידי אחרים
בשפות תכנות שונות, המסופקת באמצעות קובצי DLL, קובצי SO או קובצי Dylib. אלה יכולות
להיות מגוון של פונקציות, ובשיטה זו זמין מגוון עצום של פונקציונליות.
נתחיל בדוגמה:

```
Server קשר: ﴿
 רשימה חדש ;
 ⌝'/usr/lib/x86_64-linux-gnu/libc.so.6'⌜ ;
 ⌝'printf'⌜ ;
 ﴿ רשימה חדש ; ⌝'pointer'⌜ ; ⌝'int'⌜ ﴾ ;
 ⌝'void'⌜ ;
 ⌝'Printf'⌜ ;
 ⌝'template:number:'⌜
﴾.
>> s := Blob utf8: ⌝'FFI has %d letters.\n'⌜.
Printf template: s number: 3.
s שחרר.
```

התוצאה של קוד זה היא שתראו את הדבר הבא בשורת הפקודה:
FFI has 3 letters.
כעת אתם בוודאי חושבים: "זה הרבה קוד בשביל משהו כל כך פשוט."
כלומר, האם לא יכולנו לפתור זאת בפקודת Gui show? התשובה היא כן מהדהד!
אבל זו דוגמה להמחשה בלבד.
FFI משמש בדרך כלל למשימות מורכבות יותר, אך אלה אינן דוגמאות
טובות, ולכן בחרתי במשהו טריוויאלי.

הארגומנטים של מתודת link:

- ארגומנט #1: קובץ ה-DLL או ה-SO שבו ברצונכם להשתמש.
- ארגומנט #2: הפונקציה בקובץ זה שברצונכם לקשר.
- ארגומנט #3: רשימה עם שמות טיפוסי הנתונים של הארגומנטים של הפונקציה.
- ארגומנט #4: שם טיפוס ההחזרה של הפונקציה.
- ארגומנט #5: שם האובייקט שאליו ברצונכם לקשר פונקציה זו (אם אינו קיים, הוא ייווצר
אוטומטית).
- ארגומנט #6: ההודעה שאליה יש לקשר פונקציה זו.

בדוגמה שלמעלה, אנו רוצים לקשר את הפונקציה printf מ-libc.so. את שמות טיפוסי
הנתונים ניתן למצוא בתיעוד של התוכנה שאליה אתם מקשרים. הטיפוסים הזמינים הם:
void, pointer, float, double, int, uint, char, uchar, intX ו-uintX,
כאשר X יכול להיות 8, 16, 32 או 64.

טיפוסים אלה מתייחסים למספר הבתים הנדרש לאחסון הנתונים. עבור printf, אנו מקשרים
לאובייקט חדש בשם Printf ולהודעה template:number:. אתם מתרגמים את הפונקציה
החיצונית לניב של XOScript לפני השימוש בה. ההודעה template:number: מצפה
למאגר עם טקסט התבנית כפרמטר הראשון שלה. אנו יוצרים מאגר זה באמצעות אובייקט Blob,
המאפשר להקצות זיכרון באופן ידני. אתם אחראים לשחרר זיכרון זה לאחר מכן
באמצעות ההודעה שחרר.

ניתן למלא blob זיכרון בדרכים שונות. בדוגמה שלנו אנו ממלאים אותו בטקסט, ולכן משתמשים
בהודעה utf8: (UTF-8 הוא קידוד להמרת טקסט לבתים). ניתן גם למלא blob באמצעות
בתים:, ולהעביר רשימה של ערכי בתים. כדי לקרוא את תוכן ה-blob, השתמשו ב-התחלה:אורך:.
תקבלו את הבתים בחזרה כרשימה. ניתן אפילו ליצור C-struct באמצעות Blob בעזרת
ההודעה struct:, ולהעביר רצף של טיפוסי C. הדבר עשוי להיות נחוץ בעת קריאה לפונקציית C
בספריית תוכנה חיצונית שמצפה למצביע ל-struct.

{warning}
עליכם לשחרר blobs בעצמכם.
אוסף האשפה אינו מנקה blobs.
{/warning}

מאחר שניתן להעביר blobs לפונקציות חיצוניות מספריות, לא ניתן
לאסוף אותם אוטומטית באוסף האשפה (ייתכן שהם עדיין בשימוש על ידי
פונקציות חיצוניות, או שפונקציות חיצוניות אלה ירצו לשחרר אותם
בעצמן). לכן עליכם לשחרר blobs בעצמכם במידת הצורך.

כדי לשחרר blob השתמשו ב:

```
myblob שחרר.
```

כדי לשחרר struct השתמשו ב:

```
mystruct שחרר-struct שחרר.
```

כך שעבור struct יש לשלוח שתי הודעות: שחרר-struct ו-שחרר, כדי
לשחרר את גוש הזיכרון.
