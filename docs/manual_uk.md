Ласкаво просимо до XOScript
Мета проєкту XOScript — створити скриптову мову, простою та придатною для аудиту.
Простий не обовʼязково означає легкий.
Знайома мова програмування може бути легшою у використанні, ніж XOScript.
Тут простота означає дещо інше:
можливість скласти повну ментальну модель мови та її поведінки.

XOScript створено так, щоб вона вміщалася у вашій голові.
Її граматика та кількість понять навмисно невеликі.
Класів немає; обʼєкти можна розширювати безпосередньо.
Обʼєкти передаються за посиланням, копіювання є явним,
а функції мають єдину точку виходу.

Деякі з цих рішень суттєво відрізняються від поширених мов.
Наприклад, XOScript не має системи типів і використовує динамічну область видимості.
Повідомлення, які неможливо обробити, ігноруються, а не спричиняють виняток.
Ці рішення мають наслідки і не мають на меті усунути помилки.
Їхня мета — зберегти базову модель мови малою та послідовною.

XOScript також можна локалізувати, що дає змогу формулювати бізнес-правила
природною мовою і, можливо, ділитися ними з нетехнічними зацікавленими сторонами.

Придатність до аудиту означає застосування тієї самої філософії до реалізації.
Середовище виконання написане мовою C і має невеликий рукописний лексер, парсер і обхідник дерева.
Стандартна бібліотека та середовище виконання значною мірою відображають структуру мови,
тож звʼязок між кодом XOScript та його реалізацією досить прямий.

Тести також тісно повʼязані з документацією.
Кожен метод повинен мати відповідний тест, який можна включити до посібника,
що допомагає підтримувати документацію в узгодженні з реалізацією.

XOScript не прагне конкурувати з поширеними мовами за
можливостями чи звичністю. Вона досліджує іншу мету:
середовище програмування, яке розробник може зрозуміти повністю.

Є надія, що мала мова та мала
реалізація роблять практичним розуміння програмного забезпечення
від байта до обʼєкта, від синтаксису до середовища виконання, і дають змогу писати код
впевнено, бо ви розумієте і те, що відбувається
у скрипті, і те, що відбувається під капотом.

проста, але гнучка.

Щоб використовувати xoscript як серверну мову, потрібно встановити
серверний плагін у теку /mods/server. 

Так зроблено тому, що ми прагнемо
відокремити ядро мови від специфічних для сервера функцій,
на відміну, наприклад, від PHP чи Python. Інакше нам довелося б без жодної
потреби постачати всім усе на світі, а це просто безглуздо.
За бажанням можна встановити й інші модулі. Система дуже
гнучка.

Крім того, деякі функції краще реалізувати самою скриптовою мовою,
наприклад шаблони та обробку сесій, тому додатково ми
постачаємо для вашої зручності бібліотеки template.xo та webtools.xo.
Причина всього цього в тому, що ми не знаємо, як ви хочете
використовувати xoscript. Її можна використовувати як серверну скриптову мову,
а також для графічних інтерфейсів, вбудованих пристроїв або просто пакетної обробки.
Навіть якщо ви використовуєте її як серверну скриптову мову (що
наразі є одним з основних сценаріїв використання), ви все одно можете захотіти
використовувати інший рушій шаблонів або інший обробник сесій.
Хто ми такі, щоб вирішувати, що ви маєте використовувати наші?

Однак одна з переваг нашого власного рушія шаблонів полягає в тому, що
вам не потрібно вивчати додатковий синтаксис для створення шаблонів.
Стандартний рушій шаблонів, що постачається з xoscript, забезпечує 100%
розділення представлення та логіки. Замість спеціального
синтаксису шаблонів він просто використовує дуже гнучку систему маркерів-слотів.
Докладніше див. розділ Сервер.

Зауважте: якщо ви не хочете використовувати стандартний рушій шаблонів або
стандартні webtools, то, само собою зрозуміло, вам доведеться надати
власні.

Якщо ваш вебсервер працює в chroot, jail або іншій пісочниці,
вам також потрібно встановити залежності xo в цьому середовищі; дізнатися,
які бібліотеки потрібні, можна за допомогою ldd (див. довідкову сторінку Linux або BSD).
Якщо ви хочете використовувати команди оболонки у своїх xo-скриптах, також скопіюйте оболонку
(наприклад, bash або ksh) у це середовище.

Також зазначимо, що ми дуже серйозно ставимося до зворотної сумісності.
Існує навіть спеціальна функція зворотної сумісності під назвою
'version'. Загалом ми прагнемо, щоб ваш код працював вічно. Тож вам
ніколи не доведеться оновлювати код, щоб він залишався сумісним з новими версіями
xoscript. Наша мета: написав один раз — працює вічно.

Решта цього посібника присвячена докладному поясненню мови програмування
xoscript. Серверні скрипти розглядаються в розділі
під назвою Сервер. Якщо ви досвідчений розробник програмного забезпечення, можливо, ви захочете
пропустити кілька розділів, бо деякі з них дещо надто докладні або
дуже схожі на загальні практики програмування. Тож тим із вас,
хто вже має досвід роботи з кількома іншими мовами програмування,
краще використовувати цей посібник як довідник.

## Встановлення в Linux

Завантажте apache2 і mariadb:


```
sudo apt-get install apache2 mariadb-server
sudo a2enmod cgi
```

Завантажте xoscript.
Замініть X правильним номером версії!

```
wget https://xoscript.com/downloads/xoserver-linux-1_5_X.tar.gz
tar xvf xoserver*.tar.gz
```

Скопіюйте файли до кореневої теки вебсервера та до /bin:


```
sudo cp bin/xo /bin/xo
sudo cp -R bin/mods /var/www/html/
sudo cp *.xo /var/www/html/
```

Відредагуйте конфігурацію apache2:

```
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

Замініть Virtualhost на:

```
<VirtualHost *:80>
    <Directory /var/www/html>
        Options +ExecCGI
        AllowOverride All
        AddHandler cgi-script .xo
        Require all granted
    </Directory>
    DocumentRoot /var/www/html
</VirtualHost>
```

Створіть тестову сторінку:

```
sudo nano /var/www/html/test.xo
```

і напишіть невелику тестову програму:

```
#!/bin/xo
Server ініціалізувати.
Програма використати: ['webtools.xo'].
>> web := Веб-документ новий.
web вивести: ['Hello World'].
```

Дозвольте apache2 виконувати вашу програму через CGI:

```
sudo chmod uog+x /var/www/html/test.xo
```

Перезапустіть apache2:

```
sudo systemctl restart apache2
```

Відкрийте тестову сторінку в браузері:

```
http://localhost/test.xo
```

Ви маєте побачити:

```
Hello World
```


## Встановлення в OpenBSD

Відредагуйте /etc/httpd.conf, додайте:


```
server "mydomain.com" {
    listen on * port 80
    root "/htdocs/mydomain/"

    location "*.xo" {
        fastcgi
        fastcgi socket "/run/slowcgi.sock"   # inside chroot
    }
}
```

Якщо ви хочете використовувати SSL:

```
listen on * tls port 443
tls {
	certificate "/etc/ssl/mycert.crt"
	key "/etc/ssl/private/mykey.key"
}
```

Щоб захистити обмін ключами від квантових атак,
виберіть шифр mlkem:

```
tls {
 ... 
 ecdhe "X25519MLKEM768"
 ...
}
```

Додайте до chroot бінарний файл xo та модулі, а також усі залежності
(визначте їх за допомогою ldd).

## Запуск прикладів


Щоб запустити одну з прикладових програм із пакета:

```
./example.sh <name> <Linux/OBSD> [clean]
```

Наприклад, щоб запустити приклад FizzBuzz у Linux:

```
./example.sh fizzbuzz Linux
```

Щоб запустити той самий приклад в OpenBSD:

```
./example.sh fizzbuzz OBSD
```

Щоб запустити приклад із чистою збіркою:

```
./example.sh fizzbuzz OBSD clean
```

Щоб запустити модульні тести:

```
./runtests.sh
```

Щоб запустити модульні тести без збирання (лише тестування):

```
./runtests.sh nobuild
```

## Збирання

Щоб зібрати з вихідного коду в Linux:

```
make clean
ISO="en" make
```

В OpenBSD:

```
make -f makefile.obsd clean
ISO="en" make -f makefile.obsd
```

Щоб зібрати серверний плагін у Linux:

```
PACKAGE="server" NAME="server.so" make plugin-clean
ISO="en" PACKAGE="server" NAME="server.so" make plugin
```

Щоб зібрати серверний плагін в OpenBSD:

```
PACKAGE="server" NAME="server.so" make -f makefile.obsd plugin-clean
ISO="en" PACKAGE="server" NAME="server.so" make -f makefile.obsd plugin
```

## Привіт, світе

Після того як файл буде перенесено на ваш компʼютер, ви можете розпакувати його
і запустити xo такою командою:

```
xo
```

Щоб запустити XOScript, збережіть програму у файл, додавши суфікс -xo
(необовʼязково). Крім того, вкажіть імʼя файлу вашої програми
після команди XOScript:

```
xo myprogram.xo
```

Коли ви запускаєте команду XOScript, передавши файл програми як
параметр, xo прочитає та виконає цей файл програми.

{{note}}
Ви також можете запустити програму, перетягнувши її на піктограму xo.
{{/note}}

{{warning}}
У деяких системах потрібно заздалегідь дозволити xo завантажувати динамічні
бібліотеки.
{{/warning}}

За традицією перша програма будь-якою новою мовою
програмування має бути своєрідним привітанням світові. У XOScript така
програма **Hello world** виглядає так:

@test598

Якщо зберегти цей текст у файл, наприклад hello.xo, його можна виконати
так: .

xo hello.xo

Hello world


Вивід програми можна побачити у показаному вище чорному вікні.
У всьому посібнику таке саме відображення використовуватиметься для показу
виводу.

{{note}}
Вивід пишеться з великої літери В.
Загалом назви обʼєктів починаються з великої літери,
якщо тільки обʼєкт не діє як екземпляр (не має власних
методів, лише дані). Це відповідає домовленостям щодо класів і
екземплярів в інших мовах програмування.
{{/note}}


## Синтаксис 

XOScript — *чисто* *обʼєктно-орієнтована* мова програмування. Це означає,
що xoscript сприймає все як обʼєкт, тому інших *типів даних*
немає. У програмі, написаній на XOScript, по суті є лише три основні дії:
*присвоєння*, *надсилання повідомлень*
та *відповідь*. Обмін повідомленнями між обʼєктами — ключова частина
програми XOScript. Ці три окремі дії проілюстровано
нижче:


Дія                    | Приклад
---------------------- | --------
присвоєння             |  \>\> x := 1. 
унарні повідомлення    | x парне?.
бінарне повідомлення   | 1 + 2.
повідомлення з ключовими словами | x від: 0 довжина: 10.
відповідь              | <- answer.  


Цей розділ дає загальне уявлення про мову XOScript
і описує її основні принципи. XOScript — невелика мова,
заснована на трьох діях (див. ілюстрацію), які перетворюються приблизно
на шість граматичних правил. Це все, що потрібно, щоб опанувати
мову.

Не хвилюйтеся, якщо щось не стане зрозумілим одразу: усі будівельні
блоки буде розглянуто в наступному розділі (3), а основні правила буде
повторено. Поточний розділ є передусім загальним
вступом до мови. Основні принципи буде коротко
пояснено та проілюстровано кількома відповідними прикладами. Усі відсутні
подробиці буде викладено пізніше.

Коментарі в XOScript починаються із символу \#. Тож наступний рядок
буде проігноровано:

```
# this is just a comment
```

## Змінні

Щоб присвоїти
змінну, використовуйте символ оголошення змінної: >>. Імʼя
змінної може містити будь-які знаки, окрім: <-, :=, пробільних символів,
крапок, ком, двокрапок, лапок [' '] та круглих дужок ().
Крім того, змінна не може займати кілька рядків. Зверніть увагу,
що змінна не може починатися з цифри або знака мінус.

Ось приклади допустимих змінних:

```
>> password := ['Secret'].
>> ♡♡♡ := 3.
>> $ := ['dollar'].
>> +plus := Істина.
>> user-password := ['Pssst!'].
```

Недопустимими змінними є, наприклад:


```
>> -123 := ['negative number'].
>> password of user := ['Classified'].
>> password.of:user := ['Classified'].
>> ,x := 10.
```

{{note}}
Вам не потрібно екранувати жодні символи
(зокрема лапки, подвійні лапки, межі
рядка) у
текстовому літералі, доки це не
спричиняє неоднозначності для лексера.
{{/note}}

Після оголошення змінну можна вільно використовувати. Це означає,
що символ оголошення потрібен лише першого разу,
коли ви використовуєте змінну (під час оголошення).

Точніше кажучи, ви не можете просто так почати присвоювати значення
змінній *(x := 2)*, бо спершу потрібно оголосити змінну *(\>\>
x := 2)*. Однак після оголошення ви можете змінювати її значення
без символу оголошення*(\>\> x := 2. x := 3.)*.

Зверніть увагу, що під час оголошення змінній обовʼязково потрібно
присвоїти значення. На відміну від інших мов програмування, не дозволено
оголошувати змінну без значення. Важливо явно привʼязати
кожну змінну до початкового значення. Утім, ви можете ініціалізувати
змінну обʼєктом **Ніщо**. У такому разі змінну можна
вважати порожньою *(\>\> x := Ніщо.)*. Коротко кажучи, оголошувати
змінну без початкового значення не дозволено. Тож

```
>> x.
```

є недопустимим і призведе до повідомлення про помилку.

{{note}}
xoscript використовує динамічну область видимості
змінних; подробиці див. у розділі Функції.
{{/note}}


## Літерали

XOScript сприймає все як обʼєкт, тобто всі числа, рядки
та фрагменти коду. Числа, як-от 1, 2, 100, -999 і 1,234, є
обʼєктами Число. Усі тексти між одинарними лапками є обʼєктами
Текст. Усі фрагменти коду, згруповані у фігурних дужках {...}, є
обʼєктами Функція.

Літерал         | Кореневий обʼєкт | Приклад
--------------- | ---------------- | ----------
числа           | Число            | 1,2,3... 
рядки           | Текст            | \['hello'\]
функція         | Функція          | { 1 + 2. }.
                
     
Такі обʼєкти, як числа та рядки, завжди походять від кореневого
обʼєкта. Наприклад, усі числа походять від обʼєкта **Число**. Усі
рядки походять від **Текст**, а всі фрагменти коду — від **Функція**. Своєю
чергою, усі ці обʼєкти походять від **Обʼєкт**, який фактично є
кореневим обʼєктом усіх обʼєктів.


## Повідомлення

Програмування на XOScript по суті означає
надсилання повідомлень обʼєктам. Загальний запис надсилання повідомлення
обʼєкту такий:

```
<object> <message>
```

Щоб, наприклад, зʼясувати, чи є число **2** парним, обʼєкту **2**
надсилається повідомлення **парне?**:

```
2 парне?
```

Відповіддю буде **Істина** (знову ж таки, обʼєкт). Невідомі повідомлення
обʼєкти зазвичай ігнорують, тож помилки не виникне. Деякі обʼєкти (наприклад,
числа чи рядки) відповідають на невідоме повідомлення заздалегідь визначеним чином
(докладніше про це пізніше).

Обʼєкт може отримувати три види повідомлень. 

Тип                  | Кількість аргументів
-------------------- | -------------------
Унарне               | 0      
Бінарне              | 1     
З ключовими словами  | 1+    


По-перше, є **унарні
повідомлення** (див. приклад вище), які не мають аргументів. По-друге,
є **повідомлення з ключовими словами**, які мають один або кілька аргументів,
наприклад:

```
>> x := Число між: 1 і: 10.
```

У цьому випадку повідомлення **між:і:** надсилається до **Число**, який
є кореневим обʼєктом усіх чисел. Результатом буде випадкове число
від 1 до 10. Нарешті, є **бінарні повідомлення**, які складаються
лише з одного символу та мають один аргумент:

```
2 + 3
```

Це схоже на математичну суму, але насправді це просто ще одне повідомлення.
Повідомлення **+** надсилається до **2** з аргументом **3**, що поверне
відповідь **5**. Бінарні повідомлення дозволено писати без двокрапки.

Бінарні повідомлення можна обʼєднувати в ланцюжки:

```
>> x := 3 + 2 - 1.
```

У цьому фрагменті **+ 2** спочатку надсилається обʼєкту **Число** **3**, що
дає обʼєкт Число **5**, після чого цьому числу надсилається **-1**.
Уважні читачі слушно помітять розбіжність, яку
цей протокол демонструє щодо загальноприйнятого математичного порядку
операцій. XOScript ігнорує математичний порядок на користь
послідовності своєї системи повідомлень. Як наслідок, сума:

```
2 + 3 * 5 = 25
```

а не 17.

Так задумано. Порядок виконання можна змінити за допомогою круглих дужок:

```
2 + (3 * 5) = 17
```

Більшість обʼєктів у відповідь на певне повідомлення повертають самих
себе. Це зручно, оскільки заохочує продовжувати діалог із цим
обʼєктом, надсилаючи йому наступне повідомлення:

```
Вивід написати:
[' hello '] обрізати великі-літери.
```

```
HELLO
```

Тут обʼєкту **Текст** надсилаються два повідомлення: **обрізати**, а потім
**великі-літери**.

У наступному фрагменті кома потрібна, щоб показати,
що надходить нове повідомлення. Інакше XOScript заплутається.

```
Вивід написати: ['Hello!'], новий-рядок.
```

Спочатку символу олівця надсилається повідомлення **написати:**, а потім
**новий-рядок**. Без коми XOScript вирішила б, що ви хочете надіслати
**новий-рядок** до **текст** **Hello!**, а це марна справа.

Порядок обробки повідомлень такий: зліва направо;
спочатку повідомлення в дужках, потім унарні повідомлення. Далі
бінарні повідомлення, і насамкінець — повідомлення з ключовими словами. Див. приклад
нижче:

```
Вивід написати: 0.5 округлити + (2 - 1), новий-рядок.
```

XOScript завжди читає зліва направо: спочатку обʼєкту Вивід надсилається
повідомлення **написати:**, а за ним — повідомлення **новий-рядок**. Усередині
самого аргументу XOScript теж читає зліва направо, тож спочатку **0.5 округлити**,
потім **+**.

{{note}}
Повідомлення новий-рядок додає до рядка символ нового рядка.
Англійська назва цього повідомлення (stop) натхненна телеграфними системами.
У телеграфних повідомленнях 
часто використовували слово STOP, щоб позначити кінець речення
(оскільки розділові знаки були ненадійними або дорогими).
{{/note}}

Крім того, **округлити** має пріоритет над **+**, оскільки це
**унарне повідомлення**. Завдяки дужкам спочатку обчислюється **2 - 1**,
після чого **1** додається до результату **0.5 округлити** (1).

Увесь процес дасть результат **2**, який і буде виведено
як відповідь. Після коми йде повідомлення новий-рядок, яке переводить курсор
на новий рядок. Звісно, найкращий спосіб повністю зрозуміти порядок
виконання програм XOScript — практика.

Варто зазначити, що в XOScript, на відміну від багатьох інших мов
програмування, пробіли є фундаментальною частиною синтаксису. Зокрема,
коли йдеться про бінарні повідомлення, пробіли можуть спричинити певну
плутанину. Завжди ставте пробіл після бінарного повідомлення. Не можна
приєднувати число безпосередньо до повідомлення, наприклад: 

```
3 + 2
```

відрізняється від 

```
3 +2
```

Перший приклад (**3 + 2**) надсилає
повідомлення **+** числу **3** з аргументом — числом **2**.
Результатом у цьому випадку буде **5**. У другому прикладі (**3 +2**)
числу **3** надсилається унарне повідомлення **+2**. Залежно від
контексту це може дати зовсім інший результат.

## Неіснуючі методи

Надсилання повідомлення обʼєкту викликає функцію, яку було
привʼязано до цього обʼєкта під назвою цього повідомлення. Якщо ви надішлете повідомлення,
яке не розпізнано, обʼєкт-отримувач проігнорує ваше повідомлення
і натомість поверне посилання на себе для подальшої взаємодії.
Це називається толерантною передачею повідомлень.

Приклад:

```
Вивід написати: Обʼєкт blah, новий-рядок.
```

Це не спричинить помилки. Буде просто виведено текст **Обʼєкт**.


## Керування потоком виконання

У XOScript не потрібні окремі граматичні правила для *циклів* та
*умов*. Умовний оператор — це просто повідомлення **істина:** або **хиба:**
обʼєкту **Істина** або обʼєкту **Хиба**:

```
2 парне? істина: {
	Вивід написати: ['Two is an even number'], новий-рядок.
}.
```
У попередньому прикладі повідомлення **істина:** надсилається до **Істина** (відповіді
на запитання: чи є 2 парним числом?). Як аргумент додатково
надсилається фрагмент коду: обʼєкт **Функція**. Ця функція виводить
на екран, що 2 справді є парним числом.

Для *циклу* також не потрібні окремі правила запису. Щоб
виконати фрагмент коду тричі, просто надішліть цій **Функція**
**\*** з аргументом **3**:

@test5

У цьому фрагменті коду **i** — це індекс. Тож під час першого виконання функції
**i** дорівнює 0, під час наступного **i** = 1 і
так далі.

Розгляньмо ще один приклад. Якщо потрібно вивести таблицю перерахунку
з *кДж* (кілоджоулів) у *ккал* (кілокалорії) з кроком 100,
правильний запис наведено нижче:

Тут номер поточного рядка передається в параметр
**:line**. На початку функції визначаються її
параметри. Невикористані параметри залишаються порожніми (**Ніщо**). Параметри
завжди розміщуються на початку функції, безпосередньо після відкривної
фігурної дужки, і перед ними ставиться двокрапка.

Повідомлення **поки:** поєднує *цикл* та *умову*.
Дві функції можна повʼязати за допомогою повідомлення **поки:**. Функція-отримувач
виконуватиметься доти, доки функція після двокрапки не дасть негативний
результат. Приклад:

**x** менше за **5**. Коли це вже не так, друга

першої функції завершиться. Зверніть увагу, що **x** визначено поза
функцією і це глобальна змінна. Щоб дізнатися більше про правила області видимості,
зверніться до розділу про функції.

## Інтерполяція рядків

Список *кДж/ккал* можна зробити
охайнішим. Бажано, щоб список мав такий вигляд:

```
100 kj ➞ 23.88 kcal

200 kj ➞ 47.76 kcal
```

Якщо перетворити бажаний вивід на шаблон, його запис
може бути таким:

```
number1 kJ ➞ number2 kcal
```

Це означає, що **number1** позначає значення в кДж, а **number2** — значення
в ккал. Саме так працює інтерполяція рядків у XOScript. Для цього
в XOScript не потрібні окремі граматичні правила. Просто надішліть
тексту слово, яке потрібно замінити, а замінний текст — як
аргумент:

```
>> text :=

['number1 kJ ➞ number2 kcal']

number1: 100,

number2: 23.9.
```

Результат:

```
100 kj ➞ 23.9 kcal
```

Це правило заміни діє для кожного невизначеного повідомлення, отриманого
обʼєктом **текст**. Кожне повідомлення, яке обʼєкт **текст** не
розпізнає, тлумачиться так: *замінити текст повідомлення
текстом з аргументу повідомлення.* Програму можна змінити
так:


@test601


Щоб уникнути плутанини щодо того, яке повідомлення можна чи не можна використовувати як
замінне, найкраще запровадити маркер шаблону, наприклад &lt; &gt;,
для тих частин тексту в шаблоні, які
потрібно замінити.

# Обʼєкти

{{messages}}

Окрім зміни та розширення наявних обʼєктів, ви можете також створювати
нові обʼєкти самостійно, просто надіславши повідомлення **новий**. Припустімо,
ви хочете створити обʼєкт рахунку-фактури, який забезпечує послідовну
нумерацію; у такому разі вам спершу знадобиться обʼєкт рахунку.

Знаючи, що кожен обʼєкт походить від іншого обʼєкта, який, своєю чергою,
зрештою походить від кореневого обʼєкта всіх обʼєктів під назвою Обʼєкт,
потрібно вирішити, на якому з цих обʼєктів буде засновано ваш
новий обʼєкт. Ваш новий обʼєкт успадковує всі властивості
обʼєкта, на якому його засновано, тобто того, якому спочатку надіслали
повідомлення **новий**.

У цьому прикладі бажано взяти досить нейтральний обʼєкт, без надто
великої кількості успадкованих властивостей. Вибір простий, бо в
такому разі новий обʼєкт можна засновати на самому кореневому обʼєкті,
тобто на **Обʼєкт**. Запис задуманої системи рахунків тоді буде
таким:

@test604

Поточний номер рахунку зберігається в обʼєкті, тому перед ним
стоїть ключове слово **свій**. Це називається *властивістю*;
докладніше про це далі.

Деякі компанії воліють включати рік до номерів
рахунків. У такому разі можна створити новий обʼєкт рахунку на основі
попереднього обʼєкта рахунку, який, однак, дає користувачеві змогу

Не потрібно знову писати реалізацію повідомлення **число**,
оскільки вона успадковується від раніше написаного **обʼєкта
рахунку**; отже, старий код можна використовувати повторно. У XOScript немає
таких понять, як класи та споріднені з ними поняття. Це означає, що обʼєкти можуть
успадковувати лише від інших обʼєктів; це також називають *прототипним
успадкуванням*.

Тепер повернімося до властивостей. До властивостей обʼєкта можна звертатися лише
*зсередини ієрархії обʼєктів*, тож інші обʼєкти
не можуть бачити ці властивості.

На відміну від інших мов програмування, усі властивості обʼєктів
видимі виключно обʼєкту, який створив властивість, та
похідним обʼєктам. 

Поширений прийом — використовувати обʼєкт як своєрідне *креслення*,
як, наприклад, у випадку з розглянутими раніше рахунками.
Ще один гарний приклад — **Point**. Скажімо, ви створюєте
компʼютерну програму, яка виконує обчислення з точками на карті. Ви
можете розробити обʼєкт **Point** із властивостями
x-координата та y-координата, які будуть доступні
зовнішньому світу через повідомлення:

@test606

Повідомлення **=** порівнює дві точки за допомогою повідомлення **і:**.
Перше порівняння дає **Істина** або **Хиба**. Це логічні
обʼєкти. Якщо надіслати повідомлення **і:** обʼєкту Істина, а
обʼєкт-аргумент після двокрапки так само є **Істина**, то ви
знову отримаєте відповідь **Істина**. Якщо хоча б один із них **Хиба**, ви
отримаєте відповідь **Хиба**. Зверніть увагу, що одна точка не може прочитати координати
іншої. Потрібно надіслати іншій точці повідомлення, щоб запитати
ці дані: **x-coordinate** та **y-coordinate**. Зрештою, як уже
пояснювалося, властивості можна отримати лише зсередини
самої родини обʼєктів. 

Зверніть увагу, що тут для порівняння точок використано повідомлення **=**.
Так само можна було б використати інше повідомлення, наприклад:
**is:** або **equal:**, однак повторне використання символу **=** здалося
доречним у цьому випадку.

## Успадкування

Раніше написаний код можна використовувати повторно для створення ієрархії
обʼєктів. Наприклад:

**Обʼєкт**, кореневого обʼєкта всіх обʼєктів.

## Рекурсія

У попередньому прикладі **знак** плюс перевизначено. Зверніть
увагу, що зрештою остаточне додавання все одно має бути виконано, і

```

```

Як же XOScript розуміє, що цей **знак** плюс стосується
початкової логіки додавання?** Наприклад, можна було б тлумачити це й так,

обʼєкту, що, своєю чергою, призвело б до **нескінченного циклу**. Очевидно,
що це не задумано. Щойно ви надсилаєте обʼєкту повідомлення,
яке виконало б точно той самий код, XOScript зрозуміє,

## Обʼєкти, подібні до класів

Хоча xoscript не має класів, імітувати поведінку, подібну до класів,
дуже просто. Просто перевизначте повідомлення новий.

```
>> Animal := Обʼєкт новий.
Animal при: ['новий'] виконати: {
	<- сам новий ініціалізувати.
}.

Animal при: ['ініціалізувати'] виконати: {
	свій sound := ['?'].
	свій legs  := 4.
}.
```

У наведеному фрагменті коду ми створюємо обʼєкт під назвою Animal.
Цей обʼєкт слугує *кресленням* для всіх видів тварин,
як-от собак і котів. Батьківський обʼєкт Animal написано
з великої літери A, щоб показати, що це обʼєкт, подібний до класу.
Далі ми перевизначаємо повідомлення новий, написавши власний метод новий.
У цьому випадку він надсилає повідомлення новий до сам, а потім повідомлення
init. Оскільки xoscript за замовчуванням блокує рекурсію, це не спричинить
нескінченного циклу. Натомість повідомлення новий буде надіслано батьківському
обʼєкту (Обʼєкт), і в результаті ми отримаємо новий екземпляр Animal. Тож ми створюємо
новий обʼєкт на основі того самого обʼєкта, для якого створили свій метод новий.
Це цілком коректно. Тепер ми також надсилаємо повідомлення init, яке гарантує,
що обʼєкт Animal має значення за замовчуванням для своїх властивостей. За замовчуванням
тварина має 4 лапи, а звук невідомий (звідси знак питання).
Щоб створити новий екземпляр нашого Animal, можна просто написати:

```
>> a := Animal новий.
```

Тепер ми отримуємо новий екземпляр Animal із 4 лапами, невідомим звуком і
методом init. Так само як і в інших ООП-мовах, ми можемо також
розширити наш Animal:

```
>> Dog := Animal новий.

	сам ініціалізувати.
	свій sound := ['barks'].
}.
```

```

```

## Знімки

Обʼєкт (разом із його поточним станом) можна зберегти на диск так:

```
myobject save-as: ['saved.bin'].
```

Щоб знову завантажити обʼєкт із диска:

```
>> myobject := Обʼєкт load-from: ['saved.bin'].
```

Знімки можна використовувати, щоб зберегти певний стан або підвищити продуктивність.
Завантаження знімка дає змогу уникнути лексичного аналізу, синтаксичного аналізу та налаштування застосунку.
Крім того, у майбутньому зі знімками можуть зʼявитися додаткові переваги продуктивності,
як-от оптимізація певних шаблонів або виявлення й
оптимізація гарячих шляхів.

{{warning}}
Знімки — експериментальна функція, не використовуйте її в робочому середовищі.
Щоб увімкнути експериментальні функції, компілюйте з -D EXPERIMENTS.

# Обʼєкт Ніщо

{{messages}}

Обʼєкт Ніщо
представляє порожнечу, а точніше — відсутність інформації.
Іноді ви отримуватимете цей обʼєкт як відповідь на повідомлення,
якщо результатом є **ніщо**. Найважливіше запитання,
яке можна поставити обʼєкту **Ніщо**: **Ніщо?**.
Відповіддю завжди буде **Істина**.

```
Вивід написати: Ніщо Ніщо?.
```

результат:

```
Істина
```

Будь-який обʼєкт, окрім **Ніщо**, відповість **Хиба**.
Наведений фрагмент коду може здатися дещо філософським, проте обʼєкт **Ніщо**
безумовно має надзвичайно практичні застосування. Наприклад, ви
отримаєте обʼєкт Ніщо як відповідь, якщо запитаєте
елемент списку, якого не існує. Обʼєкт Ніщо також можна використати,
якщо ви хочете оголосити змінну, але ще не хочете задавати їй значення.
Натомість ви просто **присвоюєте** їй спеціальне значення **Ніщо**. У
XOScript не дозволено оголошувати змінну без значення, наприклад:


```
>> величина.
```

Натомість потрібно написати так:

```
>> величина := Ніщо.
```

# Логічні значення

{{messages}}

На відміну від більшості популярних на момент написання мов програмування,
XOScript має лише один обʼєкт Істина та один обʼєкт Хиба.
Тобто щоразу, коли ви пишете **Істина**, це не означає, що
створюється новий обʼєкт. Натомість ви завжди використовуєте посилання. Це
означає, що коли ви пишете таке:

\>\> x := Істина.

**x** посилається на обʼєкт **Істина**. Умовний код і цикли також
перевіряють це посилання. У XOScript значення **Істина** та **Хиба**
не є незмінним. Насправді програма XOScript добряче похитнеться від
такого виразу:

Істина := Хиба.

Результат таких дій невизначений, однак це залишається допустимою
дією, а отже, формально дозволено. Крім того, існує обʼєкт Логічний,
який є кореневим обʼєктом і для **Істина**, і для **Хиба**, оскільки обидва
є похідними від цього кореневого обʼєкта. Однак сам обʼєкт Логічний
не має практичного застосування.

## Підступи

Будьте обережні з використанням **і:** та **або:**

```
Вивід написати: (Хиба or: Істина or: Істина), новий-рядок.
Вивід написати: (Хиба або: Істина, або: Істина), новий-рядок.
```

Дає

```
Хиба
Істина
```
оскільки повідомлення **або:** приймає лише 1 аргумент. Перше повідомлення
надсилає **або:або:** до Хиба, якого не існує, тож обʼєкт ігнорує
повідомлення і повертає себе (Хиба). Натомість другий рядок
надсилає **або:**, а за ним ще одне **або:** (за допомогою символу ланцюжка, тобто коми: ,).

{{messages}}

Щоразу, коли ви пишете число, наприклад 9, -10 або 3,12, XOScript

Це справа смаку.

Різниця між бінарними математичними повідомленнями (+) та
їхніми варіантами з ключовими словами (додати:) полягає в тому, що перші повертають
нове число, яке є результатом операції, тоді як у разі
других змінюється сам обʼєкт. Це проілюстровано в

Ви можете створити копію будь-якого обʼєкта

Повідомлення | Результат
------- | ------

повідомлення | Ніщо      | Логічний           | Число                 | Текст     | Інше

текст    | ['Ніщо']  | ['Хиба']/['Істина'] | ['n']                 | н/д       | Залежить

# Функції

{{messages}}

Код можна згрупувати між { і }, і тоді він стає функцією.
У xoscript ми іноді також використовуємо термін завдання або просто
блок коду.

Запустити функцію можна, надіславши повідомлення *запустити*.


```
{ Вивід написати: 123, новий-рядок. } запустити.
```

Якщо ваша функція приймає аргументи, використовуйте **застосувати:**.

```
{ :a Вивід написати: a, новий-рядок. } застосувати: a.
```

Див. також приклади нижче.
Через простоту архітектури функція може мати лише
одну точку повернення. Щоб уникнути зайвих витрат або надмірної вкладеності
умов, можна використати процедуру (це те саме, що використати
знак множення з аргументом 1):

```
{
  (a = 1) істина: { x := 1. }, перервати.
  (a = 2) істина: { x := 2. }, перервати.
} процедура.
```

Таким чином (a = 2) не обчислюватиметься, якщо a = 1.
Крім того, так вам не потрібні вкладені повідомлення істина.
Щоразу, коли ви помічаєте, що вкладаєте умови одна в одну, згадайте
про повідомлення процедура. Воно може зробити ваш код
легшим для читання.


Ось важливий підступ:

```
{
	Хиба хиба: {
		Вивід написати: ['End the loop.'].
	}, перервати.
	
	Вивід написати: ['Dont show me.'].

} процедура.

```

У цьому випадку текст 'Dont show me' буде показано,
оскільки **перервати** надсилається до Хиба. Якщо ви хочете виконати
переривання, його потрібно надіслати як повідомлення до **Істина**.
 

```
{
	Хиба не істина: {
		Вивід написати: ['End the loop.'].
	}, перервати.
	
	Вивід написати: ['Dont show me.'].

} процедура.

```

Працюватиме, як очікується.

## Винятки

Винятки можна обробляти так:

```
{ Task 1 } перехопити: { Task 2 }, запустити.
```

Ви також можете навмисно спричинити помилку у своїй програмі і
таким чином активувати блок-обробник. Для цього потрібно надіслати
поточному завданню повідомлення **помилка:**, як показано в наступній
ілюстрації:

```
{
це-завдання помилка: ['Whoops!'].
} перехопити: { :mistake
Вивід написати: mistake.
}, запустити.
```

## Впровадження значень

XOScript дає змогу впроваджувати значення в завдання. Погляньте
на завдання нижче:

```
>> sending := {
	Newsletter кому: свій recipient.
}.
sending задати: ['recipient']
значення: ['info@recipient.org'].
sending запустити.
```


На цій ілюстрації показано уявне завдання, яке надсилає розсилку
на адресу електронної пошти або **recipient**. Цього одержувача можна впровадити
в завдання ззовні ще до запуску завдання, надіславши завданню
повідомлення **задати:значення:**. Таким чином значення
**recipient** заздалегідь задається в завданні. Це значення також можна змінити,
а потім знову запустити завдання. Це корисний метод під час роботи з
обʼєктами завдань.

## Порожні функції

Порожні завдання не дозволені. Теоретично порожнє завдання виглядало б
так: **{}**, однак XOScript сприймає це як мовну помилку. Якщо
ви хочете оголосити порожнє завдання, можна використати обʼєкт Ніщо:

```
>> task := Ніщо.
```

Хоча це не справжнє завдання, а обʼєкт Ніщо, йому все одно можна
надіслати повідомлення запустити:

```
>> answer := task запустити.
```

Насправді це те саме, що:

```
>> answer := Ніщо запустити.
```

Оскільки обʼєкт **Ніщо** не розпізнає повідомлення **запустити**, він
поверне себе як відповідь, тож відповіддю знову буде **Ніщо**.
Отже, немає потреби в порожньому завданні. Завдяки елегантному
дизайну мови програмування XOScript можна просто використати обʼєкт
Ніщо.

# Списки

{{messages}}

XOScript знає два типи колекцій: *списки* та *словники*.
**Списки** — це переліки обʼєктів у *фіксованому порядку*. Словники
не мають порядку, натомість вони нагадують легенду, що складається з ключа (або терміна) та
відповідного йому значення. Списки можна порівняти з масивами (PHP, Java, C)
та списками (Python). Словники можна порівняти з асоціативними масивами (PHP) або
словниками (Python) в інших мовах програмування. Щоб створити
новий Список, напишіть:

```
>> fibonacci := Список новий.
```

Цей порожній список можна заповнити за допомогою **додати-в-кінець:** :

```
fibonacci додати-в-кінець: 0.
fibonacci додати-в-кінець: 1.
fibonacci додати-в-кінець: 1.
fibonacci додати-в-кінець: 2.
fibonacci додати-в-кінець: 3.
fibonacci додати-в-кінець: 5.
fibonacci додати-в-кінець: 8.
fibonacci додати-в-кінець: 13.
```

Якщо вивести список на екран:

```
Вивід написати: fibonacci, новий-рядок.
```

Ми побачимо:

```
Список ← 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13
```

Замість додати-в-кінець можна також використовувати ; для додавання елементів до списку:


```
>> fibonacci := Список новий ; 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13.
```

Крапки з комою (;) — це бінарні повідомлення, які додають
значення до списку.

## Ланцюжки

Припустімо, у вас є такий список:

```
>> x := Список новий ; 1 ; 2 ; 3.
```

Якщо ви хочете видалити перший і останній елементи, то ваше
повідомлення буде таким:

```
x вилучити-перший вилучити-останній.
```

На жаль, попередній запис не працюватиме правильно.
Повідомлення **вилучити-перший** повертає перший елемент списку, який,
своєю чергою, стане отримувачем повідомлення **вилучити-останній**. Тож
повідомлення **вилучити-останній** надсилається не до **x**, а до 2.
Можливим розвʼязанням цієї проблеми було б створення двох окремих
речень, наприклад: 

```
x вилучити-перший.
x вилучити-останній.
```

Однак це досить непрактично, особливо коли потрібно
видалити більше двох елементів. Тому XOScript пропонує
альтернативну структуру повідомлень для таких ситуацій. В
**альтернативних** структурах повідомлень відповіді обʼєктів ігноруються,
і ви щоразу отримуєте як відповідь обʼєкт-отримувач.
**Альтернативна** структура повідомлень починається надсиланням обʼєкту
повідомлення **робити**, а завершити **альтернативну** структуру
повідомлень можна надсиланням повідомлення **зроблено**. У
наведеному прикладі це можна застосувати так:

```
>> x := Список новий ; 1 ; 2 ; 3.
x робити вилучити-перший вилучити-останній зроблено.
```

# Словники

{{messages}}

**І Список, і Словник є колекціями. Однак, на відміну від
списку, словник **не має** порядку. Ще одна відмінність між ними
полягає в тому, що словник складається з пар обʼєктів. Один обʼєкт діє як запис (або
ключове слово), за яким шукається інший обʼєкт. Гарний приклад
такого списку — прайс-лист, наприклад:


```
>> menu := Словник новий
	поставити: ['£5'] у: ['apple pie'],
	поставити: ['£6'] у: ['carrot cake'],
	поставити: ['£3'] у: ['fudge'].
```

Так само як і для списку, для додавання обʼєкта до списку використовується
повідомлення поставити:у:. Різниця в тому, що, на відміну від
списку, повʼязуються два обʼєкти. Перший обʼєкт, як і
в списку, — це обʼєкт, який ви зберігаєте в списку. Другий
обʼєкт — це не його позиція в колекції, а **запис**,
за допомогою якого попередній обʼєкт можна буде отримати пізніше.
Коротко кажучи, словник працює приблизно як звичайний словник: за ключовим словом
можна знайти значення. Наприклад, щоб отримати з
наведеного списку ціну помадки:

```
>> price := menu на: ['fudge'].
```

Можна також використовувати стислий запис:

```
>> price := menu ? ['fudge'].
```

Якщо записи, які ви використовуєте для зберігання обʼєктів, не містять пробілів
(і не збігаються з іншими заздалегідь визначеними повідомленнями),
можна також використовувати такий запис:

```
>> menu := Словник новий
	pie:   ['£5'],
	cake:  ['£6'],
	fudge: ['£3'].
```

Безсумнівно, наведений запис читається дещо природніше.
Щоб запитати ціну
помадки, можна використати такий спрощений запис:

```
>> price := menu fudge.
```

# Програма/StdOut

{{messages}}

Обʼєкт Програма представляє застосунок, що виконується. Цей обʼєкт
надає можливості виконувати системні команди, включати підпрограми,
читати аргументи тощо. Усі функції, повʼязані із системою.

## StdOut

Вивід — це обʼєкт стандартного виводу. По суті він має два методи:
**написати:** і **новий-рядок**. Повідомлення написати: використовується для надсилання рядка
до stdout, а повідомлення новий-рядок виводить символ нового рядка.
Замість **новий-рядок** можна також використовувати \\n.

Приклад:

```
Вивід написати: ['Hello World'], новий-рядок.
```

результат:

```
Hello World
```

## Модулі/плагіни

Світ XOScript можна розширити новими системними обʼєктами,
встановлюючи модулі. Новий системний обʼєкт можна додати до світу
XOScript, помістивши файл модуля (зазвичай файл із суфіксом .so)
до теки mods. 

Коли ви надсилаєте повідомлення обʼєкту, який стає доступним через
модуль плагіна, XOScript автоматично його завантажить.

Ви також можете самі писати плагіни. Плагіни пишуться
мовою програмування C. Приклад плагіна можна знайти в пакеті
вихідного коду в src/plugins/example.


## Рефлексія

Існують різні способи дослідження
системи під час виконання програми. XOScript має кілька методів для
виявлення того, які обʼєкти присутні і на які повідомлення ці обʼєкти
відповідають. По-перше, у кожного обʼєкта можна запитати, якого він **тип**,
однак типи в XOScript мінливі, а тому ненадійні.

Також можна запитати в обʼєкта Програма, чи
певний обʼєкт уже присутній у програмі:

```
Програма Tool істина: { ... }.
```

Якщо імʼя обʼєкта
складається з одного символу, найкраще застосовувати
такий запис, щоб уникнути плутанини:

```
Програма знайти: ['X'], істина: { ... }.
```

Окрім запитань про обʼєкти, так само можна запитувати
обʼєкт Програма про повідомлення. Наприклад, можна запитати, чи
знає обʼєкт **Число** повідомлення **між:і:**, у спосіб,
показаний нижче:

```
Програма Number: ['between:and:'], новий-рядок.
```

#!/bin/xo

Обʼєкт HTTP-Запит можна використовувати для отримання даних GET/POST/COOKIE та

>> search   := http-запит get: ['search']. # ?search=books

## База даних

Обʼєкт Database можна використовувати для запитів до MariaDB/MySQL.
Щоб підключитися до бази даних, виконайте:

```
>> db := Maria-DB новий хост: ['localhost'],
	користувач: ['xo'],
	пароль: ['pass123'],
	назва-бази: ['xobase'],
	підключити.

```

Щоб вставити запис, використовуйте:

```
>> параметри-пошуку := db запит: ['
	INSERT INTO book (id, description, price, rating) 
	VALUES (NULL, ?, ?, ?)
'], параметри: ( Список новий ; ['abc'] ; 12.35 ; 6 ). # parameterized queries

{  параметри-пошуку виконати. db підтвердити. }
перехопити: { :e db відкотити.  }, запустити.
```

Зверніть увагу, що xoscript працює *лише* з транзакціями і ніколи не виконує autocommit.
Якщо autocommit неможливо вимкнути, ви отримаєте помилку підключення.
Завжди використовуйте привʼязування параметрів у запитах, ніколи не додавайте введення користувача
безпосередньо до SQL.

Отримати вставлений id можна так:

```
Вивід написати: ['INSERTED: '] + параметри-пошуку insert-id, новий-рядок. # insert id
```

Щоб отримати записи:

```
>> параметри-пошуку :=
db
	запит: ['SELECT * FROM book order by id desc limit 2'], 
	отримати: { :row 
		Вивід написати: row id + [' '] + row description + [': '] + row price, новий-рядок.
	}. # fetching rows

```

## Сесії

Для збереження стану можна зберігати й отримувати дані з обʼєкта сесії.
Спочатку створіть новий **Веб-документ**. Обʼєкт Веб-документ обʼєднує
запит, заголовки, HTML і сесію. Річ у тім, що, коли ви
відвідуєте вебсайт у браузері, ви бачите лише HTML. Але
весь Веб-документ складається також із **заголовків**. Наприклад,
більшість HTTP-відповідей містять заголовок на кшталт Content-type:text/html, щоб
повідомити браузеру, що наступні дані слід відобразити як HTML
(а не, наприклад, завантажити як файл). Сесії — це спосіб
зберігати дані користувача між запитами. Щоб відстежувати ці дані, потрібно
встановити cookie, і цей cookie також встановлюється через заголовок. Тому
все поєднується у Веб-документ (оскільки це повний
документ, що містить і заголовки, і HTML або інші дані).


```
# First we make a new Web Document instance
>> web := Веб-документ новий.

# Now we start a session, this will generate a Header for a cookie and
# create a file to store your data, associated with that cookie
>> session := web почати-сесію.

# Now we can treat session like a dict
session userid: 123.
```

Щоб знищити сесію (під час виходу з системи):

```
web знищити-сесію.
```

## Заголовки

Веб-документ також дає змогу задавати інші відомі заголовки.
Наприклад, якщо ви хочете перенаправити користувача на іншу URL-адресу:

```
web перейти-до: ['/other.html'].
```

Під капотом ця команда також генерує HTTP-заголовок, який надсилається
разом з іншими вашими даними або HTML, щоб наказати браузеру перейти
за вказаною цільовою адресою.

Щоб додати власний заголовок:

```
web заголовок: ( 
	HTTP-Заголовок новий
	ключ: ['Content-Length']
	величина: 400
).
```

Щоб показати сторінку 404:

```
web не-знайдено: ['OOps..'].
```


## Шаблони

Стандартна система шаблонів дуже проста. Вам не потрібно вивчати
новий синтаксис шаблонів. Крім того, рушій шаблонів забезпечує справжнє розділення
представлення та бізнес-логіки.

Щоб створити шаблон із файлу:

```
>> tpl := web заготовка: ['templates/ux.tpl'].
```

Система шаблонів використовує маркери. 
Існує три типи маркерів: маркери вирізання, маркери вставлення та
маркери-слоти. Основна ідея дуже проста: ви вирізаєте
області, позначені маркерами вирізання, і можете вставити їх в
області, позначені маркерами вставлення. У маркери-слоти можна вставляти
рядки.

Тож, наприклад, маючи такий шаблон, покладімо
самоцвіт у скриньку для коштовностей і додаймо цінник.

```
<!-- cut:gem -->
<img src="gem.gif">
<b>$<!-- slot:price --></b>
<!-- /cut:gem -->

<div id="box">
<!-- paste:jewels -->
</div>
```

Це можна зробити так:

```
>> gem := tpl вирізати: ['gem'], копіювати.
gem price: 99.
tpl вставити: gem у: ['jewels'].
web вивести: tpl підчистити.
```

Останній рядок просто надсилає шаблон як рядок клієнтові
разом із потрібними HTTP-заголовками.

Результат:

```
<div id="box">
<img src="gem.gif">
<b>$99</b>
</div>
```


## Passthru

Щоб безпечно віддавати файли, завантажені користувачами, можна покластися на passthru:

```
>> uploaded := ['smile.gif'].
Server передати: uploaded префікс: ['/uploads/images/'].
Програма кінець.
```

Це віддасть завантажений користувачем вміст із відповідним
типом mime. Підтримуються лише типи mime з білого списку:
GIF, JPG, PNG, WEBP, MP4, WEBM, MP3, ZIP, GZIP, PDF і SVG.
Файли SVG, ZIP і GZIP надсилаються як завантаження, оскільки SVG
може містити скрипти, які інакше виконувалися б на вашому домені.
Цей метод запобігає атакам TOCTOU, обходу шляхів,
виконанню шкідливого коду (інʼєкціям), атакам через символічні посилання,
DDoS-атакам (обмеження файлу = 50MB), атакам перехоплення (sniffing) та
різним іншим проблемам безпеки.

## Регулярні вирази

Регулярні вирази можна використовувати, створивши шаблон.
Наприклад, щоб знайти href і target гіперпосилань:

```
Шаблон новий: ['href="([^"]+)" target="([^"]+)"'].
```

Тепер застосуйте шаблон до рядка-обʼєкта пошуку так:

```
pattern збіг: тема виконати: { :m :x .... }
```

Повний приклад:

```
>> тема := ['<html>
	<a href="http://link1" target="_blank">
	<a href="http://link2" target="_blank">
</html>'].
>> pattern := Шаблон новий: ['href="([^"]+)" target="([^"]+)"'].
>> result  := pattern збіг: тема виконати: { :m :x
	Вивід написати: m, новий-рядок.
	Вивід написати: x, новий-рядок.
	<- ['XXX'].
}.
Вивід написати: result, новий-рядок.
```

## Форматування

Обʼєкт Формат дає змогу форматувати дані, наприклад доповнювати їх або
додавати нулі. Він використовує синтаксис printf.

```
>> fmt := Формат новий: ['%06.0f'].
fmt застосувати: 56. # gives 000056
```

Формат може містити одне перетворення, і воно має відповідати значенню,
інакше ви отримаєте помилку:

- `застосувати:` з рядком: `%s`
- `застосувати:` з числом: `%f`, `%e`, `%g` або `%a`
- `застосувати-ціле:` з числом: `%d`, `%i`, `%o`, `%u`, `%x` або `%c`

Значення із запиту є рядками. Щоб відформатувати одне з них як число,
спочатку перетворіть його:

```
fmt застосувати: (http-запит get: ['amount']) число.
```

# ffi

{{messages}}

FFI надається на рівні платформи/плагіна, оскільки він
привʼязаний до архітектури базової системи, чого
ядро робити не повинно.
Серверний плагін пропонує сумісну реалізацію ffi/блобів.
За замовчуванням ядро взаємодіє з цільовою платформою
через stdin/stdout, обмежені служби файлового вводу-виводу та оболонку (Програма система:).
Додаткову інтеграцію забезпечують ffi/блоби через орієнтовані на застосунки
плагіни, як-от серверний плагін.

FFI означає Foreign Function Interface (інтерфейс сторонніх функцій). Він дає змогу використовувати функціональність, написану іншими
різними мовами програмування, що надається через файли DLL, SO або Dylib. Це можуть
бути найрізноманітніші функції, і в такий спосіб доступний величезний спектр функціональності.
Почнімо з прикладу:

```
Server звʼязати: (
 Список новий ;
 ['/usr/lib/x86_64-linux-gnu/libc.so.6'] ;
 ['printf'] ;
 ( Список новий ; ['pointer'] ; ['int'] ) ;
 ['void'] ;
 ['Printf'] ;
 ['template:number:']
).
>> s := Blob utf8: ['FFI has %d letters.\n'].
Printf template: s number: 3.
s звільнити.
```

Результатом цього коду буде те, що в командному рядку ви побачите таке:
FFI has 3 letters.
Тепер ви, мабуть, думаєте: «Забагато коду для чогось такого простого».
Тобто хіба не можна було б розвʼязати це командою Gui show? Відповідь — безумовно так!
Але це задумано як ілюстративний приклад.
FFI зазвичай використовують для складніших завдань, але з них не виходять гарні
приклади, тому я вибрав щось тривіальне.

Аргументи методу link:

- Аргумент №1: файл DLL або SO, який ви хочете використати.
- Аргумент №2: функція в цьому файлі, яку ви хочете підʼєднати.
- Аргумент №3: список із назвами типів даних аргументів функції.
- Аргумент №4: назва типу значення, що повертає функція.
- Аргумент №5: назва обʼєкта, до якого ви хочете привʼязати цю функцію (якщо його не існує, його буде створено
автоматично).
- Аргумент №6: повідомлення, до якого слід привʼязати цю функцію.

У наведеному прикладі ми хочемо підʼєднати функцію printf із libc.so. Назви типів
даних можна знайти в документації програмного забезпечення, до якого ви підʼєднуєтеся. Доступні типи:
void, pointer, float, double, int, uint, char, uchar, intX та uintX,
де X може бути 8, 16, 32 або 64.

Ці типи вказують на кількість байтів, потрібну для зберігання даних. Для printf ми привʼязуємося до
нового обʼєкта під назвою Printf і повідомлення template:number:. Ви перекладаєте зовнішню
функцію на діалект XOScript перед її використанням. Повідомлення template:number: очікує
як перший параметр буфер із текстом шаблону. Ми створюємо цей буфер за допомогою обʼєкта Blob, який
дає змогу вручну виділяти памʼять. Ви відповідаєте за звільнення цієї памʼяті після цього
за допомогою повідомлення звільнити.

Блоб памʼяті можна заповнити різними способами. У нашому прикладі ми заповнюємо його текстом, тому використовуємо
повідомлення utf8: (UTF-8 — це кодування для перетворення тексту на байти). Блоб також можна заповнити
за допомогою bytes:, передавши список значень байтів. Щоб прочитати вміст блоба, використовуйте від:довжина:.
Ви отримаєте байти назад у вигляді списку. За допомогою Blob можна навіть створити C-структуру, використавши
повідомлення struct: і передавши послідовність типів C. Це може знадобитися під час виклику функції C
у зовнішній програмній бібліотеці, яка очікує вказівник на структуру.

{warning}
Блоби потрібно звільняти самостійно.
Збирач сміття не очищує блоби.
{/warning}

Оскільки блоби можуть передаватися зовнішнім функціям із бібліотек, їх
неможливо автоматично прибрати збирачем сміття (вони можуть і далі використовуватися
зовнішніми функціями, або ці зовнішні функції можуть захотіти звільнити їх
самі). Тому за потреби блоби потрібно звільняти самостійно.

Щоб звільнити блоб, використовуйте:

```
myblob звільнити.
```

Щоб звільнити структуру, використовуйте:

```
mystruct звільнити-struct звільнити.
```

Тож для структури потрібно надіслати два повідомлення: звільнити-struct і звільнити, щоб
звільнити блок памʼяті.
