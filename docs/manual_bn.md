XOScript-এ স্বাগতম
XOScript প্রকল্পের লক্ষ্য একটি সরল ও নিরীক্ষণযোগ্য স্ক্রিপ্টিং ভাষা তৈরি করা।
সরল মানেই যে সহজ, তা নয়।
একটি পরিচিত প্রোগ্রামিং ভাষা XOScript-এর চেয়ে ব্যবহারে সহজ হতে পারে।
এখানে সরলতার অর্থ ভিন্ন:
ভাষাটি এবং তার আচরণ সম্পর্কে একটি সম্পূর্ণ মানসিক মডেল গড়ে তুলতে পারা।

XOScript এমনভাবে নকশা করা হয়েছে যাতে পুরোটা আপনার মাথায় ধরে।
এর ব্যাকরণ এবং ধারণার সংখ্যা ইচ্ছাকৃতভাবে ছোট রাখা হয়েছে।
এখানে কোনো ক্লাস নেই; বস্তুকে সরাসরি সম্প্রসারিত করা যায়।
বস্তু রেফারেন্স হিসেবে পাঠানো হয়, অনুলিপি করা স্পষ্টভাবে করতে হয়,
এবং ফাংশনের প্রস্থানের পথ একটিই।

এই সিদ্ধান্তগুলোর কয়েকটি মূলধারার ভাষা থেকে উল্লেখযোগ্যভাবে আলাদা।
যেমন, XOScript-এ কোনো টাইপ সিস্টেম নেই, এবং এটি ডায়নামিক স্কোপিং ব্যবহার করে।
যে বার্তা সামলানো যায় না, তা ব্যতিক্রম (exception) তৈরি না করে উপেক্ষা করা হয়।
এই সিদ্ধান্তগুলোর পরিণাম আছে, এবং এগুলোর উদ্দেশ্য ত্রুটি দূর করা নয়।
এগুলোর উদ্দেশ্য ভাষার অন্তর্নিহিত মডেলকে ছোট ও সামঞ্জস্যপূর্ণ রাখা।

XOScript স্থানীয় ভাষায় রূপান্তরও করা যায়, ফলে ব্যবসায়িক
নিয়মগুলো একটি প্রাকৃতিক ভাষায় প্রকাশ করা এবং সম্ভবত অ-প্রযুক্তিগত অংশীজনদের সঙ্গে ভাগ করে নেওয়া সম্ভব হয়।

নিরীক্ষণযোগ্যতা মানে একই দর্শন বাস্তবায়নের ক্ষেত্রেও প্রয়োগ করা।
রানটাইম C-তে লেখা, যাতে আছে একটি ছোট হাতে-লেখা লেক্সার, পার্সার এবং ট্রি ওয়াকার।
স্ট্যান্ডার্ড লাইব্রেরি এবং রানটাইম অনেকাংশে ভাষার কাঠামোরই প্রতিফলন,
ফলে XOScript কোড এবং তার বাস্তবায়নের সম্পর্ক তুলনামূলকভাবে সরাসরি।

পরীক্ষাগুলোও ডকুমেন্টেশনের সঙ্গে ঘনিষ্ঠভাবে যুক্ত।
প্রতিটি মেথডের একটি সংশ্লিষ্ট পরীক্ষা থাকা উচিত যা ম্যানুয়ালে অন্তর্ভুক্ত করা যায়,
এতে ডকুমেন্টেশন বাস্তবায়নের সঙ্গে সামঞ্জস্যপূর্ণ থাকে।

XOScript বৈশিষ্ট্য বা পরিচিতির দিক থেকে মূলধারার ভাষাগুলোর সঙ্গে
প্রতিযোগিতা করার উদ্দেশ্যে তৈরি নয়। এটি একটি ভিন্ন লক্ষ্য অনুসন্ধান করে:
এমন একটি প্রোগ্রামিং পরিবেশ যা একজন ডেভেলপার সামগ্রিকভাবে বুঝতে পারেন।

আশা করা হয় যে একটি ছোট ভাষা এবং একটি ছোট
বাস্তবায়ন সফটওয়্যারকে বাইট থেকে বস্তু পর্যন্ত, সিনট্যাক্স থেকে রানটাইম পর্যন্ত
বোঝা বাস্তবসম্মত করে তোলে, এবং আত্মবিশ্বাসের সঙ্গে কোড লেখা সম্ভব করে,
কারণ আপনি বোঝেন স্ক্রিপ্টে কী ঘটে এবং
ভেতরে কী ঘটে।

একটি xoscript সার্ভার সেটআপের স্থাপত্য
সরল, তবুও নমনীয়।

xoscript-কে সার্ভার ভাষা হিসেবে ব্যবহার করতে হলে আপনাকে
/mods/server নামের একটি ফোল্ডারে সার্ভার প্লাগইন ইনস্টল করতে হবে।

এর কারণ, আমরা মূল ভাষাকে সার্ভার-নির্দিষ্ট কার্যকারিতা থেকে
আলাদা রাখতে পছন্দ করি, যা উদাহরণস্বরূপ PHP বা Python-এর মতো নয়। নইলে আমাদের
অকারণে সবাইকে পুরো রান্নাঘরের সিঙ্ক পাঠাতে হতো, যা নিছক বোকামি।
চাইলে আপনি অন্যান্য মডিউলও ইনস্টল করতে পারেন। ব্যবস্থাটি খুবই
নমনীয়।

এছাড়া কিছু কার্যকারিতা, যেমন টেমপ্লেটিং এবং সেশন পরিচালনা, স্ক্রিপ্টিং ভাষাতেই
বাস্তবায়ন করা ভালো, তাই আপনার সুবিধার জন্য আমরা অতিরিক্তভাবে
template.xo এবং webtools.xo লাইব্রেরি সরবরাহ করি।
এসবের কারণ হলো, আপনি xoscript কীভাবে ব্যবহার করতে চান তা আমরা জানি না।
আপনি এটিকে সার্ভার-সাইড স্ক্রিপ্টিং ভাষা হিসেবে ব্যবহার করতে পারেন,
আবার GUI, এমবেডেড ডিভাইস বা কেবল ব্যাচ প্রসেসিংয়ের জন্যও।
এমনকি সার্ভার-সাইড স্ক্রিপ্টিং ভাষা হিসেবে ব্যবহার করলেও (যা
বর্তমানে প্রধান ব্যবহারের ক্ষেত্রগুলোর একটি), আপনি হয়তো
ভিন্ন কোনো টেমপ্লেট ইঞ্জিন বা ভিন্ন সেশন হ্যান্ডলার ব্যবহার করতে চাইবেন।
আপনাকে আমাদেরটাই ব্যবহার করতে হবে, এমন সিদ্ধান্ত নেওয়ার আমরা কে?

তবে আমাদের নিজস্ব টেমপ্লেট ইঞ্জিন ব্যবহারের একটি সুবিধা হলো,
টেমপ্লেট তৈরি করতে আপনাকে অতিরিক্ত কোনো সিনট্যাক্স শিখতে হয় না।
xoscript-এর সঙ্গে আসা ডিফল্ট টেমপ্লেট ইঞ্জিন উপস্থাপনা ও যুক্তির মধ্যে ১০০%
পৃথকীকরণ ব্যবহার করে। বিশেষ টেমপ্লেট সিনট্যাক্সের বদলে এটি কেবল
একটি অত্যন্ত নমনীয় স্লট-চিহ্ন ব্যবস্থা ব্যবহার করে।
আরও তথ্যের জন্য সার্ভার অধ্যায় দেখুন।

লক্ষ্য করুন, আপনি যদি ডিফল্ট টেমপ্লেট ইঞ্জিন বা
ডিফল্ট webtools ব্যবহার করতে না চান, তবে বলাই বাহুল্য যে আপনাকে
নিজেরটা সরবরাহ করতে হবে।

আপনি যদি আপনার ওয়েবসার্ভার chroot, jail বা অন্য কোনো ধরনের স্যান্ডবক্সে চালান,
তবে সেই পরিবেশে xo-এর নির্ভরতাগুলোও ইনস্টল করতে হবে; কোন কোন
লাইব্রেরি প্রয়োজন তা ldd ব্যবহার করে দেখতে পারেন (Linux বা BSD-র manpage দেখুন)।
আপনি যদি আপনার xo-স্ক্রিপ্টে শেল কমান্ড ব্যবহার করতে চান, তবে এই পরিবেশে একটি শেলও
(যেমন bash বা ksh) কপি করুন।

আমরা আরও উল্লেখ করতে চাই যে আমরা পশ্চাৎমুখী সামঞ্জস্যকে খুবই গুরুত্ব দিই।
এমনকি 'version' নামে একটি বিশেষ পশ্চাৎমুখী সামঞ্জস্য বৈশিষ্ট্যও
রয়েছে। সাধারণভাবে, আমাদের লক্ষ্য আপনার কোড চিরকাল চালু রাখা। ফলে xoscript-এর
নতুন সংস্করণগুলোর সঙ্গে সামঞ্জস্য বজায় রাখতে আপনাকে কখনো
কোড হালনাগাদ করতে হবে না। আমাদের লক্ষ্য: একবার লিখুন, চিরকাল চালান।

এই ম্যানুয়ালের বাকি অংশ প্রোগ্রামিং ভাষা xoscript বিস্তারিতভাবে
ব্যাখ্যা করার জন্য নিবেদিত। সার্ভার-স্ক্রিপ্টিং আলোচনা করা হয়েছে সার্ভার
নামের অধ্যায়ে। আপনি যদি একজন অভিজ্ঞ সফটওয়্যার ডেভেলপার হন, তবে হয়তো
কয়েকটি অধ্যায় বাদ দিতে চাইবেন, কারণ সেগুলোর কিছু একটু বেশি বিস্তারিত বা
সাধারণ প্রোগ্রামিং চর্চার সঙ্গে খুবই মিলে যায়। তাই যাঁদের ইতিমধ্যে
একাধিক প্রোগ্রামিং ভাষায় অভিজ্ঞতা আছে, তাঁদের জন্য
এই ম্যানুয়ালটিকে একটি রেফারেন্স গাইড হিসেবে ব্যবহার করাই ভালো।

## Linux-এ সেটআপ

apache2 এবং mariadb ডাউনলোড করুন:


```
sudo apt-get install apache2 mariadb-server
sudo a2enmod cgi
```

xoscript ডাউনলোড করুন।
X-এর জায়গায় সঠিক সংস্করণ নম্বর বসান!

```
wget https://xoscript.com/downloads/xoserver-linux-1_5_X.tar.gz
tar xvf xoserver*.tar.gz
```

ফাইলগুলো webroot এবং /bin-এ কপি করুন:


```
sudo cp bin/xo /bin/xo
sudo cp -R bin/mods /var/www/html/
sudo cp *.xo /var/www/html/
```

আপনার apache2 কনফিগ সম্পাদনা করুন:

```
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

Virtualhost-এর জায়গায় লিখুন:

```
<VirtualHost *:80>
    <Directory /var/www/html>
        Options +ExecCGI
        AllowOverride All
        AddHandler cgi-script .xo
        Require all granted
    </Directory>
    DocumentRoot /var/www/html
</VirtualHost>
```

একটি পরীক্ষামূলক পেজ তৈরি করুন:

```
sudo nano /var/www/html/test.xo
```

এবং একটি ছোট পরীক্ষামূলক প্রোগ্রাম লিখুন:

```
#!/bin/xo
Server প্রস্তুত-করো.
প্রোগ্রাম ব্যবহার: ['webtools.xo'].
>> ওয়েব := ওয়েব-নথি নতুন.
ওয়েব আউটপুট-দাও: ['Hello World'].
```

apache2-কে CGI-এর মাধ্যমে আপনার প্রোগ্রাম চালানোর অনুমতি দিন:

```
sudo chmod uog+x /var/www/html/test.xo
```

apache2 পুনরায় চালু করুন:

```
sudo systemctl restart apache2
```

ব্রাউজারে আপনার পরীক্ষামূলক পেজে যান:

```
http://localhost/test.xo
```

আপনার দেখা উচিত:

```
Hello World
```


## OpenBSD-তে সেটআপ

/etc/httpd.conf সম্পাদনা করুন, যোগ করুন:


```
server "mydomain.com" {
    listen on * port 80
    root "/htdocs/mydomain/"

    location "*.xo" {
        fastcgi
        fastcgi socket "/run/slowcgi.sock"   # inside chroot
    }
}
```

আপনি যদি SSL ব্যবহার করতে চান:

```
listen on * tls port 443
tls {
	certificate "/etc/ssl/mycert.crt"
	key "/etc/ssl/private/mykey.key"
}
```

কোয়ান্টাম আক্রমণ থেকে কী এক্সচেঞ্জ সুরক্ষিত রাখতে
mlkem সাইফার নির্বাচন করুন:

```
tls {
 ... 
 ecdhe "X25519MLKEM768"
 ...
}
```

xo বাইনারি ও mods, সেইসঙ্গে যেকোনো নির্ভরতা
chroot-এ যোগ করুন (ldd দিয়ে খুঁজে বের করুন)।

## উদাহরণ চালানো


প্যাকেজের কোনো উদাহরণ প্রোগ্রাম চালাতে:

```
./example.sh <name> <Linux/OBSD> [clean]
```

উদাহরণস্বরূপ, Linux-এ FizzBuzz উদাহরণ চালাতে:

```
./example.sh fizzbuzz Linux
```

একই উদাহরণ OpenBSD-তে চালাতে:

```
./example.sh fizzbuzz OBSD
```

```
./example.sh fizzbuzz OBSD clean
```

## হ্যালো ওয়ার্ল্ড

ফাইলটি আপনার কম্পিউটারে স্থানান্তরিত হওয়ার পর আপনি এটি এক্সট্র্যাক্ট করে
নিচের কমান্ড ব্যবহার করে xo চালু করতে পারেন:

```
xo
```

একটি XOScript চালাতে, প্রোগ্রামটিকে -xo প্রত্যয় যোগ করে (ঐচ্ছিক)
একটি ফাইল হিসেবে সংরক্ষণ করুন। এরপর XOScript কমান্ডের পরে
আপনার প্রোগ্রামের ফাইলের নাম লিখুন:

```
xo myprogram.xo
```

যখন আপনি আপনার প্রোগ্রাম ফাইলকে প্যারামিটার হিসেবে দিয়ে একটি XOScript কমান্ড চালান,
তখন xo আপনার প্রোগ্রাম ফাইলটি পড়ে এবং নির্বাহ করে।

{{note}}
আপনি আপনার প্রোগ্রামটি xo আইকনের ওপর টেনে এনেও চালু করতে পারেন।
{{/note}}

{{warning}}
কিছু সিস্টেমে আগে থেকেই xo-কে ডায়নামিক
লাইব্রেরি লোড করার অনুমতি দিতে হয়।
{{/warning}}

রীতি অনুযায়ী, যেকোনো নতুন প্রোগ্রামিং ভাষার প্রথম প্রোগ্রামটি
হওয়া উচিত বিশ্বকে এক ধরনের অভিবাদন। XOScript-এ এমন একটি
**Hello world** প্রোগ্রাম দেখতে এরকম:

@test598

এই পাঠ্যটি একটি ফাইলে, যেমন hello.xo-তে, সংরক্ষণ করা হলে এটি
নিচের মতো চালানো যায়: .

xo hello.xo

Hello world


উপরে দেখানো কালো উইন্ডোতে আপনি প্রোগ্রামের আউটপুট দেখতে পাচ্ছেন।
এই পুরো ম্যানুয়াল জুড়ে আউটপুট দেখাতে একই
দৃশ্যরূপ ব্যবহার করা হবে।

{{note}}
আউটপুট (ইংরেজিতে Out) বড় হাতের O দিয়ে লেখা হয়।
সাধারণভাবে বস্তুর নাম বড় হাতের অক্ষর দিয়ে শুরু হয়,
যদি না সেটি একটি ইনস্ট্যান্স হিসেবে কাজ করে (যার নিজস্ব কোনো
মেথড নেই, কেবল ডেটা)। এটি অন্যান্য প্রোগ্রামিং ভাষার
ক্লাস বনাম ইনস্ট্যান্স রীতির প্রতিফলন।
{{/note}}


## সিনট্যাক্স

XOScript একটি *বিশুদ্ধ* *বস্তু-ভিত্তিক* প্রোগ্রামিং ভাষা। এর অর্থ,
xoscript সবকিছুকে বস্তু হিসেবে গণ্য করে, তাই অন্য কোনো
*ডেটা টাইপ* নেই। XOScript-এ লেখা একটি প্রোগ্রামে মূলত তিনটি মৌলিক নিয়মিত ক্রিয়া
থাকে: *মান নির্ধারণ*, *বার্তা পাঠানো*
এবং *উত্তর দেওয়া*। বস্তুগুলোর মধ্যে বার্তা আদান-প্রদানই একটি
XOScript প্রোগ্রামের মূল অংশ। তিনটি পৃথক নিয়মিত ক্রিয়া নিচে
দেখানো হলো:


ক্রিয়া          | উদাহরণ
--------------- | --------
মান নির্ধারণ          |  \>\> x := 1. 
ইউনারি বার্তা  | x জোড়?.
বাইনারি বার্তা  | 1 + 2.
কীওয়ার্ড বার্তা | x শুরু: 0 দৈর্ঘ্য: 10.
উত্তর          | <- answer.  


এই অধ্যায়ে আপনি XOScript ভাষা সম্পর্কে একটি সাধারণ ধারণা পাবেন
এবং এর মৌলিক নীতিগুলোর বর্ণনা পাবেন। XOScript একটি ছোট ভাষা এবং
তিনটি ক্রিয়ার (চিত্র দেখুন) ওপর প্রতিষ্ঠিত, যা প্রায় ছয়টি
ব্যাকরণ নিয়মে রূপ নেয়। ভাষাটি আয়ত্ত করতে এটুকুই
যথেষ্ট।

সবকিছু তৎক্ষণাৎ স্পষ্ট না হলে চিন্তা করবেন না: সমস্ত গঠন-উপাদান
পরবর্তী অধ্যায়ে (৩) অনুসন্ধান করা হবে এবং মৌলিক নিয়মগুলো আবার
বলা হবে। তবে বর্তমান অধ্যায়টি মূলত ভাষার একটি সাধারণ
পরিচিতি হিসেবে কাজ করে। মৌলিক নীতিগুলো সংক্ষেপে
ব্যাখ্যা করা হবে এবং কয়েকটি প্রাসঙ্গিক উদাহরণ দিয়ে দেখানো হবে। অনুপস্থিত
বিবরণগুলো পরবর্তী সময়ে তুলে ধরা হবে।

XOScript-এ মন্তব্যের শুরুতে \# চিহ্ন থাকে। তাই নিচের লাইনটি
উপেক্ষা করা হবে:

```
# এটি শুধু একটি মন্তব্য
```

## ভেরিয়েবল

একটি ভেরিয়েবলে মান নির্ধারণ
করতে আপনি ভেরিয়েবল ঘোষণার চিহ্ন ব্যবহার করেন: >>। একটি
ভেরিয়েবলের নামে এগুলো ছাড়া সব চিহ্ন থাকতে পারে: <-, :=, হোয়াইটস্পেস,
পূর্ণচ্ছেদ, কমা, কোলন, উদ্ধৃতিচিহ্ন [' '], এবং বন্ধনী ()।
এছাড়া একটি ভেরিয়েবল একাধিক লাইন জুড়ে থাকতে পারে না। লক্ষ্য করুন,
একটি ভেরিয়েবল কোনো সংখ্যা বা বিয়োগ চিহ্ন দিয়ে শুরু হতে পারে না।

এগুলো বৈধ ভেরিয়েবলের উদাহরণ:

```
>> password := ['Secret'].
>> ♡♡♡ := 3.
>> $ := ['ডলার'].
>> +plus := সত্য.
>> ব্যবহারকারীর-পাসওয়ার্ড := ['শশশ!'].
```

অবৈধ ভেরিয়েবলের উদাহরণ হলো:


```
>> -123 := ['ঋণাত্মক সংখ্যা'].
>> password of ব্যবহারকারী := ['গোপনীয়'].
>> password.of:ব্যবহারকারী := ['গোপনীয়'].
>> ,x := 10.
```

{{note}}
স্ট্রিং লিটারেলে কোনো অক্ষর এস্কেপ করতে হয় না
(উদ্ধৃতিচিহ্ন, দ্বৈত উদ্ধৃতিচিহ্ন, স্ট্রিংয়ের
সীমানা সহ), যতক্ষণ না তা
লেক্সারের জন্য অস্পষ্টতা
তৈরি করে।
{{/note}}

একটি ভেরিয়েবল ঘোষণা করার পর তা অবাধে ব্যবহার করা যায়। এর অর্থ,
ঘোষণার চিহ্নটি কেবল প্রথমবার ভেরিয়েবলটি ব্যবহারের সময়
(ঘোষণার সময়) প্রয়োজন।

আরও নির্দিষ্ট করে বললে, আপনি হঠাৎ করে আপনার ভেরিয়েবলে একটি মান নির্ধারণ শুরু করতে পারেন না
*(x := 2)*, কারণ প্রথমে ভেরিয়েবলটি ঘোষণা করতে হবে *(\>\>
x := 2)*। তবে একবার ঘোষণা করা হলে, ঘোষণার চিহ্ন ছাড়াই
এর মান পরিবর্তন করা যায়*(\>\> x := 2. x := 3.)*।

লক্ষ্য করুন, ঘোষণার সময় ভেরিয়েবলে একটি মান নির্ধারণ করা
বাধ্যতামূলক। অন্যান্য প্রোগ্রামিং ভাষার বিপরীতে, মান ছাড়া একটি ভেরিয়েবল
ঘোষণা করার অনুমতি নেই। প্রতিটি ভেরিয়েবলকে স্পষ্টভাবে একটি প্রাথমিক মানের সঙ্গে
যুক্ত করা অপরিহার্য। তবুও, ভেরিয়েবলটিকে **শূন্য** বস্তু দিয়ে
আরম্ভ করতে পারেন। সেক্ষেত্রে ভেরিয়েবলটিকে
খালি হিসেবে গণ্য করা যায় *(\>\> x := শূন্য.)*। সংক্ষেপে, প্রাথমিক মান ছাড়া একটি
ভেরিয়েবল ঘোষণা করা অনুমোদিত নয়। তাই,

```
>> x.
```

অবৈধ এবং একটি ত্রুটি বার্তা দেবে।

{{note}}
xoscript ভেরিয়েবলের ডায়নামিক স্কোপিং ব্যবহার করে,
বিস্তারিত জানতে ফাংশন অধ্যায় দেখুন।
{{/note}}


## লিটারেল

XOScript সবকিছুকে বস্তু হিসেবে গণ্য করে; অর্থাৎ, সব সংখ্যা, স্ট্রিং
এবং কোডের অংশ। 1, 2, 100, -999 এবং 1,234-এর মতো সংখ্যাগুলো
সংখ্যা বস্তু। একক উদ্ধৃতিচিহ্নের মধ্যে থাকা সব পাঠ্য পাঠ
বস্তু। কোঁকড়া বন্ধনী {...}-এর মধ্যে গোষ্ঠীবদ্ধ সব কোডের অংশ
ফাংশন বস্তু।

লিটারেল         | মূল বস্তু  | উদাহরণ
--------------- | ------------ | ----------
সংখ্যা         | সংখ্যা       | 1,2,3... 
স্ট্রিং         | পাঠ       | \['hello'\]
ফাংশন        | ফাংশন     | { 1 + 2. }.
                
     
সংখ্যা ও স্ট্রিংয়ের মতো বস্তুগুলোর উৎস সবসময় একটি মূল
বস্তুতে। উদাহরণস্বরূপ, সব সংখ্যা **সংখ্যা** বস্তু থেকে উদ্ভূত। সব
স্ট্রিং **পাঠ** থেকে এবং সব কোডের অংশ **ফাংশন** থেকে উদ্ভূত।
আবার এই সব বস্তু **বস্তু** থেকে উদ্ভূত, যা আসলে
সব বস্তুর মূল বস্তু।


## বার্তা

XOScript-এ প্রোগ্রামিং মূলত
বস্তুগুলোকে বার্তা পাঠানো। একটি বস্তুকে বার্তা পাঠানোর সাধারণ লিখনপদ্ধতি
নিম্নরূপ:

```
<object> <message>
```

উদাহরণস্বরূপ, সংখ্যা **2** জোড় সংখ্যা কিনা তা জানতে
**2** বস্তুকে **জোড়?** বার্তাটি পাঠানো হয়:

```
2 জোড়?
```

উত্তর হবে **সত্য** (এটিও একটি বস্তু)। অজানা বার্তা সাধারণত
বস্তুগুলো উপেক্ষা করে; তাই কোনো ত্রুটি ঘটবে না। কিছু বস্তু (যেমন
সংখ্যা বা স্ট্রিং) একটি পূর্বনির্ধারিত উপায়ে অজানা বার্তার উত্তর দেয়
(এ বিষয়ে পরে আরও বলা হবে)।

একটি বস্তু তিন ধরনের বার্তা গ্রহণ করতে পারে।

ধরন            | আর্গুমেন্টের সংখ্যা
--------------- | -------------------
ইউনারি           | 0      
বাইনারি          | 1     
কীওয়ার্ড         | 1+    


প্রথমত, আছে **ইউনারি
বার্তা**, উপরের উদাহরণ দেখুন, যেগুলোর কোনো আর্গুমেন্ট নেই। দ্বিতীয়ত,
আছে **কীওয়ার্ড বার্তা**, যেগুলোর এক বা একাধিক আর্গুমেন্ট থাকে,
যেমন:

```
>> x := সংখ্যা মধ্যে: 1 থেকে: 10.
```

এক্ষেত্রে **মধ্যে:থেকে:** বার্তাটি **সংখ্যা**-কে পাঠানো হয়, যা
সব সংখ্যার মূল বস্তু। ফলাফল হবে 1 থেকে 10-এর মধ্যে একটি
এলোমেলো সংখ্যা। সবশেষে, আছে **বাইনারি বার্তা**, যেগুলোর
কেবল একটি অক্ষর এবং একটি আর্গুমেন্ট থাকে:

```
2 + 3
```

এটি দেখতে গণিতের যোগফলের মতো, কিন্তু আসলে এটি আরেকটি বার্তা মাত্র।
**+** বার্তাটি **2**-কে পাঠানো হয়, আর্গুমেন্ট **3** সহ, যা
উত্তর **5** ফেরত দেবে। বাইনারি বার্তা কোলন ছাড়া লেখা যায়।

বাইনারি বার্তা শৃঙ্খলিত করা যায়:

```
>> x := 3 + 2 - 1.
```

এই অংশে প্রথমে **+ 2** পাঠানো হয় **সংখ্যা** বস্তু **3**-কে, যার
ফলাফল সংখ্যা বস্তু **5**, এরপর এই সংখ্যাকে **-1** পাঠানো হয়।
মনোযোগী পাঠকরা সঠিকভাবেই লক্ষ্য করবেন যে এই প্রোটোকল
অপারেটরের প্রচলিত গাণিতিক ক্রমের সঙ্গে অসঙ্গতি দেখায়।
বার্তা ব্যবস্থার সামঞ্জস্যের স্বার্থে XOScript গাণিতিক ক্রম উপেক্ষা করে।
ফলে, যোগফল:

```
2 + 3 * 5 = 25
```

17 নয়।

এটি নকশাগতভাবেই এমন। ক্রম পরিবর্তন করতে বন্ধনী ব্যবহার করা যায়:

```
2 + (3 * 5) = 17
```

বেশিরভাগ বস্তু একটি নির্দিষ্ট বার্তার উত্তরে নিজেকেই ফলাফল হিসেবে
ফেরত দেয়। এটি সুবিধাজনক, কারণ এতে পরবর্তী বার্তা পাঠিয়ে
এই বস্তুর সঙ্গে আরও কথোপকথন চালিয়ে যাওয়া উৎসাহিত হয়:

```
আউটপুট লেখো:
[' হ্যালো '] ছাঁটো বড়-হাতের.
```

```
হ্যালো
```

এখানে **পাঠ** বস্তুকে দুটি বার্তা পাঠানো হয়েছে: **ছাঁটো**, এবং তারপর
**বড়-হাতের**।

নিচের অংশে, একটি নতুন বার্তা আসছে তা বোঝাতে কমা ব্যবহার করা
প্রয়োজন। নইলে XOScript বিভ্রান্ত হবে।

```
আউটপুট লেখো: ['Hello!'], নতুন-লাইন.
```

প্রথমে **লেখো:** বার্তাটি পেনসিল চিহ্নকে পাঠানো হয়, তারপর
**নতুন-লাইন**। কমা ছাড়া XOScript ভাবত যে আপনি **পাঠ** **Hello!**-কে
**নতুন-লাইন** পাঠাতে চান, যা একটি নিষ্ফল প্রচেষ্টা।

বার্তা প্রক্রিয়াকরণের ক্রম নিম্নরূপ: বাম থেকে ডানে;
প্রথমে বন্ধনীর ভেতরের বার্তা, তারপর ইউনারি বার্তা। এরপর
বাইনারি বার্তা এবং শেষে কীওয়ার্ড বার্তা। নিচের উদাহরণটি
দেখুন:

```
আউটপুট লেখো: 0.5 পূর্ণ-করো + (2 - 1), নতুন-লাইন.
```

XOScript সবসময় বাম থেকে ডানে পড়ে: প্রথমে **লেখো:** বার্তাটি
আউটপুট-কে পাঠানো হয় এবং তারপর **নতুন-লাইন** বার্তা। আর্গুমেন্টের
ভেতরেও XOScript বাম থেকে ডানে পড়ে, তাই প্রথমে **0.5 পূর্ণ-করো**
তারপর **+**।

{{note}}
নতুন-লাইন বার্তাটি স্ট্রিংয়ে একটি নতুন লাইনের অক্ষর যোগ করে।
এই বার্তার নাম টেলিগ্রাফ ব্যবস্থা থেকে অনুপ্রাণিত।
টেলিগ্রাফ ব্যবস্থার বার্তায় বাক্যের শেষ চিহ্নিত করতে প্রায়ই
STOP শব্দটি ব্যবহার করা হতো
(কারণ বিরামচিহ্ন অনির্ভরযোগ্য বা ব্যয়বহুল ছিল)।
{{/note}}

তাছাড়া **পূর্ণ-করো** **+**-এর আগে অগ্রাধিকার পায়, কারণ এটি একটি
**ইউনারি বার্তা**। বন্ধনীর কারণে প্রথমে **2 - 1** গণনা করা হয়,
তারপর **0.5 পূর্ণ-করো**-এর ফলাফলের (1) সঙ্গে **1** যোগ করা হয়।

পুরো প্রক্রিয়ার ফলাফল হবে **2**, যা লিখিত উত্তরও বটে।
কমার পরে আসে নতুন-লাইন বার্তা, যা কার্সরকে একটি নতুন লাইনে
নিয়ে যায়। অবশ্যই, XOScript প্রোগ্রামের ক্রম পুরোপুরি বোঝার
সবচেয়ে ভালো উপায় হলো অনুশীলন।

উল্লেখযোগ্য যে XOScript-এ, অন্যান্য অনেক প্রোগ্রামিং
ভাষার বিপরীতে, হোয়াইটস্পেস এর সিনট্যাক্সের একটি মৌলিক অংশ।
বিশেষ করে বাইনারি বার্তার ক্ষেত্রে হোয়াইটস্পেস কিছু
বিভ্রান্তি সৃষ্টি করতে পারে। বাইনারি বার্তার পরে সবসময় একটি হোয়াইটস্পেস ব্যবহার করুন।
বার্তার সঙ্গে সরাসরি একটি সংখ্যা জুড়ে দেওয়া যায় না, উদাহরণস্বরূপ:

```
3 + 2
```

এটি আলাদা

```
3 +2
```

থেকে। প্রথম উদাহরণটি (**3 + 2**) সংখ্যা **3**-কে
**+** বার্তাটি পাঠায়, আর্গুমেন্ট হিসেবে সংখ্যা **2** সহ।
এক্ষেত্রে ফলাফল হবে **5**। দ্বিতীয় উদাহরণে (**3 +2**),
ইউনারি বার্তা **+2** সংখ্যা **3**-কে পাঠানো হয়। প্রেক্ষাপট
অনুযায়ী এর ফলাফল সম্পূর্ণ ভিন্ন হতে পারে।

## অস্তিত্বহীন মেথড

একটি বস্তুকে বার্তা পাঠালে সেই বার্তার নামে এই বস্তুর সঙ্গে
যুক্ত ফাংশনটি চালু হয়। আপনি যদি এমন একটি বার্তা পাঠান
যা বোঝা যায় না, তবে গ্রহীতা বস্তু আপনার বার্তাটি উপেক্ষা করবে
এবং পরবর্তী যোগাযোগের জন্য এর বদলে নিজের একটি রেফারেন্স ফেরত দেবে।
একে সহনশীল বার্তা প্রেরণ (tolerant message passing) বলা হয়।

উদাহরণ:

```
আউটপুট লেখো: বস্তু blah, নতুন-লাইন.
```

এটি কোনো ত্রুটি দেবে না। এটি কেবল **বস্তু** পাঠ্যটি প্রিন্ট করবে।


## নিয়ন্ত্রণ প্রবাহ

XOScript-এ *লুপ* এবং *if*-এর জন্য আলাদা ব্যাকরণ নিয়মের প্রয়োজন নেই।
একটি if-বিবৃতি কেবল একটি **সত্য** বস্তু বা একটি **মিথ্যা** বস্তুকে পাঠানো
একটি সাধারণ **সত্য-হলে:** বা **মিথ্যা-হলে:** বার্তা:

```
2 জোড়? সত্য-হলে: {
	আউটপুট লেখো: ['দুই একটি জোড় সংখ্যা'], নতুন-লাইন.
}.
```
আগের উদাহরণে **সত্য-হলে:** বার্তাটি **সত্য**-কে পাঠানো হয়েছে (যা
এই প্রশ্নের উত্তর: 2 কি একটি জোড় সংখ্যা?)। আর্গুমেন্ট হিসেবে সঙ্গে
একটি অতিরিক্ত কোডের অংশ পাঠানো হয়: একটি **ফাংশন** বস্তু। এই ফাংশন
স্ক্রিনে লেখে যে 2 আসলেই একটি জোড় সংখ্যা।

*লুপের* জন্যও আলাদা লিখন নিয়মের প্রয়োজন নেই। একটি কোডের অংশ
তিনবার নির্বাহ করতে, কেবল সেই **ফাংশন**-কে আর্গুমেন্ট **3** সহ
**\*** পাঠান:

@test5

এই কোডের অংশে **i** হলো সূচক। তাই প্রথমবার ফাংশনটি
নির্বাহ হওয়ার সময় **i** 0-এর সমান, পরেরবার নির্বাহ হওয়ার সময় **i** = 1, এবং
এভাবে চলতে থাকে।

আরেকটি উদাহরণ বিবেচনা করা যাক। যখন *kJ* (কিলোজুল) থেকে *kcal* (কিলোক্যালরি)-তে
100-এর ধাপে একটি রূপান্তর সারণি প্রিন্ট করতে হয়,
সঠিক লিখনপদ্ধতির জন্য নিচে দেখুন:

@test599

এখানে বর্তমান লাইনের নম্বর প্যারামিটার **:line**-এ পাঠানো হয়।
একটি ফাংশনের শুরুতে ফাংশনের প্যারামিটারগুলো
সংজ্ঞায়িত করা হয়। অব্যবহৃত প্যারামিটার খালি থাকে (**শূন্য**)। প্যারামিটার
সবসময় ফাংশনের শুরুতে, প্রারম্ভিক কোঁকড়া বন্ধনীর ঠিক পরে
বসানো হয় এবং এর আগে একটি কোলন থাকে।

**যতক্ষণ:** বার্তাটি একটি *লুপ* এবং একটি *শর্তের* সমন্বয়।
**যতক্ষণ:** বার্তা ব্যবহার করে দুটি ফাংশন যুক্ত করা যায়। গ্রহীতা ফাংশনটি
ততক্ষণ চলতে থাকবে যতক্ষণ না কোলনের পরের ফাংশনটি একটি নেতিবাচক
ফলাফল দেয়। উদাহরণ:

@test600

উপরে দেখানো কোডের অংশে, যতক্ষণ **x** **5**-এর চেয়ে ছোট,
ততক্ষণ **x**-এর সঙ্গে **1** যোগ করা হয়। যখন আর তা থাকে না, দ্বিতীয়
ফাংশনটি **মিথ্যা** উত্তর দেবে, ফলে প্রথম ফাংশনের
নির্বাহ শেষ হবে। লক্ষ্য করুন, **x** ফাংশনের বাইরে সংজ্ঞায়িত হয়েছে
এবং এটি একটি গ্লোবাল ভেরিয়েবল। স্কোপিং নিয়ম সম্পর্কে আরও জানতে
ফাংশন বিষয়ক অধ্যায় দেখুন।

## স্ট্রিং ইন্টারপোলেশন

*kJ/kcal* তালিকাটি আরও
উপস্থাপনযোগ্য করা যেত। ভালো হতো যদি তালিকাটি এরকম হতো:

```
100 kj ➞ 23.88 kcal

200 kj ➞ 47.76 kcal
```

কাঙ্ক্ষিত আউটপুটকে একটি টেমপ্লেটে রূপান্তর করলে এর লিখনপদ্ধতি
হতে পারে:

```
number1 kJ ➞ number2 kcal
```

এর অর্থ, **number1** kJ-মানের এবং **number2** kcal-মানের
প্রতিনিধিত্ব করে। XOScript-এ স্ট্রিং ইন্টারপোলেশন এভাবেই কাজ করে।
এর জন্য XOScript-এ আলাদা কোনো ব্যাকরণ নিয়মের প্রয়োজন নেই। কেবল
যে শব্দটি প্রতিস্থাপন করতে হবে সেটি পাঠ্যকে পাঠান, প্রতিস্থাপক পাঠ্যটি
আর্গুমেন্ট হিসেবে দিয়ে:

```
>> text :=

['number1 kJ ➞ number2 kcal']

number1: 100,

number2: 23.9.
```

ফলাফল:

```
100 kj ➞ 23.9 kcal
```

এই প্রতিস্থাপন নিয়ম একটি **পাঠ** বস্তুর গ্রহণ করা প্রতিটি অসংজ্ঞায়িত
বার্তার ক্ষেত্রে কাজ করে। **পাঠ** বস্তু যে বার্তা চেনে না, তার প্রতিটি

## ক্লাস-সদৃশ বস্তু

যদিও xoscript ক্লাস প্রদান করে না, ক্লাস-সদৃশ আচরণ অনুকরণ করা
খুবই সহজ। কেবল নতুন বার্তাটি ওভাররাইড করুন।

```
>> প্রাণী-শ্রেণি := বস্তু নতুন.
প্রাণী-শ্রেণি যখন: ['নতুন'] করো: {
	<- নিজে নতুন প্রস্তুত-করো.
}.

প্রাণী-শ্রেণি যখন: ['প্রস্তুত-করো'] করো: {
	নিজের শব্দ := ['?'].
	নিজের পা  := 4.
}.
```

উপরের কোডের অংশে আমরা Animal নামে একটি বস্তু তৈরি করেছি।
এই বস্তু কুকুর ও বিড়ালের মতো সব ধরনের প্রাণীর জন্য একটি *নীলনকশা*
হিসেবে কাজ করে। মূল বস্তু Animal বড় হাতের A দিয়ে লেখা হয়েছে,
যাতে বোঝা যায় এটি একটি ক্লাস-সদৃশ বস্তু।
এরপর আমরা নিজস্ব নতুন-মেথড লিখে নতুন বার্তাটি ওভাররাইড করি।
এক্ষেত্রে এটি নিজে-কে একটি নতুন বার্তা পাঠায়, তারপর
প্রস্তুত-করো বার্তা। যেহেতু xoscript ডিফল্টভাবে পুনরাবৃত্তি আটকে দেয়, এতে
অসীম লুপ তৈরি হবে না। বরং এটি নতুন বার্তাটি মূল
বস্তুকে (বস্তু) পাঠাবে, যার ফলে Animal-এর একটি নতুন ইনস্ট্যান্স তৈরি হবে। অর্থাৎ আমরা
যে বস্তুর জন্য নতুন-মেথড তৈরি করেছি, সেই একই বস্তুর ওপর ভিত্তি করে
একটি নতুন বস্তু তৈরি করি। এটি সম্পূর্ণ বৈধ। এবার আমরা প্রস্তুত-করো বার্তাটিও পাঠাই, যা নিশ্চিত করে
যে Animal বস্তুর প্রপার্টিগুলোর ডিফল্ট মান আছে। ডিফল্টভাবে
একটি প্রাণীর 4টি পা থাকে এবং শব্দটি অজানা (তাই প্রশ্নবোধক চিহ্ন)।

## UTF8

xoscript-এ স্ট্রিং সাধারণত utf8 এনকোডেড পাঠ্য ধারণ করে। যদিও
প্রযুক্তিগতভাবে একটি স্ট্রিংয়ে বাইনারি বা utf8 নয় এমন বিষয়বস্তু রাখা সম্ভব,
সেজন্য blob ব্যবহার করার পরামর্শ দেওয়া হয়। blob
সার্ভার প্লাগইন সরবরাহ করে (ffi অধ্যায় দেখুন)।
সাধারণভাবে blob/ffi প্লাগইন/প্ল্যাটফর্ম ভিত্তিতে
সরবরাহ করা হয়, কারণ এগুলো প্ল্যাটফর্ম ও
স্থাপত্যের (ffi/blob) সঙ্গে যুক্ত। স্ক্রিপ্টিং ভাষার মূল অংশ যতটা সম্ভব
প্ল্যাটফর্ম-নিরপেক্ষ থাকার চেষ্টা করে।

# ফাংশন

{{messages}}

আপনি { এবং }-এর মধ্যে কোড গোষ্ঠীবদ্ধ করতে পারেন, তখন তা একটি ফাংশনে পরিণত হয়।
xoscript-এ আমরা কখনো কখনো কাজ (task) শব্দটি, বা কেবল
কোডের ব্লক শব্দটিও ব্যবহার করি।

*চালাও* বার্তাটি পাঠিয়ে আপনি একটি ফাংশন চালাতে পারেন।


```
{ আউটপুট লেখো: 123, নতুন-লাইন. } চালাও.
```

আপনার ফাংশন আর্গুমেন্ট নিলে **প্রয়োগ:** ব্যবহার করুন।

```
{ :a আউটপুট লেখো: a, নতুন-লাইন. } প্রয়োগ: a.
```

নিচের উদাহরণগুলোও দেখুন।
সরল স্থাপত্যের কারণে একটি ফাংশনের কেবল
একটি ফেরত বিন্দু থাকতে পারে। শর্তের জন্য অতিরিক্ত বোঝা বা অত্যধিক
নেস্টিং এড়াতে আপনি একটি প্রক্রিয়া ব্যবহার করতে পারেন (যা আর্গুমেন্ট 1 সহ
গুণ চিহ্ন ব্যবহারের সমান):

```
{
  (a = 1) সত্য-হলে: { x := 1. }, থামাও.
  (a = 2) সত্য-হলে: { x := 2. }, থামাও.
} প্রক্রিয়া.
```

এভাবে a = 1 হলে (a = 2) মূল্যায়ন করা হবে না।
এছাড়া এভাবে আপনার নেস্টেড সত্য-হলে: বার্তার প্রয়োজন হয় না।
যখনই দেখবেন আপনি শর্ত নেস্ট করছেন, তখন
প্রক্রিয়া বার্তাটির কথা ভাবুন। এতে আপনার কোড
পড়া সহজ হতে পারে।


এখানে একটি গুরুত্বপূর্ণ সতর্কতার বিষয়:

```
{
	মিথ্যা মিথ্যা-হলে: {
		আউটপুট লেখো: ['লুপ শেষ করো.'].
	}, থামাও.
	
	আউটপুট লেখো: ['আমাকে দেখিও না.'].

} প্রক্রিয়া.

```

এক্ষেত্রে 'Dont show me' পাঠ্যটি দেখানো হবে।
কারণ **থামাও** মিথ্যা-কে পাঠানো হয়েছে। আপনি যদি একটি থামাও
নির্বাহ করতে চান, তবে এটি **সত্য**-কে বার্তা হিসেবে পাঠাতে হবে।
 

```
{
	মিথ্যা বিপরীত সত্য-হলে: {
		আউটপুট লেখো: ['লুপ শেষ করো.'].
	}, থামাও.
	
	আউটপুট লেখো: ['আমাকে দেখিও না.'].

} প্রক্রিয়া.

```

প্রত্যাশামতো কাজ করবে।

## ব্যতিক্রম

ব্যতিক্রম এভাবে সামলানো যায়:

```
{ কাজ 1 } ধরো: { কাজ 2 }, চালাও.
```

আপনি ইচ্ছাকৃতভাবে আপনার প্রোগ্রামে একটি ত্রুটি ঘটাতেও পারেন; এবং
তা করে হ্যান্ডলার ব্লকটি সক্রিয় করতে পারেন। এটি করা হয়
বর্তমান কাজকে **ত্রুটি:** বার্তাটি পাঠিয়ে, যেমনটি পরের
চিত্রে দেখানো হয়েছে:

```
{
এই-কাজ ত্রুটি: ['ওহো!'].
} ধরো: { :ভ্রান্তি
আউটপুট লেখো: ভ্রান্তি.
}, চালাও.
```

## মান প্রবেশ করানো

XOScript কাজের জন্য মান প্রবেশ করানোর (inject) সুবিধা দেয়। এবার
নিচের কাজটি দেখুন:

```
>> পাঠানো := {
	নিউজলেটার প্রাপককে: নিজের recipient.
}.
পাঠানো নির্ধারণ: ['recipient']
মান: ['info@recipient.org'].
পাঠানো চালাও.
```


এই চিত্রে একটি কাল্পনিক কাজ দেখানো হয়েছে, যা একটি ইমেইল ঠিকানায় বা
**recipient**-কে একটি নিউজলেটার পাঠায়। কাজটি শুরু হওয়ার আগে বাইরে থেকে
কাজটিকে **নির্ধারণ:মান:** বার্তাটি পাঠিয়ে এই প্রাপককে কাজের মধ্যে
প্রবেশ করানো যায়। এভাবে **recipient**-এর মান
কাজের মধ্যে আগে থেকে নির্ধারিত হয়। এই মান পরিবর্তনও করা যায়
এবং তারপর কাজটি আবার চালানো যায়। Task বস্তু ব্যবহারের সময়
এটি একটি কার্যকর পদ্ধতি।

## খালি ফাংশন

খালি কাজ অনুমোদিত নয়। তাত্ত্বিকভাবে একটি খালি কাজ দেখতে
এরকম হতো: **{}**, তবে XOScript এটিকে একটি ভাষাগত ত্রুটি হিসেবে গণ্য করে। আপনি
যদি একটি খালি কাজ ঘোষণা করতে চান, তবে শূন্য বস্তু ব্যবহার করতে পারেন:

```
>> কাজটি := শূন্য.
```

যদিও এটি আসল কোনো কাজ নয়, বরং একটি শূন্য বস্তু, তবুও একটি চালাও বার্তা
পাঠানো যায়:

```
>> উত্তরটি := কাজটি চালাও.
```

আসলে এটি নিচেরটির সমান:

```
>> উত্তরটি := শূন্য চালাও.
```

যেহেতু **শূন্য** বস্তু **চালাও** বার্তাটি চেনে না, এটি
উত্তর হিসেবে নিজেকে ফেরত দেবে, ফলে উত্তর আবারও **শূন্য**।
তাই একটি খালি কাজের প্রয়োজন নেই। XOScript প্রোগ্রামিং ভাষার
মার্জিত নকশার কারণে আপনি এর জন্য কেবল শূন্য
বস্তুটি ব্যবহার করতে পারেন।

XOScript দুই ধরনের সংগ্রহ চেনে: *লিস্ট* এবং *অভিধান*।
**লিস্ট** হলো একটি *নির্দিষ্ট ক্রমে* সাজানো বস্তুর তালিকা। অভিধানের
কোনো ক্রম নেই, বরং এটি একটি চাবি (বা পদ) এবং তার
সংশ্লিষ্ট মান নিয়ে গঠিত একটি নির্ঘণ্টের মতো। লিস্ট অন্যান্য প্রোগ্রামিং ভাষার
array (PHP, Java, C) এবং list (Python)-এর সঙ্গে তুলনীয়। অভিধান
associative array (PHP) বা dictionary (Python)-এর সঙ্গে তুলনীয়।
একটি নতুন লিস্ট তৈরি করতে লিখুন:

```
>> ফিবোনাচি := লিস্ট নতুন.
```

এই খালি লিস্টটি **শেষে-যোগ:** ব্যবহার করে পূর্ণ করা যায়:

```
ফিবোনাচি শেষে-যোগ: 0.
ফিবোনাচি শেষে-যোগ: 1.
ফিবোনাচি শেষে-যোগ: 1.
ফিবোনাচি শেষে-যোগ: 2.
ফিবোনাচি শেষে-যোগ: 3.
ফিবোনাচি শেষে-যোগ: 5.
ফিবোনাচি শেষে-যোগ: 8.
ফিবোনাচি শেষে-যোগ: 13.
```

আমরা যদি লিস্টটি পর্দায় লিখি:

```
আউটপুট লেখো: ফিবোনাচি, নতুন-লাইন.
```

আমরা দেখব:

```
লিস্ট ← 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13
```

শেষে-যোগ-এর বদলে লিস্টে উপাদান যোগ করতে ; ব্যবহার করতে পারেন:


```
>> ফিবোনাচি := লিস্ট নতুন ; 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13.
```

সেমিকোলনগুলো (;) সবই বাইনারি বার্তা, যা লিস্টে একটি
মান রাখে।

## শৃঙ্খলিত করা

ধরুন আপনার এরকম একটি লিস্ট আছে:

```
>> x := লিস্ট নতুন ; 1 ; 2 ; 3.
```

আপনি যদি প্রথম ও শেষ উপাদান মুছতে চান, তবে আপনার
বার্তা হবে:

```
x প্রথমটি-নাও শেষটি-নাও.
```

দুর্ভাগ্যবশত, আগের লিখনপদ্ধতিটি সঠিকভাবে কাজ করবে না।
**প্রথমটি-নাও** বার্তাটি লিস্টের প্রথম উপাদান ফেরত দেয়, যা
আবার **শেষটি-নাও** বার্তার গ্রহীতা হয়ে যায়। ফলে
**শেষটি-নাও** বার্তাটি **x**-কে নয়, বরং 2-কে পাঠানো হয়। এই সমস্যার
একটি সম্ভাব্য সমাধান হলো দুটি পৃথক
বাক্য তৈরি করা, যেমন:

```
x প্রথমটি-নাও.
x শেষটি-নাও.
```

তবে এটি বেশ অব্যবহারিক, বিশেষ করে যখন দুইয়ের বেশি উপাদান
মুছতে হয়। তাই XOScript এ ধরনের পরিস্থিতির জন্য একটি
বিকল্প বার্তা কাঠামো প্রদান করে।
**বিকল্প** বার্তা কাঠামোতে বস্তুগুলোর উত্তর উপেক্ষা করা হয়
এবং আপনি প্রতিবার উত্তর হিসেবে গ্রহীতা বস্তুটিকেই ফেরত পাবেন।
একটি বস্তুকে **ধারা-শুরু** বার্তাটি পাঠিয়ে একটি **বিকল্প** বার্তা কাঠামো
শুরু করা হয়, এবং **ধারা-শেষ** বার্তাটি পাঠিয়ে **বিকল্প** বার্তা
কাঠামো শেষ করা যায়। দেখানো উদাহরণে এটি নিচের মতো
প্রয়োগ করা যায়:

```
>> x := লিস্ট নতুন ; 1 ; 2 ; 3.
x ধারা-শুরু প্রথমটি-নাও শেষটি-নাও ধারা-শেষ.
```

# অভিধান

{{messages}}

**লিস্ট এবং অভিধান উভয়ই সংগ্রহ। তবে
লিস্টের বিপরীতে, একটি অভিধানের **কোনো** ক্রম **নেই**। দুটির মধ্যে আরেকটি পার্থক্য
হলো, একটি অভিধান বস্তুর জোড়া নিয়ে গঠিত। একটি বস্তু অন্য বস্তুটি খোঁজার জন্য
এন্ট্রি (বা কীওয়ার্ড) হিসেবে কাজ করে। এর একটি ভালো উদাহরণ
হলো একটি মূল্য তালিকা, যেমন:


```
>> মেনু := অভিধান নতুন
	রাখো: ['£5'] চাবিতে: ['আপেল পাই'],
	রাখো: ['£6'] চাবিতে: ['গাজরের কেক'],
	রাখো: ['£3'] চাবিতে: ['fudge'].
```

লিস্টের মতোই, তালিকায় একটি বস্তু যোগ করতে রাখো:চাবিতে: বার্তাটি
ব্যবহার করা হয়। পার্থক্য হলো, লিস্টের বিপরীতে এখানে
দুটি বস্তু যুক্ত করা হয়। প্রথম বস্তুটি, লিস্টের মতোই,
সেই বস্তু যা আপনি তালিকায় সংরক্ষণ করবেন। দ্বিতীয়
বস্তুটি সংগ্রহের মধ্যে এর অবস্থান নয়, বরং সেই **এন্ট্রি**
যার মাধ্যমে আগের বস্তুটি পরে পুনরুদ্ধার করা যায়।
সংক্ষেপে, একটি অভিধান কিছুটা শব্দকোষের মতো কাজ করে; অর্থাৎ কীওয়ার্ড ব্যবহার করে
অর্থ খুঁজে পাওয়া যায়। উদাহরণস্বরূপ, উপরে উল্লিখিত তালিকা থেকে
একটি fudge-এর দাম পুনরুদ্ধার করতে:

```
>> price := মেনু এ: ['fudge'].
```

আপনি সংক্ষিপ্ত লিখনপদ্ধতিও ব্যবহার করতে পারেন:

```
>> price := মেনু ? ['fudge'].
```

বস্তু সংরক্ষণের জন্য আপনি যে এন্ট্রিগুলো ব্যবহার করেন সেগুলোতে যদি ফাঁকা স্থান না থাকে
(এবং অন্যান্য পূর্বনির্ধারিত বার্তার সঙ্গে সংঘর্ষ না হয়),
তবে পরের লিখনপদ্ধতিটিও ব্যবহার করা যায়:

```
>> মেনু := অভিধান নতুন
	pie:   ['£5'],
	cake:  ['£6'],
	fudge: ['£3'].
```

নিঃসন্দেহে উপরের লিখনপদ্ধতিটি পড়তে একটু বেশি স্বাভাবিক।
একটি fudge-এর দাম জানতে
নিচের সরলীকৃত লিখনপদ্ধতি ব্যবহার করা যায়:

```
>> price := মেনু fudge.
```

সিস্টেম কমান্ড নির্বাহ, উপ-প্রোগ্রাম অন্তর্ভুক্ত করা,

## StdOut

আউটপুট হলো স্ট্যান্ডার্ড আউটপুট বস্তু। এর মূলত দুটি মেথড আছে:
**লেখো:** এবং **নতুন-লাইন**। লেখো: বার্তাটি stdout-এ একটি স্ট্রিং
পাঠাতে ব্যবহৃত হয়, নতুন-লাইন বার্তাটি একটি নতুন লাইনের অক্ষর প্রিন্ট করে।
**নতুন-লাইন**-এর বদলে আপনি \\n-ও ব্যবহার করতে পারেন।

উদাহরণ:

```
আউটপুট লেখো: ['Hello World'], নতুন-লাইন.
```

ফলাফল:

```
Hello World
```

## মডিউল/প্লাগইন

মডিউল ইনস্টল করে XOScript-এর জগৎকে নতুন সিস্টেম বস্তু দিয়ে
সম্প্রসারিত করা যায়। মডিউল ফাইলটি (সাধারণত .so প্রত্যয়যুক্ত একটি ফাইল)
mods ফোল্ডারে রেখে XOScript-এর জগতে একটি নতুন সিস্টেম বস্তু
যোগ করা যায়।

প্লাগইন মডিউলের মাধ্যমে উপলব্ধ বস্তুটিকে আপনি যখন একটি বার্তা পাঠান,
তখন XOScript স্বয়ংক্রিয়ভাবে এটি লোড করে।

আপনি নিজেও প্লাগইন লিখতে পারেন। প্লাগইন লেখা হয়
C প্রোগ্রামিং ভাষায়। সোর্স কোড প্যাকেজে src/plugins/example-এর অধীনে
একটি উদাহরণ প্লাগইন পাবেন।


## রিফ্লেকশন

প্রোগ্রাম নির্বাহের সময় সিস্টেম অনুসন্ধানের
বিভিন্ন উপায় আছে। কোন বস্তুগুলো উপস্থিত এবং এই বস্তুগুলো কোন বার্তার
উত্তর দেয় তা শনাক্ত করতে XOScript-এ কয়েকটি মেথড আছে। প্রথমত, প্রতিটি বস্তুকে
জিজ্ঞাসা করা যায় এটি কোন **ধরন**-এর,
তবে XOScript-এ ধরন পরিবর্তনযোগ্য এবং তাই অনির্ভরযোগ্য।

প্রোগ্রাম বস্তুকে এটাও জিজ্ঞাসা করা সম্ভব যে একটি
প্রদত্ত বস্তু ইতিমধ্যে প্রোগ্রামে উপস্থিত কিনা:

```
প্রোগ্রাম সরঞ্জাম সত্য-হলে: { ... }.
```

বস্তুর নাম যদি একটিমাত্র চিহ্ন নিয়ে গঠিত হয়,
তবে বিভ্রান্তি এড়াতে নিচের লিখনপদ্ধতি প্রয়োগ করাই
ভালো:

```
প্রোগ্রাম খোঁজো: ['X'], সত্য-হলে: { ... }.
```

বস্তু সম্পর্কে জিজ্ঞাসা করার পাশাপাশি, প্রোগ্রাম বস্তুকে বার্তা সম্পর্কেও
জিজ্ঞাসা করা সম্ভব। উদাহরণস্বরূপ, জিজ্ঞাসা করা যায়
**সংখ্যা** বস্তু **মধ্যে:থেকে:** বার্তাটি জানে কিনা, যেভাবে
নিচে দেখানো হয়েছে:

```
প্রোগ্রাম Number: ['between:and:'], নতুন-লাইন.
```

# সার্ভার

{{messages}}

xoscript-এর সার্ভার প্লাগইন সার্ভার-সাইড অ্যাপ্লিকেশন তৈরির
কার্যকারিতা প্রদান করে। সার্ভার
প্লাগইন লোড করতে ব্যবহার করুন:

```
Server প্রস্তুত-করো.
```

আপনার সুবিধার জন্য webtools.xo এবং template.xo ফাইলগুলোও
লোড করার পরামর্শ দেওয়া হয়।

```
প্রোগ্রাম ব্যবহার: ['webtools.xo'].
প্রোগ্রাম ব্যবহার: ['template.xo'].

```

## সার্ভার সেটিংস

আপনি নিচের সার্ভার সেটিংসগুলো নির্ধারণ করতে পারেন:

```
	# ডিফল্ট মান দেওয়া আছে,
	# তাই আপনি কিছু সেট না করলে এই
	# মানগুলো ব্যবহৃত হয়...

	প্রোগ্রাম 
	সেটিং: ['max-postfields']
	মান: 40.

	প্রোগ্রাম 
	সেটিং: ['max-contentlength']
	মান: 2000000. # 2MB

	প্রোগ্রাম 
	সেটিং: ['max-time']
	মান: 5000. # 5sec

```

## হ্যালো ওয়ার্ল্ড

এখানে একটি খুব সরল ওয়েব প্রোগ্রাম দেওয়া হলো যা আপনি
Apache2, NGINX, OpenHTTPD বা অন্য যেকোনো সুপরিচিত সার্ভারের মতো
একটি স্ট্যান্ডার্ড CGI সার্ভারের সঙ্গে ব্যবহার করতে পারেন।

```
#!/bin/xo

Server প্রস্তুত-করো.
প্রোগ্রাম ব্যবহার: ['webtools.xo'].

>> ওয়েব-নথিটি := ওয়েব-নথি নতুন.

ওয়েব-নথিটি আউটপুট-দাও: ['
<html>
<body>
<b>Hello World!</b>
</body>
</html>'].

```

আপনি যদি ওয়েব-নথি বস্তু ব্যবহার করতে না চান, তাতে সমস্যা নেই, তবে
তখন HTTP হেডারগুলো আপনাকে নিজেই লিখতে হবে:

```
#!/bin/xo
আউটপুট লেখো: ['Content-type: text/html; charset=utf-8 \n\n'], নতুন-লাইন.
আউটপুট লেখো: ['ওহে বিশ্ব!'], নতুন-লাইন.
``` 

## অনুরোধ

GET/POST/COOKIE এবং UPLOAD ডেটা পেতে HTTP-অনুরোধ বস্তুটি
ব্যবহার করা যায়:

```
>> অনুরোধ-http  := HTTP-অনুরোধ নতুন.
>> search   := অনুরোধ-http get: ['search']. # ?search=books
>> password := অনুরোধ-http post: ['password']. # ফর্ম থেকে
>> নির্বাচিত := অনুরোধ-http get-তালিকা: ['sel[]']. #?sel[]=1&sel[]=2
>> নির্বাচিত := অনুরোধ-http post-তালিকা: ['sel[]'].
>> কুকি   := অনুরোধ-http cookie: ['session-id'].
>> আপলোড   := অনুরোধ-http upload: ['file'].
>> অস্থায়ী-পথ := আপলোড ? 1.
>> ফাইল-নাম := আপলোড ? 0.
```

## Maxpost/length

ডিফল্টভাবে সর্বোচ্চ post ফিল্ডের সংখ্যা 40 এবং ডিফল্ট সর্বোচ্চ বিষয়বস্তুর
দৈর্ঘ্য 2MB। প্রতিটি স্ক্রিপ্টের জন্য ভিন্নভাবে কনফিগার করতে:

```
প্রোগ্রাম সেটিং: ['max-contentlength'] মান: 1. 
প্রোগ্রাম সেটিং: ['max-postfields'] মান: 1. 
```

{{note}}
বিষয়বস্তুর দৈর্ঘ্য সর্বোচ্চ সীমা ছাড়িয়ে গেলে
প্রক্রিয়াটি বন্ধ করে দেওয়া হয়, কারণ তখন আর নিশ্চিত হওয়া যায় না
যে পেলোড নিরাপদ।
{{/note}}

maxtime সীমা নির্ধারণ করে stdin/postdata পড়ার সর্বোচ্চ সময়
(ms-এ)।

```
প্রোগ্রাম সেটিং: ['max-time'] মান: 5000. # 5sec
```

এটি কেবল post-এর I/O পড়ার ক্ষেত্রে প্রযোজ্য, যা
slowloris-জাতীয় আক্রমণ প্রতিরোধ করে। আপনি যদি সত্যিই যেকোনো ক্রিয়ার
নির্বাহের সময় সীমিত করতে চান, তবে প্রোগ্রাম সময়সীমা: ব্যবহার করুন।

## ডেটাবেস

MariaDB/MySQL-এ কোয়েরি করতে Database বস্তুটি ব্যবহার করা যায়।
একটি ডেটাবেসের সঙ্গে সংযোগ করতে:

```
>> ডিবি := Maria-DB নতুন হোস্ট: ['localhost'],
	ব্যবহারকারী-নাম: ['xo'],
	পাসওয়ার্ড: ['pass123'],
	ডেটাবেস-নাম: ['xobase'],
	যুক্ত-হও.

```

একটি রেকর্ড যোগ করতে ব্যবহার করুন:

```
>> অনুসন্ধান-প্যারামিটার := ডিবি কোয়েরি: ['
	INSERT INTO book (id, description, price, rating) 
	VALUES (NULL, ?, ?, ?)
'], প্যারামিটার: ( লিস্ট নতুন ; ['abc'] ; 12.35 ; 6 ). # প্যারামিটারযুক্ত কোয়েরি

{  অনুসন্ধান-প্যারামিটার নির্বাহ. ডিবি নিশ্চিত. }
ধরো: { :e ডিবি ফিরিয়ে-নাও.  }, চালাও.
```

লক্ষ্য করুন, xoscript *কেবল* লেনদেন (transaction) নিয়ে কাজ করে এবং কখনো স্বয়ংক্রিয়ভাবে commit করে না।
autocommit নিষ্ক্রিয় করা না গেলে আপনি একটি সংযোগ ত্রুটি পাবেন।
কোয়েরির জন্য সবসময় প্যারামিটার বাইন্ডিং ব্যবহার করুন, ব্যবহারকারীর ইনপুট কখনো সরাসরি
SQL-এ যোগ করবেন না।

যোগ করা id এভাবে পান:

```
আউটপুট লেখো: ['সন্নিবেশিত: '] + অনুসন্ধান-প্যারামিটার insert-id, নতুন-লাইন. # সন্নিবেশিত আইডি
```

রেকর্ড আনতে:

```
>> অনুসন্ধান-প্যারামিটার :=
ডিবি
	কোয়েরি: ['SELECT * FROM book order by id desc limit 2'], 
	আনো: { :সারি 
		আউটপুট লেখো: সারি id + [' '] + সারি description + [': '] + সারি price, নতুন-লাইন.
	}. # সারি আনা

```

## সেশন

স্থায়িত্বের জন্য আপনি একটি সেশন বস্তুতে ডেটা সংরক্ষণ করতে ও সেখান থেকে আনতে পারেন।
প্রথমে একটি নতুন **ওয়েব-নথি** তৈরি করুন। ওয়েব-নথি বস্তুটি অনুরোধ,
হেডার, HTML এবং সেশনকে একসঙ্গে বাঁধে। এর কারণ, যখনই আপনি
ব্রাউজার দিয়ে কোনো ওয়েবসাইট দেখেন, আপনি কেবল HTML দেখতে পান। কিন্তু
পুরো ওয়েব-নথিতে **হেডারগুলি**-ও থাকে। উদাহরণস্বরূপ,
বেশিরভাগ HTTP প্রতিক্রিয়ায় Content-type:text/html-এর মতো একটি হেডার থাকে, যা
ব্রাউজারকে জানায় যে পরবর্তী ডেটা HTML হিসেবে দেখাতে হবে
(এবং উদাহরণস্বরূপ, একটি ফাইলের মতো ডাউনলোড করতে হবে না)। সেশন হলো
অনুরোধগুলোর মাঝে ব্যবহারকারীর ডেটা সংরক্ষণের একটি উপায়। এই ডেটার হিসাব রাখতে আমাদের
একটি কুকি নির্ধারণ করতে হয়, এই কুকিও একটি হেডারের মাধ্যমে নির্ধারিত হয়। এ কারণেই
সবকিছু ওয়েব-নথিতে একত্রিত হয় (কারণ এটিই হেডার এবং HTML বা অন্যান্য ডেটা
উভয় ধারণকারী পূর্ণাঙ্গ নথি)।


```
# প্রথমে আমরা একটি নতুন ওয়েব-নথি ইনস্ট্যান্স তৈরি করি
>> ওয়েব := ওয়েব-নথি নতুন.

# এখন আমরা একটি সেশন শুরু করি, এটি একটি কুকির জন্য হেডার তৈরি করবে এবং
# ওই কুকির সাথে যুক্ত আপনার ডেটা রাখার একটি ফাইল তৈরি করবে
>> সেশনটি := ওয়েব সেশন-শুরু-করো.

# এখন আমরা সেশনকে একটি অভিধান-এর মতো ব্যবহার করতে পারি
সেশনটি userid: 123.
```

সেশন ধ্বংস করতে (লগ আউট করার সময়):

```
ওয়েব সেশন-ধ্বংস-করো.
```

## হেডার

ওয়েব-নথি আপনাকে অন্যান্য সুপরিচিত হেডারও নির্ধারণ করতে দেয়।
উদাহরণস্বরূপ, আপনি যদি ব্যবহারকারীকে অন্য একটি URL-এ পুনর্নির্দেশ করতে চান:

```
ওয়েব যাও: ['/other.html'].
```

ভেতরে ভেতরে এই কমান্ডটি HTTP হেডারও তৈরি করে, যা আপনার অন্যান্য ডেটা বা HTML-এর
সঙ্গে পাঠানো হয়, যাতে ব্রাউজার নির্দিষ্ট লক্ষ্য ঠিকানায়
যাওয়ার নির্দেশ পায়।

একটি কাস্টম হেডার যোগ করতে:

```
ওয়েব হেডার: ( 
	HTTP-হেডার নতুন
	চাবি: ['Content-Length']
	মূল্য: 400
).
```

একটি 404-পেজ দেখাতে:

```
ওয়েব পাওয়া-যায়নি: ['উফস..'].
```


## টেমপ্লেট

ডিফল্ট টেমপ্লেট ব্যবস্থা খুবই সরল। আপনাকে
নতুন কোনো টেমপ্লেট সিনট্যাক্স শিখতে হয় না। এছাড়া টেমপ্লেট ইঞ্জিন উপস্থাপনা ও
ব্যবসায়িক যুক্তির মধ্যে প্রকৃত পৃথকীকরণ নিশ্চিত করে।

একটি ফাইল থেকে টেমপ্লেট তৈরি করতে:

```
>> tpl := ওয়েব ছাঁচ: ['templates/ux.tpl'].
```

টেমপ্লেট ব্যবস্থা চিহ্ন (marker) ব্যবহার করে।
তিন ধরনের চিহ্ন আছে: কাট চিহ্ন, পেস্ট চিহ্ন এবং
স্লট চিহ্ন। মূল ধারণাটি সত্যিই সরল: কাট চিহ্ন দিয়ে চিহ্নিত
অংশগুলো আপনি কেটে নেন এবং পেস্ট চিহ্ন দিয়ে চিহ্নিত
অংশগুলোতে সেঁটে দিতে পারেন। স্লট চিহ্নে আপনি স্ট্রিং
প্রবেশ করাতে পারেন।

উদাহরণস্বরূপ, নিচের টেমপ্লেটটি দেওয়া থাকলে, চলুন রত্নটি
গয়নার বাক্সে রাখি এবং একটি মূল্য ট্যাগ যোগ করি।

```
<!-- cut:gem -->
<img src="gem.gif">
<b>$<!-- slot:price --></b>
<!-- /cut:gem -->

<div id="box">
<!-- paste:jewels -->
</div>
```

আপনি এটি এভাবে করতে পারেন:

```
>> gem := tpl কাটো: ['gem'], অনুলিপি.
gem price: 99.
tpl সাঁটো: gem চাবিতে: ['jewels'].
ওয়েব আউটপুট-দাও: tpl চিহ্ন-মোছো.
```

শেষ লাইনটি কেবল প্রয়োজনীয় HTTP হেডার সহ টেমপ্লেটটিকে একটি স্ট্রিং
হিসেবে ক্লায়েন্টের কাছে পাঠিয়ে দেয়।

ফলাফল:

```
<div id="box">
<img src="gem.gif">
<b>$99</b>
</div>
```


## Passthru

ব্যবহারকারীর আপলোড করা ফাইল নিরাপদে পরিবেশন করতে আপনি passthru-এর ওপর নির্ভর করতে পারেন:

```
>> আপলোডকৃত := ['smile.gif'].
Server পাঠিয়ে-দাও: আপলোডকৃত উপসর্গ: ['/uploads/images/'].
প্রোগ্রাম শেষ.
```

এটি ব্যবহারকারীর আপলোড করা বিষয়বস্তু উপযুক্ত
mime type সহ পরিবেশন করবে। কেবল অনুমোদিত তালিকাভুক্ত mime type সমর্থিত:
GIF, JPG, PNG, WEBP, MP4, WEBM, MP3, ZIP, GZIP, PDF এবং SVG।
SVG, ZIP এবং GZIP ফাইল ডাউনলোড হিসেবে পাঠানো হয়, কারণ একটি SVG-তে
এমন স্ক্রিপ্ট থাকতে পারে যা নইলে আপনার ডোমেইনে চলত।
এই মেথড TOCTOU-আক্রমণ, path traversal,
ক্ষতিকর কোড নির্বাহ (injection), symlink আক্রমণ,
DDoS আক্রমণ (ফাইল সীমা = 50MB), sniffing আক্রমণ এবং
অন্যান্য বিভিন্ন নিরাপত্তা সমস্যা প্রতিরোধ করে।


## JSON

একটি বস্তুকে JSON হিসেবে এনকোড করতে:

```
>> json-পাঠ্য := ( JSON jsonify: ( 
	অভিধান নতুন রাখো: ( 
		লিস্ট নতুন ; 1 ; 2 ; 3
	) চাবিতে: ['abc']
)).
```

JSON-কে একটি xoscript বস্তুতে ডিকোড করতে:

```
>> অভিধানটি := ((JSON বস্তু: json-পাঠ্য) abc ? 1).
```

500-এর বেশি স্তরের নেস্টিংযুক্ত JSON অবৈধ হিসেবে প্রত্যাখ্যান করা হয়।

সঠিক হেডার সহ একটি অভিধানকে সরাসরি json হিসেবে আউটপুট করতে:

```
ওয়েব json: অভিধানটি.
```


## Regex

একটি প্যাটার্ন তৈরি করে আপনি রেগুলার এক্সপ্রেশন ব্যবহার করতে পারেন।
উদাহরণস্বরূপ, হাইপারলিংকের href এবং target মেলাতে:

```
প্যাটার্ন নতুন: ['href="([^"]+)" target="([^"]+)"'].
```

এবার প্যাটার্নটি বিষয় স্ট্রিংয়ে এভাবে প্রয়োগ করুন:

```
নকশা মিল: বিষয় করো: { :m :x .... }
```

পূর্ণ উদাহরণ:

```
>> বিষয় := ['<html>
	<a href="http://link1" target="_blank">
	<a href="http://link2" target="_blank">
</html>'].
>> নকশা := প্যাটার্ন নতুন: ['href="([^"]+)" target="([^"]+)"'].
>> ফল  := নকশা মিল: বিষয় করো: { :m :x
	আউটপুট লেখো: m, নতুন-লাইন.
	আউটপুট লেখো: x, নতুন-লাইন.
	<- ['XXX'].
}.
আউটপুট লেখো: ফল, নতুন-লাইন.
```

## নেটওয়ার্কিং

একটি ওয়েব অনুরোধ সম্পাদন করতে নেটওয়ার্ক বস্তুটি ব্যবহার করুন।
নেটওয়ার্ক বস্তু সবসময় একটি POST অনুরোধ পাঠায়, যদি না আপনি ডেটা হিসেবে শূন্য
পাঠান; তখন এটি একটি GET অনুরোধ পাঠাবে।


```
নেটওয়ার্ক 
post: শূন্য 
প্রতি: ['https://redbeanphp.com'].
```

## এনক্রিপশন

সার্ভার প্লাগইনে XChaCha20 এবং Argon2 ভিত্তিক এনক্রিপশন রয়েছে।

উদাহরণ:

```
>> এনক্রিপ্টকৃত := সিন্দুক এনক্রিপ্ট: ['hello'] চাবি: ['world'].
>> ডিক্রিপ্টকৃত := সিন্দুক এনক্রিপ্ট: এনক্রিপ্টকৃত চাবি: ['world'].
```

## টোকেন

একটি নির্দিষ্ট দৈর্ঘ্যের ক্রিপ্টোগ্রাফিকভাবে নিরাপদ টোকেন তৈরি করতে:

```
>> আমার-টোকেন := সিন্দুক টোকেন: 40.
```

এটি 40 অক্ষরের একটি টোকেন তৈরি করবে।

## বিন্যাস করা

বিন্যাস বস্তুটি আপনাকে ডেটা বিন্যাস করতে দেয়, যেমন প্যাডিং বা
শূন্য যোগ করা। এটি printf সিনট্যাক্স ব্যবহার করে।

```
>> ফর্ম্যাট := বিন্যাস নতুন: ['%06.0f'].
ফর্ম্যাট প্রয়োগ: 56. # ফল 000056
```

একটি বিন্যাসে একটি রূপান্তর থাকতে পারে এবং তা মানের সঙ্গে মিলতে হবে,
নইলে আপনি একটি ত্রুটি পাবেন:

- একটি স্ট্রিং সহ `প্রয়োগ:`: `%s`
- একটি সংখ্যা সহ `প্রয়োগ:`: `%f`, `%e`, `%g` বা `%a`
- একটি সংখ্যা সহ `প্রয়োগ-পূর্ণসংখ্যা:`: `%d`, `%i`, `%o`, `%u`, `%x` বা `%c`

একটি অনুরোধ থেকে আসা মানগুলো স্ট্রিং। একটিকে সংখ্যা হিসেবে বিন্যাস করতে
প্রথমে রূপান্তর করুন:

```
ফর্ম্যাট প্রয়োগ: (অনুরোধ-http get: ['amount']) সংখ্যায়.
```

## এনকোডার

বেশ কয়েকটি এনকোডার ও ডিকোডার উপলব্ধ।
url এনকোডার HTML-এ লিংক হিসেবে ব্যবহারের জন্য একটি url প্রস্তুত করে:

```
Server url-এনকোড: ['https://example.com?a=6&b=1 2'].
```

XSS ইনজেকশনের ঝুঁকি ছাড়াই ব্যবহারকারীর ইনপুট নিরাপদে আপনার HTML-এ
প্রবেশ করাতে সবসময় ব্যবহার করুন:

```
Server html-এনকোড: ['<harmless>'].
```

লক্ষ্য করুন, আপনি একটি স্লট চিহ্নে লিখলে টেমপ্লেট ইঞ্জিন সবসময় html এনকোডিং
সম্পাদন করবে। তাই আপনি টেমপ্লেট ব্যবস্থা ব্যবহার করলে
এটি ব্যবহার করার প্রয়োজন নেই।

# ffi

{{messages}}

FFI প্ল্যাটফর্ম/প্লাগইন ভিত্তিতে সরবরাহ করা হয়, কারণ এটি
অন্তর্নিহিত সিস্টেম স্থাপত্যের সঙ্গে যুক্ত, যা
মূল অংশের করার কথা নয়।
সার্ভার প্লাগইন একটি মানানসই ffi/blob বাস্তবায়ন প্রদান করে।
ডিফল্টভাবে মূল অংশ লক্ষ্য প্ল্যাটফর্মের সঙ্গে যুক্ত হয়
stdin/stdout, সীমিত ফাইল i/o পরিষেবা এবং শেলের (প্রোগ্রাম সিস্টেম:) মাধ্যমে।
অতিরিক্ত সংযুক্তি প্রদান করে ffi/blob, সার্ভার প্লাগইনের মতো
অ্যাপ্লিকেশন-কেন্দ্রিক প্লাগইনের মাধ্যমে।

FFI-এর পূর্ণরূপ Foreign Function Interface। এটি আপনাকে অন্যদের দ্বারা
ভিন্ন প্রোগ্রামিং ভাষায় লেখা কার্যকারিতা ব্যবহার করতে দেয়, যা DLL ফাইল, SO ফাইল বা Dylib ফাইলের মাধ্যমে সরবরাহ করা হয়। এগুলো
বিভিন্ন ধরনের ফাংশন হতে পারে, এবং এই পদ্ধতির মাধ্যমে বিপুল পরিমাণ কার্যকারিতা পাওয়া যায়।
একটি উদাহরণ দিয়ে শুরু করা যাক:

```
Server সংযোগ: (
 লিস্ট নতুন ;
 ['/usr/lib/x86_64-linux-gnu/libc.so.6'] ;
 ['printf'] ;
 ( লিস্ট নতুন ; ['pointer'] ; ['int'] ) ;
 ['void'] ;
 ['Printf'] ;
 ['template:number:']
).
>> s := Blob utf8: ['FFI has %d letters.\n'].
Printf template: s number: 3.
s মুক্ত.
```

এই কোডের ফলে কমান্ড লাইনে আপনি নিচেরটি দেখতে পাবেন:
FFI has 3 letters.
এখন আপনি হয়তো ভাবছেন, "এত সরল একটি কাজের জন্য এ তো অনেক কোড।"
মানে, আমরা কি এটি কেবল একটি Gui show কমান্ড দিয়ে সমাধান করতে পারতাম না? উত্তর হলো, অবশ্যই পারতাম!
তবে এটি একটি দৃষ্টান্তমূলক উদাহরণ হিসেবেই দেওয়া হয়েছে।
FFI সাধারণত আরও জটিল কাজে ব্যবহৃত হয়, কিন্তু সেগুলো ভালো
উদাহরণ হয় না, তাই আমি একটি তুচ্ছ বিষয় বেছে নিয়েছি।

সংযোগ: মেথডের আর্গুমেন্টগুলো:

- আর্গুমেন্ট #1: যে DLL বা SO ফাইলটি আপনি ব্যবহার করতে চান।
- আর্গুমেন্ট #2: সেই ফাইলের যে ফাংশনটি আপনি যুক্ত করতে চান।
- আর্গুমেন্ট #3: ফাংশনের আর্গুমেন্টগুলোর ডেটা টাইপের নামসহ একটি লিস্ট।
- আর্গুমেন্ট #4: ফাংশনের ফেরত টাইপের নাম।
- আর্গুমেন্ট #5: যে বস্তুর সঙ্গে আপনি এই ফাংশনটি যুক্ত করতে চান তার নাম (এটির অস্তিত্ব না থাকলে
স্বয়ংক্রিয়ভাবে তৈরি হবে)।
- আর্গুমেন্ট #6: যে বার্তার সঙ্গে এই ফাংশনটি যুক্ত হবে।

উপরের উদাহরণে আমরা libc.so থেকে printf ফাংশনটি যুক্ত করতে চাই। ডেটা
টাইপের নামগুলো আপনি যে সফটওয়্যারের সঙ্গে যুক্ত করছেন তার ডকুমেন্টেশনে পাবেন। উপলব্ধ টাইপগুলো হলো:
void, pointer, float, double, int, uint, char, uchar, intX, এবং uintX,
যেখানে X হতে পারে 8, 16, 32, বা 64।

এই টাইপগুলো ডেটা সংরক্ষণের জন্য প্রয়োজনীয় বাইটের সংখ্যা নির্দেশ করে। printf-এর জন্য আমরা
Printf নামের একটি নতুন বস্তু এবং template:number: বার্তার সঙ্গে যুক্ত করছি। বাহ্যিক
ফাংশনটি ব্যবহারের আগে আপনি সেটিকে XOScript-এর উপভাষায় অনুবাদ করেন। template:number: বার্তাটি
প্রথম প্যারামিটার হিসেবে টেমপ্লেট পাঠ্যসহ একটি বাফার আশা করে। আমরা এই বাফারটি একটি Blob বস্তু ব্যবহার করে তৈরি করি, যা
আপনাকে হাতে মেমরি বরাদ্দ করতে দেয়। পরে মুক্ত বার্তা দিয়ে এই মেমরি মুক্ত করার
দায়িত্ব আপনার।

একটি মেমরি blob বিভিন্ন উপায়ে পূর্ণ করা যায়। আমাদের উদাহরণে আমরা এটি পাঠ্য দিয়ে পূর্ণ করি, তাই
utf8: বার্তাটি ব্যবহার করি (UTF-8 হলো পাঠ্যকে বাইটে রূপান্তরের একটি এনকোডিং)। আপনি একটি blob
bytes: দিয়েও পূর্ণ করতে পারেন, বাইট মানের একটি লিস্ট দিয়ে। একটি blob-এর বিষয়বস্তু পড়তে শুরু:দৈর্ঘ্য: ব্যবহার করুন।
বাইটগুলো আপনি একটি লিস্ট হিসেবে ফেরত পাবেন। এমনকি struct: বার্তা ব্যবহার করে, C টাইপের একটি ক্রম দিয়ে,
একটি Blob দিয়ে একটি C-struct-ও তৈরি করতে পারেন। কোনো বাহ্যিক সফটওয়্যার লাইব্রেরির এমন একটি C
ফাংশন আহ্বান করার সময় এটি প্রয়োজন হতে পারে যা একটি struct-এর পয়েন্টার আশা করে।

{warning}
blob আপনাকে নিজেই মুক্ত করতে হবে।
গারবেজ কালেক্টর blob পরিষ্কার করে না।
{/warning}

যেহেতু blob লাইব্রেরির বাহ্যিক ফাংশনের সঙ্গে আদান-প্রদান করা যায়, তাই
এগুলো স্বয়ংক্রিয়ভাবে গারবেজ কালেক্ট করা যায় না (এগুলো বাহ্যিক ফাংশনগুলো
ব্যবহার করতে থাকতে পারে, অথবা এই বাহ্যিক ফাংশনগুলো নিজেরাই এগুলো
মুক্ত করতে চাইতে পারে)। তাই প্রয়োজনে blob আপনাকে নিজেই মুক্ত করতে হবে।

একটি blob মুক্ত করতে ব্যবহার করুন:

```
আমার-ব্লব মুক্ত.
```

struct মুক্ত করতে ব্যবহার করুন:

```
আমার-স্ট্রাক্ট struct-মুক্ত মুক্ত.
```

অর্থাৎ একটি struct-এর ক্ষেত্রে মেমরি ব্লকটি মুক্ত করতে আপনাকে দুটি বার্তা পাঠাতে হবে:
struct-মুক্ত এবং মুক্ত।
