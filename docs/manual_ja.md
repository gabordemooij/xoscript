XOScript へようこそ
XOScript プロジェクトは、シンプルで監査可能なスクリプト言語を作ることを目指しています。
シンプルであることは、必ずしも簡単であることを意味しません。
慣れ親しんだプログラミング言語のほうが、XOScript より使いやすいかもしれません。
ここでいうシンプルさは、別のことを意味します。
すなわち、言語とその振る舞いについて、完全なメンタルモデルを頭の中に描けるということです。

XOScript は、頭の中に収まるように設計されています。
その文法と概念の数は、意図的に小さく抑えられています。
クラスはなく、オブジェクトを直接拡張できます。
オブジェクトは参照渡しされ、コピーは明示的に行い、
関数の出口は一つだけです。

これらの選択の中には、主流の言語と大きく異なるものがあります。
たとえば、XOScript には型システムがなく、動的スコープを使います。
処理できないメッセージは、例外を発生させるのではなく無視されます。
こうした選択にはそれなりの帰結があり、エラーをなくすことを意図したものではありません。
言語の根底にあるモデルを小さく一貫したものに保つことが目的です。

XOScript はローカライズすることもできます。そのため、ビジネスルールを
自然言語で表現し、技術者ではない関係者とも共有できる可能性があります。

監査可能性とは、同じ哲学を実装にも適用することを意味します。
ランタイムは C で書かれており、小さな手書きの字句解析器、構文解析器、ツリーウォーカーで構成されています。
標準ライブラリとランタイムは言語の構造をほぼそのまま反映しているため、
XOScript のコードとその実装との関係は比較的直接的です。

テストもドキュメントと密接に結びついています。
各メソッドには、マニュアルに組み込めるテストが対応しているべきであり、
それによってドキュメントと実装の同期が保たれます。

XOScript は、機能の多さや馴染みやすさで主流の言語と
競うことを意図していません。XOScript が追求するのは別の目標、
つまり開発者が全体として理解できるプログラミング環境です。

小さな言語と小さな実装によって、ソフトウェアを
バイトからオブジェクトまで、構文からランタイムまで理解することが現実的になり、
スクリプトの中で起きていることと内部で起きていることの両方を理解しているからこそ、
自信を持ってコードを書けるようになる。それが私たちの願いです。

xoscript のサーバー構成のアーキテクチャは、
シンプルでありながら柔軟です。

{{architecture.png}}

xoscript をサーバー言語として使うには、
/mods/server というフォルダーにサーバープラグインをインストールする必要があります。

これは、たとえば PHP や Python とは異なり、
コア言語をサーバー固有の機能から切り離しておきたいからです。
そうしなければ、何の目的もなく全員に一切合切を
同梱しなければならず、それはばかげています。
必要であれば、他のモジュールをインストールすることもできます。このシステムは非常に
柔軟です。

また、テンプレート処理やセッション処理のように、スクリプト言語そのもので
実装したほうがよい機能もあるため、便利なように
template.xo と webtools.xo のライブラリも同梱しています。
こうしたことの理由は、あなたが xoscript をどのように使いたいのか
私たちにはわからないからです。サーバーサイドのスクリプト言語として使うこともできますが、
GUI、組み込み機器、あるいは単なるバッチ処理に使うこともできます。
サーバーサイドのスクリプト言語として使う場合でも（これは
現在の主な用途の一つです）、別のテンプレートエンジンや別のセッションハンドラーを
使いたいかもしれません。
あなたが私たちのものを使うべきだと、私たちが決める筋合いはありません。

とはいえ、私たちのテンプレートエンジンを使う利点の一つは、
テンプレートを作成するために追加の構文を覚える必要がないことです。
xoscript に同梱されている標準のテンプレートエンジンは、表示とロジックを
100% 分離します。特別なテンプレート構文の代わりに、
非常に柔軟なスロットマーカーの仕組みを使うだけです。
詳しくは、サーバーの章を参照してください。

なお、標準のテンプレートエンジンや標準の webtools を使いたくない場合は、
言うまでもなく、独自のものを用意する必要があります。

ウェブサーバーを chroot、jail、その他の種類のサンドボックスで実行する場合は、
その環境にも xo の依存関係をインストールする必要があります。必要なライブラリは
ldd を使って確認できます（Linux または BSD の man ページを参照してください）。
xo スクリプトでシェルコマンドを使いたい場合は、シェル
（bash や ksh など）もこの環境にコピーしてください。

また、私たちは後方互換性を非常に重視していることも申し添えておきます。
'version' と呼ばれる、後方互換性のための特別な機能さえ用意されています。
一般に、私たちはあなたのコードが永遠に動き続けることを目指しています。ですから、
新しいバージョンの xoscript との互換性を保つためにコードを更新する必要は
決してありません。私たちの目標は「一度書けば、永遠に動く」です。

このマニュアルの残りの部分では、プログラミング言語 xoscript を
詳しく説明します。サーバースクリプトについては、サーバーという章で
扱います。経験豊富なソフトウェア開発者であれば、いくつかの章は
少し詳しすぎたり、一般的なプログラミングの慣習とよく似ていたりするので、
読み飛ばしてもよいでしょう。すでに他のいくつかのプログラミング言語の
経験がある方は、このマニュアルをリファレンスガイドとして扱うのがよいでしょう。

## Linux でのセットアップ

apache2 と mariadb をダウンロードします。


```
sudo apt-get install apache2 mariadb-server
sudo a2enmod cgi
```

xoscript をダウンロードします。
X を正しいバージョン番号に置き換えてください。

```
wget https://xoscript.com/downloads/xoserver-linux-1_5_X.tar.gz
tar xvf xoserver*.tar.gz
```

ファイルをウェブルートと /bin にコピーします。


```
sudo cp bin/xo /bin/xo
sudo cp -R bin/mods /var/www/html/
sudo cp *.xo /var/www/html/
```

apache2 の設定を編集します。

```
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

Virtualhost を次の内容に置き換えます。

```
<VirtualHost *:80>
    <Directory /var/www/html>
        Options +ExecCGI
        AllowOverride All
        AddHandler cgi-script .xo
        Require all granted
    </Directory>
    DocumentRoot /var/www/html
</VirtualHost>
```

テストページを作成します。

```
sudo nano /var/www/html/test.xo
```

そして、小さなテストプログラムを書きます。

```
#!/bin/xo
Server 初期化.
プログラム 使用: ['webtools.xo'].
>> ウェブ := ウェブ文書 新規.
ウェブ 出力: ['Hello World'].
```

apache2 が CGI を通じてプログラムを実行できるようにします。

```
sudo chmod uog+x /var/www/html/test.xo
```

apache2 を再起動します。

```
sudo systemctl restart apache2
```

ブラウザーでテストページを開きます。

```
http://localhost/test.xo
```

次のように表示されるはずです。

```
Hello World
```


## OpenBSD でのセットアップ

/etc/httpd.conf を編集し、次を追加します。


```
server "mydomain.com" {
    listen on * port 80
    root "/htdocs/mydomain/"

    location "*.xo" {
        fastcgi
        fastcgi socket "/run/slowcgi.sock"   # inside chroot
    }
}
```

SSL を使いたい場合は、次のようにします。

```
listen on * tls port 443
tls {
	certificate "/etc/ssl/mycert.crt"
	key "/etc/ssl/private/mykey.key"
}
```

鍵交換を量子コンピューターによる攻撃から守るには、
mlkem 暗号を選択します。

```
tls {
 ... 
 ecdhe "X25519MLKEM768"
 ...
}
```

xo バイナリと mods、およびすべての依存関係を
chroot に追加します（ldd で調べてください）。

## Hello world

ファイルをコンピューターに転送したら、ファイルを展開し、
次のコマンドで xo を起動できます。

```
xo
```

XOScript を実行するには、プログラムを -xo という接尾辞を付けて
（省略可）ファイルとして保存します。さらに、XOScript コマンドの後に
プログラムのファイル名を入力します。

```
xo myprogram.xo
```

プログラムファイルをパラメーターとして XOScript コマンドを実行すると、
xo はプログラムファイルを読み込んで実行します。

{{note}}
プログラムを xo のアイコンにドラッグして起動することもできます。
{{/note}}

{{warning}}
システムによっては、事前に xo が動的ライブラリを読み込む
権限を許可しておく必要があります。
{{/warning}}

新しいプログラミング言語で最初に書くプログラムは、世界への挨拶のようなものに
するのが伝統です。XOScript では、そのような
**Hello world** プログラムは次のようになります。

@test598

このテキストを hello.xo などのファイルに保存すると、
次のように実行できます。

xo hello.xo

Hello world


プログラムの出力は、上に示した黒いウィンドウで確認できます。
このマニュアル全体を通じて、出力は同じ表現で示します。

{{note}}
出力 は大文字の O で書かれます。
一般に、オブジェクトは大文字で始まります。
ただし、インスタンスとして振る舞う場合（独自の
メソッドを持たず、データだけを持つ場合）は例外です。これは、
他のプログラミング言語におけるクラスとインスタンスの
慣習を反映したものです。
{{/note}}


## 構文

XOScript は *純粋な* *オブジェクト指向* プログラミング言語です。つまり、
xoscript はすべてをオブジェクトとみなし、それ以外の
*データ型* は存在しません。XOScript で書かれたプログラムには、基本的に
三つの基本動作があります。*代入*、*メッセージの送信*、
そして *応答* です。オブジェクト間でメッセージをやり取りすることが、
XOScript プログラムの要です。三つの動作を以下に
示します。


動作            | 例
--------------- | --------
代入            |  \>\> x := 1. 
単項メッセージ  | x even?.
二項メッセージ  | 1 + 2.
キーワードメッセージ | x from: 0 length: 10.
応答            | <- answer.  


この章では、XOScript という言語の全体像を示し、
その基本原則を説明します。XOScript は小さな言語であり、
三つの動作（図を参照）に基づいています。これらはおよそ六つの文法規則に
相当します。この言語を習得するのに必要なのはそれだけです。

すぐに理解できなくても心配はいりません。すべての構成要素は
次の章（3）で詳しく見ていき、基本規則も
繰り返し説明します。ただし、この章は主に言語への全般的な
導入としての役割を果たします。基本原則を簡潔に説明し、
いくつかの適切な例で示します。足りない
詳細は後ほど説明します。

XOScript のコメントは \# 記号で始まります。したがって、次の行は
無視されます。

```
# これは単なるコメントです
```

## 変数

変数を代入するには、
変数宣言記号 >> を使います。変数の名前には、次のものを除くすべての
文字を使えます。<-、:=、空白、ピリオド、コンマ、コロン、
引用符 [' ']、丸かっこ ()。
さらに、変数は複数行にまたがることはできません。また、
変数は数字やマイナス記号で始めることはできない点に注意してください。

有効な変数の例を次に示します。

```
>> password := ['Secret'].
>> ♡♡♡ := 3.
>> $ := ['ドル'].
>> +plus := 真.
>> ユーザーパスワード := ['シーッ!'].
```

無効な変数の例は、たとえば次のとおりです。


```
>> -123 := ['負の数'].
>> password of ユーザー := ['機密'].
>> password.of:ユーザー := ['機密'].
>> ,x := 10.
```

{{note}}
字句解析器にとって曖昧さが生じない限り、
文字列リテラル内の文字（引用符、二重引用符、文字列の
境界を含む）を
エスケープする必要は
ありません。
{{/note}}

変数を宣言したら、自由に使うことができます。つまり、
宣言記号を使う必要があるのは、変数を初めて使うとき（宣言）
だけです。

より具体的には、いきなり変数に値を代入し始めること *(x := 2)* は
できません。まず変数を宣言する必要があります *(\>\>
x := 2)*。ただし、いったん宣言すれば、
宣言記号を使わずに値を変更できます *(\>\> x := 2. x := 3.)*。

変数を宣言するときには、必ず値を代入しなければならない点に注意してください。
他のプログラミング言語とは異なり、値なしで変数を宣言することは
許されていません。各変数を明示的に初期値と
結びつけることが不可欠です。とはいえ、
**無** オブジェクトで変数を初期化しても構いません。この場合、その変数は
空であるとみなせます *(\>\> x := None.)*。要するに、初期値なしで
変数を宣言することは許されません。したがって、

```
>> x.
```

は無効であり、エラーメッセージが表示されます。

{{note}}
xoscript は変数に動的スコープを使います。
詳しくは関数の章を参照してください。
{{/note}}


## リテラル

XOScript はすべてをオブジェクトとみなします。つまり、すべての数値、文字列、
コード片がオブジェクトです。1、2、100、-999、1,234 のような数値は
数値 オブジェクトです。単一引用符で囲まれたテキストはすべて 文字列
オブジェクトです。波かっこ {...} で囲まれたコード片はすべて
関数 オブジェクトです。

リテラル        | ルートオブジェクト | 例
--------------- | ------------ | ----------
数値            | 数値         | 1,2,3... 
文字列          | 文字列       | \['hello'\]
関数            | 関数         | { 1 + 2. }.
                
     
数値や文字列のようなオブジェクトは、常にルートオブジェクトに
由来します。たとえば、すべての数値はオブジェクト **数値** から派生します。すべての
文字列は **文字列** から、すべてのコード片は **関数** から派生します。さらに、
これらのオブジェクトはすべて **オブジェクト** から派生しており、これが実は
すべてのオブジェクトのルートオブジェクトです。


## メッセージ

XOScript でのプログラミングとは、基本的に
オブジェクトにメッセージを送ることです。オブジェクトにメッセージを送る
一般的な書き方は次のとおりです。

```
<object> <message>
```

たとえば、数値 **2** が偶数かどうかを調べるには、
メッセージ **偶数?** をオブジェクト **2** に送ります。

```
2 偶数?
```

答えは **真** になります（これもまたオブジェクトです）。未知のメッセージは
通常オブジェクトに無視されるため、エラーは発生しません。一部のオブジェクト（たとえば
数値や文字列）は、未知のメッセージにあらかじめ決められた方法で応答します
（これについては後ほど詳しく説明します）。

オブジェクトが受け取るメッセージには三種類あります。

種類            | 引数の数
--------------- | -------------------
単項            | 0      
二項            | 1     
キーワード      | 1+    


第一に、上の例のような **単項
メッセージ** があり、これは引数を持ちません。第二に、
**キーワードメッセージ** があり、これは一つ以上の引数を持ちます。
たとえば次のとおりです。

```
>> x := 数値 範囲: 1 から: 10.
```

この場合、メッセージ **範囲:から:** が **数値** に送られます。**数値** は
すべての数値のルートオブジェクトです。結果は 1 から 10 までの
乱数になります。最後に **二項メッセージ** があり、これは
一文字と一つの引数だけを持ちます。

```
2 + 3
```

これは数式の足し算のように見えますが、実際には単なるメッセージの一つです。
メッセージ **+** が引数 **3** とともに **2** に送られ、
答え **5** が返されます。二項メッセージはコロンなしで書くことができます。

二項メッセージは連鎖させることができます。

```
>> x := 3 + 2 - 1.
```

このコード片では、まず **+ 2** が **数値** オブジェクト **3** に送られ、
その結果 数値 オブジェクト **5** となり、その後 **-1** がこの
数値に送られます。注意深い読者は、このプロトコルが従来の数学における
演算子の順序と食い違っていることに気づくでしょう。その指摘は正しいものです。
XOScript は、メッセージシステムの一貫性を優先して、数学的な順序を無視します。
その結果、次の計算は

```
2 + 3 * 5 = 25
```

17 にはなりません。

これは意図的な設計です。丸かっこを使って順序を変更できます。

```
2 + (3 * 5) = 17
```

ほとんどのオブジェクトは、あるメッセージへの応答として自分自身を結果として
返します。これは便利です。続けてメッセージを送ることで、
そのオブジェクトとの対話を続けやすくなるからです。

```
出力 書く:
[' こんにちは '] 空白除去 大文字.
```

```
こんにちは
```

ここでは、二つのメッセージが **文字列** オブジェクトに送られています。**空白除去** と、
それに続く **大文字** です。

次のコード片では、新しいメッセージが来ることを示すために
コンマが必要です。コンマがないと、XOScript は混乱してしまいます。

```
出力 書く: ['Hello!'], 改行.
```

まず、メッセージ **書く:** が鉛筆記号に送られ、続いて
**改行** が送られます。コンマがなければ、XOScript は
**改行** を **文字列** **Hello!** に送りたいのだと解釈してしまいます。これは無意味な操作です。

メッセージの処理順序は次のとおりです。左から右へ進み、
まず丸かっこ内のメッセージ、次に単項メッセージを処理します。続いて
二項メッセージ、最後にキーワードメッセージを処理します。次の例を
見てください。

```
出力 書く: 0.5 四捨五入 + (2 - 1), 改行.
```

XOScript は常に左から右へ読みます。まず、メッセージ **書く:** が
出力 に送られ、続いて **改行** メッセージが送られます。引数の中でも
XOScript は左から右へ読むので、まず **0.5 四捨五入**、
次に **+** を処理します。

{{note}}
改行 メッセージは、文字列に改行文字を追加します。

理解する最善の方法は、実際に練習することです。

前の例では、プラス **記号** がオーバーライドされています。
最終的には、やはり最後の加算を行わなければならないことに注意してください。

# 真偽値

{{messages}}

執筆時点で一般的なほとんどのプログラミング言語とは異なり、
XOScript には 真 オブジェクトと 偽 オブジェクトがそれぞれ
一つずつしかありません。つまり、**真** と書くたびに
新しいオブジェクトが作成されるわけではありません。常に参照を使っています。
したがって、次のように書いた場合、

\>\> x := True.

**x** は **真** オブジェクトを参照します。条件付きのコードやループも
この参照を確認します。XOScript では、**真** と **偽** の意味は
固定されていません。実際、次のような文を書くと、XOScript プログラムは
かなり混乱します。

True := False.

このような操作の結果は未定義ですが、有効な
操作であり、したがって形式上は許されています。さらに、真偽値
オブジェクトがあり、これは **真** と **偽** の両方のルートオブジェクトです。どちらも
このルートオブジェクトから派生しているからです。ただし、真偽値 オブジェクトそのものには
実用的な用途はありません。

## 落とし穴

**かつ:** と **または:** の使い方には注意してください。

```
出力 書く: (偽 or: 真 or: 真), 改行.
出力 書く: (偽 または: 真, または: 真), 改行.
```

結果は次のとおりです。

```
偽
真
```
メッセージ **または:** は引数を一つしか取らないからです。最初のメッセージは
**または:または:** を 偽 に送りますが、これは存在しないため、オブジェクトは
メッセージを無視して自分自身（偽）を返します。一方、二行目は
**または:** を送り、続いてもう一つの **または:** を送ります（連鎖記号、つまりコンマ , を使っています）。

# 関数

{{messages}}

コードを { と } で囲むと、それは関数になります。
xoscript では、タスク、あるいは単にコードブロックという
用語を使うこともあります。

関数を実行するには、メッセージ *開始* を送ります。


```
{ 出力 書く: 123, 改行. } 開始.
```

関数が引数を取る場合は、**適用:** を使います。

```
{ :a 出力 書く: a, 改行. } 適用: a.
```

以下の例も参照してください。
アーキテクチャが単純なため、関数の戻り点は
一つだけです。条件のためのオーバーヘッドや過度の入れ子を避けるには、
手続き を使うことができます（これは、引数 1 を付けて
乗算記号を使うのと同じです）。

```
{
  (a = 1) 真なら: { x := 1. }, 中断.
  (a = 2) 真なら: { x := 2. }, 中断.
} 手続き.
```

こうすると、a = 1 の場合に (a = 2) は評価されません。
また、この方法なら 真なら: メッセージを入れ子にする必要もありません。
条件を入れ子にしていることに気づいたら、
手続き メッセージのことを考えてみてください。コードが
読みやすくなるかもしれません。


重要な落とし穴を次に示します。

```
{
	偽 偽なら: {
		出力 書く: ['ループを終了。'].
	}, 中断.
	
	出力 書く: ['これは表示しないで。'].

} 手続き.

```

この場合、テキスト 'Dont show me' が表示されます。
**中断** が 偽 に送られるからです。中断を実行したい場合は、
**真** へのメッセージとして送る必要があります。
 

```
{
	偽 否定 真なら: {
		出力 書く: ['ループを終了。'].
	}, 中断.
	
	出力 書く: ['これは表示しないで。'].

} 手続き.

```

これは期待どおりに動作します。

例外は次のように処理できます。

プログラム内で意図的にエラーを発生させ、
それによってハンドラーブロックを起動することもできます。これは、
次の例に示すように、現在のタスクにメッセージ **エラー:** を

```

} 例外時: { :間違い
出力 書く: 間違い.

```

## 値の注入

XOScript では、タスクに値を注入することができます。では、
次のタスクを見てください。

```
>> 送信処理 := {
	ニュースレター 宛先: 自分の recipient.
}.
送信処理 設定: ['recipient']
値: ['info@recipient.org'].
送信処理 開始.
```


この例は架空のタスクを示しており、ニュースレターを
メールアドレス、つまり **recipient** に送信します。この受信者は、
タスクの開始前に外部からタスクに注入できます。そのためには、
タスクにメッセージ **設定:値:** を送ります。こうすることで、
**recipient** の値がタスクにあらかじめ設定されます。この値は変更することもでき、
その後タスクを再び実行できます。これは
タスクオブジェクトを使う際に便利な方法です。

## 空の関数

空のタスクは許されていません。理論上、空のタスクは
**{}** のようになりますが、XOScript はこれを言語エラーとみなします。
空のタスクを宣言したい場合は、無 オブジェクトを使えます。

```
>> タスク := 無.
```

これは本当のタスクではなく 無 オブジェクトですが、それでも 開始 メッセージを
送ることができます。

```
>> 答え := タスク 開始.
```

実際、これは次と同じです。

```
>> 答え := 無 開始.
```

オブジェクト **無** はメッセージ **開始** を認識しないため、
自分自身を答えとして返し、答えはやはり **無** になります。
したがって、空のタスクを持つ必要はありません。プログラミング言語 XOScript の
洗練された設計のおかげで、代わりに単に 無
オブジェクトを使うことができます。

# リスト

{{messages}}

XOScript には二種類のコレクションがあります。*リスト* と *辞書* です。
**リスト** は、*決まった順序* でオブジェクトを列挙したものです。辞書には
順序がなく、キー（または用語）とそれに対応する値からなる
凡例のようなものです。リストは配列（PHP、Java、C）や
リスト（Python）に相当します。辞書は、他のプログラミング言語における
連想配列（PHP）や辞書（Python）に相当します。新しい リスト を作成するには、
次のように書きます。

```
>> フィボナッチ := リスト 新規.
```

この空のリストは、**末尾に追加:** を使って要素を追加できます。

```
フィボナッチ 末尾に追加: 0.
フィボナッチ 末尾に追加: 1.
フィボナッチ 末尾に追加: 1.
フィボナッチ 末尾に追加: 2.
フィボナッチ 末尾に追加: 3.
フィボナッチ 末尾に追加: 5.
フィボナッチ 末尾に追加: 8.
フィボナッチ 末尾に追加: 13.
```

リストを画面に書き出すと、

```
出力 書く: フィボナッチ, 改行.
```

次のように表示されます。

```
リスト ← 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13
```

末尾に追加 の代わりに、; を使ってリストに要素を追加することもできます。


```
>> フィボナッチ := リスト 新規 ; 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13.
```

セミコロン（;）はすべて二項メッセージで、
値をリストに入れます。

## 連鎖

次のようなリストがあるとします。

```
>> x := リスト 新規 ; 1 ; 2 ; 3.
```

最初と最後の要素を削除したい場合、
メッセージは次のようになるでしょう。

```
x 先頭を取り出す 末尾を取り出す.
```

残念ながら、この書き方は正しく機能しません。
メッセージ **先頭を取り出す** はリストの最初の要素を返し、
その要素がメッセージ **末尾を取り出す** の受信者になってしまいます。つまり、
メッセージ **末尾を取り出す** は **x** ではなく 2 に送られます。
この問題の解決策の一つは、次のように二つの文に
分けることです。

```
x 先頭を取り出す.
x 末尾を取り出す.
```

しかし、これはかなり実用的ではありません。特に、二つより多くの要素を
削除する必要がある場合はなおさらです。そこで、XOScript は
このような状況のために代替のメッセージ構造を用意しています。
**代替** メッセージ構造では、オブジェクトの答えは無視され、
毎回受信オブジェクトが答えとして返されます。
**代替** メッセージ構造は、オブジェクトにメッセージ **連続開始** を送ることで始まり、
メッセージ **連続終了** を送ることで終了します。
先の例では、次のように適用できます。

```
>> x := リスト 新規 ; 1 ; 2 ; 3.
x 連続開始 先頭を取り出す 末尾を取り出す 連続終了.
```

# 辞書

{{messages}}

**リスト と 辞書 はどちらもコレクションです。ただし、
リストとは異なり、辞書には順序が **ありません**。両者のもう一つの違いは、
辞書がオブジェクトの組で構成されていることです。一方のオブジェクトは、もう一方のオブジェクトを
探すための見出し（または
キーワード）として機能します。辞書のよい例は、
次のような価格表です。


```
>> メニュー := 辞書 新規
	格納: ['£5'] 場所: ['アップルパイ'],
	格納: ['£6'] 場所: ['キャロットケーキ'],
	格納: ['£3'] 場所: ['fudge'].
```

リストと同様に、メッセージ 格納:場所: を
使ってオブジェクトを追加します。違いは、
リストとは異なり、二つのオブジェクトが結びつけられることです。最初のオブジェクトは、
リストと同様に、保存するオブジェクトです。二番目の
オブジェクトは、コレクション内での位置ではなく、**見出し** です。
これにより、後で最初のオブジェクトを取り出すことができます。
要するに、辞書は国語辞典のように機能します。つまり、キーワードを使って
その意味を見つけることができます。たとえば、
上の表からファッジの価格を取り出すには、次のようにします。

```
>> price := メニュー 位置で: ['fudge'].
```

簡潔な書き方を使うこともできます。

```
>> price := メニュー ? ['fudge'].
```

オブジェクトを保存するのに使う見出しに空白が含まれていない
（かつ、他の定義済みメッセージと衝突しない）場合は、
次の書き方も使えます。

```
>> メニュー := 辞書 新規
	pie:   ['£5'],
	cake:  ['£6'],
	fudge: ['£3'].
```

上の書き方のほうが、少し自然に読めるのは間違いありません。
ファッジの価格を求めるには、
次の簡略化した書き方を使えます。

```
>> price := メニュー fudge.
```

# プログラム/標準出力

{{messages}}

プログラム オブジェクトは、現在実行中のアプリを表します。このオブジェクトは、
システムコマンドの実行、サブプログラムの読み込み、
引数の読み取りなどの機能を提供します。システムに関連するすべての機能です。

## 標準出力

出力 は標準出力オブジェクトです。基本的に二つのメソッドを持っています。
**書く:** と **改行** です。書く: メッセージは文字列を
stdout に送るために使い、改行 メッセージは改行文字を出力します。
**改行** の代わりに \\n を使うこともできます。

例:

```
出力 書く: ['Hello World'], 改行.
```

結果:

```
Hello World
```

## モジュール/プラグイン

XOScript の世界は、モジュールをインストールすることで、新しいシステムオブジェクトによって
拡張できます。モジュールファイル（通常は接尾辞 .so
を持つファイル）を mods フォルダーに置くことで、新しいシステムオブジェクトを
XOScript の世界に追加できます。

プラグインモジュールによって提供されるオブジェクトにメッセージを送ると、
そのモジュールは XOScript によって自動的に読み込まれます。

プラグインを自分で書くこともできます。プラグインは
C プログラミング言語で書かれます。プラグインの例は、ソース
コードパッケージの src/plugins/example にあります。


## リフレクション

プログラムの実行中にシステムを
調べる方法はいくつかあります。XOScript には、
どのオブジェクトが存在し、それらのオブジェクトがどのメッセージに
応答するかを調べるためのメソッドがいくつかあります。まず、各オブジェクトにはその **型名** を
尋ねることができます。ただし、XOScript の型は変更可能なので、信頼できません。

また、プログラム オブジェクトに、
特定のオブジェクトがすでにプログラム内に存在するかどうかを尋ねることもできます。

```
プログラム ツール 真なら: { ... }.
```

オブジェクトの
名前が一つの記号だけで構成されている場合は、混乱を避けるために
次の書き方を使うのが最善です。

```
プログラム 検索: ['X'], 真なら: { ... }.
```

オブジェクトについて尋ねるだけでなく、
プログラム オブジェクトにメッセージについて尋ねることもできます。たとえば、
オブジェクト **数値** がメッセージ **範囲:から:** を知っているかどうかを、
次のように尋ねることができます。

```
プログラム Number: ['between:and:'], 改行.
```

```
Server 初期化.
```

## サーバーの設定

次のサーバー設定を行うことができます。

```
	# 既定値が設定されています。
	# 何も設定しなければ、
	# これらの値が使われます...

	プログラム 
	設定値: ['max-postfields']

	プログラム
```

## Hello World

Apache2、NGINX、OpenHTTPD、その他のよく知られたサーバーなど、
標準的な CGI サーバーで使える、とても簡単なウェブプログラムを次に示します。

```
#!/bin/xo

Server 初期化.
プログラム 使用: ['webtools.xo'].

>> ウェブ文書値 := ウェブ文書 新規.

ウェブ文書値 出力: ['
<html>
<body>
<b>Hello World!</b>
</body>
</html>'].

```

ウェブ文書 オブジェクトを使いたくなければ、それでも構いません。ただし、
その場合は HTTP ヘッダーを自分で書く必要があります。

```
#!/bin/xo
出力 書く: ['Content-type: text/html; charset=utf-8 \n\n'], 改行.
出力 書く: ['こんにちは、世界!'], 改行.
``` 

## リクエスト

HTTP-リクエスト オブジェクトを使うと、GET/POST/COOKIE および
UPLOAD のデータを取得できます。

```
>> http要求  := HTTP-リクエスト 新規.
>> search   := http要求 get: ['search']. # ?search=books
>> password := http要求 post: ['password']. # フォームから
>> 選択項目 := http要求 get-リスト: ['sel[]']. #?sel[]=1&sel[]=2
>> 選択項目 := http要求 post-リスト: ['sel[]'].
>> cookie   := http要求 cookie: ['session-id'].
>> アップロード   := http要求 upload: ['file'].
>> 一時パス := アップロード ? 1.
>> ファイル名 := アップロード ? 0.
```

## 最大 POST 数/長さ

POST フィールドの最大数のデフォルトは 40、コンテンツの最大長の
デフォルトは 2MB です。スクリプトごとに異なる設定にするには、次のようにします。

```
プログラム 設定値: ['max-contentlength'] 値: 1. 
プログラム 設定値: ['max-postfields'] 値: 1. 
```

{{note}}
コンテンツの長さが最大値を超えると、
ペイロードが安全であるとはもはや確信できないため、
プロセスは強制終了されます。
{{/note}}

maxtime の制限は、stdin/POST データを読み取るための
最大時間をミリ秒単位で決めます。

```
プログラム 設定値: ['max-time'] 値: 5000. # 5sec
```

これは POST の I/O 読み取りにのみ適用され、
slowloris のような攻撃を防ぎます。任意の操作の実行時間を本当に
制限したい場合は、プログラム の 制限時間: を使ってください。

## データベース

Database オブジェクトを使うと、MariaDB/MySQL に問い合わせることができます。
データベースに接続するには、次のようにします。

```
>> db := Maria-DB 新規 ホスト: ['localhost'],
	ユーザー名: ['xo'],
	パスワード: ['pass123'],
	データベース名: ['xobase'],
	接続.

```

レコードを挿入するには、次のようにします。

```
>> 検索パラメータ := db クエリ: ['
	INSERT INTO book (id, description, price, rating) 
	VALUES (NULL, ?, ?, ?)
'], パラメータ: ( リスト 新規 ; ['abc'] ; 12.35 ; 6 ). # パラメーター化クエリ

{  検索パラメータ 実行. db コミット. }
例外時: { :e db ロールバック.  }, 開始.
```

xoscript はトランザクションで *のみ* 動作し、自動コミットは決して行わないことに注意してください。
自動コミットを無効にできない場合は、接続エラーになります。
クエリには常にパラメーターバインディングを使い、ユーザー入力を直接
SQL に加えないでください。

挿入された id は次のように取得します。

```
出力 書く: ['挿入済み: '] + 検索パラメータ insert-id, 改行. # 挿入された ID
```

レコードを取得するには、次のようにします。

```
>> 検索パラメータ :=
db
	クエリ: ['SELECT * FROM book order by id desc limit 2'], 
	取得: { :行 
		出力 書く: 行 id + [' '] + 行 description + [': '] + 行 price, 改行.
	}. # 行の取得

```

## セッション

データを永続化するために、セッションオブジェクトにデータを保存し、そこから取得できます。
まず、新しい **ウェブ文書** を作成します。ウェブ文書 オブジェクトは、
リクエスト、ヘッダー、HTML、セッションをまとめるものです。というのも、
ブラウザーでウェブサイトを訪れたとき、目にするのは HTML だけです。しかし、
ウェブ文書 全体は **ヘッダー** からも構成されています。たとえば、
ほとんどの HTTP レスポンスには Content-type:text/html のようなヘッダーが含まれ、
続くデータを HTML として表示すべきであること
（あるいは、たとえばファイルとしてダウンロードすべきであること）をブラウザーに伝えます。セッションは、
リクエスト間でユーザーデータを保存する方法です。このデータを追跡するには、
クッキーを設定する必要があり、このクッキーもヘッダーを通じて設定されます。そのため、
すべてが ウェブ文書 にまとめられているのです（ウェブ文書 は、ヘッダーと HTML
またはその他のデータの両方を含む完全な文書だからです）。


```
# まず新しい ウェブ文書 のインスタンスを作ります
>> ウェブ := ウェブ文書 新規.

# 次にセッションを開始します。これによりクッキー用のヘッダーと
# そのクッキーに関連付けられたデータ保存用のファイルが作られます
>> セッション値 := ウェブ セッション開始.

# これでセッションを 辞書 のように扱えます
セッション値 userid: 123.
```

（ログアウト時に）セッションを破棄するには、次のようにします。

```
ウェブ セッション破棄.
```

## ヘッダー

ウェブ文書 では、他のよく知られたヘッダーも設定できます。
たとえば、ユーザーを別の URL にリダイレクトしたい場合は、次のようにします。

```
ウェブ 移動: ['/other.html'].
```

内部では、このコマンドは HTTP ヘッダーも生成します。このヘッダーは、
他のデータや HTML とともに送られ、指定された宛先アドレスに移動するよう
ブラウザーに指示します。

独自のヘッダーを追加するには、次のようにします。

```
ウェブ ヘッダー: ( 
	HTTPヘッダー 新規
	キー: ['Content-Length']
	設定値: 400
).
```

404 ページを表示するには、次のようにします。

```
ウェブ 見つかりません: ['おっと..'].
```


## テンプレート

標準のテンプレートシステムはとても簡単です。新しい
テンプレート構文を覚える必要はありません。また、テンプレートエンジンは、
表示とビジネスロジックの本当の分離を保証します。

ファイルからテンプレートを作成するには、次のようにします。

```
>> tpl := ウェブ テンプレート: ['templates/ux.tpl'].
```

テンプレートシステムはマーカーを使います。
マーカーには三種類あります。カットマーカー、ペーストマーカー、
スロットマーカーです。基本的な考え方はとても簡単で、カットマーカーで
示された領域を切り取り、ペーストマーカーで示された領域に
貼り付けることができます。スロットマーカーには
文字列を差し込むことができます。

たとえば、次のテンプレートを使って、
宝石を宝石箱に入れ、値札を付けてみましょう。

```
<!-- cut:gem -->
<img src="gem.gif">
<b>$<!-- slot:price --></b>
<!-- /cut:gem -->

<div id="box">
<!-- paste:jewels -->
</div>
```

これは次のように行えます。

```
>> gem := tpl 切り取り: ['gem'], 複製.
gem price: 99.
tpl 貼り付け: gem 場所: ['jewels'].
ウェブ 出力: tpl マーカー除去.
```

最後の行は、必要な HTTP ヘッダーとともに、テンプレートを
文字列としてクライアントに送り出すだけです。

結果:

```
<div id="box">
<img src="gem.gif">
<b>$99</b>
</div>
```


## パススルー

ユーザーがアップロードしたファイルを安全に配信するには、パススルーを利用できます。

```
>> アップロード済み := ['smile.gif'].
Server 素通し: アップロード済み 接頭辞: ['/uploads/images/'].
プログラム 終了.
```

これにより、ユーザーがアップロードしたコンテンツが適切な
MIME タイプで配信されます。サポートされるのは、ホワイトリストに載っている MIME タイプのみです。
GIF、JPG、PNG、WEBP、MP4、WEBM、MP3、ZIP、GZIP、PDF、SVG です。
SVG、ZIP、GZIP のファイルはダウンロードとして送信されます。SVG には、
そうしなければあなたのドメイン上で実行されてしまうスクリプトが含まれている可能性があるからです。
この方法は、TOCTOU 攻撃、パストラバーサル、
悪意のあるコードの実行（インジェクション）、シンボリックリンク攻撃、
DDoS 攻撃（ファイルの上限 = 50MB）、スニッフィング攻撃、
その他さまざまなセキュリティ上の問題を防ぎます。

## 書式設定

書式 オブジェクトを使うと、パディングやゼロの追加など、
データの書式を整えることができます。printf の構文を使います。

```
>> fmt := 書式 新規: ['%06.0f'].

```

書式には変換を一つ含めることができ、その変換は値に合っていなければなりません。
そうでない場合はエラーになります。

- 文字列に対する `適用:`: `%s`
- 数値に対する `適用:`: `%f`、`%e`、`%g` または `%a`
- 数値に対する `整数に適用:`: `%d`、`%i`、`%o`、`%u`、`%x` または `%c`

リクエストから得られる値は文字列です。それを数値として書式設定するには、
まず変換してください。

```
fmt 適用: (http要求 get: ['amount']) 数値化.
```

# ffi

{{messages}}

FFI はプラットフォーム/プラグイン単位で提供されます。FFI は
下層のシステムアーキテクチャに密接に結びつくものであり、それは
コアが行うべきことではないからです。
サーバープラグインは、準拠した ffi/blob の実装を提供しています。
デフォルトでは、コアは stdin/stdout、限定的なファイル I/O サービス、
シェル（プログラム システム:）を通じて対象プラットフォームに接続します。
補助的な連携は、サーバープラグインのようなアプリケーション
中心のプラグインを通じて、ffi/blob によって提供されます。

FFI は Foreign Function Interface（外部関数インターフェース）の略です。他の人が
別のプログラミング言語で書き、DLL ファイル、SO ファイル、Dylib ファイルとして提供している機能を使うことができます。
それらはさまざまな関数であり、この方法を通じて利用できる機能は非常に幅広いものです。
例から始めましょう。

```
Server リンク: (
 リスト 新規 ;
 ['/usr/lib/x86_64-linux-gnu/libc.so.6'] ;
 ['printf'] ;
```

リンクメソッドの引数:

- 引数 #1: 使いたい DLL または SO ファイル。
- 引数 #2: そのファイル内の、リンクしたい関数。
- 引数 #3: 関数の引数のデータ型の名前のリスト。
- 引数 #4: 関数の戻り値の型の名前。
- 引数 #5: この関数をリンクしたいオブジェクトの名前（存在しない場合は
自動的に作成されます）。
- 引数 #6: この関数をリンクするメッセージ。

上の例では、libc.so の printf 関数をリンクしようとしています。データ
型の名前は、リンク先のソフトウェアのドキュメントで確認できます。利用できる型は次のとおりです。
void、pointer、float、double、int、uint、char、uchar、intX、uintX。
ここで X は 8、16、32、64 のいずれかです。

これらの型は、データを保存するのに必要なバイト数を表します。printf の場合は、
Printf という新しいオブジェクトとメッセージ template:number: にリンクしています。外部の
関数は、使う前に XOScript の方言に翻訳します。メッセージ template:number: は、
最初のパラメーターとしてテンプレートのテキストを含むバッファーを受け取ります。このバッファーは
Blob オブジェクトを使って作成します。Blob オブジェクトを使うと、
メモリを手動で確保できます。このメモリは、後で 解放 メッセージを使って
自分で解放する責任があります。

メモリ blob はさまざまな方法で埋めることができます。この例ではテキストで埋めるので、
utf8: メッセージを使います（UTF-8 はテキストをバイトに変換するためのエンコーディングです）。blob は
bytes: を使い、バイト値のリストを渡して埋めることもできます。blob の内容を読むには、開始:長さ: を使います。
バイトがリストとして返されます。さらに、
struct: メッセージに C の型の並びを渡すことで、Blob を使って C の構造体を作成することもできます。これは、
外部のソフトウェアライブラリにある、構造体へのポインターを受け取る C の
関数を呼び出すときに必要になることがあります。

{warning}
blob は自分で解放する必要があります。
blob はガベージコレクターによって片付けられません。
{/warning}

blob はライブラリの外部関数とやり取りされることがあるため、
自動的にガベージコレクションすることはできません（外部関数によって
使われ続けている可能性や、外部関数が自分で解放しようとする可能性があるためです）。
そのため、必要に応じて blob を自分で解放する必要があります。

blob を解放するには、次のようにします。

```
私のblob 解放.
```

構造体を解放するには、次のようにします。

```
私の構造体 struct-解放 解放.
```

つまり、構造体の場合は、メモリブロックを解放するために
struct-解放 と 解放 の二つのメッセージを送る必要があります。
