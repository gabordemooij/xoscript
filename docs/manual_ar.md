مرحبًا بك في XOScript
يهدف مشروع XOScript إلى إنشاء لغة برمجة نصية بسيطة وقابلة للتدقيق.
والبساطة لا تعني بالضرورة السهولة.
فقد تكون لغة برمجة مألوفة أسهل استخدامًا من XOScript.
أما هنا فللبساطة معنى مختلف:
أن تستطيع تكوين نموذج ذهني كامل للغة ولسلوكها.

صُممت XOScript لتتسع لها ذاكرتك.
فقواعدها النحوية وعدد مفاهيمها صغيرة عن قصد.
لا توجد أصناف (classes)؛ ويمكن توسيع الكائنات مباشرة.
تُمرَّر الكائنات بالمرجع، والنسخ يكون صريحًا،
وللدوال نقطة خروج واحدة فقط.

تختلف بعض هذه الخيارات اختلافًا كبيرًا عن اللغات السائدة.
فعلى سبيل المثال، لا تملك XOScript نظام أنواع، وتستخدم النطاق الديناميكي.
والرسائل التي لا يمكن معالجتها تُتجاهَل بدلًا من أن تُطلق استثناءً.
لهذه الخيارات عواقب، وليس الغرض منها القضاء على الأخطاء.
بل الغرض منها إبقاء النموذج الأساسي للغة صغيرًا ومتسقًا.

يمكن أيضًا توطين XOScript، مما يتيح التعبير عن قواعد العمل
بلغة طبيعية وربما مشاركتها مع أصحاب المصلحة من غير التقنيين.

وتعني قابلية التدقيق تطبيق الفلسفة نفسها على التنفيذ.
فبيئة التشغيل مكتوبة بلغة C، مع محلل مفردات ومحلل نحوي ومفسر شجري صغيرة ومكتوبة يدويًا.
وتعكس المكتبة القياسية وبيئة التشغيل إلى حد كبير بنية اللغة،
مما يجعل العلاقة بين شفرة XOScript وتنفيذها مباشرة نسبيًا.

كما ترتبط الاختبارات ارتباطًا وثيقًا بالتوثيق.
فلكل طريقة (method) ينبغي أن يكون اختبار مرتبط بها يمكن إدراجه في الدليل،
مما يساعد على إبقاء التوثيق متوافقًا مع التنفيذ.

لا يُقصد من XOScript منافسة اللغات السائدة في
الميزات أو الألفة. بل تستكشف هدفًا مختلفًا:
بيئة برمجة يستطيع المطور فهمها ككل.

والأمل أن تجعل اللغة الصغيرة والتنفيذ
الصغير فهم البرمجيات أمرًا عمليًا،
من البايت إلى الكائن، ومن الصياغة إلى بيئة التشغيل، وأن تكتب الشفرة
بثقة لأنك تفهم ما يحدث في
النص البرمجي وما يحدث خلف الكواليس معًا.

بنية إعداد خادم xoscript
بسيطة، ومرنة في الوقت نفسه.

لاستخدام xoscript لغةً للخادم، عليك تثبيت
إضافة الخادم في مجلد يسمى /mods/server.

والسبب أننا نحب
فصل اللغة الأساسية عن الوظائف الخاصة بالخادم،
على خلاف PHP أو Python مثلًا. وإلا لاضطررنا إلى شحن
كل شيء دون أي غرض للجميع، وهذا أمر سخيف ببساطة.
ويمكنك تثبيت وحدات أخرى أيضًا إن شئت. فالنظام
مرن جدًا.

كما أن بعض الوظائف يكون تنفيذها أفضل في لغة البرمجة النصية
نفسها، مثل القوالب وإدارة الجلسات، لذلك نشحن
إضافةً إلى ذلك مكتبتي template.xo وwebtools.xo لراحتك.
والسبب في كل هذا أننا لا نعرف كيف تريد
استخدام xoscript. يمكنك استخدامها لغةً برمجية نصية في جهة الخادم،
ولكن أيضًا للواجهات الرسومية أو الأجهزة المدمجة أو المعالجة الدفعية فحسب.
وحتى لو استخدمتها لغةً نصية في جهة الخادم (وهي
حاليًا إحدى حالات الاستخدام الرئيسية)، فقد ترغب مع ذلك في
استخدام محرك قوالب مختلف أو معالج جلسات مختلف.
فمن نحن لنقرر أن عليك استخدام ما لدينا؟

ومن مزايا استخدام محرك القوالب الخاص بنا مع ذلك أنك
لا تحتاج إلى تعلم صياغة إضافية لإنشاء القوالب.
فمحرك القوالب الافتراضي المشحون مع xoscript يفصل فصلًا تامًا بنسبة 100%
بين العرض والمنطق. وبدلًا من صياغة قوالب
خاصة، يستخدم ببساطة نظام علامات خانات مرنًا جدًا.
لمزيد من المعلومات، راجع فصل الخادم.

لاحظ أنك إن لم ترغب في استخدام محرك القوالب الافتراضي أو
أدوات الويب الافتراضية، فمن البديهي أن عليك توفير
ما يخصك.

إذا كنت تشغل خادم الويب في chroot أو jail أو أي نوع آخر من بيئات العزل،
فعليك أيضًا تثبيت اعتماديات xo في تلك البيئة، ويمكنك
معرفة المكتبات التي تحتاجها باستخدام ldd (راجع صفحة الدليل في Linux أو BSD).
وإن أردت استخدام أوامر الصدفة في نصوص xo البرمجية، فانسخ أيضًا صدفة
(مثل bash أو ksh) إلى هذه البيئة.

ونود أيضًا أن نشير إلى أننا نأخذ التوافق مع الإصدارات السابقة بجدية كبيرة.
بل توجد ميزة خاصة للتوافق مع الإصدارات السابقة تسمى
'version'. وبوجه عام، نهدف إلى أن تعمل شفرتك إلى الأبد. لذلك
لن تضطر أبدًا إلى تحديث شفرتك لتبقى متوافقة مع الإصدارات الأحدث
من xoscript. هدفنا هو: اكتب مرة واحدة، وشغّل إلى الأبد.

بقية هذا الدليل مخصصة لشرح لغة البرمجة
xoscript بالتفصيل. وتُناقَش البرمجة النصية للخادم في الفصل
المسمى الخادم. إذا كنت مطور برمجيات متمرسًا، فقد ترغب
في تخطي بعض الفصول لأن بعضها مفصل أكثر من اللازم قليلًا أو
مشابه جدًا لممارسات البرمجة العامة. لذا فمن
لديه خبرة بالفعل في عدة لغات برمجة أخرى
يحسن به أن يعامل هذا الدليل كمرجع.

## الإعداد على Linux

نزّل apache2 وmariadb:


```
sudo apt-get install apache2 mariadb-server
sudo a2enmod cgi
```

نزّل xoscript.
استبدل X برقم الإصدار الصحيح!

```
wget https://xoscript.com/downloads/xoserver-linux-1_5_X.tar.gz
tar xvf xoserver*.tar.gz
```

انسخ الملفات إلى جذر الويب وإلى /bin:


```
sudo cp bin/xo /bin/xo
sudo cp -R bin/mods /var/www/html/
sudo cp *.xo /var/www/html/
```

عدّل إعدادات apache2:

```
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

استبدل Virtualhost بما يلي:

```
<VirtualHost *:80>
    <Directory /var/www/html>
        Options +ExecCGI
        AllowOverride All
        AddHandler cgi-script .xo
        Require all granted
    </Directory>
    DocumentRoot /var/www/html
</VirtualHost>
```

أنشئ صفحة اختبار:

```
sudo nano /var/www/html/test.xo
```

واكتب برنامج اختبار صغيرًا:

```
#!/bin/xo
Server هيئ.
برنامج استخدم: ⌝'webtools.xo'⌜.
>> web := مستند-ويب جديد.
web أخرج: ⌝'Hello World'⌜.
```

اسمح لـ apache2 بتنفيذ برنامجك عبر CGI:

```
sudo chmod uog+x /var/www/html/test.xo
```

أعد تشغيل apache2:

```
sudo systemctl restart apache2
```

انتقل إلى صفحة الاختبار في المتصفح:

```
http://localhost/test.xo
```

يُفترض أن ترى:

```
Hello World
```


## الإعداد على OpenBSD

عدّل /etc/httpd.conf، وأضف:


```
server "mydomain.com" {
    listen on * port 80
    root "/htdocs/mydomain/"

    location "*.xo" {
        fastcgi
        fastcgi socket "/run/slowcgi.sock"   # inside chroot
    }
}
```

إن أردت استخدام SSL:

```
listen on * tls port 443
tls {
	certificate "/etc/ssl/mycert.crt"
	key "/etc/ssl/private/mykey.key"
}
```

لحماية تبادل المفاتيح من الحوسبة الكمومية،
اختر مجموعة التشفير mlkem:

```
tls {
 ... 
 ecdhe "X25519MLKEM768"
 ...
}
```

أضف الملف التنفيذي xo والوحدات، وكذلك أي اعتماديات، إلى
بيئة chroot (اعرفها باستخدام ldd).

## تشغيل الأمثلة


لتشغيل أحد البرامج النموذجية في الحزمة:

```
./example.sh <name> <Linux/OBSD> [clean]
```

على سبيل المثال، لتشغيل مثال FizzBuzz على Linux:

```
./example.sh fizzbuzz Linux
```

```
./example.sh fizzbuzz OBSD
```

```
./example.sh fizzbuzz OBSD clean
```

## مرحبا بالعالم

بعد نقل الملف إلى حاسوبك، يمكنك فك ضغطه
وتشغيل xo باستخدام الأمر التالي:

```
xo
```

لتشغيل برنامج XOScript، احفظ البرنامج في ملف بإضافة اللاحقة -xo
(اختياري). وأدرج كذلك اسم ملف برنامجك
بعد أمر XOScript:

```
xo myprogram.xo
```

عندما تشغل أمر XOScript مع استخدام ملف برنامجك
معاملًا، سيقرأ xo ملف برنامجك وينفذه.

{{note}}
يمكنك أيضًا تشغيل برنامجك بسحبه إلى أيقونة xo.
{{/note}}

{{warning}}
في بعض الأنظمة تحتاج إلى منح xo مسبقًا صلاحيات تحميل المكتبات
الديناميكية.
{{/warning}}

جرى العرف على أن يكون أول برنامج في أي لغة برمجة
جديدة نوعًا من التحية للعالم. في XOScript، يبدو
برنامج **Hello world** هذا كما يلي:

@test598

عند حفظ هذا النص في ملف، مثل hello.xo، يمكن تنفيذه
كما يلي: .

xo hello.xo

Hello world


يمكنك رؤية مخرجات البرنامج في النافذة السوداء الظاهرة أعلاه.
وعلى امتداد هذا الدليل، سيُستخدم العرض المرئي نفسه لإظهار
المخرجات.

{{note}}
يُكتب مخرج بحرف O كبير في النسخة الإنجليزية (Out).
وبوجه عام تبدأ الكائنات بحرف كبير
ما لم تكن تعمل كنسخة (instance) (ليس لها طرق
خاصة بها، بل بيانات فقط). وهذا يعكس أعراف الصنف مقابل النسخة
في لغات البرمجة الأخرى.
{{/note}}


## الصياغة

XOScript لغة برمجة *كائنية* *خالصة*. وهذا يعني
أن xoscript تعدّ كل شيء كائنًا، ولذلك لا توجد
*أنواع بيانات* أخرى. هناك في الأساس ثلاثة إجراءات روتينية أساسية
في برنامج مكتوب بلغة XOScript: *الإسناد*، و*إرسال الرسائل*
و*الرد*. وتبادل الرسائل بين الكائنات هو الجزء الأساسي في
برنامج XOScript. وتُوضَّح الإجراءات الروتينية الثلاثة
أدناه:


الإجراء         | مثال
--------------- | --------
الإسناد         |  \>\> x := 1. 
رسائل أحادية    | x even?.
رسالة ثنائية    | 1 + 2.
رسالة كلمة مفتاحية | x from: 0 length: 10.
الإجابة         | <- answer.  


يقدم هذا الفصل انطباعًا عامًا عن لغة XOScript
ويصف مبادئها الأساسية. XOScript لغة صغيرة
تقوم على ثلاثة إجراءات (انظر التوضيح) تُترجَم إلى
نحو ست قواعد نحوية. وهذا كل ما يلزم لإتقان
اللغة.

لا تقلق إن لم تكن الأمور واضحة لك على الفور: فكل لبنات
البناء ستُستكشف في الفصل التالي (3) وستُكرَّر القواعد
الأساسية. أما الفصل الحالي فيُعد أساسًا مقدمة عامة
للغة. وستُشرح المبادئ الأساسية باختصار
وتُوضَّح بعدة أمثلة ذات صلة. وستُعرض أي تفاصيل
ناقصة في وقت لاحق.

تبدأ التعليقات في XOScript بالرمز \#. لذا سيُتجاهَل السطر
التالي:

```
# this is just a comment
```

## المتغيرات

لإسناد
متغير، تستخدم رمز التصريح عن المتغير: >>. يمكن أن يحتوي اسم
المتغير على جميع العلامات باستثناء: <- و:= والمسافات البيضاء
والنقاط والفواصل والنقطتين الرأسيتين وعلامات الاقتباس ⌝' '⌜ والأقواس ﴿﴾.
علاوة على ذلك، لا يمكن أن يمتد المتغير على عدة أسطر. ويرجى ملاحظة
أن المتغير لا يمكن أن يبدأ برقم أو بعلامة ناقص.

هذه أمثلة على متغيرات صالحة:

```
>> password := ⌝'Secret'⌜.
>> ♡♡♡ := 3.
>> $ := ⌝'dollar'⌜.
>> +plus := صحيح.
>> user-password := ⌝'Pssst!'⌜.
```

ومن أمثلة المتغيرات غير الصالحة:


```
>> -123 := ⌝'negative number'⌜.
>> password of user := ⌝'Classified'⌜.
>> password.of:user := ⌝'Classified'⌜.
>> ,x := 10.
```

{{note}}
لا تحتاج إلى تهريب أي حرف
(بما في ذلك علامات الاقتباس المفردة والمزدوجة وحدود
النص) في
النص الحرفي ما دام ذلك لا
يسبب غموضًا لمحلل المفردات.
{{/note}}

بعد التصريح عن متغير، يمكن استخدامه بحرية. وهذا يعني
أنه لا يلزم استخدام رمز التصريح إلا في المرة الأولى
التي تستخدم فيها المتغير (التصريح).

وبتحديد أكثر، لا يمكنك أن تبدأ عشوائيًا بإسناد قيمة إلى
متغيرك *(x := 2)*، إذ يجب أولًا التصريح عن المتغير *(\>\>
x := 2)*. ولكن بعد التصريح يُسمح لك بتغيير قيمته
دون استخدام رمز التصريح*(\>\> x := 2. x := 3.)*.

لاحظ أنه من الإلزامي إسناد قيمة إلى المتغير وقت
التصريح عنه. وعلى خلاف لغات البرمجة الأخرى، لا يُسمح لك
بالتصريح عن متغير دون قيمة. فمن الضروري ربط
كل متغير صراحةً بقيمة ابتدائية. ومع ذلك، لا تتردد في تهيئة
المتغير بالكائن **لاشيء**. وفي هذه الحالة يمكن
اعتبار المتغير فارغًا *(\>\> x := لاشيء.)*. باختصار، لا يُسمح بالتصريح عن
متغير دون قيمة ابتدائية. لذا فإن

```
>> x.
```

غير صالح وسيعطي رسالة خطأ.

{{note}}
تستخدم xoscript النطاق الديناميكي للمتغيرات،
وللتفاصيل راجع فصل الدوال.
{{/note}}


## القيم الحرفية

تعدّ XOScript كل شيء كائنًا؛ أي جميع الأعداد والنصوص
وأجزاء الشفرة. فالأعداد مثل 1 و2 و100 و-999 و1,234 هي
كائنات من نوع عدد. وكل النصوص الواقعة بين علامتي اقتباس مفردتين هي كائنات
نص. وكل أجزاء الشفرة المجمّعة بين أقواس معقوصة ⎬...⎨ هي
كائنات دالة.

القيمة الحرفية  | الكائن الجذر | مثال
--------------- | ------------ | ----------
الأعداد         | عدد          | 1,2,3... 
النصوص          | نص           | ⌝'hello'⌜
الدالة          | دالة         | ⎬ 1 + 2. ⎨.
                
     
الكائنات مثل الأعداد والنصوص تجد أصلها دائمًا في كائن
جذر. فعلى سبيل المثال، كل الأعداد مشتقة من الكائن **عدد**. وكل
النصوص مشتقة من **نص** وكل أجزاء الشفرة من **دالة**. وبدورها،
تنحدر كل هذه الكائنات من **كائن**، وهو في الحقيقة
الكائن الجذر لجميع الكائنات.


## الرسائل

البرمجة في XOScript تعني في الأساس
إرسال الرسائل إلى الكائنات. والصيغة العامة لإرسال رسالة إلى
كائن هي كما يلي:

```
<object> <message>
```

لمعرفة ما إذا كان العدد **2** مثلًا عددًا زوجيًا، تُرسَل
الرسالة **زوجي?** إلى الكائن **2**:

```
2 زوجي?
```

ستكون الإجابة **صحيح** (وهو كائن مرة أخرى). والرسائل غير المعروفة
تتجاهلها الكائنات عادةً؛ لذا لن يقع أي خطأ. وبعض الكائنات (مثل
الأعداد أو النصوص) تستجيب للرسالة غير المعروفة بطريقة محددة مسبقًا
(المزيد عن هذا الموضوع لاحقًا).

يمكن للكائن أن يستقبل ثلاثة أنواع من الرسائل.

النوع           | عدد المعطيات
--------------- | -------------------
أحادية          | 0      
ثنائية          | 1     
كلمة مفتاحية    | 1+    


أولًا، هناك **الرسائل
الأحادية**، انظر المثال أعلاه، وهي بلا معطيات. ثانيًا،
هناك **رسائل الكلمات المفتاحية**، ولها معطى واحد أو أكثر،
على سبيل المثال:

```
>> x := عدد بين: 1 وبين: 10.
```

في هذه الحالة تُرسَل الرسالة **بين:وبين:** إلى **عدد**، وهو
الكائن الجذر لجميع الأعداد. وستكون النتيجة عددًا عشوائيًا
بين 1 و10. وأخيرًا، هناك **الرسائل الثنائية**، التي تتكون
من حرف واحد ومعطى واحد فقط:

```
2 + 3
```

يبدو هذا كعملية جمع رياضية، لكنه في الحقيقة مجرد رسالة أخرى. تُرسَل
الرسالة **+** إلى **2**، مع المعطى **3**، فتعيد
الإجابة **5**. ويُسمح بكتابة الرسائل الثنائية دون نقطتين رأسيتين.

يمكن تسلسل الرسائل الثنائية:

```
>> x := 3 + 2 - 1.
```

في هذا الجزء تُرسَل **+ 2** أولًا إلى الكائن **عدد** **3**، مما
ينتج الكائن عدد **5**، ثم تُرسَل **-1** إلى هذا
العدد. ومحق القراء المنتبهون في ملاحظة التعارض الذي
يُظهره هذا البروتوكول مع الترتيب الرياضي التقليدي
للعوامل. فـ XOScript تتجاهل الترتيب الرياضي لصالح
الاتساق في نظام رسائلها. ونتيجة لذلك، فإن العملية:

```
2 + 3 * 5 = 25
```

وليس 17.

وهذا مقصود في التصميم. ويمكن استخدام الأقواس لتعديل ترتيب التنفيذ:

```
2 + ﴿3 * 5﴾ = 17
```

تعيد معظم الكائنات نفسها نتيجةً استجابةً لرسالة
معينة. وهذا مفيد لأنه يشجع على مواصلة الحوار مع هذا
الكائن بإرسال رسالة لاحقة إليه:

```
مخرج اكتب:
⌝' hello '⌜ تشذيب حروف-كبيرة.
```

```
HELLO
```

هنا تُرسَل رسالتان إلى الكائن **نص**: **تشذيب**، تليها
**حروف-كبيرة**.

في الجزء التالي، استخدام الفاصلة ضروري للإشارة
إلى أن رسالة جديدة قادمة. وإلا ستلتبس الأمور على XOScript.

```
مخرج اكتب: ⌝'Hello!'⌜, سطر-جديد.
```

أولًا، تُرسَل الرسالة **اكتب:** إلى رمز القلم تليها
**سطر-جديد**. ودون الفاصلة، ستظن XOScript أنك تريد إرسال
**سطر-جديد** إلى **النص** **Hello!**، وهو جهد عقيم.

ترتيب معالجة الرسائل كما يلي: من اليسار إلى اليمين؛
ابدأ بالرسائل الواقعة بين الأقواس، تليها الرسائل الأحادية. ثم
الرسائل الثنائية، وانتهِ برسائل الكلمات المفتاحية. انظر المثال
أدناه:

```
مخرج اكتب: 0.5 تقريب + ﴿2 - 1﴾, سطر-جديد.
```

تقرأ XOScript دائمًا من اليسار إلى اليمين: أولًا تُرسَل الرسالة **اكتب:**
إلى مخرج وتليها الرسالة **سطر-جديد**. وداخل
المعطى نفسه، تقرأ XOScript من اليسار إلى اليمين، لذا **0.5 تقريب**
ثم **+**.

{{note}}
تضيف رسالة سطر-جديد حرف السطر الجديد إلى النص.
واسم هذه الرسالة في الإنجليزية (stop) مستوحى من أنظمة التلغراف.
فالرسائل في أنظمة التلغراف
كثيرًا ما استخدمت كلمة STOP لتحديد نهاية الجملة
(لأن علامات الترقيم كانت غير موثوقة أو مكلفة).
{{/note}}

علاوة على ذلك، تتقدم **تقريب** على **+**، لأنها
**رسالة أحادية**. وبسبب الأقواس، تُحسب **2 - 1**
أولًا، ثم تُضاف **1** إلى نتيجة **0.5 تقريب** (1).

ستعطي العملية كلها النتيجة **2**، وهي أيضًا الإجابة
المكتوبة. وبعد الفاصلة تأتي رسالة سطر-جديد، التي تنقل المؤشر
إلى سطر جديد. وبالطبع، أفضل طريقة لفهم ترتيب
تنفيذ برامج XOScript فهمًا تامًا هي الممارسة.

ومن الجدير بالذكر أن المسافات البيضاء في XOScript، على خلاف كثير من
لغات البرمجة الأخرى، جزء أساسي من صياغتها. وعلى وجه
الخصوص في الرسائل الثنائية، قد تسبب المسافات البيضاء بعض
الالتباس. استخدم دائمًا مسافة بيضاء بعد الرسالة الثنائية. فلا يمكنك
إلصاق عدد بالرسالة مباشرة، على سبيل المثال:

```
3 + 2
```

يختلف عن

```
3 +2
```

المثال الأول (**3 + 2**) يرسل
الرسالة **+** إلى العدد **3**، مع العدد **2** معطًى. وستكون
النتيجة في هذه الحالة **5**. وفي المثال الثاني (**3 +2**)،
تُرسَل الرسالة الأحادية **+2** إلى العدد **3**. وبحسب
السياق قد ينتج عن ذلك نتيجة مختلفة جدًا.

إرسال رسالة إلى كائن يستدعي الدالة التي
أُلحقت بهذا الكائن تحت اسم تلك الرسالة. فإذا أرسلت رسالة

ويسمى هذا تمرير الرسائل المتسامح.

مثال:

```

لن يعطي هذا خطأ. بل سيطبع ببساطة النص **كائن**.

```

⎨.

Animal عند: ⌝'هيئ'⌜ نفذ: ⎬
	خاص sound := ⌝'?'⌜.
	خاص legs  := 4.
⎨.
```

في جزء الشفرة أعلاه، ننشئ كائنًا يسمى Animal.

مثل الكلاب والقطط. ويُكتب الكائن الأب Animal
بحرف A كبير للدلالة على أنه كائن شبيه بالأصناف.

init. ولأن xoscript تمنع الاستدعاء الذاتي افتراضيًا فلن يسبب ذلك
حلقة لا نهائية. بل سترسل الرسالة جديد إلى الكائن
الأب (كائن) مما ينتج نسخة جديدة من Animal. وهكذا ننشئ
كائنًا جديدًا، مبنيًا على الكائن نفسه الذي أنشأنا له طريقة جديد.

# الكائن لاشيء

{{messages}}

يمثل الكائن لاشيء
الفراغ، أو بالأحرى غياب المعلومات. وقد
تتلقى هذا الكائن أحيانًا إجابةً عن رسالة، في
حال كانت النتيجة **لا شيء**. وأهم سؤال
يمكنك طرحه على الكائن **لاشيء** هو: **لاشيء?**. وستكون
الإجابة دائمًا **صحيح**.

```
مخرج اكتب: لاشيء لاشيء?.
```

النتيجة:

```
صحيح
```

أي كائن غير **لاشيء** سيجيب بـ **خطأ**. قد يبدو
جزء الشفرة أعلاه فلسفيًا بعض الشيء، لكن للكائن **لاشيء**
تطبيقات عملية للغاية بالتأكيد. فعلى سبيل المثال،
ستتلقى الكائن لاشيء إجابةً إذا طلبت
عنصرًا من قائمة غير موجود. ويمكنك أيضًا استخدام الكائن لاشيء
إذا أردت التصريح عن متغير دون أن تحدد له قيمة
بعد. فبدلًا من ذلك، ما عليك إلا **إسناد** القيمة الخاصة **لاشيء**. ففي
XOScript لا يُسمح بالتصريح عن متغير دون قيمة، مثل:


```
>> قيمة.
```

بل عليك أن تكتب ما يلي:

```
>> قيمة := لاشيء.
```

# القيم المنطقية

{{messages}}

على خلاف معظم لغات البرمجة الشائعة وقت كتابة هذا الدليل،
توفر XOScript كائن صحيح واحدًا فقط وكائن خطأ
واحدًا فقط. وللتوضيح، في كل مرة تكتب فيها **صحيح** فهذا لا يعني
إنشاء كائن جديد. بل تستخدم دائمًا مرجعًا. وهذا
يعني أنك عندما تكتب ما يلي:

\>\> x := True.

يشير **x** إلى الكائن **صحيح**. وتتحقق الشفرة الشرطية والحلقات
أيضًا من هذا المرجع. وفي XOScript، معنى **صحيح** و**خطأ**
ليس ثابتًا. بل في الحقيقة، يضطرب برنامج XOScript اضطرابًا شديدًا من
عبارة كهذه:

True := False.

نتيجة مثل هذه الأفعال غير معرَّفة، لكنها تبقى فعلًا صالحًا
ولذلك مسموحًا به رسميًا. علاوة على ذلك، يوجد كائن
منطقي، وهو الكائن الجذر لكل من **صحيح** و**خطأ**، إذ إن كليهما
مشتقان من هذا الكائن الجذر. غير أن الكائن المنطقي نفسه
لا يقدم أي تطبيق عملي.

## مزالق

احذر عند استخدام **و:** و**أو:**

```
مخرج اكتب: ﴿خطأ or: صحيح or: صحيح﴾, سطر-جديد.
مخرج اكتب: ﴿خطأ أو: صحيح, أو: صحيح﴾, سطر-جديد.
```

ينتج

```
خطأ
صحيح
```
لأن الرسالة **أو:** لا تأخذ إلا معطًى واحدًا. فالسطر الأول
يرسل **أو:أو:** إلى خطأ، وهي غير موجودة، لذا يتجاهل الكائن
الرسالة ويعيد نفسه (خطأ). ومن ناحية أخرى، يرسل السطر الثاني
**أو:** تليها **أو:** أخرى (باستخدام رمز التسلسل، أي الفاصلة: ,).

```

وانظر أيضًا الأمثلة أدناه.
بسبب البنية البسيطة، لا يمكن أن يكون للدالة إلا
نقطة إرجاع واحدة. ولتجنب العبء الزائد أو التداخل المفرط في
الشروط، يمكنك استخدام إجراء (وهو مماثل لاستخدام
علامة الضرب مع المعطى 1):

```
⎬
  ﴿a = 1﴾ إذا-صحيح: ⎬ x := 1. ⎨, اخرج.
  ﴿a = 2﴾ إذا-صحيح: ⎬ x := 2. ⎨, اخرج.
⎨ إجراء.
```

بهذه الطريقة، لن يُقيَّم (a = 2) إذا كانت a = 1.
كما أنك لا تحتاج بهذه الطريقة إلى رسائل إذا-صحيح متداخلة.
كلما وجدت نفسك تضع شروطًا متداخلة، ففكر
في رسالة إجراء. فقد تجعل شفرتك
أسهل قراءة.


إليك مزلقًا مهمًا:

```
⎬
	خطأ إذا-خطأ: ⎬
		مخرج اكتب: ⌝'End the loop.'⌜.
	⎨, اخرج.
	
	مخرج اكتب: ⌝'Dont show me.'⌜.

⎨ إجراء.

```

في هذه الحالة، سيُعرض النص 'Dont show me'.
لأن **اخرج** تُرسَل إلى خطأ. فإذا أردت تنفيذ
خروج، فيجب إرسالها رسالةً إلى **صحيح**.
 

```
⎬
	خطأ نفي إذا-صحيح: ⎬
		مخرج اكتب: ⌝'End the loop.'⌜.
	⎨, اخرج.
	
	مخرج اكتب: ⌝'Dont show me.'⌜.

⎨ إجراء.

```

سيعمل كما هو متوقع.

## حقن القيم

توفر XOScript للمهام خيار حقن القيم. والآن، ألقِ نظرة

```
>> sending := ⎬
	Newsletter إلى: خاص recipient.
⎨.
sending عين: ⌝'recipient'⌜
قيمة: ⌝'info@recipient.org'⌜.
sending شغل.
```


يعرض هذا التوضيح مهمة متخيلة، ترسل نشرة إخبارية
إلى عنوان بريد إلكتروني أو **recipient**. ويمكن حقن هذا المستلم
في المهمة، من الخارج وقبل بدء المهمة، بإرسال
الرسالة **عين:قيمة:** إلى المهمة. وبذلك تُضبط قيمة
**recipient** مسبقًا في المهمة. ويمكن أيضًا تعديل هذه القيمة
ثم تشغيل المهمة مرة أخرى. وهذه طريقة مفيدة عند استخدام
كائنات المهام.

## الدوال الفارغة

المهام الفارغة غير مسموح بها. نظريًا ستبدو المهمة الفارغة
هكذا: **⎬⎨**، لكن XOScript تعدّ ذلك خطأ لغويًا. فإذا
أردت التصريح عن مهمة فارغة، يمكنك استخدام الكائن لاشيء:

```
>> task := لاشيء.
```

ومع أن هذه ليست مهمة حقيقية، بل كائن لاشيء، فلا يزال
بالإمكان إرسال رسالة شغل:

```
>> answer := task شغل.
```

وهذا في الحقيقة مماثل لما يلي:

```
>> answer := لاشيء شغل.
```

لأن الكائن **لاشيء** لا يتعرف على الرسالة **شغل**، فإنه
سيعيد نفسه إجابةً، فتبقى الإجابة مرة أخرى **لاشيء**.
لذا لا ضرورة لوجود مهمة فارغة. وبفضل التصميم
الأنيق للغة البرمجة XOScript، يمكنك ببساطة استخدام الكائن
لاشيء لهذا الغرض.

# القوائم

{{messages}}

تعرف XOScript نوعين من المجموعات: *القوائم* و*القواميس*.
**القوائم** تعدادات لكائنات في *ترتيب ثابت*. أما القواميس فليس لها
ترتيب، بل تشبه مسردًا يتضمن مفتاحًا (أو مصطلحًا) و
القيمة المقابلة له. وتشبه القوائم المصفوفات (PHP وJava وC)
والقوائم (Python). وتشبه القواميس المصفوفات الترابطية (PHP) أو
القواميس (Python) في لغات البرمجة الأخرى. ولإنشاء
قائمة جديدة اكتب:

```
>> fibonacci := قائمة جديد.
```

يمكن ملء هذه القوائم الفارغة باستخدام **ألحق:** :

```
fibonacci ألحق: 0.
fibonacci ألحق: 1.
fibonacci ألحق: 1.
fibonacci ألحق: 2.
fibonacci ألحق: 3.
fibonacci ألحق: 5.
fibonacci ألحق: 8.
fibonacci ألحق: 13.
```

إذا كتبنا القائمة على الشاشة:

```
مخرج اكتب: fibonacci, سطر-جديد.
```

فسنرى:

```
قائمة ← 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13
```

بدلًا من ألحق يمكنك أيضًا استخدام ; لإضافة عناصر إلى قائمة:


```
>> fibonacci := قائمة جديد ; 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13.
```

الفواصل المنقوطة (;) كلها رسائل ثنائية تضع
قيمة في القائمة.

## التسلسل

لنفترض أن لديك قائمة مثل:

```
>> x := قائمة جديد ; 1 ; 2 ; 3.
```

إذا أردت حذف العنصر الأول والعنصر الأخير، فستكون
رسالتك:

```
x اسحب-الأول اسحب-الأخير.
```

للأسف، لن تعمل الصيغة السابقة على نحو صحيح. فالرسالة
**اسحب-الأول** تعيد العنصر الأول من القائمة، الذي
يصبح بدوره مستقبِل الرسالة **اسحب-الأخير**. لذا فإن
الرسالة **اسحب-الأخير** لا تُرسَل إلى **x**، بل إلى 2. ومن
الحلول الممكنة لهذه المشكلة إنشاء جملتين
منفصلتين، مثل:

```
x اسحب-الأول.
x اسحب-الأخير.
```

لكن هذا غير عملي إلى حد ما، ولا سيما عندما تحتاج إلى
حذف أكثر من عنصرين. لذلك توفر XOScript
بنية رسائل بديلة لمثل هذه المواقف. ففي
بنى الرسائل **البديلة**، تُتجاهَل إجابات الكائنات
وتحصل على الكائن المستقبِل إجابةً، مرة بعد مرة.
وتبدأ بنية الرسائل **البديلة** بإرسال
الرسالة **ابدأ-التتابع** إلى كائن، ويمكن إنهاء بنية الرسائل
**البديلة** بإرسال الرسالة **انتهى-التتابع**. وفي
المثال الموضح، يمكن تطبيق ذلك كما يلي:

```
>> x := قائمة جديد ; 1 ; 2 ; 3.
x ابدأ-التتابع اسحب-الأول اسحب-الأخير انتهى-التتابع.
```

# القواميس

{{messages}}

**كل من القائمة والقاموس مجموعتان. ولكن على خلاف
القائمة، **ليس للقاموس** ترتيب. ومن الفروق الأخرى بينهما
أن القاموس يتكون من أزواج من الكائنات. فأحد الكائنين يعمل مدخلًا (أو
كلمة مفتاحية) للبحث عن الكائن الآخر. ومن الأمثلة الجيدة على
القائمة قائمة الأسعار، مثل:


```
>> menu := قاموس جديد
	ضع: ⌝'£5'⌜ عند: ⌝'apple pie'⌜,
	ضع: ⌝'£6'⌜ عند: ⌝'carrot cake'⌜,
	ضع: ⌝'£3'⌜ عند: ⌝'fudge'⌜.
```

كما في القائمة، تُستخدم الرسالة ضع:عند:
لإضافة كائن إلى قائمة. والفرق أنه، على خلاف
القائمة، يُربط كائنان. فالكائن الأول، كما في
القائمة، هو الكائن الذي ستخزنه في القائمة. أما الكائن
الثاني فليس موضعه داخل المجموعة، بل **المدخل**
الذي يتيح استرجاع الكائن السابق في وقت لاحق. وباختصار،
يعمل القاموس قليلًا مثل المعجم؛ فباستخدام الكلمة المفتاحية
يمكن إيجاد المعنى. على سبيل المثال، لاسترجاع سعر الحلوى (fudge) من
القائمة المذكورة أعلاه:

```
>> price := menu في: ⌝'fudge'⌜.
```

يمكنك أيضًا استخدام الصيغة المختصرة:

```
>> price := menu ? ⌝'fudge'⌜.
```

إذا كانت المدخلات التي تستخدمها لتخزين الكائنات خالية من المسافات
(ولا تتعارض مع رسائل أخرى معرَّفة مسبقًا)،
فيمكن أيضًا استخدام الصيغة التالية:

```
>> menu := قاموس جديد
	pie:   ⌝'£5'⌜,
	cake:  ⌝'£6'⌜,
	fudge: ⌝'£3'⌜.
```

لا شك أن الصيغة أعلاه تُقرأ على نحو أكثر طبيعية قليلًا.
ولطلب سعر
الحلوى، يمكن استخدام الصيغة المبسطة التالية:

```
>> price := menu fudge.
```

# البرنامج/المخرج القياسي

{{messages}}

يمثل الكائن برنامج التطبيق قيد التشغيل حاليًا. ويوفر هذا الكائن

## المخرج القياسي

مخرج هو كائن المخرج القياسي. وله في الأساس طريقتان:
**اكتب:** و**سطر-جديد**. تُستخدم الرسالة اكتب: لإرسال نص
إلى stdout، وتطبع الرسالة سطر-جديد حرف سطر جديد.
وبدلًا من **سطر-جديد** يمكنك أيضًا استخدام \\n.

مثال:

```
مخرج اكتب: ⌝'Hello World'⌜, سطر-جديد.
```

النتيجة:

```
Hello World
```

## الوحدات/الإضافات

يمكن توسيع عالم XOScript بكائنات نظام جديدة، عبر
تثبيت الوحدات. ويمكن إضافة كائن نظام جديد إلى عالم
XOScript بوضع ملف الوحدة (عادةً ملف ذو اللاحقة .so)
في مجلد mods.

عندما ترسل رسالة إلى الكائن الذي تتيحه
وحدة الإضافة، ستحمّله XOScript تلقائيًا.

يمكنك أيضًا كتابة الإضافات بنفسك. وتُكتب الإضافات بلغة
البرمجة C. ويمكنك إيجاد إضافة نموذجية في حزمة الشفرة
المصدرية تحت src/plugins/example.


## الانعكاس

هناك طرق متنوعة لاستكشاف
النظام أثناء تنفيذ البرنامج. وتملك XOScript بضع طرق
لاكتشاف الكائنات الموجودة والرسائل التي تستجيب لها هذه
الكائنات. أولًا، يمكن سؤال كل كائن عن **نوع**ه،
غير أن الأنواع في XOScript قابلة للتشكيل ولذلك غير موثوقة.

```
برنامج Tool إذا-صحيح: ⎬ ... ⎨.
```

يتكون من رمز واحد فقط، يُستحسن استخدام

```

```

## الجلسات

للاستمرارية يمكنك تخزين البيانات وجلبها من كائن جلسة.
أنشئ أولًا **مستند-ويب** جديدًا. يربط الكائن مستند-ويب
بين الطلب والترويسات وHTML والجلسة. والسبب أنك كلما
زرت موقع ويب بمتصفحك، لا ترى إلا HTML. لكن
مستند-ويب الكامل يتكون من **الترويسات** أيضًا. فعلى سبيل المثال،
تتضمن معظم استجابات HTTP ترويسة مثل: Content-type:text/html
لإخبار المتصفح بأن البيانات التالية ينبغي عرضها بصيغة HTML
(لا تنزيلها كملف مثلًا). والجلسات طريقة
لتخزين بيانات المستخدم بين الطلبات. ولتتبع هذه البيانات نحتاج
إلى ضبط ملف تعريف ارتباط (cookie)، ويُضبط هذا الملف أيضًا عبر ترويسة.
ولهذا يجتمع كل شيء في مستند-ويب (لأنه المستند
الكامل الذي يحتوي على الترويسات وHTML أو غيرها من البيانات).


```
# First we make a new Web Document instance
>> web := مستند-ويب جديد.

# Now we start a session, this will generate a Header for a cookie and
# create a file to store your data, associated with that cookie
>> session := web ابدأ-الجلسة.

# Now we can treat session like a dict
session userid: 123.
```

لتدمير الجلسة (عند تسجيل الخروج):

```

```

المناطق المحددة بعلامات القص ويمكنك لصقها في

علامات الخانات.

# ffi

{{messages}}

يُوفَّر FFI على أساس كل منصة أو إضافة لأنه
يرتبط بمعمارية النظام الأساسي، وهو أمر
لا يُفترض أن يفعله الجوهر.
وتوفر إضافة الخادم تنفيذًا متوافقًا لـ ffi/blob.
افتراضيًا يتصل الجوهر بالمنصة المستهدفة
عبر stdin/stdout وخدمات محدودة لإدخال/إخراج الملفات والصدفة (Program os).
ويُوفَّر التكامل الإضافي عبر ffi/blobs من خلال إضافات
متمحورة حول التطبيقات مثل إضافة الخادم.

FFI اختصار لـ Foreign Function Interface (واجهة الدوال الأجنبية). وهي تتيح لك استخدام وظائف كتبها آخرون بلغات
برمجة مختلفة، وتُوفَّر عبر ملفات DLL أو ملفات SO أو ملفات Dylib. وقد تكون هذه
دوال متنوعة، وهناك نطاق واسع من الوظائف المتاحة بهذه الطريقة.
لنبدأ بمثال:

```
Server اربط: ﴿
 قائمة جديد ;
 ⌝'/usr/lib/x86_64-linux-gnu/libc.so.6'⌜ ;
 ⌝'printf'⌜ ;
 ﴿ قائمة جديد ; ⌝'pointer'⌜ ; ⌝'int'⌜ ﴾ ;
 ⌝'void'⌜ ;
 ⌝'Printf'⌜ ;
 ⌝'template:number:'⌜
﴾.
>> s := Blob utf8: ⌝'FFI has %d letters.\n'⌜.
Printf template: s number: 3.
s حرر.
```

نتيجة هذه الشفرة أنك سترى ما يلي في سطر الأوامر:
FFI has 3 letters.
والآن، ربما تفكر: "هذه شفرة كثيرة لشيء بهذه البساطة."
أعني، ألم يكن بوسعنا حل هذا بأمر Gui show؟ والجواب نعم بكل تأكيد!
لكن هذا مقصود كمثال توضيحي.
يُستخدم FFI عادةً لمهام أكثر تعقيدًا، لكنها لا تصلح
أمثلة جيدة، لذا اخترت شيئًا بسيطًا.

معطيات طريقة الربط:

- المعطى #1: ملف DLL أو SO الذي تريد استخدامه.
- المعطى #2: الدالة الموجودة في ذلك الملف التي تريد ربطها.
- المعطى #3: قائمة بأسماء أنواع بيانات معطيات الدالة.
- المعطى #4: اسم نوع القيمة المعادة من الدالة.
- المعطى #5: اسم الكائن الذي تريد ربط هذه الدالة به (إن لم يكن موجودًا فسيُنشأ
تلقائيًا).
- المعطى #6: الرسالة التي ينبغي ربط هذه الدالة بها.

في المثال أعلاه، نريد ربط الدالة printf من libc.so. ويمكنك إيجاد أسماء
أنواع البيانات في توثيق البرنامج الذي تربط به. والأنواع المتاحة هي:
void وpointer وfloat وdouble وint وuint وchar وuchar وintX وuintX،
حيث يمكن أن تكون X هي 8 أو 16 أو 32 أو 64.

تشير هذه الأنواع إلى عدد البايتات اللازمة لتخزين البيانات. وبالنسبة إلى printf، فإننا نربط بكائن
جديد يسمى Printf وبالرسالة template:number:. فأنت تترجم الدالة الخارجية
إلى لهجة XOScript قبل استخدامها. وتتوقع الرسالة template:number:
مخزنًا مؤقتًا يحتوي على نص القالب معاملًا أول. وننشئ هذا المخزن باستخدام كائن Blob، الذي
يتيح لك تخصيص الذاكرة يدويًا. وأنت مسؤول عن تحرير هذه الذاكرة بعد ذلك
بالرسالة حرر.

يمكنك ملء كتلة ذاكرة blob بطرق متنوعة. وفي مثالنا نملؤها بنص، لذا نستخدم
الرسالة utf8: (UTF-8 ترميز لتحويل النص إلى بايتات). ويمكنك أيضًا ملء blob بالرسالة
بايتات:، مع تمرير قائمة بقيم البايتات. ولقراءة محتويات blob، استخدم بداية:طول:.
وستحصل على البايتات قائمةً. بل يمكنك إنشاء C-struct باستخدام Blob عبر
الرسالة struct:، مع تمرير تسلسل من أنواع C. وقد يلزم ذلك عند استدعاء دالة C
في مكتبة برمجية خارجية تتوقع مؤشرًا إلى struct.

{warning}
عليك تحرير كائنات blob بنفسك.
فجامع المهملات لا يمسح كائنات blob.
{/warning}

بما أن كائنات blob يمكن تبادلها مع دوال خارجية من المكتبات، فإنها
لا يمكن جمعها تلقائيًا بجامع المهملات (فقد تبقى قيد الاستخدام من قبل
دوال خارجية أو قد ترغب هذه الدوال الخارجية في تحريرها
بنفسها). لذلك عليك تحرير كائنات blob بنفسك عند الحاجة.

لتحرير blob استخدم:

```
myblob حرر.
```

لتحرير struct استخدم:

```
mystruct حرر-struct حرر.
```

لذا بالنسبة إلى struct، تحتاج إلى إرسال رسالتين: حرر-struct وحرر
لإلغاء تخصيص كتلة الذاكرة.
