ยินดีต้อนรับสู่ XOScript
โครงการ XOScript มีเป้าหมายเพื่อสร้างภาษาสคริปต์ที่เรียบง่ายและตรวจสอบได้
เรียบง่ายไม่ได้แปลว่าง่ายเสมอไป
ภาษาโปรแกรมที่คุ้นเคยอาจใช้งานง่ายกว่า XOScript
ในที่นี้ ความเรียบง่ายมีความหมายต่างออกไป
คือการสามารถสร้างแบบจำลองทางความคิดของภาษาและพฤติกรรมของมันได้ครบถ้วน

XOScript ถูกออกแบบมาให้จำได้ทั้งหมดในหัว
ไวยากรณ์และจำนวนแนวคิดของมันถูกจำกัดให้น้อยโดยเจตนา
ไม่มีคลาส ออบเจกต์สามารถขยายได้โดยตรง
ออบเจกต์ถูกส่งผ่านโดยการอ้างอิง การคัดลอกต้องทำอย่างชัดแจ้ง
และฟังก์ชันมีจุดออกเพียงจุดเดียว

ทางเลือกบางอย่างเหล่านี้แตกต่างจากภาษากระแสหลักอย่างมาก
ตัวอย่างเช่น XOScript ไม่มีระบบชนิดข้อมูล และใช้ขอบเขตตัวแปรแบบไดนามิก
ข้อความที่ไม่สามารถจัดการได้จะถูกละเว้นแทนที่จะเกิดข้อยกเว้น
ทางเลือกเหล่านี้มีผลตามมา และไม่ได้มีไว้เพื่อขจัดข้อผิดพลาด
แต่มีไว้เพื่อรักษาแบบจำลองพื้นฐานของภาษาให้เล็กและสอดคล้องกัน

XOScript ยังสามารถแปลเป็นภาษาท้องถิ่นได้ ทำให้สามารถเขียนกฎทางธุรกิจ
เป็นภาษาธรรมชาติ และอาจแบ่งปันให้ผู้มีส่วนได้ส่วนเสียที่ไม่ใช่สายเทคนิคได้

ความสามารถในการตรวจสอบได้หมายถึงการนำปรัชญาเดียวกันไปใช้กับการพัฒนาตัวภาษา
รันไทม์เขียนด้วยภาษา C มีตัววิเคราะห์ศัพท์ (lexer) ตัวแยกวิเคราะห์ (parser) และตัวเดินต้นไม้ (tree walker) ขนาดเล็กที่เขียนด้วยมือ
ไลบรารีมาตรฐานและรันไทม์ส่วนใหญ่สะท้อนโครงสร้างของภาษา
ทำให้ความสัมพันธ์ระหว่างโค้ด XOScript กับการพัฒนาตัวภาษาค่อนข้างตรงไปตรงมา

การทดสอบยังเชื่อมโยงอย่างใกล้ชิดกับเอกสารประกอบด้วย
แต่ละเมธอดควรมีการทดสอบที่เกี่ยวข้องซึ่งสามารถรวมเข้าไว้ในคู่มือได้
ช่วยให้เอกสารประกอบสอดคล้องกับการพัฒนาตัวภาษาอยู่เสมอ

XOScript ไม่ได้มีเป้าหมายเพื่อแข่งขันกับภาษากระแสหลักในด้าน
ความสามารถหรือความคุ้นเคย แต่สำรวจเป้าหมายที่ต่างออกไป
นั่นคือสภาพแวดล้อมการเขียนโปรแกรมที่นักพัฒนาสามารถเข้าใจได้ทั้งหมด

ความหวังคือภาษาที่เล็กและการพัฒนาตัวภาษาที่เล็ก
จะทำให้การเข้าใจซอฟต์แวร์เป็นไปได้ในทางปฏิบัติ
ตั้งแต่ไบต์จนถึงออบเจกต์ ตั้งแต่ไวยากรณ์จนถึงรันไทม์ และทำให้เขียนโค้ดได้อย่าง
มั่นใจ เพราะคุณเข้าใจทั้งสิ่งที่เกิดขึ้นใน
สคริปต์และสิ่งที่เกิดขึ้นเบื้องหลัง

สถาปัตยกรรมของการติดตั้งเซิร์ฟเวอร์ xoscript

ปลั๊กอินเซิร์ฟเวอร์ไว้ในโฟลเดอร์ชื่อ /mods/server

เหตุผลคือเราต้องการ
แยกแกนของภาษาออกจากฟังก์ชันเฉพาะของเซิร์ฟเวอร์
ซึ่งต่างจาก PHP หรือ Python เป็นต้น มิฉะนั้นเราจะต้องส่ง
ทุกสิ่งทุกอย่างไปให้ทุกคนโดยไม่มีจุดประสงค์ ซึ่งเป็นเรื่องไร้สาระ
คุณสามารถติดตั้งโมดูลอื่นๆ ได้ตามต้องการเช่นกัน ระบบนี้
ยืดหยุ่นมาก

นอกจากนี้ ฟังก์ชันบางอย่างควรพัฒนาด้วยตัวภาษาสคริปต์
เองจะดีกว่า เช่น ระบบแม่แบบและการจัดการเซสชัน ดังนั้นเราจึง
แถมไลบรารี template.xo และ webtools.xo มาให้เพื่อความสะดวกของคุณด้วย
เหตุผลของทั้งหมดนี้คือเราไม่รู้ว่าคุณต้องการ
ใช้ xoscript อย่างไร คุณสามารถใช้เป็นภาษาสคริปต์ฝั่งเซิร์ฟเวอร์
แต่ก็ใช้กับ GUI อุปกรณ์ฝังตัว หรือแค่การประมวลผลแบบกลุ่มได้เช่นกัน
แม้ว่าคุณจะใช้เป็นภาษาสคริปต์ฝั่งเซิร์ฟเวอร์ (ซึ่งเป็น
หนึ่งในกรณีการใช้งานหลักในปัจจุบัน) คุณก็อาจยังต้องการ
ใช้เอนจินแม่แบบหรือตัวจัดการเซสชันอื่น
เราเป็นใครถึงจะตัดสินว่าคุณต้องใช้ของเรา?

อย่างไรก็ตาม ข้อดีอย่างหนึ่งของการใช้เอนจินแม่แบบของเราคือ
คุณไม่ต้องเรียนรู้ไวยากรณ์เพิ่มเติมเพื่อสร้างแม่แบบ
เอนจินแม่แบบเริ่มต้นที่มาพร้อมกับ xoscript แยก
ส่วนการแสดงผลกับตรรกะออกจากกัน 100% แทนที่จะใช้ไวยากรณ์
แม่แบบพิเศษ มันใช้เพียงระบบเครื่องหมายช่องที่ยืดหยุ่นมาก
สำหรับข้อมูลเพิ่มเติม ดูบทเซิร์ฟเวอร์

โปรดทราบว่า หากคุณไม่ต้องการใช้เอนจินแม่แบบเริ่มต้นหรือ
webtools เริ่มต้น ก็เป็นที่เข้าใจได้ว่าคุณต้องจัดหา
ของคุณเอง

หากคุณรันเว็บเซิร์ฟเวอร์ใน chroot, jail หรือแซนด์บ็อกซ์ประเภทอื่น
คุณต้องติดตั้งไลบรารีที่ xo ต้องพึ่งพาในสภาพแวดล้อมนั้นด้วย คุณสามารถ
ดูว่าต้องใช้ไลบรารีใดได้โดยใช้ ldd (ดู manpage ของ Linux หรือ BSD)
หากคุณต้องการใช้คำสั่งเชลล์ในสคริปต์ xo ให้คัดลอกเชลล์
(เช่น bash หรือ ksh) ไปยังสภาพแวดล้อมนี้ด้วย

เราขอเน้นด้วยว่าเราให้ความสำคัญกับความเข้ากันได้ย้อนหลังอย่างจริงจัง
ถึงขั้นมีคุณสมบัติพิเศษเพื่อความเข้ากันได้ย้อนหลังชื่อ
'version' โดยทั่วไป เรามุ่งให้โค้ดของคุณทำงานได้ตลอดไป ดังนั้นคุณจะ
ไม่ต้องอัปเดตโค้ดเพื่อให้เข้ากันได้กับ xoscript เวอร์ชันใหม่
เป้าหมายของเราคือ เขียนครั้งเดียว ทำงานได้ตลอดไป

ส่วนที่เหลือของคู่มือนี้มุ่งอธิบายภาษาโปรแกรม
xoscript อย่างละเอียด การเขียนสคริปต์ฝั่งเซิร์ฟเวอร์จะกล่าวถึงในบท
ที่ชื่อว่าเซิร์ฟเวอร์ หากคุณเป็นนักพัฒนาซอฟต์แวร์ที่มีประสบการณ์ คุณอาจ
ต้องการข้ามบางบท เพราะบางบทมีรายละเอียดมากเกินไปหรือ
คล้ายกับแนวปฏิบัติการเขียนโปรแกรมทั่วไปมาก ดังนั้นสำหรับผู้ที่
มีประสบการณ์กับภาษาโปรแกรมอื่นหลายภาษาแล้ว
ควรใช้คู่มือนี้เป็นคู่มืออ้างอิงจะดีกว่า

## การติดตั้งบน Linux

ดาวน์โหลด apache2 และ mariadb:


```
sudo apt-get install apache2 mariadb-server
sudo a2enmod cgi
```

ดาวน์โหลด xoscript
แทนที่ X ด้วยหมายเลขเวอร์ชันที่ถูกต้อง!

```
wget https://xoscript.com/downloads/xoserver-linux-1_5_X.tar.gz
tar xvf xoserver*.tar.gz
```

คัดลอกไฟล์ไปยัง webroot และ /bin:


```
sudo cp bin/xo /bin/xo
sudo cp -R bin/mods /var/www/html/
sudo cp *.xo /var/www/html/
```

แก้ไขการตั้งค่า apache2 ของคุณ:

```
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

แทนที่ Virtualhost ด้วย:

```
<VirtualHost *:80>
    <Directory /var/www/html>
        Options +ExecCGI
        AllowOverride All
        AddHandler cgi-script .xo
        Require all granted
    </Directory>
    DocumentRoot /var/www/html
</VirtualHost>
```

สร้างหน้าทดสอบ:

```
sudo nano /var/www/html/test.xo
```

และเขียนโปรแกรมทดสอบเล็กๆ:

```
#!/bin/xo
Server เตรียม.
โปรแกรม ใช้: ['webtools.xo'].
>> เว็บ := เอกสารเว็บ สร้างใหม่.
เว็บ แสดงผล: ['Hello World'].
```

อนุญาตให้ apache2 รันโปรแกรมของคุณผ่าน CGI:

```
sudo chmod uog+x /var/www/html/test.xo
```

รีสตาร์ท apache2:

```
sudo systemctl restart apache2
```

ไปที่หน้าทดสอบของคุณในเบราว์เซอร์:

```
http://localhost/test.xo
```

คุณควรเห็น:

```
Hello World
```


## การติดตั้งบน OpenBSD

แก้ไข /etc/httpd.conf โดยเพิ่ม:


```
server "mydomain.com" {
    listen on * port 80
    root "/htdocs/mydomain/"

    location "*.xo" {
        fastcgi
        fastcgi socket "/run/slowcgi.sock"   # inside chroot
    }
}
```

หากคุณต้องการใช้ SSL:

```
listen on * tls port 443
tls {
	certificate "/etc/ssl/mycert.crt"
	key "/etc/ssl/private/mykey.key"
}
```

เพื่อป้องกันการแลกเปลี่ยนกุญแจจากคอมพิวเตอร์ควอนตัม
ให้เลือกชุดการเข้ารหัส mlkem:

```
tls {
 ... 
 ecdhe "X25519MLKEM768"
 ...
}
```

เพิ่มไบนารี xo และ mods รวมทั้งไลบรารีที่ต้องพึ่งพาทั้งหมดลงใน
chroot (ตรวจสอบด้วย ldd)

## การรันตัวอย่าง


หากต้องการรันโปรแกรมตัวอย่างโปรแกรมหนึ่งในแพ็กเกจ:

```
./example.sh <name> <Linux/OBSD> [clean]
```

ตัวอย่างเช่น การรันตัวอย่าง FizzBuzz บน Linux:

```
./example.sh fizzbuzz Linux
```

การรันตัวอย่างเดียวกันบน OpenBSD:

```
./example.sh fizzbuzz OBSD
```

การรันตัวอย่างโดยบิลด์ใหม่ทั้งหมด:

```
./example.sh fizzbuzz OBSD clean
```

## การทดสอบหน่วย

หากต้องการรันการทดสอบหน่วย:

```
./runtests.sh
```

หากต้องการรันการทดสอบหน่วยโดยไม่บิลด์ (ทดสอบอย่างเดียว):

```
./runtests.sh nobuild
```

## การบิลด์

การบิลด์จากซอร์สโค้ดบน Linux:

```
make clean
ISO="en" make
```

บน OpenBSD:

```
make -f makefile.obsd clean
ISO="en" make -f makefile.obsd
```

การบิลด์ปลั๊กอินเซิร์ฟเวอร์บน Linux:

```
PACKAGE="server" NAME="server.so" make plugin-clean
ISO="en" PACKAGE="server" NAME="server.so" make plugin
```

การบิลด์ปลั๊กอินเซิร์ฟเวอร์บน OpenBSD:

```
PACKAGE="server" NAME="server.so" make -f makefile.obsd plugin-clean
ISO="en" PACKAGE="server" NAME="server.so" make -f makefile.obsd plugin
```

## Hello world

หลังจากถ่ายโอนไฟล์มายังคอมพิวเตอร์ของคุณแล้ว คุณสามารถแตกไฟล์
และเริ่ม xo ได้ด้วยคำสั่งต่อไปนี้:

```
xo
```

หากต้องการรัน XOScript ให้บันทึกโปรแกรมเป็นไฟล์โดยเพิ่มนามสกุล -xo
(ไม่บังคับ) นอกจากนี้ ให้ใส่ชื่อไฟล์ของโปรแกรม
ต่อท้ายคำสั่ง XOScript:

```
xo myprogram.xo
```

เมื่อคุณรันคำสั่ง XOScript โดยใช้ไฟล์โปรแกรมของคุณเป็น
พารามิเตอร์ xo จะอ่านและทำงานตามไฟล์โปรแกรมของคุณ

{{note}}
คุณยังสามารถเริ่มโปรแกรมได้โดยลากไฟล์ไปวางบนไอคอนของ xo
{{/note}}

{{warning}}
ในบางระบบ คุณต้องอนุญาตให้ xo โหลดไลบรารี
แบบไดนามิกได้ก่อน
{{/warning}}

ตามธรรมเนียมแล้ว โปรแกรมแรกในภาษาโปรแกรมใหม่ใดๆ
ควรเป็นการทักทายโลก ใน XOScript โปรแกรม
**Hello world** มีหน้าตาดังนี้:

@test598

เมื่อบันทึกข้อความนี้ลงในไฟล์ เช่น hello.xo ก็สามารถรันได้
ดังนี้:

xo hello.xo

Hello world

ตลอดทั้งคู่มือนี้ จะใช้การแสดงผลแบบเดียวกันเพื่อแสดง

แสดงผล ขึ้นต้นด้วยอักษรตัวใหญ่ในภาษาต้นฉบับ (Out เขียนด้วย O ตัวใหญ่)

เว้นแต่จะทำหน้าที่เป็นอินสแตนซ์ (ไม่มีเมธอดของ
ตัวเอง มีเพียงข้อมูล) ซึ่งสะท้อนธรรมเนียมเรื่องคลาสกับอินสแตนซ์
ในภาษาโปรแกรมอื่นๆ

## ไวยากรณ์

XOScript เป็นภาษาโปรแกรม*เชิงวัตถุ*แบบ*บริสุทธิ์* หมายความว่า
xoscript มองทุกสิ่งเป็นออบเจกต์ ดังนั้นจึง
ไม่มี*ชนิดข้อมูล*อื่น โดยพื้นฐานแล้ว มีการกระทำหลักสามอย่าง
ในโปรแกรมที่เขียนด้วย XOScript ได้แก่ *การกำหนดค่า* *การส่งข้อความ*
และ*การตอบกลับ* การแลกเปลี่ยนข้อความระหว่างออบเจกต์คือหัวใจของ
โปรแกรม XOScript การกระทำทั้งสามอย่างแสดงไว้
ด้านล่าง:


การกระทำ        | ตัวอย่าง
--------------- | --------
การกำหนดค่า     |  \>\> x := 1. 
ข้อความยูนารี   | x เลขคู่?.
ข้อความไบนารี   | 1 + 2.
ข้อความคีย์เวิร์ด | x เริ่มที่: 0 ความยาว: 10.
การตอบกลับ      | <- answer.  


บทนี้จะให้ภาพรวมทั่วไปของภาษา XOScript
และอธิบายหลักการพื้นฐานของมัน XOScript เป็นภาษาขนาดเล็กที่
ตั้งอยู่บนการกระทำสามอย่าง (ดูภาพประกอบ) ซึ่งแปลงเป็น
กฎไวยากรณ์ประมาณหกข้อ เพียงเท่านี้ก็เพียงพอที่จะเชี่ยวชาญ
ภาษานี้แล้ว

ไม่ต้องกังวลหากบางสิ่งยังไม่ชัดเจนในทันที องค์ประกอบพื้นฐาน
ทั้งหมดจะถูกสำรวจในบทถัดไป (3) และกฎพื้นฐานจะ
ถูกทบทวนอีกครั้ง อย่างไรก็ตาม บทนี้ทำหน้าที่หลักเป็นบทนำ
ทั่วไปของภาษา หลักการพื้นฐานจะถูกอธิบายสั้นๆ
และแสดงด้วยตัวอย่างที่เกี่ยวข้องหลายตัวอย่าง รายละเอียดที่ขาดหายไป
จะอธิบายในภายหลัง

หมายเหตุ (comment) ใน XOScript ขึ้นต้นด้วยสัญลักษณ์ \# ดังนั้นบรรทัดต่อไปนี้
จะถูกละเว้น:

```
# นี่เป็นเพียงความคิดเห็น
```

## ตัวแปร

ในการกำหนด
ตัวแปร ให้ใช้สัญลักษณ์ประกาศตัวแปร: >> ชื่อของ
ตัวแปรสามารถมีอักขระใดก็ได้ ยกเว้น: <-, :=, ช่องว่าง,
จุด, จุลภาค, ทวิภาค, เครื่องหมายอัญประกาศ [' '] และวงเล็บ ()
นอกจากนี้ ตัวแปรไม่สามารถมีหลายบรรทัดได้ โปรดทราบ
ว่าตัวแปรไม่สามารถขึ้นต้นด้วยตัวเลขหรือเครื่องหมายลบได้

ตัวอย่างตัวแปรที่ถูกต้อง:

```
>> password := ['Secret'].
>> ♡♡♡ := 3.
>> $ := ['ดอลลาร์'].
>> +plus := จริง.
>> รหัสผ่าน-ผู้ใช้ := ['ชู่ว!'].
```

ตัวอย่างตัวแปรที่ไม่ถูกต้อง:


```
>> -123 := ['เลขติดลบ'].
>> password of ผู้ใช้ := ['ลับสุดยอด'].
>> password.of:ผู้ใช้ := ['ลับสุดยอด'].
>> ,x := 10.
```

{{note}}
คุณไม่จำเป็นต้อง escape อักขระใดๆ
(รวมถึงอัญประกาศเดี่ยว อัญประกาศคู่ และขอบเขต
ของสตริง) ใน
สตริงลิเทอรัล ตราบใดที่ไม่
ทำให้ตัววิเคราะห์ศัพท์เกิดความกำกวม
{{/note}}

หลังจากประกาศตัวแปรแล้ว ก็สามารถใช้งานได้อย่างอิสระ หมายความว่า
จำเป็นต้องใช้สัญลักษณ์ประกาศเฉพาะครั้งแรกที่
ใช้ตัวแปรเท่านั้น (การประกาศ)

กล่าวให้เจาะจงคือ คุณไม่สามารถเริ่มกำหนดค่าให้
ตัวแปรได้ตามใจ *(x := 2)* เพราะคุณต้องประกาศตัวแปรก่อน *(\>\>
x := 2)* อย่างไรก็ตาม เมื่อประกาศแล้ว คุณสามารถเปลี่ยนค่าได้
โดยไม่ต้องใช้สัญลักษณ์ประกาศ *(\>\> x := 2. x := 3.)*

โปรดทราบว่าจำเป็นต้องกำหนดค่าให้ตัวแปรในขณะ
ประกาศ ต่างจากภาษาโปรแกรมอื่นๆ คุณไม่ได้รับอนุญาต
ให้ประกาศตัวแปรโดยไม่มีค่า จำเป็นต้องผูกตัวแปรแต่ละตัว
กับค่าเริ่มต้นอย่างชัดแจ้ง อย่างไรก็ตาม คุณสามารถกำหนดค่าเริ่มต้นให้
ตัวแปรด้วยออบเจกต์ **ว่าง** ได้ ในกรณีนี้ ตัวแปรสามารถ
ถือว่าว่างเปล่า *(\>\> x := ว่าง.)* โดยสรุป การประกาศ
ตัวแปรโดยไม่มีค่าเริ่มต้นนั้นไม่ได้รับอนุญาต ดังนั้น

```
>> x.
```

ไม่ถูกต้องและจะแสดงข้อความข้อผิดพลาด

{{note}}
xoscript ใช้ขอบเขตตัวแปรแบบไดนามิก สำหรับ
รายละเอียด โปรดดูบทฟังก์ชัน
{{/note}}


## ลิเทอรัล

XOScript มองทุกสิ่งเป็นออบเจกต์ ได้แก่ ตัวเลข สตริง
และส่วนของโค้ดทั้งหมด ตัวเลข เช่น 1, 2, 100, -999 และ 1,234 เป็น
ออบเจกต์ ตัวเลข ข้อความทั้งหมดระหว่างเครื่องหมายอัญประกาศเดี่ยวเป็นออบเจกต์
ข้อความ ส่วนของโค้ดทั้งหมดที่อยู่ในวงเล็บปีกกา {...} เป็น
ออบเจกต์ ฟังก์ชัน

ลิเทอรัล        | ออบเจกต์ราก  | ตัวอย่าง
--------------- | ------------ | ----------
ตัวเลข          | ตัวเลข       | 1,2,3... 
สตริง           | ข้อความ      | \['hello'\]
ฟังก์ชัน        | ฟังก์ชัน     | { 1 + 2. }.
                
     
ออบเจกต์อย่างตัวเลขและสตริงล้วนมีต้นกำเนิดจากออบเจกต์
ราก ตัวอย่างเช่น ตัวเลขทั้งหมดสืบทอดมาจากออบเจกต์ **ตัวเลข**
สตริงทั้งหมดสืบทอดมาจาก **ข้อความ** และส่วนของโค้ดทั้งหมดมาจาก **ฟังก์ชัน**
และออบเจกต์เหล่านี้ทั้งหมดก็สืบทอดมาจาก **ออบเจกต์** อีกทอดหนึ่ง ซึ่งแท้จริงแล้วคือ
ออบเจกต์รากของออบเจกต์ทั้งหมด


## ข้อความ

การเขียนโปรแกรมใน XOScript โดยพื้นฐานแล้วคือ
การส่งข้อความไปยังออบเจกต์ รูปแบบทั่วไปของการส่งข้อความไปยัง
ออบเจกต์มีดังนี้:

```
<object> <message>
```

หากต้องการทราบว่าตัวเลข **2** เป็นเลขคู่หรือไม่ ตัวอย่างเช่น
จะส่งข้อความ **เลขคู่?** ไปยังออบเจกต์ **2**:

```
2 เลขคู่?
```

คำตอบจะเป็น **จริง** (ซึ่งเป็นออบเจกต์เช่นกัน) โดยปกติข้อความที่ไม่รู้จัก
จะถูกออบเจกต์ละเว้น จึงไม่เกิดข้อผิดพลาด ออบเจกต์บางตัว (เช่น
ตัวเลขหรือสตริง) จะตอบสนองต่อข้อความที่ไม่รู้จักในรูปแบบที่กำหนดไว้ล่วงหน้า
(จะกล่าวถึงเรื่องนี้เพิ่มเติมภายหลัง)

ออบเจกต์สามารถรับข้อความได้สามประเภท

ประเภท          | จำนวนอาร์กิวเมนต์
--------------- | -------------------
ยูนารี          | 0      
ไบนารี          | 1     
คีย์เวิร์ด      | 1+    


ประเภทแรกคือ**ข้อความ
ยูนารี** ดูตัวอย่างด้านบน ซึ่งไม่มีอาร์กิวเมนต์ ประเภทที่สอง
คือ**ข้อความคีย์เวิร์ด** ซึ่งมีอาร์กิวเมนต์หนึ่งตัวหรือหลายตัว
ตัวอย่างเช่น:

```
>> x := ตัวเลข ระหว่าง: 1 ถึง: 10.
```

ในกรณีนี้ ข้อความ **ระหว่าง:ถึง:** ถูกส่งไปยัง **ตัวเลข** ซึ่ง
เป็นออบเจกต์รากของตัวเลขทั้งหมด ผลลัพธ์จะเป็นตัวเลขสุ่ม
ระหว่าง 1 ถึง 10 ประเภทสุดท้ายคือ**ข้อความไบนารี** ซึ่งมี
อักขระเพียงตัวเดียวและอาร์กิวเมนต์หนึ่งตัว:

```
2 + 3
```

สิ่งนี้ดูเหมือนการบวกทางคณิตศาสตร์ แต่แท้จริงแล้วเป็นเพียงข้อความอีกข้อความหนึ่ง
ข้อความ **+** ถูกส่งไปยัง **2** พร้อมอาร์กิวเมนต์ **3** ซึ่งจะคืน
คำตอบ **5** ข้อความไบนารีสามารถเขียนได้โดยไม่ต้องมีทวิภาค

ข้อความไบนารีสามารถต่อกันเป็นลูกโซ่ได้:

```
>> x := 3 + 2 - 1.
```

ในส่วนของโค้ดนี้ **+ 2** ถูกส่งไปยังออบเจกต์ **ตัวเลข** **3** ก่อน ซึ่ง
ได้ผลลัพธ์เป็นออบเจกต์ ตัวเลข **5** จากนั้น **-1** จึงถูกส่งไปยัง
ตัวเลขนี้ ผู้อ่านที่ช่างสังเกตจะสังเกตเห็นความแตกต่างที่
โปรโตคอลนี้แสดงเมื่อเทียบกับลำดับความสำคัญทางคณิตศาสตร์แบบดั้งเดิมของ
ตัวดำเนินการ XOScript ละเว้นลำดับทางคณิตศาสตร์เพื่อให้
ระบบข้อความมีความสอดคล้องกัน ผลก็คือ การคำนวณ:

```
2 + 3 * 5 = 25
```

ไม่ใช่ 17

นี่เป็นการออกแบบโดยเจตนา สามารถใช้วงเล็บเพื่อเปลี่ยนลำดับได้:

```
2 + (3 * 5) = 17
```

ออบเจกต์ส่วนใหญ่จะคืนตัวเองเป็นผลลัพธ์เมื่อตอบสนองต่อ
ข้อความหนึ่งๆ ซึ่งมีประโยชน์เพราะส่งเสริมให้สื่อสารต่อกับออบเจกต์
นั้นได้โดยส่งข้อความต่อเนื่องไป:

```
แสดงผล เขียน:
[' สวัสดี '] ตัดช่องว่าง ตัวพิมพ์ใหญ่.
```

```
สวัสดี
```

ในที่นี้ มีการส่งข้อความสองข้อความไปยังออบเจกต์ **ข้อความ** ได้แก่ **ตัดช่องว่าง** ตามด้วย
**ตัวพิมพ์ใหญ่**

ในส่วนของโค้ดต่อไปนี้ จำเป็นต้องใช้จุลภาคเพื่อระบุ
ว่ามีข้อความใหม่เข้ามา มิฉะนั้น XOScript จะสับสน

```
แสดงผล เขียน: ['Hello!'], ขึ้นบรรทัดใหม่.
```

ขั้นแรก ข้อความ **เขียน:** ถูกส่งไปยังสัญลักษณ์ดินสอ ตามด้วย
**ขึ้นบรรทัดใหม่** หากไม่มีจุลภาค XOScript จะคิดว่าคุณต้องการส่ง
**ขึ้นบรรทัดใหม่** ไปยัง**ข้อความ** **Hello!** ซึ่งไร้ประโยชน์

ลำดับการประมวลผลข้อความเป็นดังนี้: จากซ้ายไปขวา
เริ่มด้วยข้อความในวงเล็บ ตามด้วยข้อความยูนารี จากนั้น
ข้อความไบนารี และจบด้วยข้อความคีย์เวิร์ด ดูตัวอย่าง
ด้านล่าง:

```
แสดงผล เขียน: 0.5 ปัดเศษ + (2 - 1), ขึ้นบรรทัดใหม่.
```

XOScript อ่านจากซ้ายไปขวาเสมอ: ขั้นแรก ข้อความ **เขียน:**
ถูกส่งไปยัง แสดงผล และตามด้วยข้อความ **ขึ้นบรรทัดใหม่** ภายใน
ตัวอาร์กิวเมนต์เอง XOScript อ่านจากซ้ายไปขวา ดังนั้นจึงเป็น **0.5 ปัดเศษ**
แล้วจึง **+**

{{note}}
ข้อความ ขึ้นบรรทัดใหม่ (stop) จะเพิ่มอักขระขึ้นบรรทัดใหม่ให้กับสตริง
ชื่อของข้อความนี้ในภาษาอังกฤษได้แรงบันดาลใจจากระบบโทรเลข
ข้อความในระบบโทรเลข
มักใช้คำว่า STOP เพื่อระบุจุดจบของประโยค
(เนื่องจากเครื่องหมายวรรคตอนไม่น่าเชื่อถือหรือมีค่าใช้จ่ายสูง)
{{/note}}

ยิ่งไปกว่านั้น **ปัดเศษ** มีลำดับความสำคัญสูงกว่า **+** เพราะเป็น
**ข้อความยูนารี** เนื่องจากมีวงเล็บ **2 - 1** จึงถูกคำนวณ
ก่อน จากนั้น **1** จะถูกบวกเข้ากับผลลัพธ์ของ **0.5 ปัดเศษ** (1)

กระบวนการทั้งหมดจะให้ผลลัพธ์เป็น **2** ซึ่งเป็นคำตอบที่ถูกเขียนออกมาด้วย
หลังจุลภาคคือข้อความ ขึ้นบรรทัดใหม่ ซึ่งย้ายเคอร์เซอร์
ไปยังบรรทัดใหม่ แน่นอนว่าวิธีที่ดีที่สุดในการเข้าใจลำดับ
ของโปรแกรม XOScript อย่างถ่องแท้คือการฝึกฝน

ควรสังเกตว่าใน XOScript ช่องว่างเป็นส่วนสำคัญของไวยากรณ์
ซึ่งต่างจากภาษาโปรแกรมอื่นๆ หลายภาษา โดยเฉพาะ
เมื่อเป็นเรื่องข้อความไบนารี ช่องว่างอาจทำให้เกิด
ความสับสนได้ ให้ใส่ช่องว่างหลังข้อความไบนารีเสมอ คุณไม่สามารถ
เขียนตัวเลขติดกับข้อความโดยตรงได้ ตัวอย่างเช่น:

```
3 + 2
```

แตกต่างจาก

```
3 +2
```

ตัวอย่างแรก (**3 + 2**) ส่ง
ข้อความ **+** ไปยังตัวเลข **3** พร้อมอาร์กิวเมนต์คือตัวเลข **2**
ผลลัพธ์ในกรณีนี้จะเป็น **5** ในตัวอย่างที่สอง (**3 +2**)
ข้อความยูนารี **+2** ถูกส่งไปยังตัวเลข **3** ขึ้นอยู่กับ
บริบท ซึ่งอาจให้ผลลัพธ์ที่แตกต่างกันมาก

## เมธอดที่ไม่มีอยู่

ผูกไว้กับออบเจกต์นี้ภายใต้ชื่อข้อความนั้น หากคุณส่งข้อความ

อาจเป็น:

```

```

หมายความว่า **number1** แทนค่า kJ และ **number2** แทน
ค่า kcal นี่คือวิธีการทำงานของการแทรกค่าในสตริงใน XOScript

อาร์กิวเมนต์:

```
>> text :=

['number1 kJ ➞ number2 kcal']

number2: 23.9.
```

ผลลัพธ์:

```

```


ในกรณีนี้ มันส่งข้อความ สร้างใหม่ ไปยัง ตัวเอง ตามด้วยข้อความ

# ออบเจกต์ ว่าง

{{messages}}

ออบเจกต์ ว่าง
แทนความว่างเปล่า หรือกล่าวให้ดีกว่านั้นคือ การไม่มีข้อมูล ในบาง
ครั้ง คุณจะได้รับออบเจกต์นี้เป็นคำตอบของข้อความ ใน
กรณีที่ผลลัพธ์คือ**ไม่มีอะไร** คำถามที่สำคัญที่สุด
ที่คุณสามารถถามออบเจกต์ **ว่าง** ได้คือ: **ว่างไหม?**
คำตอบจะเป็น **จริง** เสมอ

```
แสดงผล เขียน: ว่าง ว่างไหม?.
```

ผลลัพธ์:

```
จริง
```

ออบเจกต์อื่นใดนอกจาก **ว่าง** จะตอบกลับด้วย **เท็จ**
ส่วนของโค้ดด้านบนอาจดูเป็นปรัชญาไปบ้าง แต่ออบเจกต์ **ว่าง**
ก็มีประโยชน์ใช้สอยอย่างยิ่งในทางปฏิบัติ ตัวอย่างเช่น คุณ
จะได้รับออบเจกต์ ว่าง เป็นคำตอบเมื่อคุณขอ
สมาชิกของลิสต์ที่ไม่มีอยู่ คุณยังสามารถใช้ออบเจกต์ ว่าง
เมื่อต้องการประกาศตัวแปรแต่ยังไม่ต้องการระบุค่า
แทนที่จะทำเช่นนั้น คุณเพียง**กำหนด**ค่าพิเศษ **ว่าง** ให้ ใน
XOScript ไม่อนุญาตให้ประกาศตัวแปรโดยไม่มีค่า เช่น:


```
>> ค่า.
```

คุณต้องเขียนดังต่อไปนี้แทน:

```
>> ค่า := ว่าง.
```

ทุกครั้งที่คุณเขียนตัวเลข เช่น 9, -10 หรือ 3,12 เบื้องหลัง
XOScript จะแปลงตัวเลขเหล่านี้เป็นออบเจกต์ **ตัวเลข** คุณ
สามารถส่งข้อความไปยังออบเจกต์ ตัวเลข นี้ หรือจะกำหนดตัวเลข
ให้กับตัวแปรแล้วส่งข้อความในภายหลังก็ได้:

```
10 เลขคู่?

>> ธนบัตรสิบ := 10.
ธนบัตรสิบ เลขคู่?

```

ทั้งสองรูปแบบถูกต้อง ออบเจกต์ ตัวเลข ตอบสนองต่อ
ข้อความต่อไปนี้...

ข้อความเหล่านี้ส่วนใหญ่เข้าใจได้ในตัว และช่วยให้คุณดำเนินการ
ทางคณิตศาสตร์หรือการเปรียบเทียบได้

{{note}}
โปรดทราบว่าคุณสามารถใช้ ≤ ≥ ≠ × และ ÷ แทนอักขระ ASCII ที่เทียบเท่าได้
ขึ้นอยู่กับความชอบ
{{/note}}

ความแตกต่างระหว่างข้อความทางคณิตศาสตร์แบบไบนารี (+) และ
รูปแบบคีย์เวิร์ดของมัน (บวก:) คือแบบแรกจะคืน
ตัวเลขใหม่ซึ่งเป็นผลลัพธ์ของการดำเนินการ ในขณะที่แบบ
หลังจะแก้ไขตัวออบเจกต์เอง ดังแสดงใน
ตัวอย่างต่อไปนี้:

@test597

ในตัวอย่างด้านบน b = 4 และ a = 3 ด้วย **บวก: 2** ค่า
ของ a จะเพิ่มขึ้น 2 ในขณะที่ **+ 3** สร้างตัวเลขใหม่ที่
เท่ากับ a + 3 หลักเดียวกันนี้ใช้กับการดำเนินการทางคณิตศาสตร์อื่นๆ เช่น
การคูณ เมื่อใช้สัญลักษณ์การคูณ คุณจะได้รับ
ออบเจกต์ใหม่เป็นคำตอบ ในกรณีที่คุณใช้ข้อความ **คูณด้วย:**
คุณจะคูณตัวเลขนั้นเอง

ด้วยข้อความ **ระหว่าง:ถึง:** เช่นใน: **ตัวเลข
ระหว่าง: X ถึง: Y** คุณจะได้ตัวเลขระหว่าง X ถึง Y ด้วย
วิธีนี้ สามารถสร้างตัวเลขสุ่มใดๆ ได้:

```
>> a := ตัวเลข ระหว่าง: 1 ถึง: 10.
แสดงผล เขียน: a, ขึ้นบรรทัดใหม่.
```

ตั้งแต่เวอร์ชัน 1.4 ตัวสร้างตัวเลขสุ่มในตัวของ xoscript
ปลอดภัยในเชิงวิทยาการเข้ารหัสลับเท่าที่เราทราบ

apples** ทุกข้อความที่ตัวเลขไม่รู้จัก

โดยพื้นฐานแล้ว หน่วยคือออบเจกต์ ข้อความ ที่ถูกเก็บไว้กับออบเจกต์
ตัวเลข หน่วยจะถูกพิมพ์ต่อท้ายตัวเลขเมื่อใช้คำสั่ง

# สตริง

{{messages}}

ทุกครั้งที่วางข้อความไว้ระหว่าง**วงเล็บเหลี่ยมและเครื่องหมายอัญประกาศ** ['...']
XOScript จะสร้างออบเจกต์สตริงใหม่ให้คุณ อย่างไรก็ตาม ต้อง
แน่ใจว่าใช้เครื่องหมายอัญประกาศที่ถูกต้อง เครื่องหมายอัญประกาศที่
จุดเริ่มต้นของข้อความแตกต่างจากที่จุดสิ้นสุด (ทำให้คุณ
ใช้อัญประกาศเดี่ยวได้โดยไม่ต้อง escape)

## UTF8

สตริงใน xoscript โดยปกติจะมีข้อความที่เข้ารหัสแบบ utf8 แม้ว่า
ในทางเทคนิคจะสามารถมีเนื้อหาไบนารีหรือเนื้อหาที่ไม่ใช่ utf8 ใน
สตริงได้ แต่แนะนำให้ใช้ blob สำหรับกรณีนั้น Blob
จัดเตรียมโดยปลั๊กอินเซิร์ฟเวอร์ (ดูบท ffi)
โดยทั่วไป blob/ffi จะจัดเตรียมให้
ตามปลั๊กอิน/แพลตฟอร์ม เนื่องจากผูกติดกับแพลตฟอร์ม
และสถาปัตยกรรม (ffi/blobs) แกนของภาษาสคริปต์พยายาม
คงความเป็นอิสระจากแพลตฟอร์มให้มากที่สุด

## การแปลงชนิด

คุณสามารถสร้างสำเนาของทุกออบเจกต์
ในชนิดที่ต่างออกไปได้โดยใช้ข้อความต่อไปนี้:

ข้อความ | ผลลัพธ์

เป็นตัวเลข  | แปลงเป็นตัวเลข

เป็นบูลีน    | แปลงเป็นบูลีน
  
กฎต่อไปนี้**มีผลใช้**:

ข้อความ  | ว่าง      | บูลีน               | ตัวเลข                | ข้อความ      | อื่นๆ

# ฟังก์ชัน

{{messages}}

คุณสามารถรวมโค้ดไว้ระหว่าง { และ } แล้วมันจะกลายเป็นฟังก์ชัน
ใน xoscript บางครั้งเราก็ใช้คำว่างาน (task) หรือเรียกง่ายๆ ว่า
บล็อกของโค้ด

คุณสามารถรันฟังก์ชันได้โดยส่งข้อความ *เริ่ม*


```
{ แสดงผล เขียน: 123, ขึ้นบรรทัดใหม่. } เริ่ม.
```

หากฟังก์ชันของคุณรับอาร์กิวเมนต์ ให้ใช้ **ใช้กับ:**

```
{ :a แสดงผล เขียน: a, ขึ้นบรรทัดใหม่. } ใช้กับ: a.
```

ดูตัวอย่างด้านล่างด้วย
เนื่องจากสถาปัตยกรรมที่เรียบง่าย ฟังก์ชันจึงมีจุดคืนค่าได้
เพียงจุดเดียว เพื่อหลีกเลี่ยงภาระเพิ่มหรือการซ้อนเงื่อนไขที่มากเกินไป
คุณสามารถใช้ กระบวนงาน ได้ (ซึ่งเหมือนกับการใช้
เครื่องหมายคูณพร้อมอาร์กิวเมนต์ 1):

```
{
  (a = 1) ถ้าจริง: { x := 1. }, หยุดวน.
  (a = 2) ถ้าจริง: { x := 2. }, หยุดวน.
} กระบวนงาน.
```

ด้วยวิธีนี้ (a = 2) จะไม่ถูกประเมินหาก a = 1
และคุณไม่ต้องซ้อนข้อความ ถ้าจริง: ด้วยวิธีนี้
เมื่อใดที่คุณพบว่าตัวเองกำลังซ้อนเงื่อนไข ให้นึกถึง
ข้อความ กระบวนงาน ซึ่งอาจทำให้โค้ดของคุณ
อ่านง่ายขึ้น


นี่คือข้อควรระวังที่สำคัญ:

```
{
	เท็จ ถ้าเท็จ: {
		แสดงผล เขียน: ['จบลูป.'].
	}, หยุดวน.
	
	แสดงผล เขียน: ['อย่าแสดงฉัน.'].

} กระบวนงาน.

```

ในกรณีนี้ ข้อความ 'Dont show me' จะถูกแสดง
เพราะ **หยุดวน** ถูกส่งไปยัง เท็จ หากคุณต้องการให้
หยุดวนทำงาน ต้องส่งเป็นข้อความไปยัง **จริง**
 

```
{
	เท็จ นิเสธ ถ้าจริง: {
		แสดงผล เขียน: ['จบลูป.'].
	}, หยุดวน.
	
	แสดงผล เขียน: ['อย่าแสดงฉัน.'].

} กระบวนงาน.

```

จะทำงานตามที่คาดไว้

## ข้อยกเว้น

ข้อยกเว้นสามารถจัดการได้ดังนี้:

```
{ งานย่อย 1 } ดักจับ: { งานย่อย 2 }, เริ่ม.
```

คุณยังสามารถทำให้เกิดข้อผิดพลาดในโปรแกรมโดยเจตนาได้ และ
เมื่อทำเช่นนั้น จะเปิดใช้บล็อกตัวจัดการ ซึ่งทำได้โดยส่ง
ข้อความ **ข้อผิดพลาด:** ไปยังงานปัจจุบัน ดังแสดงใน
ตัวอย่างต่อไปนี้:

```
{
งานนี้ ข้อผิดพลาด: ['โอ๊ะ!'].
} ดักจับ: { :ความผิด
แสดงผล เขียน: ความผิด.
}, เริ่ม.
```

## การฉีดค่า

XOScript ให้งานมีตัวเลือกในการฉีดค่า ทีนี้ ลองดู
งานด้านล่าง:

```
>> การส่ง := {
	จดหมายข่าว ถึง: ของตน recipient.
}.
การส่ง กำหนด: ['recipient']
ค่า: ['info@recipient.org'].
การส่ง เริ่ม.
```


ตัวอย่างนี้แสดงงานสมมติที่ส่งจดหมายข่าว
ไปยังที่อยู่อีเมลหรือ**ผู้รับ** (**recipient**) ผู้รับนี้สามารถถูกฉีด
เข้าไปในงานจากภายนอกได้ก่อนที่งานจะเริ่ม โดยส่ง
ข้อความ **กำหนด:ค่า:** ไปยังงาน เมื่อทำเช่นนั้น ค่าของ
**recipient** จะถูกตั้งไว้ล่วงหน้าในงาน ค่านี้ยังสามารถแก้ไขได้
แล้วจึงรันงานอีกครั้ง นี่เป็นวิธีที่มีประโยชน์เมื่อใช้

## ฟังก์ชันว่าง

ไม่อนุญาตให้มีงานว่าง ในทางทฤษฎี งานว่างจะมีลักษณะ
ดังนี้: **{}** อย่างไรก็ตาม XOScript มองว่านี่เป็นข้อผิดพลาดทางภาษา หากคุณ
ต้องการประกาศงานว่าง คุณสามารถใช้ออบเจกต์ ว่าง ได้:

```
>> งาน := ว่าง.
```

แม้ว่านี่จะไม่ใช่งานจริง แต่เป็นออบเจกต์ ว่าง ก็ยังสามารถ
ส่งข้อความ เริ่ม ได้:

```
>> คำตอบ := งาน เริ่ม.
```

แท้จริงแล้ว สิ่งนี้เหมือนกับ:

```
>> คำตอบ := ว่าง เริ่ม.
```

เนื่องจากออบเจกต์ **ว่าง** ไม่รู้จักข้อความ **เริ่ม** มัน
จะคืนตัวเองเป็นคำตอบ ทำให้คำตอบเป็น **ว่าง** อีกครั้ง
ดังนั้นจึงไม่จำเป็นต้องมีงานว่าง ด้วยการออกแบบที่สง่างาม
ของภาษาโปรแกรม XOScript คุณสามารถใช้ออบเจกต์ ว่าง
แทนได้เลย

# ลิสต์

{{messages}}

XOScript รู้จักคอลเลกชันสองประเภท: *ลิสต์*และ*พจนานุกรม*
**ลิสต์**คือการแจกแจงออบเจกต์ใน*ลำดับที่แน่นอน* พจนานุกรม
ไม่มีลำดับ แต่มีลักษณะคล้ายคำอธิบายสัญลักษณ์ที่ประกอบด้วยคีย์ (หรือคำศัพท์) และ
ค่าที่สอดคล้องกัน ลิสต์เทียบได้กับอาร์เรย์ (PHP, Java, C)
และลิสต์ (Python) พจนานุกรมเทียบได้กับอาร์เรย์แบบเชื่อมโยง (PHP) หรือ
dictionary (Python) ในภาษาโปรแกรมอื่นๆ ในการสร้าง
ลิสต์ใหม่ ให้เขียน:

```
>> ฟีโบนัชชี := ลิสต์ สร้างใหม่.
```

ลิสต์ว่างนี้สามารถเติมได้โดยใช้ **ต่อท้าย:** :

```
ฟีโบนัชชี ต่อท้าย: 0.
ฟีโบนัชชี ต่อท้าย: 1.
ฟีโบนัชชี ต่อท้าย: 1.
ฟีโบนัชชี ต่อท้าย: 2.
ฟีโบนัชชี ต่อท้าย: 3.
ฟีโบนัชชี ต่อท้าย: 5.
ฟีโบนัชชี ต่อท้าย: 8.
ฟีโบนัชชี ต่อท้าย: 13.
```

หากเราเขียนลิสต์ลงบนหน้าจอ:

```
แสดงผล เขียน: ฟีโบนัชชี, ขึ้นบรรทัดใหม่.
```

เราจะเห็น:

```
ลิสต์ ← 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13
```

แทนที่จะใช้ ต่อท้าย คุณยังสามารถใช้ ; เพื่อเพิ่มสมาชิกลงในลิสต์ได้:


```
>> ฟีโบนัชชี := ลิสต์ สร้างใหม่ ; 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13.
```

เครื่องหมายอัฒภาค (;) ทั้งหมดเป็นข้อความไบนารีที่ใส่
ค่าลงในลิสต์

## การต่อลูกโซ่

สมมติว่าคุณมีลิสต์เช่น:

```
>> x := ลิสต์ สร้างใหม่ ; 1 ; 2 ; 3.
```

หากคุณต้องการลบสมาชิกตัวแรกและตัวสุดท้าย
ข้อความของคุณจะเป็น:

```
x ดึงตัวแรก ดึงตัวท้าย.
```

น่าเสียดายที่รูปแบบการเขียนก่อนหน้าจะทำงานไม่ถูกต้อง
ข้อความ **ดึงตัวแรก** คืนสมาชิกตัวแรกของลิสต์ ซึ่ง
จะกลายเป็นผู้รับข้อความ **ดึงตัวท้าย** ดังนั้น
ข้อความ **ดึงตัวท้าย** จึงไม่ได้ถูกส่งไปยัง **x** แต่ถูกส่งไปยัง 2 แทน
วิธีแก้ปัญหาที่เป็นไปได้คือการเขียนเป็นสองประโยค
แยกกัน เช่น:

```
x ดึงตัวแรก.
x ดึงตัวท้าย.
```

อย่างไรก็ตาม วิธีนี้ค่อนข้างไม่สะดวก โดยเฉพาะเมื่อคุณต้อง
ลบสมาชิกมากกว่าสองตัว ดังนั้น XOScript จึงมี
โครงสร้างข้อความทางเลือกสำหรับสถานการณ์เช่นนี้ ใน
โครงสร้างข้อความ**ทางเลือก** คำตอบของออบเจกต์จะถูกละเว้น
และคุณจะได้ออบเจกต์ผู้รับกลับมาเป็นคำตอบทุกครั้ง
โครงสร้างข้อความ**ทางเลือก**เริ่มต้นได้โดยส่ง
ข้อความ **เริ่มทำ** ไปยังออบเจกต์ และโครงสร้างข้อความ**ทางเลือก**
สามารถจบได้โดยส่งข้อความ **ทำเสร็จ** ใน
ตัวอย่างที่แสดง สามารถใช้ได้ดังนี้:

```
>> x := ลิสต์ สร้างใหม่ ; 1 ; 2 ; 3.
x เริ่มทำ ดึงตัวแรก ดึงตัวท้าย ทำเสร็จ.
```

# พจนานุกรม

{{messages}}

**ทั้ง ลิสต์ และ พจนานุกรม ล้วนเป็นคอลเลกชัน อย่างไรก็ตาม ต่างจาก
ลิสต์ พจนานุกรม**ไม่มี**ลำดับ ข้อแตกต่างอีกประการระหว่างทั้งสอง
คือพจนานุกรมประกอบด้วยคู่ของออบเจกต์ ออบเจกต์หนึ่งทำหน้าที่เป็นรายการ (หรือ
คำสำคัญ) สำหรับค้นหาอีกออบเจกต์หนึ่ง ตัวอย่างที่ดีของ
ลิสต์ประเภทนี้คือรายการราคา เช่น:


```
>> เมนู := พจนานุกรม สร้างใหม่
	ใส่: ['£5'] ที่: ['พายแอปเปิล'],
	ใส่: ['£6'] ที่: ['เค้กแครอท'],
	ใส่: ['£3'] ที่: ['fudge'].
```

เช่นเดียวกับลิสต์ ข้อความ ใส่:ที่:
ใช้เพื่อเพิ่มออบเจกต์ลงในลิสต์ ข้อแตกต่างคือ ต่างจาก
ลิสต์ มีการเชื่อมออบเจกต์สองตัวเข้าด้วยกัน ออบเจกต์แรกคือ
ออบเจกต์ที่คุณจะเก็บไว้ในลิสต์ เช่นเดียวกับลิสต์ ส่วนออบเจกต์ที่สอง
ไม่ใช่ตำแหน่งในคอลเลกชัน แต่เป็น**รายการ** (entry)
ซึ่งทำให้สามารถดึงออบเจกต์ก่อนหน้ากลับมาได้ในภายหลัง
โดยสรุป พจนานุกรมทำงานคล้ายพจนานุกรมจริง คือใช้คำสำคัญ
เพื่อค้นหาความหมาย ตัวอย่างเช่น เพื่อดึงราคาของฟัดจ์จาก
ลิสต์ที่กล่าวถึงข้างต้น:

```
>> price := เมนู ที่: ['fudge'].
```

คุณยังสามารถใช้รูปแบบการเขียนแบบย่อได้:

```
>> price := เมนู ? ['fudge'].
```

หากรายการที่คุณใช้เก็บออบเจกต์ไม่มีช่องว่าง
(และไม่ชนกับข้อความอื่นที่กำหนดไว้ล่วงหน้า)
ก็สามารถใช้รูปแบบการเขียนถัดไปนี้ได้เช่นกัน:

```
>> เมนู := พจนานุกรม สร้างใหม่
	pie:   ['£5'],
	cake:  ['£6'],
	fudge: ['£3'].
```

ไม่ต้องสงสัยเลยว่ารูปแบบการเขียนด้านบนอ่านได้เป็นธรรมชาติกว่าเล็กน้อย
ในการขอราคาของ
ฟัดจ์ สามารถใช้รูปแบบการเขียนแบบง่ายต่อไปนี้ได้:

```
>> price := เมนู fudge.
```

# โปรแกรม/StdOut

ออบเจกต์ โปรแกรม แทนแอปที่กำลังทำงานอยู่ ออบเจกต์นี้

## StdOut

แสดงผล คือออบเจกต์เอาต์พุตมาตรฐาน โดยพื้นฐานแล้วมีสองเมธอด:
**เขียน:** และ **ขึ้นบรรทัดใหม่** ข้อความ เขียน: ใช้ส่งสตริง
ไปยัง stdout ส่วนข้อความ ขึ้นบรรทัดใหม่ จะพิมพ์อักขระขึ้นบรรทัดใหม่
แทนที่จะใช้ **ขึ้นบรรทัดใหม่** คุณยังสามารถใช้ \\n ได้

ตัวอย่าง:

```
แสดงผล เขียน: ['Hello World'], ขึ้นบรรทัดใหม่.
```

ผลลัพธ์:

```
Hello World
```

## การสะท้อน (Reflection)

มีหลายวิธีในการสำรวจ
ระบบในระหว่างการทำงานของโปรแกรม XOScript มีเมธอดสองสามตัวสำหรับ
ตรวจหาว่ามีออบเจกต์ใดอยู่บ้าง และออบเจกต์เหล่านี้ตอบสนองต่อ
ข้อความใด ประการแรก สามารถถามออบเจกต์ใดก็ได้ว่าเป็น**ชนิด**ใด
อย่างไรก็ตาม ชนิดใน XOScript ปรับเปลี่ยนได้และจึงเชื่อถือไม่ได้

ยังสามารถถามออบเจกต์ โปรแกรม ได้ว่า
ออบเจกต์ที่กำหนดมีอยู่ในโปรแกรมแล้วหรือไม่:

```
โปรแกรม เครื่องมือ ถ้าจริง: { ... }.
```

ในกรณีที่ชื่อ
ออบเจกต์ประกอบด้วยสัญลักษณ์เพียงตัวเดียว ควรใช้
รูปแบบการเขียนต่อไปนี้เพื่อหลีกเลี่ยงความสับสน:


## เซสชัน

เพื่อให้ข้อมูลคงอยู่ คุณสามารถจัดเก็บและดึงข้อมูลจากออบเจกต์เซสชันได้
ขั้นแรกให้สร้าง **เอกสารเว็บ** ใหม่ ออบเจกต์ เอกสารเว็บ รวม
คำขอ ส่วนหัว HTML และเซสชันเข้าด้วยกัน เหตุผลคือ เมื่อใดก็ตามที่คุณ
เยี่ยมชมเว็บไซต์ด้วยเบราว์เซอร์ คุณจะเห็นเพียง HTML แต่
เอกสารเว็บทั้งหมดยังประกอบด้วย**ส่วนหัว** (Headers) ด้วย ตัวอย่างเช่น
การตอบกลับ HTTP ส่วนใหญ่มีส่วนหัวเช่น Content-type:text/html เพื่อ
บอกเบราว์เซอร์ว่าข้อมูลที่ตามมาควรแสดงผลเป็น HTML
(แทนที่จะดาวน์โหลดเป็นไฟล์ เป็นต้น) เซสชันเป็นวิธีการ
จัดเก็บข้อมูลผู้ใช้ระหว่างคำขอ ในการติดตามข้อมูลนี้ เราต้อง
ตั้งคุกกี้ ซึ่งคุกกี้นี้ก็ตั้งผ่านส่วนหัวเช่นกัน นั่นคือเหตุผลที่
ทุกอย่างมารวมกันใน เอกสารเว็บ (เพราะเป็นเอกสาร
ฉบับเต็มที่มีทั้งส่วนหัวและ HTML หรือข้อมูลอื่นๆ)


```
# ก่อนอื่นเราสร้างอินสแตนซ์ เอกสารเว็บ ใหม่
>> เว็บ := เอกสารเว็บ สร้างใหม่.

# ตอนนี้เราเริ่มเซสชัน ซึ่งจะสร้างส่วนหัวสำหรับคุกกี้ และ
# สร้างไฟล์เก็บข้อมูลของคุณที่ผูกกับคุกกี้นั้น
>> เซสชันนี้ := เว็บ เริ่มเซสชัน.

# ตอนนี้เราใช้เซสชันได้เหมือน พจนานุกรม
เซสชันนี้ userid: 123.
```

ในการทำลายเซสชัน (เมื่อออกจากระบบ):

```
เว็บ ทำลายเซสชัน.
```

## แม่แบบ

ระบบแม่แบบเริ่มต้นเรียบง่ายมาก คุณไม่ต้องเรียนรู้
ไวยากรณ์แม่แบบใหม่ นอกจากนี้ เอนจินแม่แบบยังรับประกันการแยกอย่างแท้จริง
ระหว่างการแสดงผลและตรรกะทางธุรกิจ

ในการสร้างแม่แบบจากไฟล์:

```
>> tpl := เว็บ แม่แบบ: ['templates/ux.tpl'].
```

ระบบแม่แบบใช้เครื่องหมาย
มีเครื่องหมายสามประเภท: เครื่องหมายตัด เครื่องหมายวาง และ
เครื่องหมายช่อง แนวคิดพื้นฐานเรียบง่ายมาก คุณตัด
พื้นที่ที่ระบุด้วยเครื่องหมายตัดออก และสามารถวางไว้ที่
พื้นที่ที่ระบุด้วยเครื่องหมายวาง คุณสามารถฉีดสตริงลงใน
เครื่องหมายช่องได้

ตัวอย่างเช่น จากแม่แบบต่อไปนี้ มาใส่
อัญมณีลงในกล่องเครื่องประดับและเพิ่มป้ายราคากัน

```
<!-- cut:gem -->
<img src="gem.gif">
<b>$<!-- slot:price --></b>
<!-- /cut:gem -->

<div id="box">
<!-- paste:jewels -->
</div>
```

คุณสามารถทำได้ดังนี้:

```
>> gem := tpl ตัดออก: ['gem'], คัดลอก.
gem price: 99.
tpl วาง: gem ที่: ['jewels'].
เว็บ แสดงผล: tpl ลบเครื่องหมาย.
```

บรรทัดสุดท้ายเพียงส่งแม่แบบในรูปสตริงไปยังไคลเอนต์
พร้อมกับส่วนหัว HTTP ที่จำเป็น

ผลลัพธ์:

```
<div id="box">
<img src="gem.gif">
<b>$99</b>
</div>
```

## Passthru

ในการให้บริการไฟล์ที่ผู้ใช้อัปโหลดอย่างปลอดภัย คุณสามารถใช้ passthru ได้:

```
>> ที่อัปโหลด := ['smile.gif'].
Server ส่งผ่าน: ที่อัปโหลด คำนำหน้า: ['/uploads/images/'].
โปรแกรม จบ.
```

สิ่งนี้จะให้บริการเนื้อหาที่ผู้ใช้อัปโหลดด้วย mime type
ที่เหมาะสม รองรับเฉพาะ mime type ที่อยู่ในรายการที่อนุญาตเท่านั้น:
GIF, JPG, PNG, WEBP, MP4, WEBM, MP3, ZIP, GZIP, PDF และ SVG
ไฟล์ SVG, ZIP และ GZIP จะถูกส่งเป็นการดาวน์โหลด เพราะ SVG
อาจมีสคริปต์ที่มิฉะนั้นจะทำงานบนโดเมนของคุณ
วิธีนี้ป้องกันการโจมตีแบบ TOCTOU, path traversal,
การรันโค้ดอันตราย (injection), การโจมตีผ่าน symlink,
การโจมตีแบบ DDoS (ขีดจำกัดไฟล์ = 50MB), การโจมตีแบบ sniffing และ
ปัญหาด้านความปลอดภัยอื่นๆ อีกมากมาย

สิ่งนี้จะสร้างโทเค็นยาว 40 อักขระ

## การจัดรูปแบบ

ออบเจกต์ รูปแบบ ช่วยให้คุณจัดรูปแบบข้อมูลได้ เช่น การเติมช่องว่างหรือ
การเติมเลขศูนย์ โดยใช้ไวยากรณ์ของ printf

```
>> รปบ := รูปแบบ สร้างใหม่: ['%06.0f'].
รปบ ใช้กับ: 56. # ได้ 000056
```

รูปแบบหนึ่งสามารถมีการแปลงได้หนึ่งรายการ และต้องเข้ากับค่า
มิฉะนั้นคุณจะได้รับข้อผิดพลาด:

- `ใช้กับ:` กับสตริง: `%s`
- `ใช้กับ:` กับตัวเลข: `%f`, `%e`, `%g` หรือ `%a`
- `ใช้กับจำนวนเต็ม:` กับตัวเลข: `%d`, `%i`, `%o`, `%u`, `%x` หรือ `%c`

ค่าที่มาจากคำขอเป็นสตริง หากต้องการจัดรูปแบบเป็นตัวเลข
ให้แปลงก่อน:

```
รปบ ใช้กับ: (คำขอ-http get: ['amount']) เป็นตัวเลข.
```

# ffi

{{messages}}

FFI จัดเตรียมให้ตามแพลตฟอร์ม/ปลั๊กอิน เพราะมัน
ผูกติดกับสถาปัตยกรรมระบบเบื้องล่าง ซึ่งเป็นสิ่งที่
แกนของภาษาไม่ควรทำ
ปลั๊กอินเซิร์ฟเวอร์มีการพัฒนา ffi/blob ที่เป็นไปตามข้อกำหนด
โดยค่าเริ่มต้น แกนของภาษาเชื่อมต่อกับแพลตฟอร์มเป้าหมาย
ผ่าน stdin/stdout บริการ i/o ไฟล์แบบจำกัด และเชลล์ (โปรแกรม ระบบ:)
การเชื่อมต่อเพิ่มเติมจัดเตรียมโดย ffi/blob ผ่านปลั๊กอิน
ที่เน้นแอปพลิเคชัน เช่น ปลั๊กอินเซิร์ฟเวอร์

FFI ย่อมาจาก Foreign Function Interface ช่วยให้คุณใช้ความสามารถที่ผู้อื่นเขียนไว้ใน
ภาษาโปรแกรมอื่นได้ ซึ่งจัดเตรียมผ่านไฟล์ DLL, ไฟล์ SO หรือไฟล์ Dylib สิ่งเหล่านี้อาจ
เป็นฟังก์ชันหลากหลาย และมีความสามารถให้ใช้มากมายมหาศาลผ่านวิธีนี้
มาเริ่มด้วยตัวอย่างกัน:

```
Server เชื่อมโยง: (
 ลิสต์ สร้างใหม่ ;
 ['/usr/lib/x86_64-linux-gnu/libc.so.6'] ;
 ['printf'] ;
 ( ลิสต์ สร้างใหม่ ; ['pointer'] ; ['int'] ) ;
 ['void'] ;
 ['Printf'] ;
 ['template:number:']
).
>> s := Blob utf8: ['FFI has %d letters.\n'].
Printf template: s number: 3.
s คืนหน่วยความจำ.
```

ผลลัพธ์ของโค้ดนี้คือคุณจะเห็นข้อความต่อไปนี้บนบรรทัดคำสั่ง:
FFI has 3 letters.
ตอนนี้คุณอาจกำลังคิดว่า "โค้ดเยอะจังสำหรับเรื่องง่ายๆ แค่นี้"
หมายความว่า เราแก้ปัญหานี้ด้วยคำสั่ง Gui show ไม่ได้หรือ? คำตอบคือได้แน่นอน!
แต่นี่มีไว้เป็นตัวอย่างประกอบ
FFI มักใช้กับงานที่ซับซ้อนกว่านี้ แต่งานเหล่านั้นไม่เหมาะ
เป็นตัวอย่าง ผมจึงเลือกสิ่งที่เรียบง่าย

อาร์กิวเมนต์ของเมธอด link:

- อาร์กิวเมนต์ #1: ไฟล์ DLL หรือ SO ที่คุณต้องการใช้
- อาร์กิวเมนต์ #2: ฟังก์ชันในไฟล์นั้นที่คุณต้องการเชื่อม
- อาร์กิวเมนต์ #3: ลิสต์ที่มีชื่อชนิดข้อมูลของอาร์กิวเมนต์ของฟังก์ชัน
- อาร์กิวเมนต์ #4: ชื่อชนิดข้อมูลที่ฟังก์ชันคืนค่า
- อาร์กิวเมนต์ #5: ชื่อของออบเจกต์ที่คุณต้องการเชื่อมฟังก์ชันนี้เข้าไป (หากไม่มีอยู่ จะถูกสร้าง
ขึ้นโดยอัตโนมัติ)
- อาร์กิวเมนต์ #6: ข้อความที่ฟังก์ชันนี้ควรเชื่อมเข้าไป

ในตัวอย่างด้านบน เราต้องการเชื่อมฟังก์ชัน printf จาก libc.so คุณสามารถหาชื่อ
ชนิดข้อมูลได้ในเอกสารประกอบของซอฟต์แวร์ที่คุณเชื่อมต่อ ชนิดที่มีให้ใช้ได้แก่:
void, pointer, float, double, int, uint, char, uchar, intX และ uintX
โดยที่ X อาจเป็น 8, 16, 32 หรือ 64

ชนิดเหล่านี้หมายถึงจำนวนไบต์ที่ต้องใช้ในการเก็บข้อมูล สำหรับ printf เราเชื่อมกับ
ออบเจกต์ใหม่ชื่อ Printf และข้อความ template:number: คุณแปลฟังก์ชันภายนอก
เป็นภาษาถิ่นของ XOScript ก่อนใช้งาน ข้อความ template:number: ต้องการ
บัฟเฟอร์ที่มีข้อความแม่แบบเป็นพารามิเตอร์แรก เราสร้างบัฟเฟอร์นี้โดยใช้ออบเจกต์ Blob ซึ่ง
ช่วยให้คุณจัดสรรหน่วยความจำด้วยตนเองได้ คุณมีหน้าที่คืนหน่วยความจำนี้ภายหลัง
ด้วยข้อความ คืนหน่วยความจำ

คุณสามารถเติมข้อมูลลงใน blob หน่วยความจำได้หลายวิธี ในตัวอย่างของเรา เราเติมด้วยข้อความ จึงใช้
ข้อความ utf8: (UTF-8 เป็นการเข้ารหัสเพื่อแปลงข้อความเป็นไบต์) คุณยังสามารถเติม blob ด้วย
bytes: โดยส่งลิสต์ของค่าไบต์ ในการอ่านเนื้อหาของ blob ให้ใช้ เริ่มที่:ความยาว:
คุณจะได้ไบต์กลับมาเป็นลิสต์ คุณยังสามารถสร้าง C-struct ด้วย Blob โดยใช้
ข้อความ struct: พร้อมส่งลำดับของชนิดข้อมูล C ซึ่งอาจจำเป็นเมื่อเรียกฟังก์ชัน
C ในไลบรารีซอฟต์แวร์ภายนอกที่ต้องการพอยน์เตอร์ไปยัง struct

{warning}
คุณต้องคืนหน่วยความจำของ blob เอง
Blob จะไม่ถูกเก็บกวาดโดยตัวเก็บขยะ (garbage collector)
{/warning}

เนื่องจาก blob สามารถแลกเปลี่ยนกับฟังก์ชันภายนอกจากไลบรารีได้ จึง
ไม่สามารถเก็บกวาดโดยอัตโนมัติได้ (อาจยังถูกใช้งานโดย
ฟังก์ชันภายนอก หรือฟังก์ชันภายนอกเหล่านั้นอาจต้องการคืนหน่วยความจำ
เอง) ดังนั้นคุณต้องคืนหน่วยความจำของ blob เองหากจำเป็น

ในการคืนหน่วยความจำของ blob ให้ใช้:

```
blobของฉัน คืนหน่วยความจำ.
```

ในการคืนหน่วยความจำของ struct ให้ใช้:

```
structของฉัน struct-คืนหน่วยความจำ คืนหน่วยความจำ.
```

ดังนั้นสำหรับ struct คุณต้องส่งสองข้อความ: struct-คืนหน่วยความจำ และ คืนหน่วยความจำ เพื่อ
คืนบล็อกหน่วยความจำ
