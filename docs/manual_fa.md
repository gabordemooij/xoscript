به XOScript خوش آمدید
هدف پروژه XOScript ساختن یک زبان اسکریپت نویسی ساده و قابل ممیزی است.
ساده لزوما به معنای آسان نیست.
یک زبان برنامه نویسی آشنا ممکن است از XOScript آسان تر باشد.
در اینجا سادگی معنای دیگری دارد:
توانایی ساختن یک مدل ذهنی کامل از زبان و رفتار آن.

XOScript طوری طراحی شده است که در ذهن شما جا شود.
دستور زبان و تعداد مفاهیم آن عمدا اندک است.
هیچ کلاسی وجود ندارد؛ اشیاء را می توان مستقیما گسترش داد.
اشیاء به صورت ارجاع منتقل می شوند، رونوشت گرفتن صریح است،
و توابع تنها یک نقطه خروج دارند.

برخی از این انتخاب ها تفاوت چشمگیری با زبان های رایج دارند.
برای مثال XOScript هیچ سیستم نوعی ندارد و از دامنه پویا استفاده می کند.
پیام هایی که قابل پردازش نیستند به جای ایجاد استثنا نادیده گرفته می شوند.
این انتخاب ها پیامدهایی دارند و قرار نیست خطاها را از بین ببرند.
هدف آن ها کوچک و سازگار نگه داشتن مدل بنیادین زبان است.

XOScript را می توان بومی سازی نیز کرد، به طوری که بتوان قواعد کسب و کار را
به یک زبان طبیعی بیان کرد و احتمالا آن ها را با ذی نفعان غیر فنی به اشتراک گذاشت.

قابلیت ممیزی یعنی به کار بستن همین فلسفه در پیاده سازی.
محیط اجرا به زبان C نوشته شده است، با یک تحلیلگر واژگانی، تجزیه گر و پیمایشگر درختی کوچک و دست نویس.
کتابخانه استاندارد و محیط اجرا تا حد زیادی ساختار زبان را بازتاب می دهند،
و این باعث می شود رابطه میان کد XOScript و پیاده سازی آن نسبتا مستقیم باشد.

آزمون ها نیز پیوند نزدیکی با مستندات دارند.
هر متد باید آزمون مربوط به خود را داشته باشد که بتوان آن را در راهنما گنجاند،
و این کمک می کند مستندات با پیاده سازی هماهنگ بمانند.

XOScript قرار نیست از نظر امکانات یا آشنایی با زبان های رایج رقابت کند.
این زبان هدف دیگری را دنبال می کند:
یک محیط برنامه نویسی که یک توسعه دهنده بتواند آن را به طور کامل درک کند.

امید این است که یک زبان کوچک و یک
پیاده سازی کوچک، درک نرم افزار را
از بایت تا شیء و از نحو تا محیط اجرا عملی کند، و بتوانید کد را با
اطمینان بنویسید، چون هم آنچه را در
اسکریپت رخ می دهد می فهمید و هم آنچه را در پشت صحنه رخ می دهد.

معماری یک راه اندازی کارساز xoscript
ساده و در عین حال انعطاف پذیر است.

{{architecture.png}}

برای استفاده از xoscript به عنوان زبان سمت کارساز، باید
افزونه کارساز را در پوشه ای به نام /mods/server نصب کنید.

دلیل این کار آن است که ما ترجیح می دهیم
هسته زبان را از امکانات ویژه کارساز جدا کنیم،
برخلاف برای مثال PHP یا Python. در غیر این صورت مجبور بودیم
همه چیز را بی دلیل به دست همه برسانیم، که کاملا بی معنی است.
اگر بخواهید می توانید ماژول های دیگری نیز نصب کنید. این سیستم بسیار
انعطاف پذیر است.

همچنین برخی امکانات بهتر است در خود زبان اسکریپت نویسی
پیاده سازی شوند، مانند قالب بندی و مدیریت نشست، بنابراین ما افزون بر این
کتابخانه های template.xo و webtools.xo را برای راحتی شما ارائه می کنیم.
دلیل همه این ها این است که ما نمی دانیم شما چگونه می خواهید
از xoscript استفاده کنید. می توانید از آن به عنوان زبان اسکریپت نویسی سمت کارساز استفاده کنید،
اما همچنین برای رابط های گرافیکی، دستگاه های نهفته یا فقط پردازش دسته ای.
حتی اگر از آن به عنوان زبان اسکریپت نویسی سمت کارساز استفاده کنید (که
در حال حاضر یکی از کاربردهای اصلی است)، ممکن است همچنان بخواهید
از موتور قالب دیگری یا مدیر نشست دیگری استفاده کنید.
ما چه کسی هستیم که تصمیم بگیریم شما باید از نسخه ما استفاده کنید؟

با این حال یکی از مزایای استفاده از موتور قالب خود ما این است که
برای ساختن قالب ها لازم نیست نحو اضافه ای یاد بگیرید.
موتور قالب پیش فرضی که همراه xoscript ارائه می شود ۱۰۰٪
جدایی میان نمایش و منطق را رعایت می کند. به جای نحو ویژه
قالب، به سادگی از یک سیستم بسیار انعطاف پذیر نشانگر جایگاه استفاده می کند.
برای اطلاعات بیشتر فصل Server را ببینید.

توجه داشته باشید که اگر نمی خواهید از موتور قالب پیش فرض یا
webtools پیش فرض استفاده کنید، بدیهی است که باید
نسخه خودتان را فراهم کنید.

اگر کارساز وب خود را در chroot، jail یا نوع دیگری از محیط ایزوله اجرا می کنید،
باید وابستگی های xo را نیز در آن محیط نصب کنید؛ می توانید
با استفاده از ldd ببینید به کدام کتابخانه ها نیاز دارید (صفحه راهنمای Linux یا BSD را ببینید).
اگر می خواهید در اسکریپت های xo خود از فرمان های پوسته استفاده کنید، یک پوسته
(مانند bash یا ksh) را نیز به این محیط کپی کنید.

همچنین مایلیم یادآوری کنیم که سازگاری با نسخه های پیشین را بسیار جدی می گیریم.
حتی یک قابلیت ویژه سازگاری با نسخه های پیشین به نام
'version' وجود دارد. به طور کلی، هدف ما این است که کد شما برای همیشه اجرا شود. بنابراین
هرگز لازم نخواهد بود کد خود را برای سازگار ماندن با نسخه های جدیدتر
xoscript به روز کنید. هدف ما این است: یک بار بنویس، برای همیشه اجرا کن.

باقی این راهنما به توضیح مفصل زبان برنامه نویسی
xoscript اختصاص دارد. اسکریپت نویسی کارساز در فصلی
به نام Server بررسی می شود. اگر توسعه دهنده نرم افزار باتجربه ای هستید، شاید بخواهید
از چند فصل بگذرید، زیرا برخی از آن ها کمی بیش از حد جزئی هستند یا
شباهت زیادی به شیوه های عمومی برنامه نویسی دارند. بنابراین آن دسته از شما
که با چندین زبان برنامه نویسی دیگر تجربه دارند،
بهتر است این راهنما را به عنوان یک راهنمای مرجع در نظر بگیرند.

## راه اندازی در Linux

apache2 و mariadb را دریافت کنید:


```
sudo apt-get install apache2 mariadb-server
sudo a2enmod cgi
```

xoscript را دریافت کنید.
X را با شماره نسخه درست جایگزین کنید!

```
wget https://xoscript.com/downloads/xoserver-linux-1_5_X.tar.gz
tar xvf xoserver*.tar.gz
```

پرونده ها را به ریشه وب و /bin کپی کنید:


```
sudo cp bin/xo /bin/xo
sudo cp -R bin/mods /var/www/html/
sudo cp *.xo /var/www/html/
```

پیکربندی apache2 خود را ویرایش کنید:

```
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

Virtualhost را با این جایگزین کنید:

```
<VirtualHost *:80>
    <Directory /var/www/html>
        Options +ExecCGI
        AllowOverride All
        AddHandler cgi-script .xo
        Require all granted
    </Directory>
    DocumentRoot /var/www/html
</VirtualHost>
```

یک صفحه آزمایشی بسازید:

```
sudo nano /var/www/html/test.xo
```

و یک برنامه آزمایشی کوچک بنویسید:

```
#!/bin/xo
Server آماده-سازی.
برنامه به-کار-ببر: ⌝'webtools.xo'⌜.
>> web := سند-وب جدید.
web خروجی-بده: ⌝'Hello World'⌜.
```

به apache2 اجازه دهید برنامه شما را از طریق CGI اجرا کند:

```
sudo chmod uog+x /var/www/html/test.xo
```

apache2 را دوباره راه اندازی کنید:

```
sudo systemctl restart apache2
```

در مرورگر به صفحه آزمایشی خود بروید:

```
http://localhost/test.xo
```

باید این را ببینید:

```
Hello World
```


## راه اندازی در OpenBSD

پرونده /etc/httpd.conf را ویرایش کنید و این را بیفزایید:


```
server "mydomain.com" {
    listen on * port 80
    root "/htdocs/mydomain/"

    location "*.xo" {
        fastcgi
        fastcgi socket "/run/slowcgi.sock"   # inside chroot
    }
}
```

اگر می خواهید از SSL استفاده کنید:

```
listen on * tls port 443
tls {
	certificate "/etc/ssl/mycert.crt"
	key "/etc/ssl/private/mykey.key"
}
```

برای محافظت از تبادل کلید در برابر رایانش کوانتومی،
رمز mlkem را برگزینید:

```
tls {
 ... 
 ecdhe "X25519MLKEM768"
 ...
}
```

پرونده اجرایی xo و ماژول ها و همچنین همه وابستگی ها را در
chroot قرار دهید (با ldd پیدا کنید).

## اجرای نمونه ها


برای اجرای یکی از برنامه های نمونه موجود در بسته:

```
./example.sh <name> <Linux/OBSD> [clean]
```

برای مثال، برای اجرای نمونه FizzBuzz در Linux:

```
./example.sh fizzbuzz Linux
```

برای اجرای همان نمونه در OpenBSD:

```
./example.sh fizzbuzz OBSD
```

برای اجرای نمونه با یک ساخت تمیز:

```
./example.sh fizzbuzz OBSD clean
```

## آزمون های واحد

برای اجرای آزمون های واحد:

```
./runtests.sh
```

برای اجرای آزمون های واحد بدون ساختن (فقط آزمودن):

```
./runtests.sh nobuild
```

## ساختن

برای ساختن از کد منبع در Linux:

```
make clean
ISO="en" make
```

در OpenBSD:

```
make -f makefile.obsd clean
ISO="en" make -f makefile.obsd
```

برای ساختن افزونه کارساز در Linux:

```
PACKAGE="server" NAME="server.so" make plugin-clean
ISO="en" PACKAGE="server" NAME="server.so" make plugin
```

برای ساختن افزونه کارساز در OpenBSD:

```
PACKAGE="server" NAME="server.so" make -f makefile.obsd plugin-clean
ISO="en" PACKAGE="server" NAME="server.so" make -f makefile.obsd plugin
```

## سلام دنیا

پس از اینکه پرونده به رایانه شما منتقل شد، می توانید آن را از حالت فشرده خارج کنید
و xo را با فرمان زیر اجرا کنید:

```
xo
```

برای اجرای یک XOScript، برنامه را به صورت یک پرونده با پسوند -xo
ذخیره کنید (اختیاری). افزون بر این، نام پرونده برنامه خود را
پس از فرمان XOScript وارد کنید:

```
xo myprogram.xo
```

وقتی یک فرمان XOScript را با پرونده برنامه خود به عنوان
پارامتر اجرا می کنید، xo پرونده برنامه شما را می خواند و اجرا می کند.

{{note}}
همچنین می توانید برنامه خود را با کشیدن آن روی نماد xo اجرا کنید.
{{/note}}

{{warning}}
در برخی سیستم ها باید از پیش به xo اجازه بارگذاری کتابخانه های
پویا را بدهید.
{{/warning}}

سنت حکم می کند که نخستین برنامه در هر زبان برنامه نویسی تازه
نوعی سلام به دنیا باشد. در XOScript چنین
برنامه **Hello world** به این شکل است:

@test598

وقتی این متن در یک پرونده، برای مثال hello.xo، ذخیره شود، می توان آن را
به این صورت اجرا کرد: .

xo hello.xo

Hello world


خروجی برنامه را می توانید در پنجره سیاه بالا ببینید.
در سراسر این راهنما از همین نمایش برای
نشان دادن خروجی استفاده می شود.

{{note}}
خروجی با حرف آغازین بزرگ O نوشته می شود.
به طور کلی نام اشیاء با حرف بزرگ آغاز می شود،
مگر اینکه به عنوان یک نمونه عمل کند (هیچ متدی
از خود ندارد، فقط داده دارد). این همانند قراردادهای کلاس و نمونه
در زبان های برنامه نویسی دیگر است.
{{/note}}


## نحو

XOScript یک زبان برنامه نویسی *کاملا* *شیء گرا* است. این یعنی
xoscript همه چیز را شیء می داند و بنابراین هیچ
*نوع داده* دیگری وجود ندارد. در اصل سه کنش پایه ای
در برنامه ای که به XOScript نوشته شده وجود دارد: *انتساب*، *فرستادن پیام*
و *پاسخ دادن*. تبادل پیام میان اشیاء بخش کلیدی یک
برنامه XOScript است. این سه کنش جداگانه در زیر
نشان داده شده اند:


کنش          | مثال
--------------- | --------
انتساب          |  \>\> x := 1. 
پیام های یگانی  | x زوج?.
پیام دودویی  | 1 + 2.
پیام کلیدواژه ای | x آغاز: 0 طول: 10.
پاسخ          | <- answer.  


این فصل تصویری کلی از زبان XOScript به شما می دهد
و اصول پایه آن را شرح می دهد. XOScript زبانی کوچک است و
بر پایه سه کنش (تصویر را ببینید) بنا شده که به
حدود شش قاعده دستوری تبدیل می شوند. این تمام چیزی است که برای تسلط بر
زبان لازم است.

نگران نباشید اگر همه چیز بی درنگ برایتان روشن نیست: همه
اجزای سازنده در فصل بعد (۳) بررسی خواهند شد و قواعد پایه
تکرار خواهند شد. با این حال فصل کنونی عمدتا به عنوان یک
مقدمه کلی بر زبان عمل می کند. اصول پایه به طور خلاصه
توضیح داده شده و با چند مثال مرتبط نشان داده می شوند. هر
جزئیات ناگفته ای در ادامه شرح داده خواهد شد.

توضیحات در XOScript با نماد \# آغاز می شوند. بنابراین سطر زیر
نادیده گرفته می شود:

```
# this is just a comment
```

## متغیرها

برای انتساب
یک متغیر از نماد اعلان متغیر استفاده می کنید: >>. نام یک
متغیر می تواند شامل همه نشانه ها باشد به جز: <-، :=، فاصله های سفید،
نقطه ها، ویرگول ها، دونقطه ها، علامت های نقل قول ⌝' '⌜ و پرانتزها ﴿﴾.
افزون بر این، یک متغیر نمی تواند از چند سطر تشکیل شود. توجه داشته باشید
که یک متغیر نمی تواند با عدد یا علامت منفی آغاز شود.

این ها نمونه هایی از متغیرهای معتبر هستند:

```
>> password := ⌝'Secret'⌜.
>> ♡♡♡ := 3.
>> $ := ⌝'dollar'⌜.
>> +plus := درست.
>> user-password := ⌝'Pssst!'⌜.
```

متغیرهای نامعتبر برای مثال این ها هستند:


```
>> -123 := ⌝'negative number'⌜.
>> password of user := ⌝'Classified'⌜.
>> password.of:user := ⌝'Classified'⌜.
>> ,x := 10.
```

{{note}}
لازم نیست هیچ نویسه ای را
(از جمله نقل قول ها، نقل قول های دوتایی، مرزهای
رشته) در
یک رشته لفظی گریز دهید، تا زمانی که
برای تحلیلگر واژگانی ابهام ایجاد نکند.
{{/note}}

پس از اعلان یک متغیر، می توان آزادانه از آن استفاده کرد. این یعنی
فقط نخستین باری که از متغیر استفاده می کنید (اعلان)
لازم است نماد اعلان را به کار ببرید.

به بیان دقیق تر، نمی توانید همین طور شروع به دادن مقدار به
متغیر خود کنید *(x := 2)*، زیرا ابتدا باید متغیر را اعلان کنید *(\>\>
x := 2)*. با این حال، پس از اعلان اجازه دارید مقدار آن را
بدون استفاده از نماد اعلان تغییر دهید*(\>\> x := 2. x := 3.)*.

توجه داشته باشید که دادن مقدار به یک متغیر در زمان
اعلان الزامی است. برخلاف زبان های برنامه نویسی دیگر، اجازه ندارید
یک متغیر را بدون مقدار اعلان کنید. ضروری است که
هر متغیر صریحا به یک مقدار اولیه پیوند داده شود. با این حال، می توانید
متغیر را با شیء **هیچ** مقداردهی اولیه کنید. در این حالت می توان متغیر را
خالی در نظر گرفت *(\>\> x := هیچ.)*. خلاصه اینکه اعلان یک
متغیر بدون مقدار اولیه مجاز نیست. بنابراین،

```
>> x.
```

نامعتبر است و یک پیام خطا خواهد داد.

{{note}}
xoscript از دامنه پویای متغیرها استفاده می کند؛ برای
جزئیات فصل توابع را ببینید.
{{/note}}


## لفظ ها

XOScript همه چیز را شیء می داند؛ یعنی همه اعداد، رشته ها
و تکه های کد. اعدادی مانند 1، 2، 100، -999 و 1,234 اشیاء
عدد هستند. همه متن های میان علامت های نقل قول تکی اشیاء رشته
هستند. همه تکه های کدی که میان آکولادها ⎬...⎨ قرار گرفته اند اشیاء
تابع هستند.

لفظ         | شیء ریشه  | مثال
--------------- | ------------ | ----------
اعداد         | عدد       | 1,2,3... 
رشته ها         | رشته       | ⌝'hello'⌜
تابع        | تابع     | ⎬ 1 + 2. ⎨.
                
     
اشیائی مانند اعداد و رشته ها همیشه از یک شیء ریشه سرچشمه
می گیرند. برای مثال، همه اعداد از شیء **عدد** مشتق می شوند. همه
رشته ها از **رشته** و همه تکه های کد از **تابع** مشتق می شوند. به
نوبه خود، همه این اشیاء از **شیء** سرچشمه می گیرند که در واقع
شیء ریشه همه اشیاء است.


## پیام ها

برنامه نویسی در XOScript اساسا به معنای
فرستادن پیام به اشیاء است. نشانه گذاری کلی برای فرستادن پیام به
یک شیء به این صورت است:

```
<object> <message>
```

برای مثال، برای فهمیدن اینکه آیا عدد **2** زوج است یا نه،
پیام **زوج?** به شیء **2** فرستاده می شود:

```
2 زوج?
```

پاسخ **درست** خواهد بود (باز هم یک شیء). پیام های ناشناخته
معمولا از سوی اشیاء نادیده گرفته می شوند؛ بنابراین خطایی رخ نمی دهد. برخی اشیاء (مانند
اعداد یا رشته ها) به یک پیام ناشناخته به شیوه ای از پیش تعیین شده پاسخ می دهند
(در ادامه بیشتر در این باره).

یک شیء می تواند سه نوع پیام دریافت کند.

نوع            | تعداد آرگومان ها
--------------- | -------------------
یگانی           | 0      
دودویی          | 1     
کلیدواژه ای         | 1+    


نخست، **پیام های
یگانی** وجود دارند، مثال بالا را ببینید، که بدون آرگومان هستند. دوم،
**پیام های کلیدواژه ای** وجود دارند که یک یا چند آرگومان دارند،
برای مثال:

```
>> x := عدد بین: 1 تا: 10.
```

در این حالت پیام **بین:تا:** به **عدد** فرستاده می شود که
شیء ریشه همه اعداد است. نتیجه یک عدد تصادفی
میان 1 و 10 خواهد بود. سرانجام، **پیام های دودویی** وجود دارند که
تنها یک نویسه و یک آرگومان دارند:

```
2 + 3
```

این شبیه یک جمع ریاضی به نظر می رسد، اما در واقع فقط یک پیام دیگر است.
پیام **+** با آرگومان **3** به **2** فرستاده می شود که
پاسخ **5** را برمی گرداند. پیام های دودویی را می توان بدون دونقطه نوشت.

پیام های دودویی را می توان زنجیروار پشت سر هم آورد:

```
>> x := 3 + 2 - 1.
```

در این تکه ابتدا **+ 2** به شیء **عدد** **3** فرستاده می شود که
نتیجه آن شیء عدد **5** است و پس از آن **-1** به این
عدد فرستاده می شود. خوانندگان دقیق به درستی متوجه ناهمخوانی می شوند که
این پروتکل با ترتیب متعارف ریاضی عملگرها
نشان می دهد. XOScript ترتیب ریاضی را به نفع
سازگاری در سیستم پیام خود نادیده می گیرد. در نتیجه، جمع:

```
2 + 3 * 5 = 25
```

نه 17.

این عمدی است. می توان از پرانتزها برای تغییر ترتیب استفاده کرد:

```
2 + ﴿3 * 5﴾ = 17
```

بیشتر اشیاء در پاسخ به یک پیام معین خودشان را به عنوان نتیجه
برمی گردانند. این مفید است، زیرا گفتگوی بیشتر با این
شیء را با فرستادن یک پیام بعدی به آن تشویق می کند:

```
خروجی بنویس:
⌝' hello '⌜ پیرایش حروف-بزرگ.
```

```
HELLO
```

در اینجا دو پیام به شیء **رشته** فرستاده می شود: **پیرایش** و سپس
**حروف-بزرگ**.

در تکه زیر، استفاده از ویرگول لازم است تا نشان داده شود
که پیام تازه ای در راه است. در غیر این صورت XOScript سردرگم می شود.

```
خروجی بنویس: ⌝'Hello!'⌜, سطر-نو.
```

ابتدا پیام **بنویس:** به نماد مداد فرستاده می شود و سپس
**سطر-نو**. بدون ویرگول، XOScript گمان می کرد که می خواهید
**سطر-نو** را به **رشته** **Hello!** بفرستید، که کاری بیهوده است.

ترتیب پردازش پیام ها به این صورت است: از چپ به راست؛
ابتدا پیام های درون پرانتز و سپس پیام های یگانی. پس از آن
پیام های دودویی و در پایان پیام های کلیدواژه ای. مثال
زیر را ببینید:

```
خروجی بنویس: 0.5 گرد + ﴿2 - 1﴾, سطر-نو.
```

XOScript همیشه از چپ به راست می خواند: ابتدا پیام **بنویس:**
به خروجی فرستاده می شود و پس از آن پیام **سطر-نو** می آید. درون
خود آرگومان نیز XOScript از چپ به راست می خواند، بنابراین ابتدا **0.5 گرد**
و سپس **+**.

{{note}}
پیام سطر-نو یک نویسه سطر جدید به رشته می افزاید.
نام این پیام از سیستم های تلگراف الهام گرفته شده است.
پیام ها در سیستم های تلگراف
اغلب از واژه STOP برای نشان دادن پایان یک جمله استفاده می کردند
(زیرا نشانه گذاری غیر قابل اعتماد یا پرهزینه بود).
{{/note}}

افزون بر این، **گرد** بر **+** اولویت دارد، زیرا یک
**پیام یگانی** است. با توجه به پرانتزها، ابتدا **2 - 1** محاسبه
می شود و پس از آن **1** به نتیجه **0.5 گرد** (1) افزوده می شود.

کل این فرایند نتیجه **2** را می دهد که همان پاسخ
نوشته شده است. پس از ویرگول پیام سطر-نو می آید که مکان نما را
به سطر جدیدی می برد. البته بهترین راه برای درک کامل ترتیب
اجرای برنامه های XOScript تمرین است.

شایان ذکر است که در XOScript، برخلاف بسیاری از زبان های برنامه نویسی
دیگر، فاصله های سفید بخش بنیادینی از نحو آن هستند. به ویژه
در مورد پیام های دودویی، فاصله های سفید ممکن است باعث
سردرگمی شوند. همیشه پس از یک پیام دودویی از فاصله سفید استفاده کنید. نمی توانید
یک عدد را مستقیما به پیام بچسبانید، برای مثال:

```
3 + 2
```

متفاوت است از

```
3 +2
```

مثال نخست (**3 + 2**) پیام
**+** را با آرگومان عدد **2** به عدد **3** می فرستد.
نتیجه در این حالت **5** خواهد بود. در مثال دوم (**3 +2**)
پیام یگانی **+2** به عدد **3** فرستاده می شود. بسته به
زمینه، این ممکن است نتیجه بسیار متفاوتی بدهد.

## متدهای ناموجود

فرستادن یک پیام به یک شیء، تابعی را فراخوانی می کند که
زیر آن نام پیام به این شیء پیوست شده است. اگر پیامی بفرستید
که فهمیده نشود، شیء گیرنده پیام شما را نادیده می گیرد
و به جای آن ارجاعی به خودش را برای ارتباط بیشتر برمی گرداند.
به این کار ارسال پیام بردبارانه گفته می شود.

مثال:

```
خروجی بنویس: شیء blah, سطر-نو.
```

این خطایی نمی دهد. فقط متن **Object** را چاپ می کند.


## جریان کنترل

در XOScript نیازی به قواعد دستوری جداگانه برای *حلقه ها* و
*شرط ها* نیست. یک دستور شرطی فقط یک پیام ساده **اگر-درست:** یا **اگر-نادرست:**
به یک شیء **درست** یا یک شیء **نادرست** است:

```
2 زوج? اگر-درست: ⎬
	خروجی بنویس: ⌝'Two is an even number'⌜, سطر-نو.
⎨.
```
در مثال پیشین، پیام **اگر-درست:** به **درست** فرستاده می شود (که
پاسخ این پرسش است: آیا 2 عددی زوج است؟). به عنوان آرگومان یک
تکه کد اضافی همراه آن فرستاده می شود: یک شیء **تابع**. این تابع روی
صفحه می نویسد که 2 در واقع عددی زوج است.

برای یک *حلقه* نیز نیازی به قواعد نگارشی جداگانه نیست. برای
اجرای یک تکه کد به تعداد سه بار، کافی است **\*** را با آرگومان
**3** به آن **تابع** بفرستید:

در این تکه کد **i** شاخص است. بنابراین نخستین باری که تابع
اجرا می شود، **i** برابر 0 است، بار بعدی که اجرا می شود، **i** = 1 و
به همین ترتیب.

بیایید مثال دیگری را در نظر بگیریم. وقتی لازم است یک جدول تبدیل
از *kJ* (کیلوژول) به *kcal* (کیلوکالری) با گام های 100 چاپ شود،
نشانه گذاری درست را در زیر ببینید:

در اینجا شماره سطر کنونی به پارامتر
**:line** منتقل می شود. در آغاز یک تابع، پارامترهای تابع
تعریف می شوند. پارامترهای استفاده نشده خالی می مانند (**هیچ**). پارامترها
همیشه در آغاز تابع، درست پس از آکولاد آغازین قرار می گیرند
و پیش از آن ها یک دونقطه می آید.

پیام **تا-وقتی:** ترکیبی از یک *حلقه* و یک *شرط* است.
دو تابع را می توان با پیام **تا-وقتی:** به هم پیوند داد. تابع گیرنده
تا زمانی به اجرا ادامه می دهد که تابع پس از دونقطه نتیجه
منفی بدهد. مثال:

در تکه کد بالا تا زمانی که **x** کمتر از **5** است، **1** به **x**
افزوده می شود. وقتی دیگر چنین نباشد، تابع دوم
با **نادرست** پاسخ می دهد و در نتیجه اجرای
تابع نخست پایان می یابد. توجه داشته باشید که **x** بیرون از
تابع تعریف شده و یک متغیر سراسری است. برای آشنایی بیشتر با قواعد دامنه،
فصل توابع را ببینید.

## درون یابی رشته

فهرست *kJ/kcal* را می توان
نمایش پذیرتر کرد. ترجیحا فهرست باید به این صورت باشد:

```
100 kj ➞ 23.88 kcal

200 kj ➞ 47.76 kcal
```

وقتی خروجی دلخواه را به یک قالب تبدیل می کنید، نشانه گذاری آن
می تواند این باشد:

```
number1 kJ ➞ number2 kcal
```

این یعنی **number1** نماینده مقدار kJ و **number2** نماینده
مقدار kcal است. درون یابی رشته در XOScript این گونه عمل می کند. در
XOScript برای این کار نیازی به قواعد دستوری جداگانه نیست. کافی است
واژه ای را که باید جایگزین شود با متن جایگزین به عنوان آرگومان
به متن بفرستید:

```
>> text :=

⌝'number1 kJ ➞ number2 kcal'⌜

number1: 100,

number2: 23.9.
```

نتیجه:

```
100 kj ➞ 23.9 kcal
```

این قاعده جایگزینی برای هر پیام تعریف نشده ای که
یک شیء **رشته** دریافت می کند کار می کند. هر پیامی که از سوی
شیء **رشته** شناخته نشود، به این صورت تفسیر می شود: *متن پیام را
با متن درون آرگومان پیام جایگزین کن.* می توانید
برنامه را به این صورت تغییر دهید:


@test601


برای جلوگیری از سردرگمی درباره اینکه کدام پیام را می توان یا نمی توان به عنوان
جایگزین به کار برد، بهتر است یک نشانگر قالب مانند &lt; &gt;
برای بخش هایی از متن قالب که
باید جایگزین شوند معرفی کنید.

## اشیاء شبه کلاس

اگرچه xoscript کلاس ارائه نمی دهد، تقلید رفتار

در تکه کد بالا شیئی به نام Animal می سازیم.

برخلاف بیشتر زبان های برنامه نویسی محبوب در زمان نگارش،

یعنی وقتی این را می نویسید:

\>\> x := درست.

**x** به شیء **درست** ارجاع می دهد. کد شرطی و حلقه ها نیز

ثابت نیست. در واقع یک برنامه XOScript با
دستوری مانند این به کلی به هم می ریزد:

درست := نادرست.

معتبر است و بنابراین به طور رسمی مجاز است. افزون بر این، یک شیء
بولی وجود دارد که شیء ریشه هر دو **درست** و **نادرست** است، زیرا هر دو
مشتق های این شیء ریشه هستند. با این حال خود شیء بولی

# توابع

{{messages}}

می توانید کد را میان ⎬ و ⎨ گروه بندی کنید؛ در این صورت به یک تابع تبدیل می شود.
در xoscript گاهی از اصطلاح کار یا به سادگی
بلوک کد نیز استفاده می کنیم.

می توانید یک تابع را با فرستادن پیام *اجرا* اجرا کنید.


```
⎬ خروجی بنویس: 123, سطر-نو. ⎨ اجرا.
```

اگر تابع شما آرگومان می گیرد، از **اعمال:** استفاده کنید.

```
⎬ :a خروجی بنویس: a, سطر-نو. ⎨ اعمال: a.
```

مثال های زیر را نیز ببینید.
به دلیل معماری ساده، یک تابع تنها می تواند
یک نقطه بازگشت داشته باشد. برای پرهیز از سربار یا تودرتویی بیش از حد
شرط ها، می توانید از یک رویه استفاده کنید (که همانند استفاده از
علامت ضرب با آرگومان 1 است):

```
⎬
  ﴿a = 1﴾ اگر-درست: ⎬ x := 1. ⎨, بشکن.
  ﴿a = 2﴾ اگر-درست: ⎬ x := 2. ⎨, بشکن.
⎨ رویه.
```

به این شیوه، اگر a = 1 باشد، (a = 2) ارزیابی نمی شود.
همچنین به این شیوه به پیام های درست تودرتو نیازی ندارید.
هر گاه دیدید که شرط ها را تودرتو می کنید، به
پیام رویه فکر کنید. ممکن است کد شما را
خواناتر کند.


این یک دام مهم است:

```
⎬
	نادرست اگر-نادرست: ⎬
		خروجی بنویس: ⌝'End the loop.'⌜.
	⎨, بشکن.
	
	خروجی بنویس: ⌝'Dont show me.'⌜.

⎨ رویه.

```

در این حالت متن 'Dont show me' نمایش داده می شود،
زیرا **بشکن** به نادرست فرستاده می شود. اگر می خواهید
بشکن اجرا شود، باید به عنوان پیام به **درست** فرستاده شود.
 

```
⎬
	نادرست وارون اگر-درست: ⎬
		خروجی بنویس: ⌝'End the loop.'⌜.
	⎨, بشکن.
	
	خروجی بنویس: ⌝'Dont show me.'⌜.

⎨ رویه.

```

همان طور که انتظار می رود کار می کند.

## استثناها

استثناها را می توان به این صورت مدیریت کرد:

```
⎬ Task 1 ⎨ بگیر: ⎬ Task 2 ⎨, اجرا.
```

همچنین می توانید عمدا باعث رخ دادن خطا در برنامه خود شوید و
با این کار بلوک مدیریت کننده را فعال کنید. این کار با فرستادن
پیام **خطا:** به کار کنونی انجام می شود، همان طور که در
نمونه بعدی نشان داده شده است:

```
⎬
این-کار خطا: ⌝'Whoops!'⌜.
⎨ بگیر: ⎬ :mistake
خروجی بنویس: mistake.
⎨, اجرا.
```

## تزریق مقادیر

XOScript برای کارها امکان تزریق مقادیر را فراهم می کند. اکنون به
کار زیر نگاه کنید:

```
>> sending := ⎬
	Newsletter به: خودم recipient.
⎨.
sending تنظیم: ⌝'recipient'⌜
مقدار: ⌝'info@recipient.org'⌜.
sending اجرا.
```


این نمونه یک کار خیالی را نشان می دهد که یک خبرنامه
به یک نشانی ایمیل یا **recipient** می فرستد. این گیرنده را می توان
از بیرون و پیش از آغاز کار، با فرستادن
پیام **تنظیم:مقدار:** به کار، به درون کار تزریق کرد. با این کار مقدار
**recipient** از پیش در کار تنظیم می شود. این مقدار را می توان تغییر نیز داد
و سپس کار را دوباره اجرا کرد. این روشی مفید هنگام استفاده از
اشیاء کار است.

## توابع تهی

کارهای تهی مجاز نیستند. در نظریه یک کار تهی به این
شکل خواهد بود: **⎬⎨**، اما XOScript این را یک خطای زبانی می داند. اگر
می خواهید یک کار تهی اعلان کنید، می توانید از شیء هیچ استفاده کنید:

```
>> task := هیچ.
```

اگرچه این یک کار واقعی نیست، بلکه یک شیء هیچ است، همچنان می توان
پیام اجرا را به آن فرستاد:

```
>> answer := task اجرا.
```

در واقع این همانند این است:

```
>> answer := هیچ اجرا.
```

چون شیء **هیچ** پیام **اجرا** را نمی شناسد،
خودش را به عنوان پاسخ برمی گرداند و پاسخ باز هم **هیچ** می ماند.
بنابراین نیازی به داشتن یک کار تهی نیست. به لطف طراحی
زیبای زبان برنامه نویسی XOScript، می توانید به سادگی از شیء هیچ
برای این کار استفاده کنید.

**لیست ها** شمارش هایی از اشیاء با *ترتیب ثابت* هستند. واژه-نامه ها
ترتیبی ندارند و در عوض به یک راهنما شباهت دارند که شامل یک کلید (یا اصطلاح) و
مقدار متناظر آن است. لیست ها با آرایه ها (PHP، Java، C)

>> fibonacci := لیست جدید.

fibonacci بیفزا-به-پایان: 2.
fibonacci بیفزا-به-پایان: 3.
fibonacci بیفزا-به-پایان: 5.
fibonacci بیفزا-به-پایان: 8.
fibonacci بیفزا-به-پایان: 13.

## زنجیره سازی

>> x := لیست جدید ; 1 ; 2 ; 3.

اگر بخواهید عنصر نخست و آخر را پاک کنید،
پیام شما این خواهد بود:

متأسفانه نشانه گذاری پیشین درست کار نمی کند.
پیام **بردار-اولی** عنصر نخست لیست را برمی گرداند که
به نوبه خود گیرنده پیام **بردار-آخری** می شود. بنابراین
پیام **بردار-آخری** به **x** فرستاده نمی شود، بلکه به 2. یک
راه حل ممکن برای این مسئله ساختن دو جمله
جداگانه است، مانند:

```

x بردار-آخری.
```

اما این نسبتا ناکارآمد است، به ویژه وقتی لازم است
بیش از دو عنصر را پاک کنید. بنابراین XOScript یک
ساختار پیام جایگزین برای این گونه موقعیت ها ارائه می دهد. در
ساختارهای پیام **جایگزین**، پاسخ های اشیاء نادیده گرفته می شوند
و هر بار شیء گیرنده را به عنوان پاسخ پس می گیرید.
یک ساختار پیام **جایگزین** با فرستادن
پیام **آغاز-زنجیره** به یک شیء آغاز می شود و ساختار پیام **جایگزین**
را می توان با فرستادن پیام **پایان-زنجیره** به پایان برد. در
مثال نشان داده شده، این را می توان به این صورت به کار برد:

```
>> x := لیست جدید ; 1 ; 2 ; 3.
x آغاز-زنجیره بردار-اولی بردار-آخری پایان-زنجیره.
```

# واژه-نامه ها

{{messages}}

**هم لیست و هم واژه-نامه مجموعه هستند. با این حال، برخلاف یک
لیست، یک واژه-نامه ترتیبی **ندارد**. تفاوت دیگر میان این دو
این است که یک واژه-نامه از جفت های شیء تشکیل می شود. یک شیء به عنوان مدخل (یا
کلیدواژه) برای جستجوی شیء دیگر عمل می کند. یک مثال خوب از یک
لیست، یک فهرست قیمت است، مانند:


```
>> menu := واژه-نامه جدید
	بگذار: ⌝'£5'⌜ کلید: ⌝'apple pie'⌜,
	بگذار: ⌝'£6'⌜ کلید: ⌝'carrot cake'⌜,
	بگذار: ⌝'£3'⌜ کلید: ⌝'fudge'⌜.
```

همانند یک لیست، پیام بگذار:کلید:
برای افزودن یک شیء به یک لیست به کار می رود. تفاوت این است که برخلاف
یک لیست، دو شیء به هم پیوند داده می شوند. شیء نخست، همانند
یک لیست، شیئی است که در لیست ذخیره می کنید. شیء
دوم جایگاه آن در مجموعه نیست، بلکه **مدخلی** است
که امکان بازیابی شیء پیشین را در زمانی دیگر فراهم می کند. به
طور خلاصه، یک واژه-نامه کمی مانند یک فرهنگ لغت کار می کند؛ یعنی با استفاده از کلیدواژه
می توان معنا را یافت. برای مثال، برای بازیابی قیمت یک فاج از
لیست بالا:

```
>> price := menu در: ⌝'fudge'⌜.
```

همچنین می توانید از نشانه گذاری کوتاه استفاده کنید:

```
>> price := menu ? ⌝'fudge'⌜.
```

اگر مدخل هایی که برای ذخیره اشیاء به کار می برید بدون فاصله باشند
(و با پیام های از پیش تعریف شده دیگر تداخل نداشته باشند)،
می توان از نشانه گذاری بعدی نیز استفاده کرد:

```
>> menu := واژه-نامه جدید
	pie:   ⌝'£5'⌜,
	cake:  ⌝'£6'⌜,
	fudge: ⌝'£3'⌜.
```

بی گمان نشانه گذاری بالا کمی طبیعی تر خوانده می شود.
برای درخواست قیمت یک
فاج می توان از نشانه گذاری ساده شده زیر استفاده کرد:

```
>> price := menu fudge.
```

# تاریخ و زمان

# برنامه و خروجی استاندارد

{{messages}}

شیء برنامه نماینده برنامه ای است که در حال اجراست. این شیء
امکاناتی برای اجرای فرمان های سیستمی، گنجاندن زیربرنامه ها،
خواندن آرگومان ها و موارد دیگر ارائه می دهد. همه توابع مرتبط با سیستم.

## خروجی استاندارد

خروجی شیء خروجی استاندارد است. این شیء در اصل دو متد دارد:
**بنویس:** و **سطر-نو**. پیام بنویس: برای فرستادن یک رشته
به stdout به کار می رود و پیام سطر-نو یک نویسه سطر جدید چاپ می کند.
به جای **سطر-نو** می توانید از \\n نیز استفاده کنید.

مثال:

```
خروجی بنویس: ⌝'Hello World'⌜, سطر-نو.
```

نتیجه:

```
Hello World
```

## ماژول ها و افزونه ها

جهان XOScript را می توان با نصب ماژول ها با اشیاء سیستمی تازه
گسترش داد. یک شیء سیستمی تازه را می توان با قرار دادن پرونده ماژول
(معمولا پرونده ای با پسوند .so) در پوشه mods به جهان
XOScript افزود.

وقتی پیامی به شیئی می فرستید که از طریق
ماژول افزونه در دسترس قرار گرفته است، XOScript آن را به طور خودکار بارگذاری می کند.

همچنین می توانید خودتان افزونه بنویسید. افزونه ها به
زبان برنامه نویسی C نوشته می شوند. یک افزونه نمونه را می توانید در بسته
کد منبع در src/plugins/example بیابید.


## بازتاب

راه های گوناگونی برای کاوش
سیستم در حین اجرای برنامه وجود دارد. XOScript چند متد برای
تشخیص اینکه کدام اشیاء موجود هستند و این اشیاء به کدام پیام ها
پاسخ می دهند در اختیار دارد. نخست اینکه از هر شیء می توان پرسید که چه **نوع** است،
اما نوع ها در XOScript انعطاف پذیر و بنابراین غیر قابل اعتماد هستند.

همچنین می توان از شیء برنامه پرسید که آیا یک
شیء معین از پیش در برنامه موجود است:

```
برنامه Tool اگر-درست: ⎬ ... ⎨.
```

در مورد نام
شیئی که تنها از یک نماد تشکیل شده است، بهتر است برای پرهیز از سردرگمی از
نشانه گذاری زیر استفاده کنید:

```
برنامه بیاب: ⌝'X'⌜, اگر-درست: ⎬ ... ⎨.
```

افزون بر پرسیدن درباره اشیاء، می توان از
شیء برنامه درباره پیام ها نیز پرسید. برای مثال، می توان پرسید که آیا
شیء **عدد** پیام **بین:تا:** را می شناسد، به
شیوه ای که در زیر نشان داده شده است:

```
برنامه Number: ⌝'between:and:'⌜, سطر-نو.
```

# کارساز

{{messages}}

افزونه کارساز در xoscript امکاناتی برای
ساختن برنامه های سمت کارساز ارائه می دهد. برای بارگذاری افزونه
کارساز از این استفاده کنید:

```
Server آماده-سازی.
```

برای راحتی شما همچنین توصیه می شود
پرونده های webtools.xo و template.xo را بارگذاری کنید.

```
برنامه به-کار-ببر: ⌝'webtools.xo'⌜.
برنامه به-کار-ببر: ⌝'template.xo'⌜.

```

## تنظیمات کارساز

می توانید تنظیمات کارساز زیر را تعیین کنید:

```
	# default values are given
	# so if you do not set anything these
	# values are used...

	برنامه 
	پیکربندی: ⌝'max-postfields'⌜
	مقدار: 40.

	برنامه 
	پیکربندی: ⌝'max-contentlength'⌜
	مقدار: 2000000. # 2MB

	برنامه 
	پیکربندی: ⌝'max-time'⌜
	مقدار: 5000. # 5sec

```

## سلام دنیا

این یک برنامه وب بسیار ساده است که می توانید آن را با یک
کارساز CGI استاندارد مانند Apache2، NGINX، OpenHTTPD یا هر کارساز
شناخته شده دیگری به کار ببرید.

```
#!/bin/xo

Server آماده-سازی.
برنامه به-کار-ببر: ⌝'webtools.xo'⌜.

>> web-document := سند-وب جدید.

web-document خروجی-بده: ⌝'
<html>
<body>
<b>Hello World!</b>
</body>
</html>'⌜.

```

اگر نمی خواهید از شیء سند-وب استفاده کنید، اشکالی ندارد، اما
در آن صورت باید سرآیندهای HTTP را خودتان بنویسید:

```
#!/bin/xo
خروجی بنویس: ⌝'Content-type: text/html; charset=utf-8 \n\n'⌜, سطر-نو.
خروجی بنویس: ⌝'hello world!'⌜, سطر-نو.
``` 

## درخواست

شیء درخواست-HTTP را می توان برای به دست آوردن داده های GET/POST/COOKIE و
UPLOAD به کار برد:

```
>> درخواست-http  := درخواست-HTTP جدید.
>> search   := درخواست-http get: ⌝'search'⌜. # ?search=books
>> password := درخواست-http post: ⌝'password'⌜. # from form
>> selected := درخواست-http get-فهرست: ⌝'sel[]'⌜. #?sel[]=1&sel[]=2
>> selected := درخواست-http post-فهرست: ⌝'sel[]'⌜.
>> cookie   := درخواست-http cookie: ⌝'session-id'⌜.
>> upload   := درخواست-http upload: ⌝'file'⌜.
>> temppath := upload ? 1.
>> filename := upload ? 0.
```

## حداکثر پست و طول

حداکثر پیش فرض فیلدهای پست 40 و حداکثر پیش فرض طول
محتوا 2MB است. برای پیکربندی متفاوت برای هر اسکریپت:

```
برنامه پیکربندی: ⌝'max-contentlength'⌜ مقدار: 1. 
برنامه پیکربندی: ⌝'max-postfields'⌜ مقدار: 1. 
```

{{note}}
اگر طول محتوا از حداکثر فراتر رود،
فرایند کشته می شود، زیرا دیگر نمی توانیم مطمئن باشیم
که محموله امن است.
{{/note}}

محدودیت maxtime حداکثر زمان به میلی ثانیه را
برای خواندن stdin/postdata تعیین می کند.

```
برنامه پیکربندی: ⌝'max-time'⌜ مقدار: 5000. # 5sec
```

این تنها به خواندن ورودی و خروجی پست مربوط می شود و از
حملاتی شبیه slowloris جلوگیری می کند. اگر واقعا می خواهید زمان
اجرای هر عملیاتی را محدود کنید، از برنامه مهلت: استفاده کنید.

## پایگاه داده

شیء Database را می توان برای پرس و جو از MariaDB/MySQL به کار برد.
برای اتصال به یک پایگاه داده:

```
>> db := Maria-DB جدید میزبان: ⌝'localhost'⌜,
	نام-کاربری: ⌝'xo'⌜,
	گذرواژه: ⌝'pass123'⌜,
	نام-پایگاه: ⌝'xobase'⌜,
	وصل-شو.

```

برای درج یک رکورد از این استفاده کنید:

```
>> پارامترهای-جستجو := db پرس-و-جو: ⌝'
	INSERT INTO book (id, description, price, rating) 
	VALUES (NULL, ?, ?, ?)
'⌜, پارامترها: ﴿ لیست جدید ; ⌝'abc'⌜ ; 12.35 ; 6 ﴾. # parameterized queries

⎬  پارامترهای-جستجو اجرا-کن. db تایید. ⎨
بگیر: ⎬ :e db برگردان.  ⎨, اجرا.
```

توجه داشته باشید که xoscript *تنها* با تراکنش ها کار می کند و هرگز به طور خودکار تأیید نمی کند.
اگر نتوان autocommit را غیرفعال کرد، یک خطای اتصال دریافت می کنید.
همیشه برای پرس و جوها از پیوند پارامتر استفاده کنید و هرگز ورودی کاربر را مستقیما
به SQL نیفزایید.

شناسه درج شده را این گونه به دست آورید:

```
خروجی بنویس: ⌝'INSERTED: '⌜ + پارامترهای-جستجو insert-id, سطر-نو. # insert id
```

برای واکشی رکوردها:

```
>> پارامترهای-جستجو :=
db
	پرس-و-جو: ⌝'SELECT * FROM book order by id desc limit 2'⌜, 
	واکشی: ⎬ :row 
		خروجی بنویس: row id + ⌝' '⌜ + row description + ⌝': '⌜ + row price, سطر-نو.
	⎨. # fetching rows

```

## نشست ها

برای ماندگاری می توانید داده ها را در یک شیء نشست ذخیره و از آن واکشی کنید.
ابتدا یک **سند-وب** تازه بسازید. شیء سند-وب
درخواست، سرآیندها، HTML و نشست را به هم پیوند می دهد. دلیلش این است که هر گاه
با مرورگر خود از یک وب سایت بازدید می کنید، تنها HTML را می بینید. اما
کل سند-وب از **سرآیندها** نیز تشکیل می شود. برای مثال
بیشتر پاسخ های HTTP شامل سرآیندی مانند Content-type:text/html هستند تا
به مرورگر بگویند که داده های پس از آن باید به صورت HTML نمایش داده شوند
(و نه برای مثال مانند یک پرونده دریافت شوند). نشست ها راهی برای
ذخیره داده های کاربر میان درخواست ها هستند. برای پیگیری این داده ها باید
یک کوکی تنظیم کنیم؛ این کوکی نیز از طریق یک سرآیند تنظیم می شود. به همین دلیل
همه چیز در سند-وب گرد هم می آید (زیرا سند کاملی است
که هم سرآیندها و هم HTML یا داده های دیگر را در بر دارد).


```
# First we make a new Web Document instance
>> web := سند-وب جدید.

# Now we start a session, this will generate a Header for a cookie and
# create a file to store your data, associated with that cookie
>> session := web شروع-نشست.

# Now we can treat session like a dict
session userid: 123.
```

برای نابود کردن نشست (هنگام خروج از سیستم):

```
web نابودی-نشست.
```

## سرآیندها

سند-وب همچنین به شما امکان می دهد سرآیندهای شناخته شده دیگری را تنظیم کنید.
برای مثال، اگر می خواهید کاربر را به نشانی URL دیگری هدایت کنید:

```
web برو-به: ⌝'/other.html'⌜.
```

در پشت صحنه، این فرمان سرآیند HTTP را نیز تولید می کند تا
همراه با داده ها یا HTML دیگر شما فرستاده شود و به مرورگر دستور دهد
به نشانی مقصد مشخص شده برود.

برای افزودن یک سرآیند سفارشی:

```
web سرآیند: ﴿ 
	سرآیند-HTTP جدید
	کلید: ⌝'Content-Length'⌜
	مقدار: 400
﴾.
```

برای نمایش یک صفحه 404:

```
web یافت-نشد: ⌝'OOps..'⌜.
```


## قالب ها

سیستم قالب پیش فرض بسیار ساده است. لازم نیست
نحو قالب تازه ای یاد بگیرید. همچنین موتور قالب جدایی واقعی
میان نمایش و منطق کسب و کار را تضمین می کند.

برای ساختن یک قالب از یک پرونده:

```
>> tpl := web شابلون: ⌝'templates/ux.tpl'⌜.
```

سیستم قالب از نشانگرها استفاده می کند.
سه نوع نشانگر وجود دارد: نشانگرهای برش، نشانگرهای چسباندن و
نشانگرهای جایگاه. ایده پایه واقعا ساده است: نواحی ای را که
با نشانگرهای برش مشخص شده اند می بُرید و می توانید آن ها را در
نواحی مشخص شده با نشانگرهای چسباندن بچسبانید. می توانید رشته ها را در
نشانگرهای جایگاه تزریق کنید.

بنابراین برای مثال، با قالب زیر، بیایید
گوهر را در جعبه جواهر بگذاریم و یک برچسب قیمت بیفزاییم.

```
<!-- cut:gem -->
<img src="gem.gif">
<b>$<!-- slot:price --></b>
<!-- /cut:gem -->

<div id="box">
<!-- paste:jewels -->
</div>
```

## عبور مستقیم

برای ارائه امن پرونده های بارگذاری شده از سوی کاربر می توانید به passthru تکیه کنید:

```
>> uploaded := ⌝'smile.gif'⌜.
Server عبور-بده: uploaded پیشوند: ⌝'/uploads/images/'⌜.
برنامه پایان.
```

این کار محتوای بارگذاری شده از سوی کاربر را با نوع
mime مناسب ارائه می کند. تنها نوع های mime موجود در فهرست مجاز پشتیبانی می شوند:
GIF، JPG، PNG، WEBP، MP4، WEBM، MP3، ZIP، GZIP، PDF و SVG.
پرونده های SVG، ZIP و GZIP به صورت دریافت فرستاده می شوند، زیرا یک SVG
می تواند اسکریپت هایی داشته باشد که در غیر این صورت روی دامنه شما اجرا می شوند.
این روش از حملات TOCTOU، پیمایش مسیر،
اجرای کد مخرب (تزریق)، حملات symlink،
حملات DDoS (محدودیت پرونده = 50MB)، حملات شنود و
مشکلات امنیتی گوناگون دیگر جلوگیری می کند.

## عبارت های باقاعده

می توانید با ساختن یک الگو از عبارت های باقاعده استفاده کنید.
برای مثال، برای تطبیق href ها و target های پیوندها:

```
الگو جدید: ⌝'href="([^"]+)" target="([^"]+)"'⌜.
```

اکنون الگو را به این صورت روی رشته موضوع اعمال کنید:

```
pattern تطبیق: موضوع انجام: ⎬ :m :x .... ⎨
```

مثال کامل:

```
>> موضوع := ⌝'<html>
	<a href="http://link1" target="_blank">
	<a href="http://link2" target="_blank">
</html>'⌜.
>> pattern := الگو جدید: ⌝'href="([^"]+)" target="([^"]+)"'⌜.
>> result  := pattern تطبیق: موضوع انجام: ⎬ :m :x
	خروجی بنویس: m, سطر-نو.
	خروجی بنویس: x, سطر-نو.
	<- ⌝'XXX'⌜.
⎨.
خروجی بنویس: result, سطر-نو.
```

## قالب بندی

شیء قالب به شما امکان می دهد داده ها را قالب بندی کنید، مانند لایه گذاری یا
افزودن صفرها. این شیء از نحو printf استفاده می کند.

```
>> fmt := قالب جدید: ⌝'%06.0f'⌜.
fmt اعمال: 56. # gives 000056
```

یک قالب می تواند یک تبدیل داشته باشد و این تبدیل باید با مقدار سازگار باشد،
در غیر این صورت یک خطا دریافت می کنید:

- `اعمال:` با یک رشته: `%s`
- `اعمال:` با یک عدد: `%f`، `%e`، `%g` یا `%a`
- `اعمال-صحیح:` با یک عدد: `%d`، `%i`، `%o`، `%u`، `%x` یا `%c`

مقادیر یک درخواست رشته هستند. برای قالب بندی یکی از آن ها به صورت عدد،
ابتدا آن را تبدیل کنید:

```
fmt اعمال: ﴿درخواست-http get: ⌝'amount'⌜﴾ به-عدد.
```

FFI بر پایه سکو یا افزونه فراهم می شود، زیرا
به معماری سیستم زیرین وابسته است، کاری که
هسته قرار نیست انجام دهد.
افزونه کارساز یک پیاده سازی سازگار ffi/blob ارائه می دهد.
به طور پیش فرض هسته از طریق stdin/stdout، خدمات محدود ورودی و خروجی پرونده
و پوسته (برنامه سیستم:) به سکوی مقصد متصل می شود.
یکپارچه سازی کمکی از سوی ffi/blobs از طریق افزونه های
برنامه محور مانند افزونه کارساز فراهم می شود.

FFI مخفف Foreign Function Interface است. این امکان را می دهد که از امکاناتی که دیگران در
زبان های برنامه نویسی دیگر نوشته اند و از طریق پرونده های DLL، SO یا Dylib ارائه می شوند استفاده کنید. این ها می توانند
توابع گوناگونی باشند و از این راه گستره وسیعی از امکانات در دسترس است.
بیایید با یک مثال آغاز کنیم:

```
Server پیوند: ﴿
 لیست جدید ;
 ⌝'/usr/lib/x86_64-linux-gnu/libc.so.6'⌜ ;
 ⌝'printf'⌜ ;
 ﴿ لیست جدید ; ⌝'pointer'⌜ ; ⌝'int'⌜ ﴾ ;
 ⌝'void'⌜ ;
 ⌝'Printf'⌜ ;
 ⌝'template:number:'⌜
﴾.
>> s := Blob utf8: ⌝'FFI has %d letters.\n'⌜.
Printf template: s number: 3.
s آزاد-کن.
```

نتیجه این کد این است که موارد زیر را در خط فرمان می بینید:
FFI has 3 letters.
اکنون احتمالا فکر می کنید: «این برای چیزی به این سادگی کد زیادی است.»
یعنی آیا نمی شد این را فقط با یک فرمان Gui show حل کرد؟ پاسخ قاطعانه بله است!
اما این تنها یک مثال توضیحی است.
FFI معمولا برای کارهای پیچیده تری به کار می رود، اما آن ها مثال های خوبی
نیستند، بنابراین چیزی ساده را برگزیدم.

آرگومان های متد پیوند:

- آرگومان #1: پرونده DLL یا SO که می خواهید به کار ببرید.
- آرگومان #2: تابعی در آن پرونده که می خواهید پیوند دهید.
- آرگومان #3: لیستی با نام های نوع داده آرگومان های تابع.
- آرگومان #4: نام نوع بازگشتی تابع.
- آرگومان #5: نام شیئی که می خواهید این تابع را به آن پیوند دهید (اگر وجود نداشته باشد، به طور
خودکار ساخته می شود).
- آرگومان #6: پیامی که این تابع باید به آن پیوند داده شود.

در مثال بالا می خواهیم تابع printf از libc.so را پیوند دهیم. نام های نوع
داده را می توانید در مستندات نرم افزاری که به آن پیوند می دهید بیابید. نوع های موجود عبارتند از:
void، pointer، float، double، int، uint، char، uchar، intX و uintX،
که در آن X می تواند 8، 16، 32 یا 64 باشد.

این نوع ها به تعداد بایت های لازم برای ذخیره داده ها اشاره دارند. برای printf به یک
شیء تازه به نام Printf و پیام template:number: پیوند می دهیم. شما تابع
بیرونی را پیش از استفاده به گویش XOScript ترجمه می کنید. پیام template:number: یک
بافر با متن قالب به عنوان نخستین پارامتر انتظار دارد. این بافر را با یک شیء Blob می سازیم که
به شما امکان می دهد حافظه را به صورت دستی تخصیص دهید. شما مسئول آزاد کردن این حافظه پس از آن
با پیام آزاد-کن هستید.

می توانید یک blob حافظه را به شیوه های گوناگون پر کنید. در مثال ما آن را با متن پر می کنیم، بنابراین از
پیام utf8: استفاده می کنیم (UTF-8 یک رمزگذاری برای تبدیل متن به بایت است). همچنین می توانید یک blob را با
بایت-ها: پر کنید و لیستی از مقادیر بایت را بفرستید. برای خواندن محتوای یک blob از آغاز:طول: استفاده کنید.
بایت ها را به صورت یک لیست پس می گیرید. حتی می توانید با یک Blob با استفاده از
پیام struct: یک C-struct بسازید و دنباله ای از نوع های C را بفرستید. این ممکن است هنگام فراخوانی یک تابع C
در یک کتابخانه نرم افزاری بیرونی که اشاره گری به یک struct انتظار دارد لازم باشد.

{warning}
باید blob ها را خودتان آزاد کنید.
blob ها از سوی زباله روب پاک نمی شوند.
{/warning}

از آنجا که blob ها را می توان با توابع بیرونی کتابخانه ها مبادله کرد،
نمی توان آن ها را به طور خودکار زباله روبی کرد (ممکن است همچنان از سوی
توابع بیرونی در حال استفاده باشند یا این توابع بیرونی بخواهند خودشان آن ها را
آزاد کنند). بنابراین در صورت لزوم باید blob ها را خودتان آزاد کنید.

برای آزاد کردن یک blob از این استفاده کنید:

```
myblob آزاد-کن.
```

برای آزاد کردن struct از این استفاده کنید:

```
mystruct آزاد-کن-struct آزاد-کن.
```

بنابراین برای یک struct باید دو پیام بفرستید: آزاد-کن-struct و آزاد-کن تا
بلوک حافظه آزاد شود.
