XOScript에 오신 것을 환영합니다
XOScript 프로젝트의 목표는 단순하고 감사(audit) 가능한 스크립트 언어를 만드는 것입니다.
단순하다는 것이 반드시 쉽다는 뜻은 아닙니다.
익숙한 프로그래밍 언어가 XOScript보다 사용하기 더 쉬울 수도 있습니다.
여기서 단순함은 다른 의미입니다.
언어와 그 동작 방식에 대한 완전한 사고 모델을 머릿속에 그릴 수 있다는 뜻입니다.

XOScript는 머릿속에 다 들어가도록 설계되었습니다.
문법과 개념의 수는 의도적으로 적게 유지됩니다.
클래스는 없으며, 객체를 직접 확장할 수 있습니다.
객체는 참조로 전달되고, 복사는 명시적으로 해야 하며,
함수의 출구는 하나뿐입니다.

이러한 선택 중 일부는 주류 언어와 크게 다릅니다.
예를 들어 XOScript에는 타입 시스템이 없으며 동적 스코핑을 사용합니다.
처리할 수 없는 메시지는 예외를 발생시키지 않고 무시됩니다.
이러한 선택에는 결과가 따르며, 오류를 없애려는 것이 목적은 아닙니다.
목적은 언어의 근본 모델을 작고 일관되게 유지하는 것입니다.

XOScript는 현지화도 가능하므로, 비즈니스 규칙을 자연어로
표현하고 이를 비기술 이해관계자와 공유할 수도 있습니다.

감사 가능성이란 같은 철학을 구현에도 적용한다는 뜻입니다.
런타임은 C로 작성되었으며, 손으로 작성한 작은 렉서, 파서, 트리 워커로 이루어져 있습니다.
표준 라이브러리와 런타임은 대체로 언어의 구조를 그대로 반영하므로,
XOScript 코드와 그 구현 사이의 관계가 비교적 직접적입니다.

테스트 또한 문서와 밀접하게 연결되어 있습니다.
각 메서드에는 매뉴얼에 포함할 수 있는 테스트가 있어야 하며,
이를 통해 문서가 구현과 일치하도록 유지됩니다.

XOScript는 기능이나 친숙함으로 주류 언어와 경쟁하려는 것이
아닙니다. XOScript는 다른 목표를 탐구합니다.
개발자가 전체를 이해할 수 있는 프로그래밍 환경입니다.

작은 언어와 작은 구현 덕분에 소프트웨어를
바이트에서 객체까지, 문법에서 런타임까지 이해하는 것이 현실적으로 가능해지고,
스크립트에서 일어나는 일과 내부에서 일어나는 일을 모두 이해하기 때문에
자신 있게 코드를 작성할 수 있기를 바랍니다.

xoscript 서버 구성의 아키텍처는
단순하면서도 유연합니다.

{{architecture.png}}

xoscript를 서버 언어로 사용하려면 서버 플러그인을
/mods/server라는 폴더에 설치해야 합니다. 

예를 들어 PHP나 Python과 달리,
핵심 언어를 서버 전용 기능과 분리하는 것을 선호하기 때문입니다.
그렇지 않으면 아무 목적도 없이 모든 사람에게 온갖 것을
다 담아 배포해야 하는데, 이는 그저 어리석은 일입니다.
원한다면 다른 모듈도 설치할 수 있습니다. 시스템은 매우
유연합니다.

또한 템플릿 처리나 세션 처리처럼 스크립트 언어 자체로
구현하는 편이 나은 기능도 있으므로, 편의를 위해
template.xo와 webtools.xo 라이브러리도 함께 제공합니다.
이 모든 것의 이유는 여러분이 xoscript를 어떻게 사용하고 싶어 할지
우리가 알 수 없기 때문입니다. 서버 측 스크립트 언어로 사용할 수도 있지만,
GUI, 임베디드 장치 또는 단순한 일괄 처리에도 사용할 수 있습니다.
서버 측 스크립트 언어로 사용하더라도(현재 주요 사용 사례 중
하나입니다), 다른 템플릿 엔진이나 다른 세션 핸들러를
사용하고 싶을 수 있습니다.
우리 것을 써야 한다고 우리가 정할 이유가 있을까요?

하지만 우리 템플릿 엔진을 사용하면 템플릿을 만들기 위해
추가 문법을 배울 필요가 없다는 장점이 있습니다.
xoscript와 함께 제공되는 기본 템플릿 엔진은 표현과 로직을
100% 분리합니다. 특별한 템플릿 문법 대신
매우 유연한 슬롯 마커 시스템을 사용할 뿐입니다.
자세한 내용은 서버 장을 참조하십시오.

기본 템플릿 엔진이나 기본 webtools를 사용하고 싶지 않다면,
당연히 직접 대안을 마련해야 합니다.

웹 서버를 chroot, jail 또는 다른 종류의 샌드박스에서 실행한다면
그 환경에도 xo의 의존성을 설치해야 합니다. 필요한 라이브러리는
ldd로 확인할 수 있습니다(Linux 또는 BSD의 매뉴얼 페이지 참조).
xo 스크립트에서 셸 명령을 사용하려면 셸(bash나 ksh 등)도
이 환경에 복사하십시오.

또한 우리는 하위 호환성을 매우 중요하게 여긴다는 점을 말씀드립니다.
'version'이라는 특별한 하위 호환성 기능도 있습니다.
일반적으로 우리는 여러분의 코드가 영원히 실행되도록 하는 것을 목표로 합니다. 따라서
새 버전의 xoscript와 호환되도록 코드를 업데이트할 필요가
전혀 없습니다. 우리의 목표는 한 번 작성하면 영원히 실행되는 것입니다.

이 매뉴얼의 나머지 부분은 프로그래밍 언어 xoscript를 자세히
설명하는 데 할애됩니다. 서버 스크립팅은 서버라는 장에서
다룹니다. 숙련된 소프트웨어 개발자라면 몇몇 장을 건너뛰어도
좋습니다. 일부 장은 다소 지나치게 자세하거나 일반적인
프로그래밍 관행과 매우 비슷하기 때문입니다. 따라서 이미 여러
다른 프로그래밍 언어를 경험한 분이라면
이 매뉴얼을 참고 안내서로 활용하는 것이 좋습니다.

## Linux 설정

apache2와 mariadb를 다운로드합니다:


```
sudo apt-get install apache2 mariadb-server
sudo a2enmod cgi
```

xoscript를 다운로드합니다.
X를 올바른 버전 번호로 바꾸십시오!

```
wget https://xoscript.com/downloads/xoserver-linux-1_5_X.tar.gz
tar xvf xoserver*.tar.gz
```

파일을 웹 루트와 /bin에 복사합니다:


```
sudo cp bin/xo /bin/xo
sudo cp -R bin/mods /var/www/html/
sudo cp *.xo /var/www/html/
```

apache2 설정을 편집합니다:

```
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

Virtualhost를 다음으로 바꿉니다:

```
<VirtualHost *:80>
    <Directory /var/www/html>
        Options +ExecCGI
        AllowOverride All
        AddHandler cgi-script .xo
        Require all granted
    </Directory>
    DocumentRoot /var/www/html
</VirtualHost>
```

테스트 페이지를 만듭니다:

```
sudo nano /var/www/html/test.xo
```

그리고 작은 테스트 프로그램을 작성합니다:

```
#!/bin/xo
Server 초기화.
프로그램 사용: ['webtools.xo'].
>> web := 웹문서 새로.
web 출력: ['Hello World'].
```

apache2가 CGI를 통해 프로그램을 실행할 수 있도록 허용합니다:

```
sudo chmod uog+x /var/www/html/test.xo
```

apache2를 다시 시작합니다:

```
sudo systemctl restart apache2
```

브라우저에서 테스트 페이지로 이동합니다:

```
http://localhost/test.xo
```

다음과 같이 표시되어야 합니다:

```
Hello World
```


## OpenBSD 설정

/etc/httpd.conf를 편집하여 다음을 추가합니다:


```
server "mydomain.com" {
    listen on * port 80
    root "/htdocs/mydomain/"

    location "*.xo" {
        fastcgi
        fastcgi socket "/run/slowcgi.sock"   # inside chroot
    }
}
```

SSL을 사용하려면:

```
listen on * tls port 443
tls {
	certificate "/etc/ssl/mycert.crt"
	key "/etc/ssl/private/mykey.key"
}
```

키 교환을 양자 컴퓨터 공격으로부터 보호하려면
mlkem 암호를 선택합니다:

```
tls {
 ... 
 ecdhe "X25519MLKEM768"
 ...
}
```

xo 바이너리와 mods, 그리고 모든 의존성을
chroot에 추가합니다(ldd로 확인하십시오).

## 예제 실행


패키지에 포함된 예제 프로그램 중 하나를 실행하려면:

```
./example.sh <name> <Linux/OBSD> [clean]
```

예를 들어 Linux에서 FizzBuzz 예제를 실행하려면:

```
./example.sh fizzbuzz Linux
```

같은 예제를 OpenBSD에서 실행하려면:

```
./example.sh fizzbuzz OBSD
```

깨끗한 빌드로 예제를 실행하려면:

```
./example.sh fizzbuzz OBSD clean
```

## 단위 테스트

단위 테스트를 실행하려면:

```
./runtests.sh
```

빌드하지 않고 단위 테스트만 실행하려면:

```
./runtests.sh nobuild
```

## 빌드

Linux에서 소스로부터 빌드하려면:

```
make clean
ISO="en" make
```

OpenBSD에서는:

```
make -f makefile.obsd clean
ISO="en" make -f makefile.obsd
```

Linux에서 서버 플러그인을 빌드하려면:

```
PACKAGE="server" NAME="server.so" make plugin-clean
ISO="en" PACKAGE="server" NAME="server.so" make plugin
```

OpenBSD에서 서버 플러그인을 빌드하려면:

```
PACKAGE="server" NAME="server.so" make -f makefile.obsd plugin-clean
ISO="en" PACKAGE="server" NAME="server.so" make -f makefile.obsd plugin
```

## Hello world

파일을 컴퓨터로 내려받은 후 압축을 풀고
다음 명령으로 xo를 시작할 수 있습니다:

```
xo
```

XOScript를 실행하려면 프로그램을 파일로 저장하고 -xo
접미사를 붙입니다(선택 사항). 그리고 XOScript 명령 뒤에
프로그램의 파일 이름을 넣습니다:

```
xo myprogram.xo
```

프로그램 파일을 매개변수로 하여 XOScript 명령을 실행하면
xo가 프로그램 파일을 읽고 실행합니다.

{{note}}
프로그램을 xo 아이콘으로 끌어다 놓아서 시작할 수도 있습니다.
{{/note}}

{{warning}}
일부 시스템에서는 미리 xo에 동적 라이브러리를 불러올
권한을 허용해야 합니다.
{{/warning}}

전통적으로 새로운 프로그래밍 언어의 첫 프로그램은
세상에 보내는 일종의 인사여야 합니다. XOScript에서
그러한 **Hello world** 프로그램은 다음과 같습니다:

@test598

이 텍스트를 hello.xo 같은 파일에 저장하면 다음과 같이
실행할 수 있습니다: .

xo hello.xo

Hello world


위에 보이는 검은 창에서 프로그램 출력을 볼 수 있습니다.
이 매뉴얼 전체에서 출력을 보여 줄 때 같은 방식의 표현을
사용합니다.

{{note}}
출력(영어로 Out)은 대문자 O로 씁니다.
일반적으로 객체는 대문자로 시작합니다.
단, 인스턴스 역할을 하는 경우(자체 메서드 없이
데이터만 가진 경우)는 예외입니다. 이는 다른
프로그래밍 언어의 클래스와 인스턴스 관례를 반영한 것입니다.
{{/note}}


## 구문 

XOScript는 *순수* *객체 지향* 프로그래밍 언어입니다. 이는
xoscript가 모든 것을 객체로 간주하므로 다른 *데이터 타입*이
없다는 뜻입니다. XOScript로 작성된 프로그램에는 본질적으로 세 가지
기본 동작이 있습니다. *대입*, *메시지 보내기*, 그리고 *응답*입니다.
객체 사이에 메시지를 주고받는 것이 XOScript 프로그램의 핵심입니다.
세 가지 개별 동작은 아래와 같습니다:


동작            | 예
--------------- | --------
대입            |  \>\> x := 1. 
단항 메시지     | x 짝수?.
이항 메시지     | 1 + 2.
키워드 메시지   | x 시작: 0 길이: 10.
응답            | <- answer.  


이 장에서는 XOScript 언어의 전반적인 인상을 전하고 기본 원리를
설명합니다. XOScript는 작은 언어이며 세 가지 동작(그림 참조)에
기반하고, 이는 대략 여섯 개의 문법 규칙으로 이어집니다. 언어를
익히는 데 필요한 것은 이것이 전부입니다.

바로 이해되지 않더라도 걱정하지 마십시오. 모든 구성 요소는
다음 장(3)에서 살펴보며 기본 규칙도 다시 설명합니다. 다만 이번
장은 주로 언어에 대한 전반적인 소개 역할을 합니다. 기본 원리를
간단히 설명하고 관련 예제 몇 가지로 보여 줍니다. 빠진 세부 사항은
나중에 설명합니다.

XOScript에서 주석은 \# 기호로 시작합니다. 따라서 다음 줄은
무시됩니다:

```
# this is just a comment
```

## 변수

변수를 대입하려면 변수 선언 기호 >>를 사용합니다. 변수 이름에는
다음을 제외한 모든 기호를 사용할 수 있습니다: <-, :=, 공백,
마침표, 쉼표, 콜론, 따옴표 [' '], 괄호 ().
또한 변수는 여러 줄에 걸칠 수 없습니다. 변수는 숫자나 빼기 기호로
시작할 수 없다는 점에 유의하십시오.

다음은 올바른 변수의 예입니다:

```
>> password := ['Secret'].
>> ♡♡♡ := 3.
>> $ := ['dollar'].
>> +plus := 참.
>> user-password := ['Pssst!'].
```

올바르지 않은 변수의 예는 다음과 같습니다:


```
>> -123 := ['negative number'].
>> password of user := ['Classified'].
>> password.of:user := ['Classified'].
>> ,x := 10.
```

{{note}}
문자열 리터럴 안에서는 렉서에 모호함을
일으키지 않는 한 어떤 문자도(따옴표, 큰따옴표,
문자열 경계 포함) 이스케이프할
필요가 없습니다.
{{/note}}

변수를 선언한 후에는 자유롭게 사용할 수 있습니다. 즉, 선언
기호는 변수를 처음 사용할 때(선언할 때)만 쓰면 됩니다.

좀 더 구체적으로 말하면, 변수에 곧바로 값을 대입할 수는
없습니다 *(x := 2)*. 먼저 변수를 선언해야 합니다 *(\>\>
x := 2)*. 그러나 일단 선언한 후에는 선언 기호 없이 값을
바꿀 수 있습니다*(\>\> x := 2. x := 3.)*.

변수를 선언할 때 반드시 값을 대입해야 한다는 점에 유의하십시오.
다른 프로그래밍 언어와 달리 값 없이 변수를 선언하는 것은
허용되지 않습니다. 각 변수를 초깃값에 명시적으로 연결하는 것이
필수입니다. 그렇지만 **없음** 객체로 변수를 초기화해도
됩니다. 이 경우 변수는 비어 있는 것으로 볼 수 있습니다 *(\>\> x := 없음.)*.
요컨대 초깃값 없이 변수를 선언하는 것은 허용되지 않습니다. 따라서,

```
>> x.
```

는 올바르지 않으며 오류 메시지가 표시됩니다.

{{note}}
xoscript는 변수에 동적 스코핑을 사용합니다.
자세한 내용은 함수 장을 참조하십시오.
{{/note}}


## 리터럴

XOScript는 모든 것을 객체로 간주합니다. 즉 모든 숫자, 문자열,
코드 조각이 객체입니다. 1, 2, 100, -999, 1,234 같은 숫자는
숫자 객체입니다. 작은따옴표 사이의 모든 텍스트는 문자열
객체입니다. 중괄호 {...} 사이에 묶인 모든 코드 조각은
함수 객체입니다.

리터럴          | 루트 객체    | 예
--------------- | ------------ | ----------
숫자            | 숫자         | 1,2,3... 
문자열          | 문자열       | \['hello'\]
함수            | 함수         | { 1 + 2. }.
                
     
숫자나 문자열 같은 객체는 항상 루트 객체에서 비롯됩니다. 예를 들어
모든 숫자는 **숫자** 객체에서 파생됩니다. 모든 문자열은 **문자열**에서,
모든 코드 조각은 **함수**에서 파생됩니다. 그리고 이 모든 객체는
**객체**에서 비롯되며, 이것이 사실상 모든 객체의 루트 객체입니다.


## 메시지

XOScript로 프로그래밍한다는 것은 기본적으로
객체에 메시지를 보내는 것을 뜻합니다. 객체에 메시지를 보내는
일반적인 표기법은 다음과 같습니다:

```
<object> <message>
```

예를 들어 숫자 **2**가 짝수인지 알아보려면 메시지
**짝수?**를 객체 **2**에 보냅니다:

```
2 짝수?
```

답은 **참**입니다(이것도 객체입니다). 알 수 없는 메시지는
보통 객체가 무시하므로 오류가 발생하지 않습니다. 일부 객체(예:
숫자나 문자열)는 알 수 없는 메시지에 미리 정해진 방식으로
응답합니다(이에 대해서는 나중에 자세히 설명합니다).

객체는 세 종류의 메시지를 받을 수 있습니다. 

종류            | 인수 개수
--------------- | -------------------
단항            | 0      
이항            | 1     
키워드          | 1+    


첫째, 위 예처럼 인수가 없는 **단항
메시지**가 있습니다. 둘째, 하나 이상의 인수를 갖는
**키워드 메시지**가 있습니다. 예를 들면:

```
>> x := 숫자 사이: 1 와: 10.
```

이 경우 메시지 **사이:와:**가 모든 숫자의 루트 객체인 **숫자**에
보내집니다. 결과는 1과 10 사이의 난수입니다. 마지막으로
문자 하나와 인수 하나로 이루어진 **이항 메시지**가 있습니다:

```
2 + 3
```

이것은 수학 덧셈처럼 보이지만 실제로는 또 하나의 메시지일 뿐입니다.
메시지 **+**가 인수 **3**과 함께 **2**에 보내지고, 그 결과
답 **5**가 반환됩니다. 이항 메시지는 콜론 없이 쓸 수 있습니다.

이항 메시지는 연결할 수 있습니다:

```
>> x := 3 + 2 - 1.
```

이 조각에서는 먼저 **+ 2**가 **숫자** 객체 **3**에 보내져
숫자 객체 **5**가 되고, 그다음 이 숫자에 **-1**이 보내집니다.
주의 깊은 독자라면 이 규칙이 연산자의 일반적인 수학적 우선순위와
어긋난다는 점을 알아차렸을 것입니다. XOScript는 메시지 체계의
일관성을 위해 수학적 우선순위를 무시합니다. 그 결과 다음 식은:

```
2 + 3 * 5 = 25
```

17이 아닙니다.

이는 의도된 설계입니다. 괄호를 사용하여 순서를 바꿀 수 있습니다:

```
2 + (3 * 5) = 17
```

대부분의 객체는 특정 메시지에 대한 응답으로 자기 자신을 결과로
반환합니다. 이는 후속 메시지를 보내 이 객체와 대화를 이어 가도록
해 주므로 유용합니다:

```
출력 쓰기:
[' hello '] 공백제거 대문자.
```

```
HELLO
```

여기서는 **문자열** 객체에 두 개의 메시지, 즉 **공백제거**와 이어서
**대문자**가 보내집니다.

다음 조각에서는 새 메시지가 온다는 것을 나타내기 위해 쉼표를
사용해야 합니다. 그렇지 않으면 XOScript가 혼동합니다.

```
출력 쓰기: ['Hello!'], 줄바꿈.
```

먼저 메시지 **쓰기:**가 연필 기호에 보내지고 이어서
**줄바꿈**이 보내집니다. 쉼표가 없으면 XOScript는 여러분이
**줄바꿈**을 **문자열** **Hello!**에 보내려 한다고 생각할 것이고, 이는 쓸모없는 일입니다.

메시지의 처리 순서는 다음과 같습니다. 왼쪽에서 오른쪽으로,
괄호 안의 메시지부터 시작하고 이어서 단항 메시지를 처리합니다. 그다음
이항 메시지, 마지막으로 키워드 메시지를 처리합니다. 아래
예를 보십시오:

```
출력 쓰기: 0.5 반올림 + (2 - 1), 줄바꿈.
```

XOScript는 항상 왼쪽에서 오른쪽으로 읽습니다. 먼저 메시지 **쓰기:**가
출력에 보내지고 이어서 **줄바꿈** 메시지가 보내집니다. 인수 안에서도
XOScript는 왼쪽에서 오른쪽으로 읽으므로 **0.5 반올림**을
먼저, 그다음 **+**를 처리합니다.

{{note}}
줄바꿈 메시지는 문자열에 줄 바꿈 문자를 추가합니다.
이 메시지의 영어 이름(stop)은 전신 시스템에서 따온 것입니다.
전신 시스템의 메시지에서는
문장의 끝을 나타내기 위해 STOP이라는 단어를 자주 사용했습니다
(문장 부호는 신뢰할 수 없거나 비쌌기 때문입니다).
{{/note}}

또한 **반올림**은 **단항 메시지**이므로 **+**보다 우선합니다.
괄호가 있으므로 **2 - 1**이 먼저 계산되고, 그다음 **0.5 반올림**의
결과(1)에 **1**이 더해집니다.

전체 과정의 결과는 **2**이며, 이것이 출력되는 답이기도 합니다.
쉼표 다음에는 줄바꿈 메시지가 오며, 이는 커서를 새 줄로
옮깁니다. 물론 XOScript 프로그램의 처리 순서를 완전히 이해하는
가장 좋은 방법은 연습입니다.

XOScript에서는 다른 많은 프로그래밍 언어와 달리 공백이 구문의
근본적인 일부라는 점에 주목할 필요가 있습니다. 특히 이항
메시지의 경우 공백 때문에 혼동이 생길 수 있습니다. 이항 메시지
뒤에는 항상 공백을 넣으십시오. 예를 들어 숫자를 메시지에
바로 붙일 수 없습니다: 

```
3 + 2
```

는 다음과 다릅니다 

```
3 +2
```

첫 번째 예(**3 + 2**)는 숫자 **3**에 메시지 **+**를 숫자
**2**를 인수로 하여 보냅니다. 이 경우 결과는 **5**입니다.
두 번째 예(**3 +2**)에서는 단항 메시지 **+2**가 숫자 **3**에
보내집니다. 상황에 따라 이는 전혀 다른 결과를 낳을 수 있습니다.

## 존재하지 않는 메서드

객체에 메시지를 보내면 그 메시지 이름으로 이 객체에 연결된
함수가 호출됩니다. 이해되지 않는 메시지를 보내면 받는 객체는
메시지를 무시하고, 이후의 통신을 위해 대신 자기 자신에 대한
참조를 반환합니다. 이를 관용적 메시지 전달(tolerant message passing)이라고 합니다.

예:

```
출력 쓰기: 객체 blah, 줄바꿈.
```

이는 오류를 일으키지 않습니다. 단순히 텍스트 **객체**를 출력합니다.


## 제어 흐름

XOScript에는 *반복문*과 *조건문*을 위한 별도의 문법 규칙이 필요
없습니다. if 문은 **참** 객체나 **거짓** 객체에 보내는 단순한
**참이면:** 또는 **거짓이면:** 메시지일 뿐입니다:

```

	출력 쓰기: ['Two is an even number'], 줄바꿈.
}.
```
앞의 예에서 메시지 **참이면:**가 **참**(2가 짝수인가라는 질문에
대한 답)에 보내집니다. 인수로는 추가 코드 조각, 즉 **함수** 객체가
함께 보내집니다. 이 함수는 2가 실제로 짝수라는 것을 화면에 씁니다.

*반복문*을 위한 별도의 작성 규칙도 필요 없습니다. 코드 조각을
세 번 실행하려면 그 **함수**에 인수 **3**과 함께 **\***를
보내기만 하면 됩니다:

실행될 때 **i**는 0이고, 다음 실행 때 **i** = 1이 되는

예:

정의되었으며 전역 변수라는 점에 유의하십시오. 스코핑 규칙에 대해
더 알아보려면 함수에 관한 장을 참조하십시오.

## 문자열 보간

*kJ/kcal* 목록을 더 보기 좋게 만들 수 있습니다.
목록은 다음과 같은 모양이 바람직합니다:

```
100 kj ➞ 23.88 kcal

200 kj ➞ 47.76 kcal
```

원하는 출력을 템플릿으로 바꾸면 표기법은 다음과 같을 수
있습니다:

```
number1 kJ ➞ number2 kcal
```

이는 **number1**이 kJ 값을, **number2**가 kcal 값을 나타낸다는
뜻입니다. XOScript에서 문자열 보간은 이렇게 작동합니다. 이를 위한
별도의 문법 규칙은 XOScript에 필요 없습니다. 바꿀 단어를
메시지로 하고 대체할 텍스트를 인수로 하여 텍스트에 보내기만 하면
됩니다:

```

['number1 kJ ➞ number2 kcal']

number1: 100,

number2: 23.9.
```

결과:

```
100 kj ➞ 23.9 kcal
```

이 치환 규칙은 **문자열** 객체가 받는 정의되지 않은 모든 메시지에
적용됩니다. **문자열** 객체가 인식하지 못하는 각 메시지는 다음과
같이 해석됩니다: *메시지 텍스트를 메시지 인수 안의 텍스트로 바꾼다.*
프로그램을 다음과 같이 고칠 수 있습니다:

새 객체는 기반이 되는 객체, 즉 처음에 **새로** 메시지를 보낸
객체의 모든 속성을 상속합니다.

이 예에서는 상속된 속성이 너무 많지 않은, 다소 중립적인 객체가

기반으로 만들 수 있으므로 선택은 간단합니다. 의도한 송장
시스템의 표기법은 다음과 같습니다:

현재 송장 번호는 객체에 저장되므로 그 앞에 **자기** 키워드가

## 클래스와 비슷한 객체

xoscript는 클래스를 제공하지 않지만, 클래스와 비슷한 동작을
흉내 내는 것은 아주 간단합니다. 새로 메시지를 재정의하기만 하면 됩니다.

```
>> Animal := 객체 새로.
Animal 받으면: ['새로'] 실행: {
	<- 자신 새로 초기화.
}.

Animal 받으면: ['초기화'] 실행: {
	자기 sound := ['?'].
	자기 legs  := 4.
}.
```

위의 코드 조각에서는 Animal이라는 객체를 만듭니다.
이 객체는 개나 고양이 같은 모든 종류의 동물을 위한 *청사진*
역할을 합니다. 부모 객체 Animal은 클래스와 비슷한 객체임을
나타내기 위해 대문자 A로 씁니다.
다음으로 자체 새로 메서드를 작성하여 새로 메시지를 재정의합니다.
이 경우 이 메서드는 자신에게 새로 메시지를 보내고 이어서 초기화
메시지를 보냅니다. xoscript는 기본적으로 재귀를 막기 때문에 이는
무한 루프를 일으키지 않습니다. 대신 새로 메시지를 부모
객체(객체)에 보내어 Animal의 새 인스턴스가 만들어집니다. 즉 새로
메서드를 만든 바로 그 객체를 기반으로 새 객체를 만드는 것입니다.
이는 완전히 올바른 방법입니다. 이제 초기화 메시지도 보내는데, 이는
Animal 객체의 속성이 기본값을 갖도록 보장합니다. 기본적으로
동물은 다리가 4개이고 소리는 알 수 없습니다(그래서 물음표를 씁니다).
Animal의 새 인스턴스를 만들려면 간단히 다음과 같이 쓰면 됩니다:

```
>> a := Animal 새로.
```

# 불리언

{{messages}}

이 글을 쓰는 시점의 대부분의 인기 프로그래밍 언어와 달리,
XOScript는 단 하나의 참 객체와 단 하나의 거짓 객체만 제공합니다.
다시 말해 **참**이라고 쓸 때마다 새 객체가 만들어지는 것이
아닙니다. 대신 항상 참조를 사용합니다. 따라서 다음과 같이 쓰면:

\>\> x := 참.

**x**는 **참** 객체를 참조합니다. 조건 코드와 반복문도 이 참조를
확인합니다. XOScript에서 **참**과 **거짓**의 의미는 고정되어 있지
않습니다. 실제로 XOScript 프로그램은 다음과 같은 문장에 꽤
크게 흔들립니다:

참 := 거짓.

이러한 동작의 결과는 정의되어 있지 않지만, 여전히 올바른 동작이므로
형식적으로는 허용됩니다. 또한 **참**과 **거짓** 모두의 루트 객체인
불리언 객체가 있으며, 둘 다 이 루트 객체에서 파생됩니다. 그러나
불리언 객체 자체는 실용적인 쓰임새가 없습니다.

{{messages}}

코드를 { 와 } 사이에 묶으면 함수가 됩니다.
xoscript에서는 작업 또는 단순히 코드 블록이라는 용어를
쓰기도 합니다.

함수는 메시지 *시작*을 보내서 실행할 수 있습니다.


```
{ 출력 쓰기: 123, 줄바꿈. } 시작.
```

함수가 인수를 받는다면 **적용:**을 사용합니다.

```
{ :a 출력 쓰기: a, 줄바꿈. } 적용: a.
```

아래 예제도 참조하십시오.
아키텍처가 단순하기 때문에 함수의 반환 지점은 하나뿐입니다.
조건에 대한 오버헤드나 지나친 중첩을 피하려면 절차를 사용할 수
있습니다(곱셈 기호에 인수 1을 주는 것과 같습니다):

```
{
  (a = 1) 참이면: { x := 1. }, 중단.
  (a = 2) 참이면: { x := 2. }, 중단.
} 절차.
```

이렇게 하면 a = 1인 경우 (a = 2)는 평가되지 않습니다.
또한 이 방식에서는 참이면 메시지를 중첩할 필요가 없습니다.
조건을 중첩하고 있다는 생각이 들 때마다 절차 메시지를
떠올리십시오. 코드를 더 읽기 쉽게 만들어 줄 수 있습니다.


다음은 중요한 주의 사항입니다:

```
{
	거짓 거짓이면: {
		출력 쓰기: ['End the loop.'].
	}, 중단.
	
	출력 쓰기: ['Dont show me.'].

} 절차.

```

이 경우 텍스트 'Dont show me'가 표시됩니다.
**중단**이 거짓에 보내지기 때문입니다. 중단을 실행하려면
**참**에 메시지로 보내야 합니다.
 

```
{
	거짓 부정 참이면: {
		출력 쓰기: ['End the loop.'].
	}, 중단.
	
	출력 쓰기: ['Dont show me.'].

} 절차.

```

이는 예상대로 작동합니다.

## 값 주입

XOScript는 작업에 값을 주입하는 기능을 제공합니다. 아래 작업을
살펴보십시오:

```
>> sending := {
	Newsletter 받는사람: 자기 recipient.
}.
sending 설정: ['recipient']
값: ['info@recipient.org'].
sending 시작.
```


이 예는 이메일 주소, 즉 **recipient**에게 뉴스레터를 보내는 가상의
작업을 보여 줍니다. 작업이 시작되기 전에 외부에서 작업에 메시지
**설정:값:**을 보내 이 수신자를 작업에 주입할 수 있습니다. 이렇게
하면 **recipient**의 값이 작업에 미리 설정됩니다. 이 값을 바꾼 뒤
작업을 다시 실행할 수도 있습니다. 이는 작업 객체를 사용할 때
유용한 방법입니다.

## 빈 함수

빈 작업은 허용되지 않습니다. 이론적으로 빈 작업은 **{}**처럼
보이겠지만 XOScript는 이를 언어 오류로 간주합니다. 빈 작업을
선언하고 싶다면 없음 객체를 사용할 수 있습니다:

```
>> task := 없음.
```

이것은 실제 작업이 아니라 없음 객체이지만, 그래도 시작 메시지를
보낼 수 있습니다:

```
>> answer := task 시작.
```

사실 이는 다음과 같습니다:

```
>> answer := 없음 시작.
```

**없음** 객체는 메시지 **시작**을 인식하지 못하므로 자기 자신을
답으로 반환하고, 답은 다시 **없음**이 됩니다.
따라서 빈 작업이 있을 필요가 없습니다. 프로그래밍 언어 XOScript의
우아한 설계 덕분에 이 용도로 없음 객체를 그냥 사용할 수 있습니다.

## 연결

다음과 같은 리스트가 있다고 가정해 봅시다:

```
>> x := 리스트 새로 ; 1 ; 2 ; 3.
```

첫 번째와 마지막 요소를 삭제하고 싶다면 메시지는 다음과
같을 것입니다:

```
x 첫항목꺼내기 끝항목꺼내기.
```

안타깝게도 앞의 표기법은 올바르게 작동하지 않습니다. 메시지
**첫항목꺼내기**는 리스트의 첫 번째 요소를 반환하고, 그 요소가
메시지 **끝항목꺼내기**를 받게 됩니다. 따라서 메시지
**끝항목꺼내기**는 **x**가 아니라 2에 보내집니다. 이 문제의
해결책 중 하나는 다음과 같이 두 개의 문장으로 나누는 것입니다: 

```
x 첫항목꺼내기.
x 끝항목꺼내기.
```

그러나 이는 특히 두 개보다 많은 요소를 삭제해야 할 때 다소
비실용적입니다. 그래서 XOScript는 이런 상황을 위한 대체 메시지
구조를 제공합니다. **대체** 메시지 구조에서는 객체의 답이 무시되고
매번 받는 객체가 답으로 돌아옵니다.
**대체** 메시지 구조는 객체에 메시지 **연속시작**을 보내서
시작하고, 메시지 **연속끝**을 보내서 끝낼 수 있습니다. 위의
예에는 다음과 같이 적용할 수 있습니다:

```
>> x := 리스트 새로 ; 1 ; 2 ; 3.
x 연속시작 첫항목꺼내기 끝항목꺼내기 연속끝.
```

# 사전

{{messages}}

**리스트와 사전은 모두 컬렉션입니다. 그러나 리스트와 달리
사전에는 순서가 **없습니다**. 둘 사이의 또 다른 차이는 사전이 객체
쌍으로 이루어진다는 점입니다. 한 객체는 다른 객체를 찾기 위한
표제어(또는 키워드) 역할을 합니다. 좋은 예로 다음과 같은 가격표가
있습니다:


```
>> menu := 사전 새로
	넣기: ['£5'] 위치: ['apple pie'],
	넣기: ['£6'] 위치: ['carrot cake'],
	넣기: ['£3'] 위치: ['fudge'].
```

리스트와 마찬가지로 메시지 넣기:위치:를
사용하여 객체를 추가합니다. 차이는 리스트와 달리 두 객체가
연결된다는 점입니다. 첫 번째 객체는 리스트와 마찬가지로 저장할
객체입니다. 두 번째 객체는 컬렉션 안의 위치가 아니라, 나중에 앞의
객체를 다시 찾을 수 있게 해 주는 **표제어**입니다. 요컨대 사전은
사전(딕셔너리)과 비슷하게 작동하여, 표제어를 사용해 뜻을 찾을 수
있습니다. 예를 들어 위의 목록에서 퍼지의 가격을 가져오려면:

```
>> price := menu 위치에서: ['fudge'].
```

간결한 표기법을 사용할 수도 있습니다:

```
>> price := menu ? ['fudge'].
```

객체를 저장하는 데 사용하는 표제어에 공백이 없다면(그리고 미리
정의된 다른 메시지와 충돌하지 않는다면),
다음 표기법도 사용할 수 있습니다:

```
>> menu := 사전 새로
	pie:   ['£5'],
	cake:  ['£6'],
	fudge: ['£3'].
```

위 표기법이 좀 더 자연스럽게 읽힌다는 것은 분명합니다.
퍼지의 가격을 요청하려면 다음과 같은 간단한 표기법을 사용할 수
있습니다:

```
>> price := menu fudge.
```

# 프로그램/표준 출력

{{messages}}

프로그램 객체는 현재 실행 중인 앱을 나타냅니다. 이 객체는
시스템 명령 실행, 하위 프로그램 포함, 인수 읽기 등의 기능을
제공합니다. 시스템과 관련된 모든 기능입니다.

## 표준 출력

출력은 표준 출력 객체입니다. 기본적으로 두 개의 메서드가 있습니다:
**쓰기:**와 **줄바꿈**. 쓰기: 메시지는 문자열을 stdout으로 보내는
데 사용하고, 줄바꿈 메시지는 줄 바꿈 문자를 출력합니다.
**줄바꿈** 대신 \\n을 사용할 수도 있습니다.

예:

```
출력 쓰기: ['Hello World'], 줄바꿈.
```

결과:

```
Hello World
```

## 모듈/플러그인

모듈을 설치하면 XOScript의 세계를 새로운 시스템 객체로 확장할 수
있습니다. 모듈 파일(보통 접미사가 .so
인 파일)을 mods 폴더에 넣으면 XOScript의 세계에 새 시스템 객체가
추가됩니다. 

플러그인 모듈을 통해 제공되는 객체에 메시지를 보내면 XOScript가
그 모듈을 자동으로 불러옵니다.

플러그인을 직접 작성할 수도 있습니다. 플러그인은 C 프로그래밍
언어로 작성합니다. 예제 플러그인은 소스 코드 패키지의
src/plugins/example에서 찾을 수 있습니다.


## 리플렉션

프로그램 실행 중에 시스템을 탐색하는 방법은 여러 가지가 있습니다.
XOScript에는 어떤 객체가 존재하는지, 그리고 그 객체들이 어떤
메시지에 응답하는지 알아내는 메서드가 몇 가지 있습니다. 먼저 각
객체에 어떤 **유형**인지 물어볼 수 있습니다. 그러나 XOScript의
유형은 바뀔 수 있으므로 신뢰할 수 없습니다.

주어진 객체가 이미 프로그램에 존재하는지 프로그램 객체에 물어볼
수도 있습니다:

```
프로그램 Tool 참이면: { ... }.
```

객체 이름이 기호 하나로 이루어진 경우에는 혼동을 피하기 위해
다음 표기법을 사용하는 것이 가장 좋습니다:

```
프로그램 찾기: ['X'], 참이면: { ... }.
```

객체에 대해 묻는 것 외에도 프로그램 객체에 메시지에 대해 물어볼
수도 있습니다. 예를 들어 **숫자** 객체가 메시지 **사이:와:**를
아는지 다음과 같이 물어볼 수 있습니다:

```
프로그램 Number: ['between:and:'], 줄바꿈.
```

# 서버

{{messages}}

xoscript의 서버 플러그인은 서버 측 애플리케이션을 만드는
기능을 제공합니다. 서버 플러그인을 불러오려면 다음을
사용합니다:

```
Server 초기화.
```

편의를 위해 webtools.xo와 template.xo 파일도 불러오는 것을
권장합니다.

```
프로그램 사용: ['webtools.xo'].
프로그램 사용: ['template.xo'].

```

## 서버 설정

다음 서버 설정을 지정할 수 있습니다:

```
	# default values are given
	# so if you do not set anything these
	# values are used...

	프로그램 
	설정값: ['max-postfields']
	값: 40.

	프로그램 
	설정값: ['max-contentlength']
	값: 2000000. # 2MB

	프로그램 
	설정값: ['max-time']
	값: 5000. # 5sec

```

## Hello World

다음은 Apache2, NGINX, OpenHTTPD 또는 그 밖의 잘 알려진 서버 같은
표준 CGI 서버에서 사용할 수 있는 아주 간단한 웹 프로그램입니다.

```
#!/bin/xo

Server 초기화.
프로그램 사용: ['webtools.xo'].

>> web-document := 웹문서 새로.

web-document 출력: ['
<html>
<body>
<b>Hello World!</b>
</body>
</html>'].

```

웹문서 객체를 사용하고 싶지 않다면 그래도 괜찮지만,
그 경우 HTTP 헤더를 직접 작성해야 합니다:

```
#!/bin/xo
출력 쓰기: ['Content-type: text/html; charset=utf-8 \n\n'], 줄바꿈.
출력 쓰기: ['hello world!'], 줄바꿈.
``` 

## 요청

HTTP-요청 객체를 사용하여 GET/POST/COOKIE 및
UPLOAD 데이터를 얻을 수 있습니다:

```
>> http요청  := HTTP-요청 새로.
>> search   := http요청 get: ['search']. # ?search=books
>> password := http요청 post: ['password']. # from form
>> selected := http요청 get-목록: ['sel[]']. #?sel[]=1&sel[]=2
>> selected := http요청 post-목록: ['sel[]'].
>> cookie   := http요청 cookie: ['session-id'].
>> upload   := http요청 upload: ['file'].
>> temppath := upload ? 1.
>> filename := upload ? 0.
```

## Maxpost/length

기본 최대 POST 필드 수는 40이고 기본 최대 콘텐츠 길이는
2MB입니다. 스크립트별로 다르게 설정하려면:

```
프로그램 설정값: ['max-contentlength'] 값: 1. 
프로그램 설정값: ['max-postfields'] 값: 1. 
```

{{note}}
콘텐츠 길이가 최대값을 넘으면
더 이상 페이로드가 안전하다고 확신할 수 없으므로
프로세스가 종료됩니다.
{{/note}}

maxtime 제한은 stdin/POST 데이터를 읽는 최대 시간을 ms 단위로
정합니다.

```
프로그램 설정값: ['max-time'] 값: 5000. # 5sec
```

이는 POST의 입출력 읽기에만 적용되며 slowloris 같은 공격을
막아 줍니다. 어떤 작업이든 실행 시간을 정말로 제한하고 싶다면
프로그램 제한시간:을 사용하십시오.

## 데이터베이스

Database 객체를 사용하여 MariaDB/MySQL에 쿼리할 수 있습니다.
데이터베이스에 접속하려면:

```
>> db := Maria-DB 새로 호스트: ['localhost'],
	사용자이름: ['xo'],
	비밀번호: ['pass123'],
	데이터베이스이름: ['xobase'],
	접속.

```

레코드를 삽입하려면:

```
>> 검색매개변수 := db 쿼리: ['
	INSERT INTO book (id, description, price, rating) 
	VALUES (NULL, ?, ?, ?)
'], 매개변수: ( 리스트 새로 ; ['abc'] ; 12.35 ; 6 ). # parameterized queries

{  검색매개변수 실행. db 커밋. }
예외시: { :e db 롤백.  }, 시작.
```

xoscript는 트랜잭션으로*만* 작동하며 절대 자동 커밋하지 않는다는 점에 유의하십시오.
자동 커밋을 끌 수 없으면 접속 오류가 발생합니다.
쿼리에는 항상 매개변수 바인딩을 사용하고, 사용자 입력을 SQL에
직접 넣지 마십시오.

삽입된 id는 다음과 같이 얻습니다:

```
출력 쓰기: ['INSERTED: '] + 검색매개변수 insert-id, 줄바꿈. # insert id
```

레코드를 가져오려면:

```
>> 검색매개변수 :=
db
	쿼리: ['SELECT * FROM book order by id desc limit 2'], 
	가져오기: { :row 
		출력 쓰기: row id + [' '] + row description + [': '] + row price, 줄바꿈.
	}. # fetching rows

```

## 세션

데이터를 유지하기 위해 세션 객체에 데이터를 저장하고 가져올 수 있습니다.
먼저 새 **웹문서**를 만듭니다. 웹문서 객체는 요청, 헤더, HTML,
세션을 하나로 묶습니다. 브라우저로 웹사이트를 방문하면 HTML만
보이지만, 웹문서 전체에는 **헤더**도 포함되기 때문입니다. 예를 들어
대부분의 HTTP 응답에는 Content-type:text/html 같은 헤더가 있어서
뒤따르는 데이터를 HTML로 렌더링해야 한다고(예를 들어 파일처럼
다운로드하는 것이 아니라) 브라우저에 알려 줍니다. 세션은 요청 사이에
사용자 데이터를 저장하는 방법입니다. 이 데이터를 추적하려면 쿠키를
설정해야 하는데, 이 쿠키도 헤더를 통해 설정됩니다. 그래서 모든 것이
웹문서에 모입니다(웹문서는 헤더와 HTML 또는 기타 데이터를 모두
담은 완전한 문서이기 때문입니다).


```
# First we make a new Web Document instance
>> web := 웹문서 새로.

# Now we start a session, this will generate a Header for a cookie and
# create a file to store your data, associated with that cookie
>> session := web 세션시작.

# Now we can treat session like a dict
session userid: 123.
```

(로그아웃할 때) 세션을 파기하려면:

```
web 세션파기.
```

## 헤더

웹문서를 사용하면 그 밖의 잘 알려진 헤더도 설정할 수 있습니다.
예를 들어 사용자를 다른 URL로 리디렉션하려면:

```
web 이동: ['/other.html'].
```

내부적으로 이 명령은 다른 데이터나 HTML과 함께 보낼 HTTP 헤더도
생성하여, 브라우저가 지정된 대상 주소로 이동하도록 지시합니다.

사용자 정의 헤더를 추가하려면:

```
web 헤더: ( 
	HTTP헤더 새로
	키값: ['Content-Length']
	설정값: 400
).
```

404 페이지를 표시하려면:

```
web 찾을수없음: ['OOps..'].
```


## 템플릿

기본 템플릿 시스템은 매우 단순합니다. 새로운 템플릿 문법을 배울
필요가 없습니다. 또한 템플릿 엔진은 표현과 비즈니스 로직을 진정으로
분리해 줍니다.

파일에서 템플릿을 만들려면:

```
>> tpl := web 템플릿: ['templates/ux.tpl'].
```

템플릿 시스템은 마커를 사용합니다. 
마커에는 세 종류가 있습니다: 잘라내기 마커, 붙여넣기 마커,
슬롯 마커. 기본 개념은 정말 간단합니다. 잘라내기 마커로 표시된
영역을 잘라 내어 붙여넣기 마커로 표시된 영역에 붙여 넣을 수
있습니다. 슬롯 마커에는 문자열을 주입할 수 있습니다.

예를 들어 다음 템플릿이 주어졌을 때, 보석을 보석함에 넣고
가격표를 붙여 봅시다.

```
<!-- cut:gem -->
<img src="gem.gif">
<b>$<!-- slot:price --></b>
<!-- /cut:gem -->

<div id="box">
<!-- paste:jewels -->
</div>
```

다음과 같이 할 수 있습니다:

```
>> gem := tpl 잘라내기: ['gem'], 복사.
gem price: 99.
tpl 붙여넣기: gem 위치: ['jewels'].
web 출력: tpl 표시제거.
```

마지막 줄은 필요한 HTTP 헤더와 함께 템플릿을 문자열로
클라이언트에 내보냅니다.

결과:

```
<div id="box">
<img src="gem.gif">
<b>$99</b>
</div>
```


## 패스스루

사용자가 업로드한 파일을 안전하게 제공하려면 passthru를 사용할 수 있습니다:

```
>> uploaded := ['smile.gif'].
Server 통과: uploaded 접두사: ['/uploads/images/'].
프로그램 종료.
```

이렇게 하면 사용자가 업로드한 콘텐츠를 적절한 MIME 타입으로
제공합니다. 허용 목록에 있는 MIME 타입만 지원됩니다:
GIF, JPG, PNG, WEBP, MP4, WEBM, MP3, ZIP, GZIP, PDF, SVG.
SVG, ZIP, GZIP 파일은 다운로드로 보내집니다. SVG에는 그렇지 않으면
여러분의 도메인에서 실행될 스크립트가 들어 있을 수 있기 때문입니다.
이 방법은 TOCTOU 공격, 경로 탐색(path traversal),
악성 코드 실행(인젝션), 심볼릭 링크 공격,
DDoS 공격(파일 제한 = 50MB), 스니핑 공격 및
그 밖의 다양한 보안 문제를 방지합니다.


## JSON

객체를 JSON으로 인코딩하려면:

```
>> json := ( JSON jsonify: ( 
	사전 새로 넣기: ( 
		리스트 새로 ; 1 ; 2 ; 3
	) 위치: ['abc']
)).
```

JSON을 xoscript 객체로 디코딩하려면:

```
>> dict := ((JSON 객체: json) abc ? 1).
```

중첩 수준이 500을 넘는 JSON은 올바르지 않은 것으로 거부됩니다.

사전을 올바른 헤더와 함께 json으로 바로 출력하려면:

```
web json: dict.
```


## 정규식

패턴을 만들어 정규 표현식을 사용할 수 있습니다.
예를 들어 하이퍼링크의 href와 target을 찾으려면:

```
패턴 새로: ['href="([^"]+)" target="([^"]+)"'].
```

이제 다음과 같이 대상 문자열에 패턴을 적용합니다:

```
pattern 일치: 제목 실행: { :m :x .... }
```

전체 예제:

```
>> 제목 := ['<html>
	<a href="http://link1" target="_blank">
	<a href="http://link2" target="_blank">
</html>'].
>> pattern := 패턴 새로: ['href="([^"]+)" target="([^"]+)"'].
>> result  := pattern 일치: 제목 실행: { :m :x
	출력 쓰기: m, 줄바꿈.
	출력 쓰기: x, 줄바꿈.
	<- ['XXX'].
}.
출력 쓰기: result, 줄바꿈.
```

## 서식 지정

형식 객체를 사용하면 패딩이나 0 채우기 같은 데이터 서식을
지정할 수 있습니다. printf 문법을 사용합니다.

```
>> fmt := 형식 새로: ['%06.0f'].
fmt 적용: 56. # gives 000056
```

형식에는 변환 지정자를 하나만 넣을 수 있으며 값과 맞아야 합니다.
그렇지 않으면 오류가 발생합니다:

- 문자열과 함께 `적용:`: `%s`
- 숫자와 함께 `적용:`: `%f`, `%e`, `%g` 또는 `%a`
- 숫자와 함께 `정수에적용:`: `%d`, `%i`, `%o`, `%u`, `%x` 또는 `%c`

요청에서 온 값은 문자열입니다. 숫자로 서식을 지정하려면
먼저 변환하십시오:

```
fmt 적용: (http요청 get: ['amount']) 숫자로.
```

# ffi

{{messages}}

FFI는 플랫폼/플러그인별로 제공됩니다. 핵심이 해서는 안 되는 일인
하위 시스템 아키텍처와의 결합이 필요하기 때문입니다.
서버 플러그인은 규격에 맞는 ffi/blob 구현을 제공합니다.
기본적으로 핵심은 stdin/stdout, 제한된 파일 입출력 서비스,
셸(프로그램 시스템:)을 통해 대상 플랫폼과 연결됩니다.
그 밖의 통합은 서버 플러그인 같은 애플리케이션 중심 플러그인의
ffi/blob이 제공합니다.

FFI는 Foreign Function Interface(외부 함수 인터페이스)의 약자입니다. 이를 통해 다른
사람들이 다른 프로그래밍 언어로 작성하여 DLL 파일, SO 파일 또는 Dylib 파일로 제공하는
기능을 사용할 수 있습니다. 이는 다양한 함수일 수 있으며, 이 방법을 통해 사용할 수 있는
기능의 범위는 매우 넓습니다.
예제로 시작해 보겠습니다:

```
Server 연결: (
 리스트 새로 ;
 ['/usr/lib/x86_64-linux-gnu/libc.so.6'] ;
 ['printf'] ;
 ( 리스트 새로 ; ['pointer'] ; ['int'] ) ;
 ['void'] ;
 ['Printf'] ;
 ['template:number:']
).
>> s := Blob utf8: ['FFI has %d letters.\n'].
Printf template: s number: 3.
s 해제.
```

이 코드를 실행하면 명령줄에 다음이 표시됩니다:
FFI has 3 letters.
이제 아마 "이렇게 간단한 일에 코드가 너무 많은데"라고 생각하실 것입니다.
Gui show 명령으로 해결할 수 있지 않느냐고요? 대답은 단연코 '그렇다'입니다!
하지만 이것은 설명을 위한 예제입니다.
FFI는 보통 더 복잡한 작업에 사용되지만, 그런 작업은 좋은 예제가
되지 못하므로 간단한 것을 골랐습니다.

연결 메서드의 인수는 다음과 같습니다:

- 인수 #1: 사용하려는 DLL 또는 SO 파일.
- 인수 #2: 그 파일에서 연결하려는 함수.
- 인수 #3: 함수 인수의 데이터 타입 이름을 담은 리스트.
- 인수 #4: 함수 반환 타입의 이름.
- 인수 #5: 이 함수를 연결할 객체의 이름(존재하지 않으면 자동으로
생성됩니다).
- 인수 #6: 이 함수를 연결할 메시지.

위 예제에서는 libc.so의 printf 함수를 연결하려고 합니다. 데이터
타입 이름은 연결하려는 소프트웨어의 문서에서 찾을 수 있습니다. 사용할 수 있는 타입은 다음과 같습니다:
void, pointer, float, double, int, uint, char, uchar, intX, uintX.
여기서 X는 8, 16, 32 또는 64입니다.

이 타입들은 데이터를 저장하는 데 필요한 바이트 수를 나타냅니다. printf의 경우
Printf라는 새 객체와 메시지 template:number:에 연결합니다. 외부 함수는
사용하기 전에 XOScript 방언으로 옮깁니다. 메시지 template:number:는 첫 번째
매개변수로 템플릿 텍스트를 담은 버퍼를 기대합니다. 이 버퍼는 메모리를 직접 할당할 수
있게 해 주는 Blob 객체로 만듭니다. 나중에 이 메모리를 해제 메시지로 해제하는 것은
여러분의 책임입니다.

메모리 blob은 여러 방법으로 채울 수 있습니다. 이 예제에서는 텍스트로 채우므로
utf8: 메시지를 사용합니다(UTF-8은 텍스트를 바이트로 변환하는 인코딩입니다). blob을
bytes:로 채울 수도 있으며, 이때는 바이트 값의 리스트를 넘깁니다. blob의 내용을 읽으려면
시작:길이:를 사용합니다. 바이트를 리스트로 돌려받습니다. struct: 메시지에 C 타입의
나열을 넘겨 Blob으로 C 구조체를 만들 수도 있습니다. 이는 외부 소프트웨어 라이브러리의
C 함수가 구조체에 대한 포인터를 기대할 때 필요할 수 있습니다.

{warning}
blob은 직접 해제해야 합니다.
blob은 가비지 컬렉터가 정리하지 않습니다.
{/warning}

blob은 라이브러리의 외부 함수와 주고받을 수 있기 때문에 자동으로
가비지 컬렉션될 수 없습니다(외부 함수가 계속 사용하고 있을 수도 있고,
외부 함수가 직접 해제하려 할 수도 있습니다). 따라서 필요하다면 blob을
직접 해제해야 합니다.

blob을 해제하려면:

```
myblob 해제.
```

구조체를 해제하려면:

```
mystruct struct-해제 해제.
```

따라서 구조체의 경우 메모리 블록을 해제하려면 두 메시지, 즉 struct-해제와
해제를 보내야 합니다.
