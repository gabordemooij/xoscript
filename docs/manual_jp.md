XOScriptへようこそ

XOScriptプロジェクトは、シンプルで監査可能なスクリプト言語の実現を目指しています。
シンプルであることは、必ずしも簡単に使えることを意味しません。
使い慣れたプログラミング言語のほうが、XOScriptより簡単に使える場合もあります。
ここでいう「シンプルさ」には、別の意味があります。
それは、言語そのものとその動作について、完全なメンタルモデルを構築できることです。

XOScriptは、頭の中に収まるように設計されています。
文法と概念の数は、意図的に小さく抑えられています。
クラスは存在せず、オブジェクトを直接拡張できます。
オブジェクトは参照渡しされ、コピーは明示的に行われます。
また、関数には単一の終了点があります。

これらの設計上の選択の一部は、一般的なプログラミング言語とは大きく異なります。
たとえば、XOScriptには型システムがなく、動的スコープを使用します。
処理できないメッセージは、例外を発生させるのではなく無視されます。
これらの選択にはそれぞれ結果が伴い、エラーをなくすことを目的としたものではありません。
その目的は、言語の基盤となるモデルを小さく、一貫したものに保つことです。

XOScriptはローカライズすることもできるため、ビジネスルールを自然言語で記述し、
技術者ではない関係者とも共有できる可能性があります。

監査可能性という考え方は、実装にも同じ哲学を適用することを意味します。
ランタイムはCで記述されており、小規模な手書きの字句解析器、パーサー、ツリーウォーカーで構成されています。
標準ライブラリとランタイムは、言語の構造をおおむねそのまま反映しているため、
XOScriptのコードとその実装との関係を比較的直接的に追うことができます。

テストもドキュメントと密接に結び付いています。
各メソッドには対応するテストを用意し、それをマニュアルに組み込めるようにすることで、
ドキュメントと実装の同期を保ちやすくしています。

XOScriptは、機能の多さや使い慣れた構文によって一般的なプログラミング言語と競争することを目的としていません。
XOScriptが探求しているのは、別の目標です。
それは、開発者が全体を一つのものとして理解できるプログラミング環境です。

小さな言語と小さな実装を組み合わせることで、
バイトからオブジェクトまで、構文からランタイムまでソフトウェアを理解することが現実的になり、
スクリプト内で何が起きているのか、そしてその裏側で何が起きているのかの両方を理解したうえで、
確信を持ってコードを書けるようになることを目指しています。

xoscriptサーバー構成のアーキテクチャは、
シンプルでありながら柔軟です。

## Setup Linux

Apache2とMariaDBをインストールします。


```
sudo apt-get install apache2 mariadb-server
sudo a2enmod cgi
```

xoscriptをダウンロードします。
Xは正しいバージョン番号に置き換えてください。

```
wget https://xoscript.com/downloads/xoserver-linux-1_5_X.tar.gz
tar xvf xoserver*.tar.gz
```

ファイルをWebルートと/binにコピーします。


```
sudo cp bin/xo /bin/xo
sudo cp -R bin/mods /var/www/html/
sudo cp *.xo /var/www/html/
```

Apache2の設定を編集します。

```
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

VirtualHostを次の内容に置き換えます。

```
<VirtualHost *:80>
    <Directory /var/www/html>
        Options +ExecCGI
        AllowOverride All
        AddHandler cgi-script .xo
        Require all granted
    </Directory>
    DocumentRoot /var/www/html
</VirtualHost>
```

テストページを作成します。

```
sudo nano /var/www/html/test.xo
```

そして、簡単なテストプログラムを記述します。

```
#!/bin/xo
Server init.
Program use: ['webtools.xo'].
>> web := Web-Document new.
web out: ['Hello World'].
```

CGI経由でApache2がプログラムを実行できるようにします。

```
sudo chmod uog+x /var/www/html/test.xo
```

Apache2を再起動します。

```
sudo systemctl restart apache2
```

ブラウザーでテストページを開きます。

```
http://localhost/test.xo
```

次のように表示されるはずです。

```
Hello World
```


## Setup OpenBSD

/etc/httpd.confを編集し、次の内容を追加します。


```
server "mydomain.com" {
    listen on * port 80
    root "/htdocs/mydomain/"

    location "*.xo" {
        fastcgi
        fastcgi socket "/run/slowcgi.sock"   # inside chroot
    }
}
```

xoバイナリとmods、および必要な依存関係をchroot内に追加します
（lddを使用して必要なものを確認してください）。

## Syntax

XOScriptは*純粋な* *オブジェクト指向*プログラミング言語です。
これは、xoscriptではすべてをオブジェクトとして扱うことを意味します。
したがって、その他の*データ型*は存在しません。
XOScriptで記述されたプログラムには、基本的な処理として
*代入*、*メッセージ送信*、*応答*の3つがあります。
オブジェクト間でメッセージを交換することが、XOScriptプログラムの中心的な要素です。
この3つの基本的な処理を以下に示します：

| 操作 | 例 |
|---|---|
| 代入 | `>> x := 1.` |
| 単項メッセージ | `x even?.` |
| 二項メッセージ | `1 + 2.` |
| キーワードメッセージ | `x from: 0 length: 10.` |
| 戻り値 | `<- answer.` |

この章では、XOScriptという言語についての全体的な印象を説明し、その基本原則を紹介します。XOScriptは小さな言語であり、3つの操作（図を参照）を基盤として構成されています。これらはおよそ6つの文法規則に対応しています。言語を習得するために必要なのは、それだけです。

すぐにはすべてが明確に理解できなくても心配ありません。すべての構成要素については次の章（3）で詳しく説明し、基本的な規則も繰り返し取り上げます。ただし、この章は主に言語全体への導入を目的としています。基本原則を簡単に説明し、いくつかの関連する例を使って示します。ここでは扱わない詳細については、後の章で説明します。

XOScriptでは、コメントの先頭に\#記号を付けます。そのため、次の行は無視されます。

```
# this is just a comment
```

## Variables

変数を代入するには、変数宣言記号 `>>` を使用します。変数名には、`<-`、`:=`、空白文字、ピリオド、コンマ、コロン、引用符 `[' ']`、括弧 `()` を除くすべての記号を使用できます。
また、変数を複数行にわたって記述することはできません。
変数名は数字またはマイナス記号から始めることもできません。

以下は有効な変数の例です：

```
>> password := ['Secret'].
>> ♡♡♡ := 3.
>> $ := ['dollar'].
>> +plus := True.
>> user-password := ['Pssst!'].
```

無効な変数の例：

```
>> -123 := ['negative number'].
>> password of user := ['Classified'].
>> password.of:user := ['Classified'].
>> ,x := 10.
```

{{note}}
文字列リテラル内では、字句解析器にとって曖昧さが生じない限り、
引用符、二重引用符、文字列の境界を含め、どの文字も
エスケープする必要はありません。
{{/note}}

変数を一度宣言すると、その後は自由に使用できます。
つまり、変数を最初に使用するとき（宣言時）だけ宣言記号を使えばよいということです。

より具体的に言えば、変数に対してランダムに値を代入し始めること（`x := 2`）はできません。
まず変数を宣言する必要があります（`>> x := 2`）。
しかし、一度宣言した後は、宣言記号を使わずに値を変更できます（`>> x := 2. x := 3.`）。

変数を宣言するときには、必ず同時に値を代入する必要があることに注意してください。
他のプログラミング言語とは異なり、値を持たない変数を宣言することはできません。
各変数を初期値に明示的に結び付けることが重要です。
ただし、変数を**None**オブジェクトで初期化することはできます。
この場合、その変数は空であるとみなすことができます（`>> x := None.`）。
つまり、初期値を持たない変数を宣言することはできません。

したがって、

```
>> x.
```

は無効であり、エラーメッセージが表示されます。

{{note}}
xoscriptでは変数に動的スコープを使用します。
詳細については、Functionsの章を参照してください。
{{/note}}


## Literals

XOScriptでは、すべてをオブジェクトとして扱います。つまり、すべての数値、文字列、コード断片もオブジェクトです。
1、2、100、-999、1,234などの数値はNumberオブジェクトです。
単一引用符で囲まれたすべてのテキストはStringオブジェクトです。
波括弧 `{...}` で囲まれたすべてのコード断片はFunctionオブジェクトです。

| リテラル | ルートオブジェクト | 例 |
|---|---|---|
| 数値 | Number | `1,2,3...` |
| 文字列 | String | `['hello']` |
| 関数 | Function | `{ 1 + 2. }` |

数値や文字列などのオブジェクトは、常にルートオブジェクトを起源としています。
たとえば、すべての数値は**Number**オブジェクトから派生します。
すべての文字列は**String**から、すべてのコード断片は**Function**から派生します。
そして、これらすべてのオブジェクトは**Object**から派生しています。
実際、**Object**はすべてのオブジェクトのルートオブジェクトです。


## Messages

XOScriptでのプログラミングとは、基本的にオブジェクトへメッセージを送ることです。
オブジェクトにメッセージを送る一般的な記法は次のとおりです：

```
<object> <message>
```

たとえば、数値**2**が偶数かどうかを調べるには、
**even?**というメッセージをオブジェクト**2**に送ります：

```
2 even?
```

その結果は**True**になります（これもオブジェクトです）。
未知のメッセージは通常、オブジェクトによって無視されるため、エラーは発生しません。
一部のオブジェクト（たとえば数値や文字列）は、
未知のメッセージを受け取った場合にあらかじめ定義された方法で応答します
（この点については後で詳しく説明します）。

オブジェクトが受け取ることのできるメッセージには、3つの種類があります。

| 種類 | 引数の数 |
|---|---:|
| 単項（Unary） | 0 |
| 二項（Binary） | 1 |
| キーワード（Keyword） | 1+ |

まず、上記の例にあるような**単項メッセージ（unary messages）**があります。これは引数を持ちません。
次に、1つまたは複数の引数を持つ**キーワードメッセージ（keyword messages）**があります。たとえば：

```
>> x := Number between: 1 and: 10.
```

この場合、**between:and:**というメッセージが、すべての数値のルートオブジェクトである**Number**に送られます。
結果として、1から10までのランダムな数値が返されます。
最後に、1文字と1つの引数だけを持つ**二項メッセージ（binary messages）**があります：

```
2 + 3
```

これは数学の足し算のように見えますが、実際には単なるメッセージです。
**+**というメッセージが**2**に送られ、引数として**3**が渡されます。その結果、答えとして**5**が返されます。
二項メッセージはコロンなしで記述できます。

二項メッセージは連鎖させることができます：

```
>> x := 3 + 2 - 1.
```

このコード断片では、まず**+ 2**が**Number**オブジェクトである**3**に送られます。
その結果としてNumberオブジェクト**5**が得られ、その後、この数値に**-1**が送られます。
注意深い読者なら、この仕組みが通常の数学における演算子の優先順位と異なることに気付くでしょう。
XOScriptでは、メッセージシステムの一貫性を優先し、数学的な演算子の優先順位を無視します。
その結果、次の計算は：

```
2 + 3 * 5 = 25
```

17ではなく25になります。

これは意図された動作です。
括弧を使って演算の順序を変更できます：

```
2 + (3 * 5) = 17
```

多くのオブジェクトは、特定のメッセージに応答すると自分自身を結果として返します。
これは、そのオブジェクトに続けて別のメッセージを送ることで、さらに処理を続けられるため便利です：

```
Out write:
[' hello '] trim upper.
```

```
HELLO
```

ここでは、**String**オブジェクトに2つのメッセージが送られています。
最初に**trim**、続いて**upper**です。

次のコード断片では、新しいメッセージが続くことを示すためにコンマを使用する必要があります。
そうしないと、XOScriptは混乱してしまいます。

```
Out write: ['Hello!'], stop.
```

まず、**write:**メッセージがpencilシンボルに送られ、その後に**stop**が続きます。
コンマがなければ、XOScriptは**stop**を文字列**Hello!**に送ろうとしていると解釈します。
これは意味のない処理です。

メッセージの処理順序は次のとおりです：左から右へ読み取り、まず括弧内のメッセージを処理し、その後に単項メッセージを処理します。
次に二項メッセージを処理し、最後にキーワードメッセージを処理します。
以下の例を参照してください：

```
Out write: 0.5 round + (2 - 1), stop.
```

XOScriptは常に左から右へ読み取ります。
まず、**write:**メッセージがOutに送られ、その後に**stop**メッセージが続きます。
引数の内部でもXOScriptは左から右へ読み取るため、まず**0.5 round**が処理され、その後に**+**が処理されます。

{{note}}
stopメッセージは文字列に改行文字を追加します。
このメッセージ名は電信システムに由来しています。
電信システムでは、句読点の送信が信頼できなかったり、
コストがかかったりしたため、文の終わりを示すために
STOPという単語がよく使用されていました。
{{/note}}

さらに、**round**は**+**より優先されます。これは**unary message**だからです。
括弧があるため、まず**2 - 1**が計算され、その後、その結果である**1**が**0.5 round**の結果（1）に加算されます。

処理全体の結果は**2**となり、これが出力される答えでもあります。
コンマの後にはstopメッセージが続き、カーソルを新しい行へ移動させます。
もちろん、XOScriptプログラムにおける処理順序を完全に理解する最良の方法は、実際に練習することです。

XOScriptでは、他の多くのプログラミング言語とは異なり、空白文字が構文の基本的な一部であることにも注意してください。
特に二項メッセージでは、空白文字によって混乱が生じることがあります。
二項メッセージの後には必ず空白を入れてください。
たとえば、数値をメッセージに直接続けて記述することはできません：

```
3 + 2
```

これは次とは異なります：

```
3 +2
```

最初の例（**3 + 2**）では、メッセージ**+**が数値**3**に送られ、引数として数値**2**が渡されます。
この場合、結果は**5**になります。
2番目の例（**3 +2**）では、単項メッセージ**+2**が数値**3**に送られます。
文脈によっては、まったく異なる結果になる可能性があります。

## Non-existing methods

オブジェクトにメッセージを送ると、そのメッセージ名に対応してそのオブジェクトに登録されている関数が呼び出されます。
理解できないメッセージを送った場合、受信側のオブジェクトはそのメッセージを無視し、代わりにさらなる通信のために自分自身への参照を返します。
これは**tolerant message passing**と呼ばれます。

例：

```

```

これはエラーになりません。
単純にテキスト**Object**を出力します。

## Recursion

前の例では、plus **sign** がオーバーライドされています。
ただし、最終的な加算処理自体は、最終的には実行する必要があります。
実際には、次の行でその処理が行われています：
```
>> answer := self + (number x factor).
```

では、XOScript は、この plus **sign** が元の加算ロジックを指していることを、どのように理解するのでしょうか？
たとえば別の解釈として、XOScript が同じオブジェクトに同じメッセージを繰り返し送信し続け、その結果 **endless loop** が発生することも考えられます。
もちろん、これは意図された動作ではありません。
オブジェクトにメッセージを送信した結果、まったく同じコードが実行されることになると、XOScript は、この場合、オーバーライドされる前の元のメッセージが意図されていることを認識します。
そのため、プログラムはこの種の endless loop から自動的に保護されます。

しかし、現在実行している関数から同じ関数を実際に実行したい場合は、まず **recursive** メッセージを送信する必要があります。
この場合、結果として無限ループが発生します。
ただし、再帰処理には有用な用途があります。
たとえば、ある数値の階乗を計算したいとします。
その場合は、Number に **factorial** メッセージを追加するだけです：

これは再帰処理を必要とします。
実際、**factorial** メッセージに関連付けられたタスクを、その関数の実行中にもう一度実行する必要があります。
つまり、factorial 関数自身の中から factorial 関数を呼び出す必要があります。

## Class-like Objects

xoscript はクラスを提供していませんが、クラスのような動作を再現することは簡単です。
**new** メッセージをオーバーライドするだけです。
```
>> Animal := Object new.
Animal on: ['new'] do: {
	<- self new init.
}.

Animal on: ['init'] do: {
	own sound := ['?'].
	own legs  := 4.
}.
```

上のコードでは、Animal という名前のオブジェクトを作成しています。
このオブジェクトは、犬や猫など、さまざまな動物の *blueprint* として機能します。
親オブジェクトである Animal は、これがクラスのようなオブジェクトであることを示すため、大文字の A で始まっています。
次に、独自の new メソッドを定義して new メッセージをオーバーライドします。
この場合、self に new メッセージを送信し、その後に init メッセージを送信しています。
xoscript はデフォルトでは再帰呼び出しをブロックするため、これは無限ループを引き起こしません。
代わりに、new メッセージは親オブジェクト（Object）に送信され、その結果として Animal の新しいインスタンスが作成されます。
つまり、new メソッドを定義した元のオブジェクトを基にして、新しいオブジェクトを作成しているわけです。
これは完全に正当な使い方です。
さらに init メッセージも送信しています。

# Booleans

{{messages}}

現在一般的に使われている多くのプログラミング言語とは異なり、XOScript には True オブジェクトが1つ、False オブジェクトが1つだけ存在します。
つまり、**True** と記述するたびに新しいオブジェクトが作成されるわけではありません。
常に同じオブジェクトへの参照を使用しています。
したがって、次のように記述した場合：

\>\> x := True.

**x** は **True** オブジェクトを参照します。
条件分岐やループも、この参照を検証します。

XOScript では、**True** と **False** の意味は固定されていません。
実際、次のような文があると、XOScript プログラムは大きく様変わりすることになります：

True := False.

このような操作の結果は未定義ですが、それでも有効な操作であり、形式的には許可されています。
さらに、**True** と **False** の両方のルートオブジェクトとなる Boolean オブジェクトも存在します。
どちらもこのルートオブジェクトから派生しています。
ただし、Boolean オブジェクト自体には実用的な用途はありません。

## Gotchas

**and:** と **or:** の使用には注意してください。
```
Out write: (False or: True or: True), stop.
Out write: (False or: True, or: True), stop.
```

結果：
```
False
True
```

これは、**or:** メッセージが1つの引数しか受け取らないためです。
最初のメッセージは False に対して **or:or:** を送信しますが、これは存在しないため、オブジェクトはそのメッセージを無視して自身（False）を返します。
一方、2行目では **or:** を送信した後、別の **or:** を送信しています（チェーン記号、つまりカンマ `,` を使用しています）。

数値、たとえば 9、-10、3,12 のいずれかを記述すると、画面の裏側で XOScript はこれらの数値を **Number** オブジェクトに変換します。
この Number オブジェクトにメッセージを送信することもできますし、数値を変数に代入してからメッセージを送信することもできます：
```
10 even?

>> tenner := 10.
tenner even?
```

どちらの記法も有効です。

これらのメッセージのほとんどは、その名前から動作が明らかであり、数学的な演算や比較を実行できます。

≤、≥、≠、×、÷ を、それぞれ ASCII の対応する記号の代わりに使用することもできます。
これは好みによるものです。
{{/note}}

乗算記号を使用すると、結果として新しいオブジェクトが返されます。

# Strings

{{messages}}

**blocks and quotation marks** ['...'] の間にテキストを記述すると、XOScript は新しい stringobject を作成します。
ただし、正しい quotation marks を使用するように注意してください。
テキストの先頭にある quotation mark と末尾にある quotation mark は異なります（これにより、single quote をエスケープせずに使用できます）。

## UTF8

xoscript の文字列には通常、UTF-8 でエンコードされたテキストが含まれます。
技術的には、文字列にバイナリデータや UTF-8 以外のコンテンツを含めることも可能ですが、その用途には blobs を使用することが推奨されます。
Blobs は server plugin によって提供されます（ffi の章を参照してください）。
一般に、blobs/ffi はプラットフォームおよびアーキテクチャとの結び付きがあるため、plugin/platform 単位で提供されます（ffi/blobs）。
スクリプト言語のコア部分は、可能な限り platform agnostic であり続けることを目指しています。

## Casting

次のメッセージを使用すると、各オブジェクトを異なる型のコピーとして作成できます：

| メッセージ | 結果 |
| ---------- | ---- |
| number | 数値に変換 |
| string | 文字列に変換 |
| bool | Boolean に変換 |

次のルールが **適用されます**：

| メッセージ | None | Bool | Number | Text | その他 |
| ---------- | ---- | ---- | ------ | ---- | ------ |
| bool | False | n/a | 0→False、それ以外→True | True | 主に True |
| number | 0 | False→0、True→1 | n/a | ['n']→n | 主に 1 |
| string | ['None'] | ['False']/['True'] | ['n'] | n/a | 状況による |

# Functions

{{messages}}

{ と } の間にコードを記述すると、それは function になります。
xoscript では、function を task と呼ぶこともあり、単に code block と呼ぶ場合もあります。

function は、*start* メッセージを送信することで実行できます。
```
{ Out write: 123, stop. } start.
```

function が引数を取る場合は、**apply:** を使用します。
```
{ :a Out write: a, stop. } apply: a.
```

以下の例も参照してください。
単純なアーキテクチャであるため、function には return point を1つしか持たせることができません。
条件分岐によるオーバーヘッドや過度なネストを避けるために、procedure を使用できます（これは引数 1 を指定して multiplication sign を使用する場合と同じです）：
```
{
  (a = 1) true: { x := 1. }, break.
  (a = 2) true: { x := 2. }, break.
} procedure.
```

このようにすると、a = 1 の場合、(a = 2) は評価されません。
また、この方法なら true メッセージを入れ子にする必要もありません。
条件をネストしたくなったときは、procedure メッセージの使用を検討してください。
コードが読みやすくなるかもしれません。

ここで重要な注意点があります：
```
{
	False false: {
		Out write: ['End the loop.'].
	}, break.
	
	Out write: ['Dont show me.'].

} procedure.
```

この場合、'Dont show me' というテキストが表示されます。
これは、**break** が False に送信されるためです。
break を実行したい場合は、**True** に対するメッセージとして送信する必要があります。
```
{
	False not true: {
		Out write: ['End the loop.'].
	}, break.
	
	Out write: ['Dont show me.'].

} procedure.
```

この場合は、期待どおりに動作します。

## Exceptions

例外は次のように処理できます：

```
{ Task 1 } except: { Task 2 }, start.
```

プログラム内で意図的にエラーを発生させることもできます。これにより、ハンドラーブロックを実行させることができます。これは、次の例のように、現在のタスクへ **error:** メッセージを送信することで行います：

```
{
this-task error: ['Whoops!'].
} except: { :mistake
Out write: mistake.
}, start.
```

## Injecting values

XOScript では、タスクに値を注入することができます。次のタスクを見てみましょう：

```
>> sending := {
	Newsletter to: own recipient.
}.
sending set: ['recipient']
value: ['info@recipient.org'].
sending start.
```

この例は、メールアドレス、つまり **recipient** にニュースレターを送信する架空のタスクを示しています。この recipient は、タスクを開始する前に外部からタスクへ注入することができます。これは、タスクに **set:value:** メッセージを送信することで行います。これにより、**recipient** の値がタスク内にあらかじめ設定されます。この値は後から変更することもでき、そのうえでタスクを再度実行できます。これは、Task オブジェクトを使用する際に便利な方法です。

## Empty Functions

空のタスクは許可されていません。理論上、空のタスクは **{}** のようになりますが、XOScript ではこれを言語エラーとして扱います。空のタスクを宣言したい場合は、None オブジェクトを使用できます：

```
>> task := None.
```

これは実際のタスクではなく None オブジェクトですが、start メッセージを送信することはできます：

```
>> answer := task start.
```

実際、これは次と同じです：

```
>> answer := None start.
```

オブジェクト **None** は **start** メッセージを認識しないため、自身を答えとして返します。そのため、答えは再び **None** になります。したがって、空のタスクを用意する必要はありません。プログラミング言語 XOScript の洗練された設計により、単純に None オブジェクトを使用できます。

この検索処理は、変数が見つかるまで続きます。
それでも変数が見つからない場合は、エラーメッセージが表示されます。このような変数の検索方法を **Dynamic Scoping** と呼びます。

## Catch-all methods

通常、オブジェクトに対応するメソッドが存在しないメッセージを送信すると、そのメッセージは無視されます。しかし、いわゆる **magic methods** または **catch-all** メソッドを指定することができます。これらのメソッドは、オブジェクトがメッセージを理解できない場合に呼び出されます。

利用可能な catch-all メソッドは4つあります。それぞれのメッセージは、特定の数の引数に対応します。

| Catch-all メッセージ | 引数の数 |
| -------------------- | -------- |
| respond: | 0 |
| respond:and: | 1 |
| respond:and:and: | 2 |
| respond:and:and:and: | 3 |

# Lists

{{messages}}

XOScript には、*lists* と *dicts* という2種類のコレクションがあります。
**Lists** は、オブジェクトを *固定された順序* で列挙したものです。Dicts には順序がなく、代わりにキー（または用語）と、それに対応する値からなる凡例のような構造になっています。Lists は、他のプログラミング言語における配列（PHP、Java、C）やリスト（Python）に相当します。Dicts は、連想配列（PHP）や辞書（Python）に相当します。新しい List を作成するには、次のように記述します：
```
>> fibonacci := List new.
```

この空の List には、**append:** を使って値を追加できます：
```
fibonacci append: 0.
fibonacci append: 1.
fibonacci append: 1.
fibonacci append: 2.
fibonacci append: 3.
fibonacci append: 5.
fibonacci append: 8.
fibonacci append: 13.
```

リストを画面に出力すると：
```
Out write: fibonacci, stop.
```

次のように表示されます：
```
List ← 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13
```

append の代わりに、`;` を使ってリストに要素を追加することもできます：
```
>> fibonacci := List new ; 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13.
```

セミコロン（`;`）はすべてバイナリメッセージであり、値をリストに格納します。

## Chaining

次のようなリストがあるとします：
```
>> x := List new ; 1 ; 2 ; 3.
```

最初と最後の要素を削除したい場合、メッセージは次のようになります：
```
x shift pop.
```

残念ながら、上記の記法は正しく動作しません。メッセージ **shift** はリストの最初の要素を返し、その要素が次のメッセージ **pop** のレシーバになります。つまり、メッセージ **pop** は **x** に送られるのではなく、2 に送られてしまいます。この問題を解決する方法の1つは、次のように2つの独立した文に分けることです：

```
x shift.
x pop.
```

しかし、これはあまり実用的ではありません。特に、3つ以上の要素を削除する必要がある場合には不便です。そこで XOScript は、このような状況のために別のメッセージ構造を提供しています。**alternative** メッセージ構造では、オブジェクトから返された結果は無視され、代わりにレシーバであるオブジェクト自体が繰り返し結果として返されます。**alternative** メッセージ構造は、オブジェクトに **do** メッセージを送ることで開始し、**done** メッセージを送ることで終了できます。上の例では、次のように使用できます：
```
>> x := List new ; 1 ; 2 ; 3.
x do shift pop done.
```

# Dicts

{{messages}}

**List と Dict はどちらもコレクションです。しかし、list とは異なり、dict には順序が**ありません**。両者のもう1つの違いは、dict がオブジェクトのペアから構成されていることです。一方のオブジェクトが entry（またはキーワード）として機能し、それを使ってもう一方のオブジェクトを検索します。list の良い例として、次のような価格表があります：
```
>> menu := Dict new
	put: ['£5'] at: ['apple pie'],
	put: ['£6'] at: ['carrot cake'],
	put: ['£3'] at: ['fudge'].
```

list と同様に、オブジェクトをコレクションに追加するには put:at: メッセージを使用します。ただし、list とは異なり、ここでは2つのオブジェクトが関連付けられます。1つ目のオブジェクトは、list と同様に、コレクションに格納するオブジェクトです。2つ目のオブジェクトはコレクション内での位置ではなく、**entry** であり、後から先ほどのオブジェクトを取得するために使用されます。つまり、dict は辞書のように機能し、キーワードを使って対応する値を見つけることができます。たとえば、上記の価格表から fudge の価格を取得するには：
```
>> price := menu at: ['fudge'].
```

より簡潔な記法を使用することもできます：
```
>> price := menu ? ['fudge'].
```

オブジェクトを格納するために使用する entry にスペースがなく（かつ、他の定義済みメッセージと衝突しない）場合は、次の記法も使用できます：
```
>> menu := Dict new
	pie:   ['£5'],
	cake:  ['£6'],
	fudge: ['£3'].
```

上記の記法のほうが、より自然に読めることは間違いありません。
fudge の価格を取得するには、次の簡略化された記法を使用できます：
```
>> price := menu fudge.
```

# Program/StdOut

{{messages}}

Program オブジェクトは、現在実行されているアプリを表します。このオブジェクトは、システムコマンドの実行、サブプログラムの読み込み、引数の読み取りなどの機能を提供します。システム関連のすべての機能が含まれます。

## StdOut

Out は標準出力オブジェクトです。基本的に **write:** と **stop** の2つのメソッドを持ちます。write: メッセージは文字列を stdout に送信するために使用され、stop メッセージは改行文字を出力します。
**stop** の代わりに \\n を使用することもできます。

例：
```
Out write: ['Hello World'], stop.
```

結果：
```
Hello World
```

## Modules/Plugins

XOScript の世界は、モジュールをインストールすることで新しいシステムオブジェクトを追加し、拡張することができます。XOScript の世界に新しいシステムオブジェクトを追加するには、モジュールファイル（通常は .so サフィックスを持つファイル）を mods フォルダに配置します。

プラグインモジュールによって利用可能になったオブジェクトにメッセージを送信すると、XOScript によって自動的にロードされます。

自分でプラグインを作成することもできます。プラグインは C プログラミング言語で記述します。ソースコードパッケージの src/plugins/example にサンプルプラグインがあります。


## Reflection

プログラムの実行中にシステムを探索する方法はいくつかあります。XOScript には、どのオブジェクトが存在しているか、またそれらのオブジェクトがどのメッセージに応答するかを確認するためのいくつかのメソッドがあります。まず、各オブジェクトに **type** を問い合わせることができます。ただし、XOScript の型は変更可能であるため、信頼できる情報とは限りません。

Program オブジェクトに対して、指定したオブジェクトがすでにプログラム内に存在するかどうかを問い合わせることもできます：
```
Program Tool true: { ... }.
```

オブジェクト名が単一のシンボルだけで構成されている場合は、混乱を避けるために次の記法を使用するのが最適です：
```
Program find: ['X'], true: { ... }.
```

オブジェクトについて問い合わせるだけでなく、Program オブジェクトに対してメッセージについて問い合わせることもできます。たとえば、オブジェクト **Number** が **between:and:** メッセージを認識するかどうかを、次のように確認できます：
```
Program Number: ['between:and:'], stop.
```

```
	# so if you do not set anything these
	# values are used...

	Program 
	setting: ['max-postfields']
	value: 40.

	Program 
	setting: ['max-contentlength']
	value: 2000000. # 2MB

	Program 
	setting: ['max-time']
	value: 5000. # 5sec
```

## Hello World

ここでは、Apache2、NGINX、OpenHTTPD などの一般的な CGI サーバーや、その他のよく知られたサーバーで使用できる非常にシンプルな Web プログラムを示します。
```
#!/bin/xo

Server init.
Program use: ['webtools.xo'].

>> web-document := Web-Document new.

web-document out: ['
<html>
<body>
<b>Hello World!</b>
</body>
</html>'].
```

Web-Document オブジェクトを使用したくない場合でも問題ありません。ただし、その場合は HTTP ヘッダーを自分で記述する必要があります：
```
#!/bin/xo
Out write: ['Content-type: text/html; charset=utf-8 \n\n'], stop.
Out write: ['hello world!'], stop.
``` 

## Request

HTTP-Request オブジェクトを使用すると、GET/POST/COOKIE および UPLOAD データを取得できます：
```
>> request  := HTTP-Request new.
>> search   := request get: ['search']. # ?search=books
>> password := request post: ['password']. # from form
>> selected := request get-list: ['sel[]']. #?sel[]=1&sel[]=2
>> selected := request post-list: ['sel[]'].
>> cookie   := request cookie: ['session-id'].
>> upload   := request upload: ['file'].
>> temppath := upload ? 0.
>> filename := upload ? 1.
```

## Maxpost/length

デフォルトの最大 POST フィールド数は 40、デフォルトの最大コンテンツ長は 2MB です。スクリプトごとに異なる値を設定するには：
```
Program setting: ['max-contentlength'] value: 1. 
Program setting: ['max-postfields'] value: 1. 
```

{{note}}
コンテンツ長が最大値を超えた場合、ペイロードが安全であることを保証できなくなるため、プロセスは強制終了されます。
{{/note}}

maxtime の制限は、stdin/postdata の読み取りに許可される最大時間をミリ秒単位で指定します。
```
Program setting: ['max-time'] value: 5000. # 5sec
```

これは POST の I/O 読み取りにのみ適用され、slowloris 型の攻撃を防止します。任意の操作の実行時間そのものに上限を設定したい場合は、Program alarm を使用してください。

## Database

Database オブジェクトを使用すると、MariaDB/MySQL に対してクエリを実行できます。
データベースに接続するには、次のようにします：

```
>> db := Maria-DB new host: ['localhost'],
	username: ['xo'],
	password: ['pass123'],
	dbname: ['xobase'],
	connect.

```

レコードを挿入するには：

```
>> query := db query: ['
	INSERT INTO book (id, description, price, rating) 
	VALUES (NULL, ?, ?, ?)
'], parameters: ( List new ; ['abc'] ; 12.35 ; 6 ). # parameterized queries

{  query execute. db commit. }
except: { :e db rollback.  }, start.
```

xoscript はトランザクションのみを使用し、autocommit を決して行わないことに注意してください。
autocommit を無効にできない場合は、接続エラーが発生します。
クエリでは常にパラメータバインディングを使用し、ユーザー入力を SQL に直接追加しないでください。

挿入された id は次のように取得できます：
```
Out write: ['INSERTED: '] + query insert-id, stop. # insert id
```

レコードを取得するには：
```
>> query :=
db
	query: ['SELECT * FROM book order by id desc limit 2'], 
	fetch: { :row 
		Out write: row id + [' '] + row description + [': '] + row price, stop.
	}. # fetching rows
```

## Sessions

データを永続化するには、session オブジェクトにデータを保存したり、そこから取得したりできます。
まず新しい **Web-Document** を作成します。Web-Document オブジェクトは、request、headers、HTML、session をひとつにまとめます。これは、ブラウザで Web サイトを訪れたとき、実際に目にするのは HTML だけだからです。しかし、Web-Document 全体には **Headers** も含まれています。たとえば、ほとんどの HTTP レスポンスには `Content-type:text/html` のようなヘッダーが含まれており、その後に続くデータを HTML として表示すべきこと（たとえばファイルとしてダウンロードするのではなく）をブラウザに伝えます。Sessions は、リクエスト間でユーザーデータを保存するための仕組みです。このデータを追跡するためには cookie を設定する必要があり、この cookie も Header を通じて設定されます。そのため、すべてが Web-Document にまとめられています（Web-Document は、Headers と HTML、またはその他のデータの両方を含む完全なドキュメントだからです）。

```
# First we make a new Web Document instance
>> web := Web-Document new.

# Now we start a session, this will generate a Header for a cookie and
# create a file to store your data, associated with that cookie
>> session := web session-start.

# Now we can treat session like a dict
session userid: 123.
```

session を破棄するには（ログアウト時など）：
```
web session-destroy.
```

## Headers

Web-Document を使うと、その他のよく知られた Header も設定できます。
たとえば、ユーザーを別の URL にリダイレクトしたい場合：
```
web goto: ['/other.html'].
```

内部では、このコマンドによって、他のデータや HTML とともに送信する HTTP ヘッダーも生成され、ブラウザに指定されたターゲットアドレスへ移動するよう指示します。

カスタムヘッダーを追加するには：
```
web header: ( 
	HTTP-Header new
	key: ['Content-Length']
	value: 400
).
```

404 ページを表示するには：
```
web not-found: ['OOps..'].
```


## Templates

デフォルトのテンプレートシステムは非常にシンプルです。新しいテンプレート構文を学ぶ必要はありません。また、テンプレートエンジンによって、プレゼンテーションとビジネスロジックが明確に分離されます。

ファイルからテンプレートを作成するには：
```
>> tpl := web template: ['templates/ux.tpl'].
```

テンプレートシステムではマーカーを使用します。
マーカーには、cut マーカー、paste マーカー、slot マーカーの3種類があります。基本的な考え方は非常にシンプルです。cut マーカーで識別された領域を切り出し、それを paste マーカーで識別された領域に貼り付けることができます。slot マーカーには文字列を注入できます。

たとえば、次のテンプレートがあるとします。ここでは宝石を宝石箱に入れ、価格タグを付けてみましょう。
```
<!-- cut:gem -->
<img src="gem.gif">
<b>$<!-- slot:price --></b>
<!-- /cut:gem -->

<div id="box">
<!-- paste:jewels -->
</div>
```

これは次のように行えます：
```
>> gem := tpl cut: ['gem'], copy.
gem price: 99.
tpl paste: gem at: ['jewels'].
web out: tpl clean.
```

最後の行では、必要な HTTP ヘッダーとともにテンプレートを文字列としてクライアントへ送信します。

結果：
```
<div id="box">
<img src="gem.gif">
<b>$99</b>
</div>
``` 

## Passthru

ユーザーがアップロードしたファイルを安全に配信するには、passthru を利用できます：

```
>> uploaded := ['smile.gif'].
Server passthru: uploaded prefix: ['/uploads/images/'].
Program end.
```

これにより、ユーザーがアップロードしたコンテンツが、適切な MIME タイプで配信されます。サポートされる MIME タイプはホワイトリストで指定されたものだけです：
GIF、JPG、PNG、WEBP、MP4、WEBM、MP3、ZIP、GZIP、PDF。
この方法により、TOCTOU 攻撃、パストラバーサル、悪意のあるコード実行（インジェクション）、シンボリックリンク攻撃、DDoS 攻撃（ファイルサイズ上限 = 50MB）、スニッフィング攻撃、およびその他さまざまなセキュリティ上の問題を防止できます。

## Regex

パターンを作成することで、正規表現を使用できます。
たとえば、ハイパーリンクの href と target をマッチさせるには：

```
Pattern new: ['href="([^"]+)" target="([^"]+)"'].
```

次に、次のように対象文字列にパターンを適用します：

```
pattern match: subject do: { :m :x .... }
```

完全な例：

```
>> subject := ['<html>
	<a href="http://link1" target="_blank">
	<a href="http://link2" target="_blank">
</html>'].
>> pattern := Pattern new: ['href="([^"]+)" target="([^"]+)"'].
>> result  := pattern match: subject do: { :m :x
	Out write: m, stop.
	Out write: x, stop.
	<- ['XXX'].
}.
Out write: result, stop.
```

# ffi

{{messages}}

FFI は、基盤となるシステムアーキテクチャと結び付いているため、プラットフォーム／プラグイン単位で提供されています。このような処理はコアが担うべきものではないためです。
server プラグインは、準拠した ffi/blob 実装を提供します。
デフォルトでは、コアは stdin/stdout、限定的なファイル I/O サービス、および shell（Program os）を介して対象プラットフォームに接続します。
補助的な統合機能は、server プラグインのようなアプリケーション中心のプラグインを通じて、ffi/blobs によって提供されます。

FFI は Foreign Function Interface の略です。これにより、DLL ファイル、SO ファイル、または Dylib ファイルを介して提供される、他のプログラミング言語で記述された機能を利用できます。利用できる機能にはさまざまなものがあり、この方法によって非常に幅広い機能を利用できます。
まず、例を見てみましょう：
```
Server link: (
 List new ;
 ['/usr/lib/x86_64-linux-gnu/libc.so.6'] ;
 ['printf'] ;
 ( List new ; ['pointer'] ; ['int'] ) ;
 ['void'] ;
 ['Printf'] ;
 ['template:number:']
).
>> s := Blob utf8: ['FFI has %d letters.\n'].
Printf template: s number: 3.
s free.
``` 

このコードを実行すると、コマンドラインに次のように表示されます：

FFI has 3 letters.

おそらく、「こんなに単純なことをするのに、ずいぶん大量のコードが必要だな」と思うでしょう。
つまり、Gui show コマンドを使えば同じことを簡単に実現できるのではないでしょうか？答えは、もちろん「はい」です！
ただし、これはあくまで説明のための例です。
FFI は通常、もっと複雑な処理に使用されますが、そのような処理は良い例にはならないため、ここではあえて単純なものを選びました。

link メソッドの引数：

- Argument #1: 使用する DLL または SO ファイル。
- Argument #2: リンクする対象ファイル内の関数。
- Argument #3: その関数の引数のデータ型名を格納したリスト。
- Argument #4: 関数の戻り値の型名。
- Argument #5: この関数をリンクする対象となるオブジェクトの名前（存在しない場合は自動的に作成されます）。
- Argument #6: この関数にリンクするメッセージ。

上の例では、libc.so の printf 関数をリンクしています。データ型の名前は、リンク対象となるソフトウェアのドキュメントで確認できます。利用可能な型は、void、pointer、float、double、int、uint、char、uchar、intX、uintX です。ここで X には 8、16、32、64 のいずれかを指定できます。

これらの型は、データを格納するために必要なバイト数を表します。printf では、新しいオブジェクト Printf と message template:number: にリンクしています。外部関数は、使用する前に XOScript の方言へ変換します。メッセージ template:number: は、最初のパラメータとしてテンプレート文字列を格納したバッファを必要とします。このバッファは Blob オブジェクトを使って作成します。Blob オブジェクトを使用すると、メモリを手動で確保できます。確保したメモリは、後から free メッセージを使って自分で解放する必要があります。

メモリ Blob には、さまざまな方法でデータを格納できます。この例ではテキストを格納するため、utf8: メッセージを使用しています（UTF-8 はテキストをバイト列へ変換するためのエンコーディングです）。bytes: を使って、バイト値のリストを渡して Blob にバイト列を格納することもできます。Blob の内容を読み取るには from:length: を使用します。結果としてバイト列がリストとして返されます。また、struct: メッセージに C の型の並びを渡すことで、Blob を使って C-struct を作成することもできます。これは、外部ソフトウェアライブラリの C 関数が struct へのポインタを要求する場合などに必要になります。

{warning}
Blob は自分で解放する必要があります。
Blob はガベージコレクターによって解放されません。
{/warning}

Blob はライブラリの外部関数と受け渡しできるため、自動的にガベージコレクションすることができません（外部関数が Blob を使用し続けている可能性があり、また外部関数自身が Blob を解放しようとする可能性もあります）。そのため、必要に応じて Blob は自分で解放する必要があります。

Blob を解放するには：

```
myblob free.
```

struct を解放するには：

```
mystruct structfree free.
```

つまり、struct の場合はメモリブロックを解放するために、structfree と free の2つのメッセージを送信する必要があります。

## Server script

サーバー上で実行される典型的なスクリプトは、次のようになります：

```
#!/bin/xo

# keep backward compat.
Program version: (
	Moment 
	zone: ['CEST'],
	from: ['2026-06-15 10:00:00']
).

Server init.

# I prefer a central loader that loads
# webtools.xo and template.xo
Program use: ['app/libs/loader.xo'].

# create a new document
>> web-document := Web-Document new.
>> tpl := Template new: ( 
	File new: ['app/templates/greeting.tpl'], read
).

# cut the message section
>> message := tpl cut: ['message'].

# add a message (will be encoded properly to avoid xss)
message greeting: ['hello world!'].

# paste the element at the designated slot
tpl paste: message at: ['messages'].

# output including http headers
web-document out: tpl.
```

これにより、Hello World メッセージを含む HTML ドキュメントが生成されます。
ご覧のとおり、ここでは HTML とプレゼンテーションロジックを非常に厳密に分離しています（デフォルトのテンプレートエンジンを使用しています）。そのため、テンプレート開発者はコードを変更することなくテンプレートを更新できます。
