Καλώς ήρθατε στο XOScript
Το έργο XOScript στοχεύει στη δημιουργία μιας γλώσσας σεναρίων που είναι απλή και ελέγξιμη.
Απλή δεν σημαίνει απαραίτητα εύκολη.
Μια οικεία γλώσσα προγραμματισμού μπορεί να είναι ευκολότερη στη χρήση από το XOScript.
Εδώ, η απλότητα σημαίνει κάτι διαφορετικό:
τη δυνατότητα να σχηματίσει κανείς ένα πλήρες νοητικό μοντέλο της γλώσσας και της συμπεριφοράς της.

Το XOScript έχει σχεδιαστεί ώστε να χωράει στο μυαλό σας.
Η γραμματική του και ο αριθμός των εννοιών του είναι σκόπιμα μικρά.
Δεν υπάρχουν κλάσεις· τα αντικείμενα μπορούν να επεκταθούν απευθείας.
Τα αντικείμενα μεταβιβάζονται με αναφορά, η αντιγραφή γίνεται ρητά,
και οι συναρτήσεις έχουν ένα μόνο σημείο εξόδου.

Ορισμένες από αυτές τις επιλογές διαφέρουν σημαντικά από τις γλώσσες ευρείας χρήσης.
Το XOScript, για παράδειγμα, δεν έχει σύστημα τύπων και χρησιμοποιεί δυναμική εμβέλεια.
Τα μηνύματα που δεν μπορούν να χειριστούν αγνοούνται αντί να προκαλούν εξαίρεση.
Αυτές οι επιλογές έχουν συνέπειες και δεν έχουν σκοπό να εξαλείψουν τα σφάλματα.
Σκοπός τους είναι να διατηρούν το υποκείμενο μοντέλο της γλώσσας μικρό και συνεπές.

Το XOScript μπορεί επίσης να τοπικοποιηθεί, κάτι που επιτρέπει την έκφραση επιχειρηματικών
κανόνων σε φυσική γλώσσα και, ενδεχομένως, τον διαμοιρασμό τους με μη τεχνικούς ενδιαφερόμενους.

Ελεγξιμότητα σημαίνει την εφαρμογή της ίδιας φιλοσοφίας στην υλοποίηση.
Το περιβάλλον εκτέλεσης είναι γραμμένο σε C, με έναν μικρό, χειρόγραφο λεκτικό αναλυτή, συντακτικό αναλυτή και διερμηνέα δέντρου.
Η τυπική βιβλιοθήκη και το περιβάλλον εκτέλεσης αντικατοπτρίζουν σε μεγάλο βαθμό τη δομή της γλώσσας,
κάνοντας τη σχέση ανάμεσα στον κώδικα XOScript και την υλοποίησή του σχετικά άμεση.

Οι δοκιμές συνδέονται επίσης στενά με την τεκμηρίωση.
Κάθε μέθοδος θα πρέπει να έχει μια σχετική δοκιμή που μπορεί να ενσωματωθεί στο εγχειρίδιο,
βοηθώντας να διατηρείται η τεκμηρίωση συγχρονισμένη με την υλοποίηση.

Το XOScript δεν προορίζεται να ανταγωνιστεί τις γλώσσες ευρείας χρήσης σε
δυνατότητες ή οικειότητα. Εξερευνά έναν διαφορετικό στόχο:
ένα προγραμματιστικό περιβάλλον που ένας προγραμματιστής μπορεί να κατανοήσει στο σύνολό του.

Η ελπίδα είναι ότι μια μικρή γλώσσα και μια μικρή
υλοποίηση καθιστούν πρακτικά εφικτή την κατανόηση του λογισμικού
από το byte έως το αντικείμενο, από τη σύνταξη έως το περιβάλλον εκτέλεσης, και τη συγγραφή κώδικα με
σιγουριά, επειδή καταλαβαίνετε τόσο τι συμβαίνει στο
σενάριο όσο και τι συμβαίνει στο παρασκήνιο.

Η αρχιτεκτονική μιας εγκατάστασης διακομιστή xoscript
είναι απλή, αλλά ευέλικτη.

{{architecture.png}}

Για να χρησιμοποιήσετε το xoscript ως γλώσσα διακομιστή, πρέπει να εγκαταστήσετε το
πρόσθετο διακομιστή σε έναν φάκελο με όνομα /mods/server. 

Αυτό συμβαίνει επειδή προτιμούμε να
διαχωρίζουμε τον πυρήνα της γλώσσας από τις λειτουργίες που αφορούν τον διακομιστή,
σε αντίθεση, για παράδειγμα, με την PHP ή την Python. Διαφορετικά θα έπρεπε να στέλνουμε
σε όλους ολόκληρο τον νεροχύτη της κουζίνας χωρίς λόγο, κάτι που είναι απλώς ανόητο.
Μπορείτε επίσης να εγκαταστήσετε άλλες μονάδες αν θέλετε. Το σύστημα είναι πολύ
ευέλικτο.

Επιπλέον, ορισμένες λειτουργίες υλοποιούνται καλύτερα στην ίδια τη γλώσσα σεναρίων,
όπως τα πρότυπα και ο χειρισμός συνεδριών, γι' αυτό παρέχουμε επιπλέον
τις βιβλιοθήκες template.xo και webtools.xo για τη διευκόλυνσή σας.
Ο λόγος για όλα αυτά είναι ότι δεν γνωρίζουμε πώς θέλετε να
χρησιμοποιήσετε το xoscript. Μπορείτε να το χρησιμοποιήσετε ως γλώσσα σεναρίων στην πλευρά του διακομιστή,
αλλά και για γραφικά περιβάλλοντα, ενσωματωμένες συσκευές ή απλώς για μαζική επεξεργασία.
Ακόμη κι αν το χρησιμοποιείτε ως γλώσσα σεναρίων στην πλευρά του διακομιστή (που είναι
σήμερα μία από τις κύριες περιπτώσεις χρήσης), μπορεί να θέλετε να
χρησιμοποιήσετε διαφορετική μηχανή προτύπων ή διαφορετικό χειριστή συνεδριών.
Ποιοι είμαστε εμείς για να αποφασίσουμε ότι πρέπει να χρησιμοποιήσετε τους δικούς μας;

Ένα από τα πλεονεκτήματα της χρήσης της δικής μας μηχανής προτύπων είναι ωστόσο ότι
δεν χρειάζεται να μάθετε πρόσθετη σύνταξη για να δημιουργήσετε πρότυπα.
Η προεπιλεγμένη μηχανή προτύπων που συνοδεύει το xoscript εφαρμόζει 100%
διαχωρισμό μεταξύ παρουσίασης και λογικής. Αντί για ειδική
σύνταξη προτύπων, χρησιμοποιεί απλώς ένα πολύ ευέλικτο σύστημα δεικτών θέσεων.
Για περισσότερες πληροφορίες, δείτε το κεφάλαιο Διακομιστής.

Σημειώστε ότι, αν δεν θέλετε να χρησιμοποιήσετε την προεπιλεγμένη μηχανή προτύπων ή
τα προεπιλεγμένα webtools, είναι αυτονόητο ότι πρέπει να παρέχετε
τα δικά σας.

Αν εκτελείτε τον διακομιστή ιστού σας σε chroot, jail ή άλλου είδους απομονωμένο περιβάλλον,
πρέπει επίσης να εγκαταστήσετε τις εξαρτήσεις του xo σε αυτό το περιβάλλον· μπορείτε
να δείτε ποιες βιβλιοθήκες χρειάζεστε χρησιμοποιώντας το ldd (δείτε τη σελίδα manpage του Linux ή του BSD).
Αν θέλετε να χρησιμοποιείτε εντολές φλοιού στα xo-σενάριά σας, αντιγράψτε επίσης έναν φλοιό
(όπως bash ή ksh) σε αυτό το περιβάλλον.

Θέλουμε επίσης να σημειώσουμε ότι παίρνουμε πολύ σοβαρά τη συμβατότητα προς τα πίσω.
Υπάρχει μάλιστα μια ειδική δυνατότητα συμβατότητας προς τα πίσω με την ονομασία
'version'. Γενικά, στόχος μας είναι ο κώδικάς σας να εκτελείται για πάντα. Έτσι, δεν θα
χρειαστεί ποτέ να ενημερώσετε τον κώδικά σας για να παραμείνει συμβατός με νεότερες εκδόσεις
του xoscript. Ο στόχος μας είναι: γράψε μία φορά, εκτέλεσε για πάντα.

Το υπόλοιπο αυτού του εγχειριδίου είναι αφιερωμένο στη λεπτομερή εξήγηση της γλώσσας
προγραμματισμού xoscript. Ο προγραμματισμός σεναρίων διακομιστή εξετάζεται στο κεφάλαιο
με τίτλο Διακομιστής. Αν είστε έμπειρος προγραμματιστής, ίσως θέλετε
να παραλείψετε μερικά κεφάλαια, επειδή ορισμένα είναι κάπως υπερβολικά λεπτομερή ή
μοιάζουν πολύ με τις γενικές πρακτικές προγραμματισμού. Όσοι λοιπόν από εσάς
έχετε ήδη εμπειρία με αρκετές άλλες γλώσσες προγραμματισμού,
καλύτερα να αντιμετωπίσετε αυτό το εγχειρίδιο ως οδηγό αναφοράς.

## Εγκατάσταση σε Linux

Κατεβάστε τα apache2 και mariadb:


```
sudo apt-get install apache2 mariadb-server
sudo a2enmod cgi
```

Κατεβάστε το xoscript.
Αντικαταστήστε το X με τον σωστό αριθμό έκδοσης!

```
wget https://xoscript.com/downloads/xoserver-linux-1_5_X.tar.gz
tar xvf xoserver*.tar.gz
```

Αντιγράψτε τα αρχεία στον ριζικό κατάλογο ιστού και στο /bin:


```
sudo cp bin/xo /bin/xo
sudo cp -R bin/mods /var/www/html/
sudo cp *.xo /var/www/html/
```

Επεξεργαστείτε τη ρύθμιση του apache2:

```
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

Αντικαταστήστε το Virtualhost με:

```
<VirtualHost *:80>
    <Directory /var/www/html>
        Options +ExecCGI
        AllowOverride All
        AddHandler cgi-script .xo
        Require all granted
    </Directory>
    DocumentRoot /var/www/html
</VirtualHost>
```

Δημιουργήστε μια δοκιμαστική σελίδα:

```
sudo nano /var/www/html/test.xo
```

και γράψτε ένα μικρό δοκιμαστικό πρόγραμμα:

```
#!/bin/xo
Server αρχικοποίησε.
Πρόγραμμα χρήση: ['webtools.xo'].
>> web := Έγγραφο-Ιστού νέο.
web έξοδος: ['Hello World'].
```

Επιτρέψτε στο apache2 να εκτελεί το πρόγραμμά σας μέσω CGI:

```
sudo chmod uog+x /var/www/html/test.xo
```

Επανεκκινήστε το apache2:

```
sudo systemctl restart apache2
```

Μεταβείτε στη δοκιμαστική σελίδα σας στο πρόγραμμα περιήγησης:

```
http://localhost/test.xo
```

Θα πρέπει να δείτε:

```
Hello World
```


## Εγκατάσταση σε OpenBSD

Επεξεργαστείτε το /etc/httpd.conf και προσθέστε:


```
server "mydomain.com" {
    listen on * port 80
    root "/htdocs/mydomain/"

    location "*.xo" {
        fastcgi
        fastcgi socket "/run/slowcgi.sock"   # inside chroot
    }
}
```

Αν θέλετε να χρησιμοποιήσετε SSL:

```
listen on * tls port 443
tls {
	certificate "/etc/ssl/mycert.crt"
	key "/etc/ssl/private/mykey.key"
}
```

Για να προστατέψετε την ανταλλαγή κλειδιών από κβαντικές επιθέσεις,
επιλέξτε τον κρυπταλγόριθμο mlkem:

```
tls {
 ... 
 ecdhe "X25519MLKEM768"
 ...
}
```

Προσθέστε το εκτελέσιμο xo και τα mods, καθώς και τυχόν εξαρτήσεις, στο
chroot (βρείτε τες με το ldd).

## Εκτέλεση παραδειγμάτων


Για να εκτελέσετε ένα από τα παραδείγματα προγραμμάτων του πακέτου:

```
./example.sh <name> <Linux/OBSD> [clean]
```

Για παράδειγμα, για να εκτελέσετε το παράδειγμα FizzBuzz σε Linux:

```
./example.sh fizzbuzz Linux
```

Για να εκτελέσετε το ίδιο παράδειγμα σε OpenBSD:

```
./example.sh fizzbuzz OBSD
```

Για να εκτελέσετε το παράδειγμα με καθαρή μεταγλώττιση:

```
./example.sh fizzbuzz OBSD clean
```

## Δοκιμές μονάδων

Για να εκτελέσετε τις δοκιμές μονάδων:

```
./runtests.sh
```

Για να εκτελέσετε τις δοκιμές μονάδων χωρίς μεταγλώττιση (μόνο δοκιμή):

```
./runtests.sh nobuild
```

## Μεταγλώττιση

Για να μεταγλωττίσετε από τον πηγαίο κώδικα σε Linux:

```
make clean
ISO="en" make
```

Σε OpenBSD:

```
make -f makefile.obsd clean
ISO="en" make -f makefile.obsd
```

Για να μεταγλωττίσετε το πρόσθετο διακομιστή σε Linux:

```
PACKAGE="server" NAME="server.so" make plugin-clean
ISO="en" PACKAGE="server" NAME="server.so" make plugin
```

Για να μεταγλωττίσετε το πρόσθετο διακομιστή σε OpenBSD:

```
PACKAGE="server" NAME="server.so" make -f makefile.obsd plugin-clean
ISO="en" PACKAGE="server" NAME="server.so" make -f makefile.obsd plugin
```

## Γεια σου κόσμε

Αφού μεταφερθεί στον υπολογιστή σας, μπορείτε να αποσυμπιέσετε το αρχείο
και να ξεκινήσετε το xo με την ακόλουθη εντολή:

```
xo
```

Για να εκτελέσετε ένα XOScript, αποθηκεύστε το πρόγραμμα ως αρχείο προσθέτοντας την κατάληξη -xo
(προαιρετικά). Επιπλέον, γράψτε το όνομα αρχείου του προγράμματός σας
μετά την εντολή XOScript:

```
xo myprogram.xo
```

Όταν εκτελείτε μια εντολή XOScript με το αρχείο του προγράμματός σας ως
παράμετρο, το xo θα διαβάσει και θα εκτελέσει το αρχείο του προγράμματός σας.

{{note}}
Μπορείτε επίσης να ξεκινήσετε το πρόγραμμά σας σύροντάς το πάνω στο εικονίδιο του xo.
{{/note}}

{{warning}}
Σε ορισμένα συστήματα πρέπει πρώτα να δώσετε στο xo δικαιώματα για τη φόρτωση δυναμικών
βιβλιοθηκών.
{{/warning}}

Η παράδοση ορίζει ότι το πρώτο πρόγραμμα σε κάθε νέα γλώσσα
προγραμματισμού πρέπει να είναι ένα είδος χαιρετισμού προς τον κόσμο. Στο XOScript, ένα τέτοιο
πρόγραμμα **Hello world** μοιάζει ως εξής:

@test598

Όταν αυτό το κείμενο αποθηκευτεί σε ένα αρχείο, π.χ. hello.xo, μπορεί να εκτελεστεί ως
εξής: .

xo hello.xo

Hello world


Μπορείτε να δείτε την έξοδο του προγράμματος στο μαύρο παράθυρο που φαίνεται παραπάνω.
Σε όλο το εγχειρίδιο θα χρησιμοποιείται η ίδια απεικόνιση για την παρουσίαση
της εξόδου.

{{note}}
Το Έξοδος γράφεται με κεφαλαίο Ε.
Γενικά τα αντικείμενα ξεκινούν με κεφαλαίο γράμμα,
εκτός αν λειτουργούν ως στιγμιότυπο (δεν έχουν δικές τους
μεθόδους, μόνο δεδομένα). Αυτό αντανακλά τις συμβάσεις κλάσης και στιγμιότυπου
σε άλλες γλώσσες προγραμματισμού.
{{/note}}


## Σύνταξη 

Το XOScript είναι μια *καθαρά* *αντικειμενοστρεφής* γλώσσα προγραμματισμού. Αυτό σημαίνει
ότι το xoscript αντιλαμβάνεται τα πάντα ως αντικείμενα, επομένως δεν υπάρχουν
άλλοι *τύποι δεδομένων*. Υπάρχουν ουσιαστικά τρεις βασικές ενέργειες
σε ένα πρόγραμμα γραμμένο σε XOScript: η *ανάθεση*, η *αποστολή μηνυμάτων*
και η *απάντηση*. Η ανταλλαγή μηνυμάτων μεταξύ αντικειμένων είναι το βασικό μέρος ενός
προγράμματος XOScript. Οι τρεις επιμέρους ενέργειες παρουσιάζονται
παρακάτω:


Ενέργεια             | Παράδειγμα
-------------------- | --------
ανάθεση              |  \>\> x := 1. 
μοναδιαία μηνύματα   | x άρτιος?.
δυαδικό μήνυμα       | 1 + 2.
μήνυμα λέξης-κλειδιού | x από: 0 μήκος: 10.
απάντηση             | <- answer.  


Αυτό το κεφάλαιο θα σας δώσει μια γενική εικόνα της γλώσσας XOScript
και περιγράφει τις βασικές της αρχές. Το XOScript είναι μια μικρή γλώσσα,
θεμελιωμένη σε τρεις ενέργειες (δείτε την απεικόνιση) που μεταφράζονται σε
περίπου έξι γραμματικούς κανόνες. Αυτό είναι το μόνο που χρειάζεται για να κατακτήσετε τη
γλώσσα.

Μην ανησυχείτε αν κάποια πράγματα δεν σας είναι αμέσως προφανή: όλα τα δομικά
στοιχεία θα εξεταστούν στο επόμενο κεφάλαιο (3) και οι βασικοί κανόνες θα
επαναληφθούν. Το τρέχον κεφάλαιο, ωστόσο, χρησιμεύει κυρίως ως γενική
εισαγωγή στη γλώσσα. Οι βασικές αρχές θα εξηγηθούν σύντομα
και θα παρουσιαστούν με αρκετά σχετικά παραδείγματα. Τυχόν λεπτομέρειες που λείπουν
θα αναλυθούν αργότερα.

Τα σχόλια στο XOScript ξεκινούν με το σύμβολο \#. Έτσι, η ακόλουθη γραμμή
θα αγνοηθεί:

```
# this is just a comment
```

## Μεταβλητές

Για να αναθέσετε
μια μεταβλητή χρησιμοποιείτε το σύμβολο δήλωσης μεταβλητής: >>. Το όνομα μιας
μεταβλητής μπορεί να περιέχει όλα τα σύμβολα εκτός από: <-, :=, κενούς χαρακτήρες,
τελείες, κόμματα, άνω και κάτω τελείες, εισαγωγικά [' '] και παρενθέσεις ().
Επιπλέον, μια μεταβλητή δεν μπορεί να εκτείνεται σε πολλές γραμμές. Σημειώστε
ότι μια μεταβλητή δεν μπορεί να ξεκινά με αριθμό ή με το σύμβολο μείον.

Αυτά είναι παραδείγματα έγκυρων μεταβλητών:

```
>> password := ['Secret'].
>> ♡♡♡ := 3.
>> $ := ['dollar'].
>> +plus := Αληθές.
>> user-password := ['Pssst!'].
```

Μη έγκυρες μεταβλητές είναι για παράδειγμα:


```
>> -123 := ['negative number'].
>> password of user := ['Classified'].
>> password.of:user := ['Classified'].
>> ,x := 10.
```

{{note}}
Δεν χρειάζεται να κάνετε διαφυγή σε κανέναν χαρακτήρα
(συμπεριλαμβανομένων των απλών και διπλών εισαγωγικών και των ορίων
κειμένου) σε
μια σταθερά κειμένου, εφόσον αυτό δεν
προκαλεί ασάφεια για τον λεκτικό αναλυτή.
{{/note}}

Αφού δηλωθεί μια μεταβλητή, μπορεί να χρησιμοποιηθεί ελεύθερα. Αυτό σημαίνει
ότι το σύμβολο δήλωσης χρειάζεται μόνο την πρώτη φορά
που χρησιμοποιείτε τη μεταβλητή (τη δήλωση).

Για να είμαστε πιο συγκεκριμένοι, δεν μπορείτε απλώς να αρχίσετε να αναθέτετε μια τιμή στη
μεταβλητή σας *(x := 2)*, καθώς πρέπει πρώτα να δηλώσετε τη μεταβλητή *(\>\>
x := 2)*. Ωστόσο, αφού δηλωθεί, επιτρέπεται να αλλάξετε την τιμή της
χωρίς να χρησιμοποιήσετε το σύμβολο δήλωσης*(\>\> x := 2. x := 3.)*.

Σημειώστε ότι είναι υποχρεωτικό να αναθέσετε μια τιμή σε μια μεταβλητή τη στιγμή της
δήλωσης. Σε αντίθεση με άλλες γλώσσες προγραμματισμού, δεν επιτρέπεται
να δηλώσετε μια μεταβλητή χωρίς τιμή. Είναι απαραίτητο να συνδέσετε ρητά
κάθε μεταβλητή με μια αρχική τιμή. Παρ' όλα αυτά, μπορείτε άνετα να αρχικοποιήσετε
τη μεταβλητή με το αντικείμενο **Κενό**. Σε αυτή την περίπτωση, η μεταβλητή μπορεί να
θεωρηθεί κενή *(\>\> x := Κενό.)*. Με λίγα λόγια, η δήλωση μιας
μεταβλητής χωρίς αρχική τιμή δεν επιτρέπεται. Έτσι,

```
>> x.
```

δεν είναι έγκυρο και θα προκαλέσει μήνυμα σφάλματος.

{{note}}
Το xoscript χρησιμοποιεί δυναμική εμβέλεια μεταβλητών· για
λεπτομέρειες συμβουλευτείτε το κεφάλαιο Συναρτήσεις.
{{/note}}


## Σταθερές

Το XOScript αντιλαμβάνεται τα πάντα ως αντικείμενα· δηλαδή όλους τους αριθμούς, τα κείμενα
και τα τμήματα κώδικα. Οι αριθμοί, όπως 1, 2, 100, -999 και 1,234, είναι
αντικείμενα Αριθμός. Όλα τα κείμενα ανάμεσα σε απλά εισαγωγικά είναι αντικείμενα
Κείμενο. Όλα τα τμήματα κώδικα που περικλείονται σε άγκιστρα {...} είναι
αντικείμενα Συνάρτηση.

Σταθερά         | Ριζικό αντικείμενο | Παράδειγμα
--------------- | ------------------ | ----------
αριθμοί         | Αριθμός            | 1,2,3... 
κείμενα         | Κείμενο            | \['hello'\]
συνάρτηση       | Συνάρτηση          | { 1 + 2. }.
                
     
Αντικείμενα όπως οι αριθμοί και τα κείμενα έχουν πάντα την προέλευσή τους σε ένα ριζικό
αντικείμενο. Για παράδειγμα, όλοι οι αριθμοί προέρχονται από το αντικείμενο **Αριθμός**. Όλα
τα κείμενα προέρχονται από το **Κείμενο** και όλα τα τμήματα κώδικα από το **Συνάρτηση**. Με
τη σειρά τους, όλα αυτά τα αντικείμενα προέρχονται από το **Αντικείμενο**, το οποίο είναι στην πραγματικότητα το
ριζικό αντικείμενο όλων των αντικειμένων.


## Μηνύματα

Ο προγραμματισμός σε XOScript σημαίνει βασικά
αποστολή μηνυμάτων σε αντικείμενα. Ο γενικός συμβολισμός για την αποστολή ενός μηνύματος σε
ένα αντικείμενο είναι ο εξής:

```
<object> <message>
```

Για να μάθουμε, για παράδειγμα, αν ο αριθμός **2** είναι άρτιος, το
μήνυμα **άρτιος?** αποστέλλεται στο αντικείμενο **2**:

```
2 άρτιος?
```

Η απάντηση θα είναι **Αληθές** (και πάλι ένα αντικείμενο). Τα άγνωστα μηνύματα
συνήθως αγνοούνται από τα αντικείμενα· έτσι δεν προκύπτει σφάλμα. Ορισμένα αντικείμενα (π.χ.
αριθμοί ή κείμενα) αποκρίνονται σε ένα άγνωστο μήνυμα με προκαθορισμένο τρόπο
(περισσότερα για αυτό το θέμα αργότερα).

Ένα αντικείμενο μπορεί να λάβει τρία είδη μηνυμάτων. 

Είδος           | Πλήθος ορισμάτων
--------------- | -------------------
Μοναδιαίο       | 0      
Δυαδικό         | 1     
Λέξης-κλειδιού  | 1+    


Πρώτον, υπάρχουν τα **μοναδιαία
μηνύματα**, δείτε το παραπάνω παράδειγμα, τα οποία δεν έχουν ορίσματα. Δεύτερον,
υπάρχουν τα **μηνύματα λέξης-κλειδιού**, τα οποία έχουν ένα ή περισσότερα ορίσματα,
για παράδειγμα:

```
>> x := Αριθμός μεταξύ: 1 και: 10.
```

Σε αυτή την περίπτωση το μήνυμα **μεταξύ:και:** αποστέλλεται στο **Αριθμός**, το οποίο
είναι το ριζικό αντικείμενο όλων των αριθμών. Το αποτέλεσμα θα είναι ένας τυχαίος αριθμός
μεταξύ 1 και 10. Τέλος, υπάρχουν τα **δυαδικά μηνύματα**, τα οποία έχουν
μόνο έναν χαρακτήρα και ένα όρισμα:

```
2 + 3
```

Αυτό μοιάζει με μαθηματική πράξη, αλλά στην πραγματικότητα είναι απλώς ένα ακόμη μήνυμα. Το
μήνυμα **+** αποστέλλεται στο **2**, με όρισμα το **3**, και επιστρέφει
την απάντηση **5**. Τα δυαδικά μηνύματα επιτρέπεται να γράφονται χωρίς άνω και κάτω τελεία.

Τα δυαδικά μηνύματα μπορούν να συνδεθούν σε αλυσίδα:

```
>> x := 3 + 2 - 1.
```

Σε αυτό το απόσπασμα το **+ 2** αποστέλλεται πρώτα στο αντικείμενο **Αριθμός** **3**, κάτι που
δίνει ως αποτέλεσμα το αντικείμενο Αριθμός **5**, και στη συνέχεια το **-1** αποστέλλεται σε αυτόν τον
αριθμό. Οι παρατηρητικοί αναγνώστες σωστά θα προσέξουν την ασυμφωνία που
παρουσιάζει αυτό το πρωτόκολλο σε σχέση με τη συμβατική μαθηματική προτεραιότητα των
τελεστών. Το XOScript αγνοεί τη μαθηματική προτεραιότητα υπέρ της
συνέπειας του συστήματος μηνυμάτων του. Ως αποτέλεσμα, η πράξη:

```
2 + 3 * 5 = 25
```

όχι 17.

Αυτό γίνεται σκόπιμα. Μπορείτε να χρησιμοποιήσετε παρενθέσεις για να αλλάξετε τη σειρά:

```
2 + (3 * 5) = 17
```

Τα περισσότερα αντικείμενα επιστρέφουν τον εαυτό τους ως αποτέλεσμα σε απόκριση ενός
μηνύματος. Αυτό είναι χρήσιμο, καθώς ενθαρρύνει τη συνέχιση του διαλόγου με αυτό το
αντικείμενο με την αποστολή ενός επόμενου μηνύματος:

```
Έξοδος γράψε:
[' hello '] περικοπή κεφαλαία.
```

```
HELLO
```

Εδώ, δύο μηνύματα αποστέλλονται στο αντικείμενο **Κείμενο**: το **περικοπή**, ακολουθούμενο
από το **κεφαλαία**.

Στο ακόλουθο απόσπασμα, η χρήση κόμματος είναι απαραίτητη για να δηλωθεί
ότι έρχεται ένα νέο μήνυμα. Διαφορετικά, το XOScript θα μπερδευτεί.

```
Έξοδος γράψε: ['Hello!'], νέα-γραμμή.
```

Πρώτα, το μήνυμα **γράψε:** αποστέλλεται στο σύμβολο του μολυβιού και ακολουθεί το
**νέα-γραμμή**. Χωρίς το κόμμα, το XOScript θα νόμιζε ότι θέλετε να στείλετε το
**νέα-γραμμή** στο **κείμενο** **Hello!**, μια μάταιη προσπάθεια.

Η σειρά επεξεργασίας των μηνυμάτων είναι η εξής: από αριστερά προς τα δεξιά·
πρώτα τα μηνύματα μέσα σε παρενθέσεις και έπειτα τα μοναδιαία μηνύματα. Στη συνέχεια
τα δυαδικά μηνύματα και τέλος τα μηνύματα λέξης-κλειδιού. Δείτε το
παράδειγμα παρακάτω:

```
Έξοδος γράψε: 0.5 στρογγύλευση + (2 - 1), νέα-γραμμή.
```

Το XOScript διαβάζει πάντα από αριστερά προς τα δεξιά: πρώτα, το μήνυμα **γράψε:**
αποστέλλεται στο Έξοδος και ακολουθεί το μήνυμα **νέα-γραμμή**. Μέσα στο ίδιο το
όρισμα, το XOScript διαβάζει από αριστερά προς τα δεξιά, άρα πρώτα **0.5 στρογγύλευση**
και έπειτα **+**.

{{note}}
Το μήνυμα νέα-γραμμή προσθέτει έναν χαρακτήρα νέας γραμμής στο κείμενο.
Το αγγλικό όνομα αυτού του μηνύματος (stop) είναι εμπνευσμένο από τα τηλεγραφικά συστήματα.
Τα μηνύματα στα τηλεγραφικά συστήματα 
χρησιμοποιούσαν συχνά τη λέξη STOP για να σημειώσουν το τέλος μιας πρότασης
(επειδή τα σημεία στίξης ήταν αναξιόπιστα ή δαπανηρά).
{{/note}}

Επιπλέον, το **στρογγύλευση** έχει προτεραιότητα έναντι του **+**, επειδή είναι
**μοναδιαίο μήνυμα**. Λόγω των παρενθέσεων, το **2 - 1** υπολογίζεται
πρώτο, και έπειτα το **1** προστίθεται στο αποτέλεσμα του **0.5 στρογγύλευση** (1).

Όλη η διαδικασία θα δώσει το αποτέλεσμα **2**, το οποίο είναι και η γραπτή
απάντηση. Μετά το κόμμα ακολουθεί το μήνυμα νέα-γραμμή, που μετακινεί τον δρομέα
σε νέα γραμμή. Φυσικά, ο καλύτερος τρόπος για να κατανοήσετε πλήρως τη σειρά
εκτέλεσης των προγραμμάτων XOScript είναι η εξάσκηση.

Αξίζει να σημειωθεί ότι στο XOScript, σε αντίθεση με πολλές άλλες γλώσσες
προγραμματισμού, οι κενοί χαρακτήρες αποτελούν θεμελιώδες μέρος της σύνταξης. Ειδικά
όσον αφορά τα δυαδικά μηνύματα, οι κενοί χαρακτήρες μπορεί να προκαλέσουν κάποια
σύγχυση. Χρησιμοποιείτε πάντα έναν κενό χαρακτήρα μετά από ένα δυαδικό μήνυμα. Δεν μπορείτε
να κολλήσετε έναν αριθμό απευθείας στο μήνυμα, για παράδειγμα: 

```
3 + 2
```

διαφέρει από το 

```
3 +2
```

Το πρώτο παράδειγμα (**3 + 2**) στέλνει το
μήνυμα **+** στον αριθμό **3**, με όρισμα τον αριθμό **2**. Το
αποτέλεσμα, σε αυτή την περίπτωση, θα είναι **5**. Στο δεύτερο παράδειγμα (**3 +2**),
το μοναδιαίο μήνυμα **+2** αποστέλλεται στον αριθμό **3**. Ανάλογα με το
πλαίσιο, αυτό μπορεί να δώσει ένα πολύ διαφορετικό αποτέλεσμα.

## Ανύπαρκτες μέθοδοι

Η αποστολή ενός μηνύματος σε ένα αντικείμενο καλεί τη συνάρτηση που έχει
συνδεθεί με αυτό το αντικείμενο με το όνομα του μηνύματος. Αν στείλετε ένα μήνυμα
που δεν γίνεται κατανοητό, το αντικείμενο-παραλήπτης θα αγνοήσει το μήνυμά σας
και θα επιστρέψει αντί γι' αυτό μια αναφορά στον εαυτό του για περαιτέρω επικοινωνία.
Αυτό ονομάζεται ανεκτική μεταβίβαση μηνυμάτων.

Παράδειγμα:

```
Έξοδος γράψε: Αντικείμενο blah, νέα-γραμμή.
```

Αυτό δεν θα προκαλέσει σφάλμα. Απλώς θα εκτυπώσει το κείμενο **Αντικείμενο**.


## Ροή ελέγχου

Στο XOScript δεν χρειάζονται ξεχωριστοί γραμματικοί κανόνες για *βρόχους* και
*συνθήκες if*. Μια εντολή if είναι απλώς ένα μήνυμα **αληθές:** ή **ψευδές:**
προς ένα αντικείμενο **Αληθές** ή ένα αντικείμενο **Ψευδές**:

```
2 άρτιος? αληθές: {
	Έξοδος γράψε: ['Two is an even number'], νέα-γραμμή.
}.
```
Στο προηγούμενο παράδειγμα, το μήνυμα **αληθές:** αποστέλλεται στο **Αληθές** (την
απάντηση στην ερώτηση: είναι το 2 άρτιος αριθμός;). Ως όρισμα αποστέλλεται επιπλέον ένα
τμήμα κώδικα: ένα αντικείμενο **Συνάρτηση**. Αυτή η συνάρτηση γράφει στην
οθόνη ότι το 2 είναι πράγματι άρτιος αριθμός.

Δεν χρειάζονται ούτε ξεχωριστοί κανόνες σύνταξης για έναν *βρόχο*. Για να
εκτελέσετε ένα τμήμα κώδικα τρεις φορές, απλώς στείλτε το **\*** με όρισμα
**3** σε αυτή τη **Συνάρτηση**:

ούτω καθεξής.

από *kJ* (κιλοτζάουλ) σε *kcal* (χιλιοθερμίδες) με βήματα του 100,

συνάρτησης. Οι παράμετροι που δεν χρησιμοποιούνται παραμένουν κενές (**Κενό**). Οι παράμετροι
τοποθετούνται πάντα στην αρχή της συνάρτησης, αμέσως μετά το αρχικό

## Παρεμβολή κειμένου

Η λίστα *kJ/kcal* θα μπορούσε να γίνει πιο
ευπαρουσίαστη. Κατά προτίμηση, η λίστα θα ήταν ως εξής:

```
100 kj ➞ 23.88 kcal

200 kj ➞ 47.76 kcal
```

Όταν μετατρέψετε την επιθυμητή έξοδο σε πρότυπο, ο συμβολισμός της
θα μπορούσε να είναι:

```
number1 kJ ➞ number2 kcal
```

Αυτό σημαίνει ότι το **number1** αντιστοιχεί στην τιμή kJ και το **number2** στην
τιμή kcal. Έτσι λειτουργεί η παρεμβολή κειμένου στο XOScript. Δεν
χρειάζονται ξεχωριστοί γραμματικοί κανόνες για αυτό στο XOScript. Απλώς στείλτε
τη λέξη που πρέπει να αντικατασταθεί στο κείμενο, με το κείμενο αντικατάστασης
ως όρισμα:

```
>> text :=

['number1 kJ ➞ number2 kcal']

number1: 100,

number2: 23.9.
```

Το αποτέλεσμα:

```
100 kj ➞ 23.9 kcal
```

Αυτός ο κανόνας αντικατάστασης ισχύει για κάθε μη ορισμένο μήνυμα που λαμβάνει
ένα αντικείμενο **κείμενο**. Κάθε μήνυμα που δεν αναγνωρίζεται από το αντικείμενο
**κείμενο** θα ερμηνευτεί ως εξής: *αντικατάστησε το κείμενο του μηνύματος
με το κείμενο του ορίσματος του μηνύματος.* Μπορείτε να προσαρμόσετε το
πρόγραμμα ως εξής:

# Αντικείμενα

{{messages}}

Εκτός από την προσαρμογή και την επέκταση υπαρχόντων αντικειμένων, μπορείτε επίσης να δημιουργήσετε
νέα αντικείμενα μόνοι σας, απλώς στέλνοντας το μήνυμα **νέο**. Ας υποθέσουμε ότι
θέλετε να δημιουργήσετε ένα αντικείμενο τιμολογίου που επιβάλλει μια αριθμητική
ακολουθία· σε αυτή την περίπτωση, χρειάζεστε πρώτα ένα αντικείμενο τιμολογίου.

Γνωρίζοντας ότι κάθε αντικείμενο προέρχεται από ένα άλλο αντικείμενο, το οποίο με τη σειρά του
προέρχεται τελικά από το ριζικό αντικείμενο όλων των αντικειμένων, που ονομάζεται Αντικείμενο,
πρέπει να επιλέξετε σε ποιο από αυτά τα άλλα αντικείμενα θα βασιστεί το
νέο σας αντικείμενο. Το νέο σας αντικείμενο κληρονομεί όλες τις ιδιότητες του
αντικειμένου στο οποίο βασίζεται, δηλαδή εκείνου στο οποίο στάλθηκε αρχικά
το μήνυμα **νέο**.

Σε αυτό το παράδειγμα προτιμάται ένα σχετικά ουδέτερο αντικείμενο, χωρίς πάρα
πολλές κληρονομημένες ιδιότητες. Αυτό κάνει την επιλογή εύκολη, επειδή σε αυτή την
περίπτωση το νέο αντικείμενο μπορεί να βασιστεί στο ίδιο το ριζικό αντικείμενο, δηλαδή το
**Αντικείμενο**. Ο συμβολισμός του σκοπούμενου συστήματος τιμολόγησης θα είναι τότε ο
εξής:

@test604

Ο τρέχων αριθμός τιμολογίου αποθηκεύεται στο αντικείμενο, γι' αυτό
τοποθετείται μπροστά του η λέξη-κλειδί **δικό**. Αυτό ονομάζεται *ιδιότητα*·
περισσότερες λεπτομέρειες θα ακολουθήσουν.

Ορισμένες επιχειρήσεις προτιμούν να ενσωματώνουν το έτος στους αριθμούς
τιμολογίων. Σε αυτή την περίπτωση, μπορείτε να δημιουργήσετε ένα νέο αντικείμενο τιμολογίου βασισμένο σε
ένα προηγούμενο αντικείμενο τιμολογίου, το οποίο όμως δίνει στον χρήστη του τη δυνατότητα να
εισαγάγει ένα συγκεκριμένο έτος:

@test605

Δεν χρειάζεται να γράψετε ξανά την υλοποίηση του μηνύματος **αριθμός**,
καθώς κληρονομείται από το προηγουμένως γραμμένο **αντικείμενο
τιμολογίου**· κατά συνέπεια, ο παλιός κώδικας μπορεί να επαναχρησιμοποιηθεί. Το XOScript δεν διαθέτει έννοιες
όπως οι κλάσεις και άλλες σχετικές έννοιες. Αυτό σημαίνει ότι τα αντικείμενα μπορούν
να κληρονομούν αποκλειστικά από άλλα αντικείμενα, κάτι που είναι γνωστό και ως *κληρονομικότητα
μέσω πρωτοτύπων*.

## Αναδρομή

Στο προηγούμενο παράδειγμα, υπερκαλύπτεται το **σύμβολο** συν. Σημειώστε
ότι τελικά η τελική πρόσθεση πρέπει ακόμη να γίνει, κάτι που στην πραγματικότητα
συμβαίνει στην ακόλουθη γραμμή:

```
>> answer := εαυτός + (αριθμός x factor).
```

Πώς όμως καταλαβαίνει το XOScript ότι αυτό το **σύμβολο** συν αναφέρεται στην
αρχική λογική της πρόσθεσης;** Μια άλλη ερμηνεία, για παράδειγμα, θα μπορούσε
να είναι ότι το XOScript θα στέλνει επανειλημμένα το ίδιο μήνυμα στο ίδιο
αντικείμενο, κάτι που με τη σειρά του θα οδηγούσε σε **ατέρμονο βρόχο**. Προφανώς,
αυτή δεν είναι η πρόθεση. Μόλις στείλετε ένα μήνυμα σε ένα αντικείμενο
που θα εκτελούσε ακριβώς τον ίδιο κώδικα, το XOScript θα καταλάβει,

βρόχων. Ωστόσο, όταν πράγματι θέλετε να εκτελέσετε την ίδια συνάρτηση από την
τρέχουσα συνάρτηση, θα πρέπει πρώτα να στείλετε το μήνυμα
**αναδρομικό**. Σε αυτή την περίπτωση, το αποτέλεσμα θα είναι ένας ατέρμονος
βρόχος. Υπάρχουν όμως χρήσιμες εφαρμογές για αναδρομικές εργασίες· για
παράδειγμα, ας υποθέσουμε ότι θέλετε να υπολογίσετε το παραγοντικό ενός δεδομένου

## Αντικείμενα τύπου κλάσης

Αν και το xoscript δεν προσφέρει κλάσεις, η μίμηση συμπεριφοράς τύπου
κλάσης είναι απλή υπόθεση. Απλώς υπερκαλύψτε το μήνυμα νέο.

```
>> Animal := Αντικείμενο νέο.
Animal όταν: ['νέο'] κάνε: {
	<- εαυτός νέο αρχικοποίησε.
}.

Animal όταν: ['αρχικοποίησε'] κάνε: {
	δικό sound := ['?'].
	δικό legs  := 4.
}.
```

Στο παραπάνω τμήμα κώδικα, δημιουργούμε ένα αντικείμενο με όνομα Animal.
Αυτό το αντικείμενο χρησιμεύει ως *σχέδιο* για όλα τα είδη ζώων,
όπως σκύλους και γάτες. Το γονικό αντικείμενο Animal γράφεται
με κεφαλαίο A για να δηλωθεί ότι πρόκειται για αντικείμενο τύπου κλάσης.
Στη συνέχεια υπερκαλύπτουμε το μήνυμα νέο γράφοντας τη δική μας μέθοδο νέο.
Σε αυτή την περίπτωση στέλνει ένα μήνυμα νέο στο εαυτός, ακολουθούμενο από το μήνυμα
αρχικοποίησε. Επειδή το xoscript εμποδίζει την αναδρομή από προεπιλογή, αυτό δεν θα προκαλέσει
ατέρμονο βρόχο. Αντίθετα, θα στείλει το μήνυμα νέο στο γονικό
αντικείμενο (Αντικείμενο), με αποτέλεσμα ένα νέο στιγμιότυπο του Animal. Έτσι δημιουργούμε
ένα νέο αντικείμενο, βασισμένο στο ίδιο αντικείμενο για το οποίο δημιουργήσαμε τη μέθοδο νέο.

ότι το αντικείμενο Animal έχει προεπιλεγμένες τιμές για τις ιδιότητές του. Από προεπιλογή
ένα ζώο έχει 4 πόδια και ο ήχος του είναι άγνωστος (εξ ου και το ερωτηματικό).

# Λογικές τιμές

{{messages}}

Σε αντίθεση με τις περισσότερες δημοφιλείς γλώσσες προγραμματισμού τη στιγμή της συγγραφής,
το XOScript παρέχει μόνο ένα μοναδικό αντικείμενο Αληθές και ένα μοναδικό αντικείμενο Ψευδές.
Για να γίνει σαφές, κάθε φορά που γράφετε **Αληθές** δεν σημαίνει ότι
δημιουργείται ένα νέο αντικείμενο. Αντίθετα, χρησιμοποιείτε πάντα μια αναφορά. Αυτό
σημαίνει ότι όταν γράφετε το εξής:

\>\> x := Αληθές.

Το **x** αναφέρεται στο αντικείμενο **Αληθές**. Ο κώδικας συνθηκών και οι βρόχοι επίσης
ελέγχουν αυτή την αναφορά. Στο XOScript, η σημασία των **Αληθές** και **Ψευδές**
δεν είναι σταθερή. Στην πραγματικότητα, ένα πρόγραμμα XOScript αναστατώνεται αρκετά από μια
εντολή όπως αυτή:

Αληθές := Ψευδές.

Το αποτέλεσμα τέτοιων ενεργειών είναι απροσδιόριστο, ωστόσο παραμένει έγκυρη
ενέργεια και επομένως επιτρέπεται τυπικά. Επιπλέον, υπάρχει ένα αντικείμενο Λογικό,
το οποίο είναι το ριζικό αντικείμενο τόσο του **Αληθές** όσο και του **Ψευδές**, καθώς και τα δύο
είναι παράγωγα του ριζικού αντικειμένου. Το ίδιο το αντικείμενο Λογικό, ωστόσο,
δεν έχει καμία πρακτική εφαρμογή.

## Εισαγωγή τιμών

Το XOScript παρέχει στις εργασίες τη δυνατότητα εισαγωγής τιμών. Δείτε
την παρακάτω εργασία:

```
>> sending := {
	Newsletter προς: δικό recipient.
}.
sending ορισμός: ['recipient']
τιμή: ['info@recipient.org'].
sending εκκίνηση.
```


Αυτή η απεικόνιση παρουσιάζει μια φανταστική εργασία, η οποία στέλνει ένα ενημερωτικό δελτίο
σε μια διεύθυνση email ή **recipient** (παραλήπτη). Αυτός ο παραλήπτης μπορεί να εισαχθεί
στην εργασία εξωτερικά, πριν από την εκκίνηση της εργασίας, στέλνοντας το
μήνυμα **ορισμός:τιμή:** στην εργασία. Με αυτόν τον τρόπο, η τιμή του
**recipient** προκαθορίζεται μέσα στην εργασία. Αυτή η τιμή μπορεί επίσης να τροποποιηθεί
και η εργασία μπορεί στη συνέχεια να εκτελεστεί ξανά. Αυτή είναι μια χρήσιμη μέθοδος όταν χρησιμοποιείτε
αντικείμενα εργασιών.

Οι κενές εργασίες δεν επιτρέπονται. Θεωρητικά μια κενή εργασία θα έμοιαζε

## Αλυσίδες μηνυμάτων

Ας υποθέσουμε ότι έχετε μια λίστα όπως:

```
>> x := Λίστα νέο ; 1 ; 2 ; 3.
```

Αν θέλετε να διαγράψετε το πρώτο και το τελευταίο στοιχείο, τότε το
μήνυμά σας θα ήταν:

```
x αφαίρεση-πρώτου αφαίρεση-τελευταίου.
```

Δυστυχώς, ο προηγούμενος συμβολισμός δεν θα λειτουργήσει σωστά. Το
μήνυμα **αφαίρεση-πρώτου** επιστρέφει το πρώτο στοιχείο της λίστας, το οποίο
με τη σειρά του γίνεται ο παραλήπτης του μηνύματος **αφαίρεση-τελευταίου**. Έτσι, το
μήνυμα **αφαίρεση-τελευταίου** δεν αποστέλλεται στο **x**, αλλά στο 2. Μια
πιθανή λύση σε αυτό το πρόβλημα θα ήταν η δημιουργία δύο ξεχωριστών
προτάσεων, όπως: 

```
x αφαίρεση-πρώτου.
x αφαίρεση-τελευταίου.
```

Ωστόσο, αυτό είναι μάλλον μη πρακτικό, ιδιαίτερα όταν χρειάζεται να
διαγράψετε περισσότερα από δύο στοιχεία. Γι' αυτό το XOScript προσφέρει μια
εναλλακτική δομή μηνυμάτων για τέτοιου είδους καταστάσεις. Στις
**εναλλακτικές** δομές μηνυμάτων, οι απαντήσεις των αντικειμένων αγνοούνται
και λαμβάνετε ως απάντηση ξανά και ξανά το αντικείμενο-παραλήπτη.
Μια **εναλλακτική** δομή μηνυμάτων ξεκινά με την αποστολή του
μηνύματος **κάνε** σε ένα αντικείμενο, και η **εναλλακτική** δομή
μηνυμάτων τερματίζεται με την αποστολή του μηνύματος **έτοιμο**. Στο

# Λεξικά

{{messages}}

**Τόσο η Λίστα όσο και το Λεξικό είναι συλλογές. Ωστόσο, σε αντίθεση με μια
λίστα, ένα λεξικό **δεν έχει** σειρά. Μια άλλη διάκριση ανάμεσα στα δύο
είναι ότι ένα λεξικό αποτελείται από ζεύγη αντικειμένων. Το ένα αντικείμενο λειτουργεί ως λήμμα (ή
λέξη-κλειδί) για την αναζήτηση του άλλου αντικειμένου. Ένα καλό παράδειγμα
τέτοιας λίστας είναι ένας τιμοκατάλογος, όπως:


```
>> menu := Λεξικό νέο
	τοποθέτηση: ['£5'] στο: ['apple pie'],
	τοποθέτηση: ['£6'] στο: ['carrot cake'],
	τοποθέτηση: ['£3'] στο: ['fudge'].
```

Όπως και σε μια λίστα, το μήνυμα τοποθέτηση:στο:
χρησιμοποιείται για την προσθήκη ενός αντικειμένου σε μια λίστα. Η διαφορά είναι ότι, σε αντίθεση με
μια λίστα, συνδέονται δύο αντικείμενα. Το πρώτο αντικείμενο είναι, όπως
σε μια λίστα, το αντικείμενο που θα αποθηκεύσετε στη λίστα. Το δεύτερο
αντικείμενο δεν είναι η θέση του μέσα στη συλλογή, αλλά το **λήμμα**
που επιτρέπει την ανάκτηση του προηγούμενου αντικειμένου αργότερα. Με
λίγα λόγια, ένα λεξικό λειτουργεί λίγο σαν ένα λεξικό βιβλίο· χρησιμοποιώντας τη λέξη-κλειδί
μπορεί να βρεθεί η σημασία. Για παράδειγμα, για να ανακτήσετε από την
παραπάνω λίστα την τιμή μιας καραμέλας fudge:

```
>> price := menu στο: ['fudge'].
```

Μπορείτε επίσης να χρησιμοποιήσετε τον συνοπτικό συμβολισμό:

```
>> price := menu ? ['fudge'].
```

Αν τα λήμματα που χρησιμοποιείτε για την αποθήκευση αντικειμένων δεν περιέχουν κενά
(και δεν συγκρούονται με άλλα προκαθορισμένα μηνύματα),
μπορεί επίσης να χρησιμοποιηθεί ο επόμενος συμβολισμός:

```
>> menu := Λεξικό νέο
	pie:   ['£5'],
	cake:  ['£6'],
	fudge: ['£3'].
```

Αναμφίβολα ο παραπάνω συμβολισμός διαβάζεται λίγο πιο φυσικά.
Για να ζητήσετε την τιμή μιας
καραμέλας fudge, μπορεί να χρησιμοποιηθεί ο ακόλουθος απλοποιημένος συμβολισμός:

```
>> price := menu fudge.
```

# Πρόγραμμα/StdOut

{{messages}}

Το αντικείμενο Πρόγραμμα αναπαριστά την εφαρμογή που εκτελείται τη δεδομένη στιγμή. Αυτό το αντικείμενο
προσφέρει λειτουργίες για την εκτέλεση εντολών συστήματος, τη συμπερίληψη υποπρογραμμάτων,
την ανάγνωση ορισμάτων και άλλα. Όλες τις λειτουργίες που σχετίζονται με το σύστημα.

## StdOut

Το Έξοδος είναι το αντικείμενο τυπικής εξόδου. Έχει βασικά δύο μεθόδους:
το **γράψε:** και το **νέα-γραμμή**. Το μήνυμα γράψε: χρησιμοποιείται για την αποστολή ενός κειμένου
στο stdout, ενώ το μήνυμα νέα-γραμμή εκτυπώνει έναν χαρακτήρα νέας γραμμής.
Αντί για το **νέα-γραμμή** μπορείτε επίσης να χρησιμοποιήσετε το \\n.

Παράδειγμα:

```
Έξοδος γράψε: ['Hello World'], νέα-γραμμή.
```

αποτέλεσμα:

```
Hello World
```

## Μονάδες/Πρόσθετα

Ο κόσμος του XOScript μπορεί να επεκταθεί με νέα αντικείμενα συστήματος, με
την εγκατάσταση μονάδων. Ένα νέο αντικείμενο συστήματος μπορεί να προστεθεί στον κόσμο του
XOScript τοποθετώντας το αρχείο της μονάδας (συνήθως ένα αρχείο με κατάληξη .so
) στον φάκελο mods. 

Όταν στέλνετε ένα μήνυμα στο αντικείμενο που γίνεται διαθέσιμο μέσω της
μονάδας πρόσθετου, αυτή φορτώνεται αυτόματα από το XOScript.

Μπορείτε επίσης να γράψετε πρόσθετα μόνοι σας. Τα πρόσθετα γράφονται στη
γλώσσα προγραμματισμού C. Μπορείτε να βρείτε ένα παράδειγμα πρόσθετου στο πακέτο πηγαίου
κώδικα, στο src/plugins/example.


## Ανάκλαση

Υπάρχουν διάφοροι τρόποι εξερεύνησης του συστήματος
κατά την εκτέλεση του προγράμματος. Το XOScript διαθέτει μερικές μεθόδους για να
εντοπίσετε ποια αντικείμενα υπάρχουν και σε ποια μηνύματα αποκρίνονται αυτά τα
αντικείμενα. Πρώτον, μπορείτε να ρωτήσετε κάθε αντικείμενο τι **τύπος** είναι,
ωστόσο οι τύποι στο XOScript είναι εύπλαστοι και επομένως αναξιόπιστοι.

Είναι επίσης δυνατό να ρωτήσετε το αντικείμενο Πρόγραμμα αν ένα
δεδομένο αντικείμενο υπάρχει ήδη στο πρόγραμμα:

```
Πρόγραμμα Tool αληθές: { ... }.
```

Στην περίπτωση ονόματος αντικειμένου
που αποτελείται από ένα μόνο σύμβολο, είναι καλύτερο να εφαρμόσετε τον
ακόλουθο συμβολισμό για να αποφύγετε τη σύγχυση:

```
Πρόγραμμα εύρεση: ['X'], αληθές: { ... }.
```

Εκτός από ερωτήσεις για αντικείμενα, είναι εξίσου δυνατό να ρωτήσετε το
αντικείμενο Πρόγραμμα για μηνύματα. Για παράδειγμα, μπορείτε να ρωτήσετε αν το
αντικείμενο **Αριθμός** γνωρίζει το μήνυμα **μεταξύ:και:**, με τον τρόπο
που φαίνεται παρακάτω:

```
Πρόγραμμα Number: ['between:and:'], νέα-γραμμή.
```

## Γεια σου κόσμε

Ακολουθεί ένα πολύ απλό πρόγραμμα ιστού που μπορείτε να χρησιμοποιήσετε με έναν
τυπικό διακομιστή CGI, όπως Apache2, NGINX, OpenHTTPD ή οποιονδήποτε άλλο

```
#!/bin/xo

Server αρχικοποίησε.
Πρόγραμμα χρήση: ['webtools.xo'].

>> web-document := Έγγραφο-Ιστού νέο.

web-document έξοδος: ['
<html>
<body>
<b>Hello World!</b>
```

Αν δεν θέλετε να χρησιμοποιήσετε το αντικείμενο Έγγραφο-Ιστού, δεν πειράζει, αλλά
τότε πρέπει να γράψετε μόνοι σας τις κεφαλίδες HTTP:

```
#!/bin/xo
Έξοδος γράψε: ['Content-type: text/html; charset=utf-8 \n\n'], νέα-γραμμή.
Έξοδος γράψε: ['hello world!'], νέα-γραμμή.
``` 

## Αίτημα

Το αντικείμενο HTTP-Αίτημα μπορεί να χρησιμοποιηθεί για τη λήψη δεδομένων GET/POST/COOKIE και
UPLOAD:

```
>> αίτημα  := HTTP-Αίτημα νέο.
>> search   := αίτημα get: ['search']. # ?search=books
>> password := αίτημα post: ['password']. # from form
>> selected := αίτημα get-λίστα: ['sel[]']. #?sel[]=1&sel[]=2
>> selected := αίτημα post-λίστα: ['sel[]'].
>> cookie   := αίτημα cookie: ['session-id'].
>> upload   := αίτημα upload: ['file'].
>> temppath := upload ? 1.
>> filename := upload ? 0.
```

## Μέγιστο πλήθος/μήκος POST

Το προεπιλεγμένο μέγιστο πλήθος πεδίων POST είναι 40 και το προεπιλεγμένο μέγιστο μήκος
περιεχομένου είναι 2MB. Για διαφορετική ρύθμιση ανά σενάριο:

```
Πρόγραμμα ρύθμιση: ['max-contentlength'] τιμή: 1. 
Πρόγραμμα ρύθμιση: ['max-postfields'] τιμή: 1. 
```

{{note}}
Αν το μήκος του περιεχομένου υπερβεί το μέγιστο, η
διεργασία τερματίζεται, επειδή δεν μπορούμε πλέον να είμαστε βέβαιοι
ότι το φορτίο δεδομένων είναι ασφαλές.
{{/note}}

Το όριο maxtime καθορίζει τον μέγιστο χρόνο σε ms
για την ανάγνωση του stdin/των δεδομένων POST.

```
Πρόγραμμα ρύθμιση: ['max-time'] τιμή: 5000. # 5sec
```

Αυτό ισχύει μόνο για την ανάγνωση εισόδου/εξόδου του POST και αποτρέπει
επιθέσεις τύπου slowloris. Αν θέλετε πραγματικά να περιορίσετε τον
χρόνο εκτέλεσης οποιασδήποτε λειτουργίας, χρησιμοποιήστε το Πρόγραμμα ξυπνητήρι:.

## Βάση δεδομένων

Το αντικείμενο Database μπορεί να χρησιμοποιηθεί για ερωτήματα σε MariaDB/MySQL.
Για να συνδεθείτε σε μια βάση δεδομένων:

```
>> db := Maria-DB νέο κόμβος: ['localhost'],
	χρήστης: ['xo'],
	κωδικός: ['pass123'],
	όνομα-βάσης: ['xobase'],
	συνδέσου.

```

Για να εισαγάγετε μια εγγραφή χρησιμοποιήστε:

```
>> παράμετροι-αναζήτησης := db ερώτημα: ['
	INSERT INTO book (id, description, price, rating) 
	VALUES (NULL, ?, ?, ?)
'], παράμετροι: ( Λίστα νέο ; ['abc'] ; 12.35 ; 6 ). # parameterized queries

{  παράμετροι-αναζήτησης εκτέλεση. db επικύρωση. }
σύλληψη: { :e db αναίρεση.  }, εκκίνηση.
```

Σημειώστε ότι το xoscript λειτουργεί *μόνο* με συναλλαγές και δεν κάνει ποτέ αυτόματη επικύρωση (autocommit).
Αν η αυτόματη επικύρωση δεν μπορεί να απενεργοποιηθεί, θα λάβετε σφάλμα σύνδεσης.
Χρησιμοποιείτε πάντα δέσμευση παραμέτρων στα ερωτήματα· μην προσθέτετε ποτέ είσοδο χρήστη απευθείας
στην SQL.

Λάβετε το αναγνωριστικό της εισαχθείσας εγγραφής ως εξής:

```
Έξοδος γράψε: ['INSERTED: '] + παράμετροι-αναζήτησης insert-id, νέα-γραμμή. # insert id
```

Για να ανακτήσετε εγγραφές:

```
>> παράμετροι-αναζήτησης :=
db
	ερώτημα: ['SELECT * FROM book order by id desc limit 2'], 
	ανάκτηση: { :row 
		Έξοδος γράψε: row id + [' '] + row description + [': '] + row price, νέα-γραμμή.
	}. # fetching rows

```

## Συνεδρίες

Για μόνιμη διατήρηση δεδομένων μπορείτε να αποθηκεύετε και να ανακτάτε δεδομένα από ένα αντικείμενο συνεδρίας.
Πρώτα δημιουργήστε ένα νέο **Έγγραφο-Ιστού**. Το αντικείμενο Έγγραφο-Ιστού συνδέει
το αίτημα, τις κεφαλίδες, την HTML και τη συνεδρία. Αυτό συμβαίνει επειδή, όποτε
επισκέπτεστε έναν ιστότοπο με το πρόγραμμα περιήγησής σας, βλέπετε μόνο την HTML. Όμως
ολόκληρο το Έγγραφο-Ιστού αποτελείται επίσης από **Κεφαλίδες**. Για παράδειγμα,
οι περισσότερες αποκρίσεις HTTP περιλαμβάνουν μια κεφαλίδα όπως: Content-type:text/html για να
ενημερώσουν το πρόγραμμα περιήγησης ότι τα δεδομένα που ακολουθούν πρέπει να αποδοθούν ως HTML
(και όχι, για παράδειγμα, να ληφθούν σαν αρχείο). Οι συνεδρίες είναι ένας τρόπος
αποθήκευσης δεδομένων χρήστη μεταξύ αιτημάτων. Για να παρακολουθούμε αυτά τα δεδομένα πρέπει
να ορίσουμε ένα cookie· και αυτό το cookie ορίζεται μέσω μιας Κεφαλίδας. Γι' αυτό
όλα συνδυάζονται στο Έγγραφο-Ιστού (επειδή είναι το πλήρες
έγγραφο που περιέχει τόσο τις κεφαλίδες όσο και την HTML ή άλλα δεδομένα).


```
# First we make a new Web Document instance
>> web := Έγγραφο-Ιστού νέο.

# Now we start a session, this will generate a Header for a cookie and
# create a file to store your data, associated with that cookie
>> session := web ξεκίνα-συνεδρία.

# Now we can treat session like a dict
session userid: 123.
```

Για να καταστρέψετε τη συνεδρία (κατά την αποσύνδεση):

```
web κατάστρεψε-συνεδρία.
```

## Κεφαλίδες

Το Έγγραφο-Ιστού σας επιτρέπει επίσης να ορίζετε άλλες γνωστές κεφαλίδες.
Για παράδειγμα, αν θέλετε να ανακατευθύνετε τον χρήστη σε άλλο URL:

```
web μετάβαση: ['/other.html'].
```

Στο παρασκήνιο, αυτή η εντολή δημιουργεί επίσης την κεφαλίδα HTTP που αποστέλλεται
μαζί με τα υπόλοιπα δεδομένα ή την HTML σας, για να δώσει εντολή στο πρόγραμμα περιήγησης να μεταβεί
στην καθορισμένη διεύθυνση προορισμού.

Για να προσθέσετε μια προσαρμοσμένη κεφαλίδα:

```
web κεφαλίδα: ( 
	Κεφαλίδα-HTTP νέο
	κλειδί: ['Content-Length']
	τιμή: 400
).
```

Για να εμφανίσετε μια σελίδα 404:

```
web δεν-βρέθηκε: ['OOps..'].
```


## Πρότυπα

Το προεπιλεγμένο σύστημα προτύπων είναι πολύ απλό. Δεν χρειάζεται να μάθετε
νέα σύνταξη προτύπων. Επιπλέον, η μηχανή προτύπων εξασφαλίζει πραγματικό διαχωρισμό
μεταξύ παρουσίασης και επιχειρησιακής λογικής.

Για να δημιουργήσετε ένα πρότυπο από ένα αρχείο:

```
>> tpl := web πρότυπο: ['templates/ux.tpl'].
```

Το σύστημα προτύπων χρησιμοποιεί δείκτες. 
Υπάρχουν τρία είδη δεικτών: δείκτες αποκοπής, δείκτες επικόλλησης και
δείκτες θέσεων. Η βασική ιδέα είναι πραγματικά απλή: αποκόπτετε
περιοχές που προσδιορίζονται από δείκτες αποκοπής και μπορείτε να τις επικολλήσετε σε
περιοχές που προσδιορίζονται από δείκτες επικόλλησης. Μπορείτε να εισαγάγετε κείμενα σε
δείκτες θέσεων.

Έτσι, για παράδειγμα, με το ακόλουθο πρότυπο, ας βάλουμε το
πετράδι στη μπιζουτιέρα και ας προσθέσουμε μια ετικέτα τιμής.

```
<!-- cut:gem -->
<img src="gem.gif">
<b>$<!-- slot:price --></b>
<!-- /cut:gem -->

<div id="box">
<!-- paste:jewels -->
</div>
```

Μπορείτε να το κάνετε ως εξής:

```
>> gem := tpl αποκοπή: ['gem'], αντιγραφή.
gem price: 99.
tpl επικόλλησε: gem στο: ['jewels'].
web έξοδος: tpl συμμάζεψε.
```

Η τελευταία γραμμή απλώς στέλνει το πρότυπο ως κείμενο στον πελάτη
μαζί με τις απαιτούμενες κεφαλίδες HTTP.

Αποτέλεσμα:

```
<div id="box">
<img src="gem.gif">
<b>$99</b>
</div>
```


## Passthru

Για να εξυπηρετείτε με ασφάλεια αρχεία που ανεβάζουν οι χρήστες, μπορείτε να βασιστείτε στο passthru:

```
>> uploaded := ['smile.gif'].
Server προώθηση: uploaded πρόθεμα: ['/uploads/images/'].
Πρόγραμμα τέλος.
```

Αυτό θα εξυπηρετήσει το περιεχόμενο που ανέβασε ο χρήστης με τον κατάλληλο
τύπο mime. Υποστηρίζονται μόνο τύποι mime από λίστα επιτρεπόμενων:
GIF, JPG, PNG, WEBP, MP4, WEBM, MP3, ZIP, GZIP, PDF και SVG.
Τα αρχεία SVG, ZIP και GZIP αποστέλλονται για λήψη, επειδή ένα SVG
μπορεί να περιέχει σενάρια που διαφορετικά θα εκτελούνταν στον τομέα σας.
Αυτή η μέθοδος αποτρέπει επιθέσεις TOCTOU, διάσχιση διαδρομών,
εκτέλεση κακόβουλου κώδικα (έγχυση), επιθέσεις μέσω συμβολικών συνδέσμων,
επιθέσεις DDoS (όριο αρχείου = 50MB), επιθέσεις υποκλοπής και
διάφορα άλλα ζητήματα ασφάλειας.

## Μορφοποίηση

Το αντικείμενο Μορφή σας επιτρέπει να μορφοποιείτε δεδομένα, για παράδειγμα με συμπλήρωση ή
προσθήκη μηδενικών. Χρησιμοποιεί τη σύνταξη της printf.

```
>> fmt := Μορφή νέο: ['%06.0f'].
fmt εφαρμογή: 56. # gives 000056
```

Μια μορφή μπορεί να περιέχει μία μετατροπή, η οποία πρέπει να ταιριάζει με την τιμή,
διαφορετικά λαμβάνετε σφάλμα:

- `εφαρμογή:` με κείμενο: `%s`
- `εφαρμογή:` με αριθμό: `%f`, `%e`, `%g` ή `%a`
- `εφαρμογή-ακεραίου:` με αριθμό: `%d`, `%i`, `%o`, `%u`, `%x` ή `%c`

Οι τιμές από ένα αίτημα είναι κείμενα. Για να μορφοποιήσετε μια τέτοια τιμή ως αριθμό,
μετατρέψτε την πρώτα:

```
fmt εφαρμογή: (αίτημα get: ['amount']) αριθμός.
```

# ffi

{{messages}}

Το FFI παρέχεται ανά πλατφόρμα/πρόσθετο, επειδή
συνδέεται με την υποκείμενη αρχιτεκτονική του συστήματος, κάτι που ο
πυρήνας δεν προορίζεται να κάνει.
Το πρόσθετο διακομιστή προσφέρει μια συμβατή υλοποίηση ffi/blob.
Από προεπιλογή ο πυρήνας συνδέεται με την πλατφόρμα-στόχο
μέσω stdin/stdout, περιορισμένων υπηρεσιών εισόδου/εξόδου αρχείων και του φλοιού (Πρόγραμμα σύστημα:).
Η πρόσθετη ενοποίηση παρέχεται από τα ffi/blobs μέσω πρόσθετων
προσανατολισμένων σε εφαρμογές, όπως το πρόσθετο διακομιστή.

FFI σημαίνει Foreign Function Interface (διεπαφή ξένων συναρτήσεων). Σας επιτρέπει να χρησιμοποιείτε λειτουργίες γραμμένες από άλλους σε
διαφορετικές γλώσσες προγραμματισμού, που παρέχονται μέσω αρχείων DLL, SO ή Dylib. Αυτές μπορεί
να είναι ποικίλες συναρτήσεις, και μέσω αυτής της μεθόδου είναι διαθέσιμο ένα τεράστιο εύρος λειτουργιών.
Ας ξεκινήσουμε με ένα παράδειγμα:

```
Server σύνδεση: (
 Λίστα νέο ;
 ['/usr/lib/x86_64-linux-gnu/libc.so.6'] ;
 ['printf'] ;
 ( Λίστα νέο ; ['pointer'] ; ['int'] ) ;
 ['void'] ;
 ['Printf'] ;
 ['template:number:']
).
>> s := Blob utf8: ['FFI has %d letters.\n'].
Printf template: s number: 3.
s αποδέσμευση.
```

Το αποτέλεσμα αυτού του κώδικα είναι ότι θα δείτε το εξής στη γραμμή εντολών:
FFI has 3 letters.
Τώρα πιθανώς σκέφτεστε: «Πολύς κώδικας για κάτι τόσο απλό.»
Δηλαδή, δεν θα μπορούσαμε απλώς να το λύσουμε με μια εντολή εμφάνισης Gui; Η απάντηση είναι ένα ηχηρό ναι!
Αυτό όμως προορίζεται ως επεξηγηματικό παράδειγμα.
Το FFI χρησιμοποιείται συνήθως για πιο σύνθετες εργασίες, αλλά αυτές δεν αποτελούν καλά
παραδείγματα, γι' αυτό επέλεξα κάτι απλό.

Τα ορίσματα της μεθόδου σύνδεσης:

- Όρισμα #1: Το αρχείο DLL ή SO που θέλετε να χρησιμοποιήσετε.
- Όρισμα #2: Η συνάρτηση σε αυτό το αρχείο που θέλετε να συνδέσετε.
- Όρισμα #3: Μια λίστα με τα ονόματα των τύπων δεδομένων των ορισμάτων της συνάρτησης.
- Όρισμα #4: Το όνομα του τύπου επιστροφής της συνάρτησης.
- Όρισμα #5: Το όνομα του αντικειμένου στο οποίο θέλετε να συνδέσετε αυτή τη συνάρτηση (αν δεν υπάρχει, θα δημιουργηθεί
αυτόματα).
- Όρισμα #6: Το μήνυμα με το οποίο πρέπει να συνδεθεί αυτή η συνάρτηση.

Στο παραπάνω παράδειγμα, θέλουμε να συνδέσουμε τη συνάρτηση printf από τη libc.so. Μπορείτε να βρείτε τα ονόματα
των τύπων δεδομένων στην τεκμηρίωση του λογισμικού με το οποίο συνδέεστε. Οι διαθέσιμοι τύποι είναι:
void, pointer, float, double, int, uint, char, uchar, intX και uintX,
όπου το X μπορεί να είναι 8, 16, 32 ή 64.

Αυτοί οι τύποι αναφέρονται στον αριθμό των byte που απαιτούνται για την αποθήκευση των δεδομένων. Για την printf, συνδέουμε σε ένα
νέο αντικείμενο με όνομα Printf και το μήνυμα template:number:. Μεταφράζετε την εξωτερική
συνάρτηση στη διάλεκτο του XOScript πριν τη χρησιμοποιήσετε. Το μήνυμα template:number: αναμένει
ως πρώτη παράμετρο έναν ενδιάμεσο χώρο μνήμης (buffer) με το κείμενο του προτύπου. Δημιουργούμε αυτόν τον χώρο με ένα αντικείμενο Blob, το οποίο
σας επιτρέπει να δεσμεύετε μνήμη χειροκίνητα. Είστε υπεύθυνοι για την αποδέσμευση αυτής της μνήμης στη συνέχεια
με το μήνυμα αποδέσμευση.

Μπορείτε να γεμίσετε ένα blob μνήμης με διάφορους τρόπους. Στο παράδειγμά μας, το γεμίζουμε με κείμενο, οπότε χρησιμοποιούμε το
μήνυμα utf8: (το UTF-8 είναι μια κωδικοποίηση για τη μετατροπή κειμένου σε byte). Μπορείτε επίσης να γεμίσετε ένα blob με το
bytes:, περνώντας μια λίστα με τιμές byte. Για να διαβάσετε τα περιεχόμενα ενός blob, χρησιμοποιήστε το από:μήκος:.
Θα πάρετε πίσω τα byte ως λίστα. Μπορείτε ακόμη να δημιουργήσετε μια C-struct με ένα Blob χρησιμοποιώντας το
μήνυμα struct:, περνώντας μια ακολουθία τύπων C. Αυτό μπορεί να είναι απαραίτητο όταν καλείτε μια συνάρτηση C
σε μια εξωτερική βιβλιοθήκη λογισμικού που αναμένει δείκτη σε struct.

{warning}
Πρέπει να αποδεσμεύετε μόνοι σας τα blobs.
Τα blobs δεν καθαρίζονται από τον συλλέκτη απορριμμάτων.
{/warning}

Επειδή τα blobs μπορούν να ανταλλάσσονται με εξωτερικές συναρτήσεις από βιβλιοθήκες,
δεν μπορούν να συλλεχθούν αυτόματα από τον συλλέκτη απορριμμάτων (μπορεί να παραμένουν σε χρήση από
εξωτερικές συναρτήσεις ή αυτές οι εξωτερικές συναρτήσεις μπορεί να θέλουν να τα αποδεσμεύσουν
οι ίδιες). Επομένως, πρέπει να αποδεσμεύετε μόνοι σας τα blobs όταν χρειάζεται.

Για να αποδεσμεύσετε ένα blob χρησιμοποιήστε:

```
myblob αποδέσμευση.
```

Για να αποδεσμεύσετε μια struct χρησιμοποιήστε:

```
mystruct αποδέσμευση-struct αποδέσμευση.
```

Έτσι, για μια struct, πρέπει να στείλετε δύο μηνύματα: αποδέσμευση-struct και αποδέσμευση για να
αποδεσμεύσετε το μπλοκ μνήμης.
