Добро пожаловать в XOScript
Цель проекта XOScript — создать простой и проверяемый (auditable) скриптовый язык.
Простой не обязательно означает лёгкий.
Привычный язык программирования может оказаться проще в использовании, чем XOScript.
Здесь простота означает нечто иное:
возможность составить полную мысленную модель языка и его поведения.

XOScript задуман так, чтобы целиком умещаться в голове.
Его грамматика и число понятий намеренно невелики.
Классов нет; объекты можно расширять напрямую.
Объекты передаются по ссылке, копирование выполняется явно,
а у функций есть только одна точка выхода.

Некоторые из этих решений заметно отличаются от распространённых языков.
Например, в XOScript нет системы типов, и в нём используется динамическая область видимости.
Сообщения, которые не могут быть обработаны, игнорируются, а не вызывают исключение.
У этих решений есть последствия, и они не призваны устранить ошибки.
Их задача — сохранить базовую модель языка маленькой и согласованной.

XOScript также можно локализовать, что позволяет выражать бизнес-правила
на естественном языке и, возможно, делиться ими с людьми без технической подготовки.

Проверяемость означает применение той же философии к реализации.
Среда выполнения написана на C и содержит небольшой написанный вручную лексер, парсер и интерпретатор обхода дерева.
Стандартная библиотека и среда выполнения во многом повторяют структуру языка,
поэтому связь между кодом XOScript и его реализацией остаётся относительно прямой.

Тесты также тесно связаны с документацией.
У каждого метода должен быть свой тест, который можно включить в руководство,
что помогает поддерживать документацию в соответствии с реализацией.

XOScript не стремится конкурировать с распространёнными языками
по возможностям или привычности. Он преследует другую цель:
среду программирования, которую разработчик может понять целиком.

Надежда состоит в том, что маленький язык и маленькая
реализация позволяют на практике понимать программное обеспечение
от байта до объекта, от синтаксиса до среды выполнения, и писать код
уверенно, потому что вы понимаете, что происходит
и в скрипте, и «под капотом».

Чтобы использовать xoscript как серверный язык, нужно установить

Так сделано потому, что мы предпочитаем
отделять ядро языка от функциональности, специфичной для сервера,
в отличие, например, от PHP или Python. Иначе нам пришлось бы без всякой
надобности поставлять всем «всё и сразу», что попросту глупо.
При желании вы можете установить и другие модули. Система очень
гибкая.

Кроме того, некоторые функции лучше реализовать на самом скриптовом
языке, например шаблоны и работу с сессиями, поэтому дополнительно мы
для вашего удобства поставляем библиотеки template.xo и webtools.xo.
Причина всего этого в том, что мы не знаем, как именно вы захотите
использовать xoscript. Его можно применять как серверный скриптовый язык,
но также для графических интерфейсов, встраиваемых устройств или просто пакетной обработки.
Даже если вы используете его как серверный скриптовый язык (что
сейчас является одним из основных сценариев), вы всё равно можете захотеть
использовать другой шаблонизатор или другой обработчик сессий.
Кто мы такие, чтобы решать, что вы должны пользоваться нашими?

Впрочем, одно из преимуществ нашего собственного шаблонизатора в том,
что для создания шаблонов не нужно учить дополнительный синтаксис.
Шаблонизатор по умолчанию, поставляемый с xoscript, обеспечивает 100%
разделение представления и логики. Вместо специального
синтаксиса шаблонов он использует очень гибкую систему маркеров-слотов.
Подробнее см. главу «Сервер».

Само собой разумеется, если вы не хотите использовать шаблонизатор по умолчанию или
стандартные webtools, вам придётся предоставить
свои собственные.

Если ваш веб-сервер работает в chroot, jail или другой песочнице,
в этом окружении также нужно установить зависимости xo; узнать,
какие библиотеки нужны, можно с помощью ldd (см. man-страницу Linux или BSD).
Если вы хотите использовать в своих xo-скриптах команды оболочки, скопируйте в это окружение также оболочку
(например, bash или ksh).

Также хотим отметить, что мы очень серьёзно относимся к обратной совместимости.
Для этого есть даже специальная функция обратной совместимости под названием
'version'. В целом мы стремимся к тому, чтобы ваш код работал вечно. Вам
никогда не придётся обновлять код, чтобы он оставался совместимым с новыми версиями
xoscript. Наша цель: написал один раз — работает вечно.

Оставшаяся часть руководства посвящена подробному описанию языка
программирования xoscript. Серверные скрипты рассматриваются в главе
«Сервер». Если вы опытный разработчик, возможно, вы захотите
пропустить несколько глав, поскольку некоторые из них слишком подробны или
очень похожи на общепринятые практики программирования. Поэтому тем из вас,
у кого уже есть опыт работы с несколькими другими языками программирования,
лучше использовать это руководство как справочник.

## Установка в Linux

Загрузите apache2 и mariadb:


```
sudo apt-get install apache2 mariadb-server
sudo a2enmod cgi
```

Загрузите xoscript.
Замените X на правильный номер версии!

```
wget https://xoscript.com/downloads/xoserver-linux-1_5_X.tar.gz
tar xvf xoserver*.tar.gz
```

Скопируйте файлы в корневой каталог веб-сервера и в /bin:


```
sudo cp bin/xo /bin/xo
sudo cp -R bin/mods /var/www/html/
sudo cp *.xo /var/www/html/
```

Отредактируйте конфигурацию apache2:

```
sudo nano /etc/apache2/sites-enabled/000-default.conf
```

Замените Virtualhost на:

```
<VirtualHost *:80>
    <Directory /var/www/html>
        Options +ExecCGI
        AllowOverride All
        AddHandler cgi-script .xo
        Require all granted
    </Directory>
    DocumentRoot /var/www/html
</VirtualHost>
```

Создайте тестовую страницу:

```
sudo nano /var/www/html/test.xo
```

и напишите небольшую тестовую программу:

```
#!/bin/xo
Server инициализировать.
Программа импортировать: ['webtools.xo'].
>> веб := Веб-документ новый.
веб вывести: ['Hello World'].
```

Разрешите apache2 выполнять вашу программу через CGI:

```
sudo chmod uog+x /var/www/html/test.xo
```

Перезапустите apache2:

```
sudo systemctl restart apache2
```

Откройте тестовую страницу в браузере:

```
http://localhost/test.xo
```

Вы должны увидеть:

```
Hello World
```


## Установка в OpenBSD

Отредактируйте /etc/httpd.conf и добавьте:


```
server "mydomain.com" {
    listen on * port 80
    root "/htdocs/mydomain/"

    location "*.xo" {
        fastcgi
        fastcgi socket "/run/slowcgi.sock"   # inside chroot
    }
}
```

Если вы хотите использовать SSL:

```
listen on * tls port 443
tls {
	certificate "/etc/ssl/mycert.crt"
	key "/etc/ssl/private/mykey.key"
}
```

Чтобы защитить обмен ключами от квантовых атак,
выберите шифр mlkem:

```
tls {
 ... 
 ecdhe "X25519MLKEM768"
 ...
}
```

Добавьте в chroot исполняемый файл xo и модули, а также все зависимости
(их можно определить с помощью ldd).

## Запуск примеров


Чтобы запустить одну из примерных программ из пакета:

```
./example.sh <name> <Linux/OBSD> [clean]
```

Например, чтобы запустить пример FizzBuzz в Linux:

```
./example.sh fizzbuzz Linux
```

Чтобы запустить тот же пример в OpenBSD:

```
./example.sh fizzbuzz OBSD
```

Чтобы запустить пример с чистой сборкой:

```
./example.sh fizzbuzz OBSD clean
```

```

```

```
./runtests.sh nobuild
```

Чтобы собрать из исходного кода в Linux:

```
make clean
ISO="en" make
```

В OpenBSD:

```
make -f makefile.obsd clean
ISO="en" make -f makefile.obsd
```

Чтобы собрать серверный плагин в Linux:

```
PACKAGE="server" NAME="server.so" make plugin-clean
ISO="en" PACKAGE="server" NAME="server.so" make plugin
```

Чтобы собрать серверный плагин в OpenBSD:

```
PACKAGE="server" NAME="server.so" make -f makefile.obsd plugin-clean

```

## Hello world

После того как файл перенесён на ваш компьютер, его можно распаковать
и запустить xo следующей командой:

```
xo
```

Чтобы запустить программу на XOScript, сохраните её в файл, добавив суффикс -xo
(необязательно). Кроме того, укажите имя файла вашей программы
после команды XOScript:

```
xo myprogram.xo
```

Если запустить команду XOScript, передав ей файл программы в качестве
параметра, xo прочитает и выполнит этот файл.

{{note}}
Программу можно также запустить, перетащив её на значок xo.
{{/note}}

{{warning}}
В некоторых системах нужно заранее разрешить xo загружать динамические
библиотеки.
{{/warning}}

По традиции первая программа на любом новом языке
программирования должна быть своего рода приветствием миру. В XOScript такая
программа **Hello world** выглядит так:

@test598

Если сохранить этот текст в файл, например hello.xo, его можно выполнить
следующим образом: .

xo hello.xo

Hello world


Вывод программы виден в показанном выше чёрном окне.
На протяжении всего руководства вывод будет показываться
таким же образом.

{{note}}
Выход пишется с прописной буквы В.
Как правило, имена объектов начинаются с прописной буквы,
если только объект не выступает в роли экземпляра (у него нет
собственных методов, только данные). Это повторяет соглашения
о классах и экземплярах в других языках программирования.
{{/note}}


## Синтаксис

XOScript — *чисто* *объектно-ориентированный* язык программирования. Это означает,
что xoscript считает всё объектом, поэтому других
*типов данных* в нём нет. По сути, в программе на XOScript есть три базовых
действия: *присваивание*, *отправка сообщений*
и *ответ*. Обмен сообщениями между объектами — ключевая часть
программы на XOScript. Эти три действия показаны
ниже:


Действие            | Пример
------------------- | --------
присваивание        |  \>\> x := 1. 
унарные сообщения   | x четное?.
бинарное сообщение  | 1 + 2.
сообщение с ключевыми словами | x от: 0 длина: 10.
ответ               | <- answer.  


В этой главе даётся общее представление о языке XOScript
и описываются его основные принципы. XOScript — небольшой язык,
основанный на трёх действиях (см. иллюстрацию), которые выражаются
примерно в шести грамматических правилах. Это всё, что нужно, чтобы освоить
язык.

Не беспокойтесь, если что-то сразу не станет понятным: все строительные
блоки будут рассмотрены в следующей главе (3), а основные правила будут
повторены. Текущая же глава служит в основном общим
введением в язык. Основные принципы будут кратко
объяснены и проиллюстрированы рядом подходящих примеров. Недостающие
подробности будут изложены позже.

Комментарии в XOScript начинаются с символа \#. Поэтому следующая строка
будет проигнорирована:

```
# это просто комментарий
```

## Переменные

Чтобы объявить
переменную, используется символ объявления переменной: >>. Имя
переменной может содержать любые знаки, кроме: <-, :=, пробельных символов,
точек, запятых, двоеточий, кавычек [' '] и круглых скобок ().
Кроме того, имя переменной не может занимать несколько строк. Обратите внимание,
что имя переменной не может начинаться с цифры или знака минус.

Вот примеры допустимых переменных:

```
>> password := ['Secret'].
>> ♡♡♡ := 3.
>> $ := ['доллар'].
>> +plus := Истина.
>> пароль-пользователя := ['Тсс!'].
```

Недопустимые переменные, например:


```
>> -123 := ['отрицательное число'].
>> password of пользователя := ['Секретно'].
>> password.of:пользователя := ['Секретно'].
>> ,x := 10.
```

{{note}}
В строковом литерале не нужно экранировать никакие символы
(включая кавычки, двойные кавычки и границы
строки), пока это не
создаёт неоднозначности для лексера.
{{/note}}

После объявления переменную можно свободно использовать. Это означает,
что символ объявления нужен только при первом
использовании переменной (при объявлении).

Точнее говоря, нельзя просто так начать присваивать значение
переменной *(x := 2)*: сначала нужно объявить переменную *(\>\>
x := 2)*. Однако после объявления её значение можно менять
без символа объявления *(\>\> x := 2. x := 3.)*.

Обратите внимание, что при объявлении переменной обязательно присвоить ей значение.
В отличие от других языков программирования, объявить
переменную без значения нельзя. Каждую переменную необходимо явно связать
с начальным значением. Тем не менее вы можете инициализировать
переменную объектом **Пустой**. В этом случае переменную можно
считать пустой *(\>\> x := Пустой.)*. Короче говоря, объявлять
переменную без начального значения нельзя. Поэтому

```
>> x.
```

недопустимо и приведёт к сообщению об ошибке.

{{note}}
В xoscript используется динамическая область видимости
переменных; подробнее см. главу «Функции».
{{/note}}


## Литералы

XOScript считает всё объектом, то есть все числа, строки
и фрагменты кода. Числа, такие как 1, 2, 100, -999 и 1,234, являются
объектами Число. Любой текст между одинарными кавычками — это объект
Текст. Любой фрагмент кода, заключённый в фигурные скобки {...}, — это объект
Код.

Литерал         | Корневой объект | Пример
--------------- | --------------- | ----------
числа           | Число           | 1,2,3... 
строки          | Текст           | \['hello'\]
функция         | Код             | { 1 + 2. }.
                
     
Такие объекты, как числа и строки, всегда происходят от корневого
объекта. Например, все числа происходят от объекта **Число**. Все
строки происходят от **Текст**, а все фрагменты кода — от **Код**. В
свою очередь, все эти объекты происходят от **Объект**, который на самом деле является
корневым объектом всех объектов.


## Сообщения

Программировать на XOScript по сути означает
отправлять сообщения объектам. Общая запись отправки сообщения
объекту выглядит так:

```
<object> <message>
```

Чтобы узнать, является ли, например, число **2** чётным, объекту **2**
отправляется сообщение **четное?**:

```
2 четное?
```

Ответом будет **Истина** (опять же объект). Неизвестные сообщения
объекты обычно игнорируют, поэтому ошибки не возникает. Некоторые объекты (например,
числа или строки) отвечают на неизвестное сообщение заранее определённым образом
(подробнее об этом позже).

Объект может получать сообщения трёх видов.

Вид                         | Число аргументов
--------------------------- | -------------------
Унарное                     | 0      
Бинарное                    | 1     
С ключевыми словами         | 1+    


Во-первых, есть **унарные
сообщения** (см. пример выше), у которых нет аргументов. Во-вторых,
есть **сообщения с ключевыми словами**, у которых один или несколько аргументов,
например:

```
>> x := Число между: 1 и: 10.
```

В этом случае сообщение **между:и:** отправляется объекту **Число**, который
является корневым объектом всех чисел. Результатом будет случайное число
от 1 до 10. Наконец, есть **бинарные сообщения**, которые состоят
всего из одного символа и имеют один аргумент:

```
2 + 3
```

Это похоже на математическое сложение, но на самом деле это просто ещё одно сообщение.
Сообщение **+** отправляется объекту **2** с аргументом **3** и возвращает
ответ **5**. Бинарные сообщения разрешается записывать без двоеточия.

Бинарные сообщения можно выстраивать в цепочку:

```
>> x := 3 + 2 - 1.
```

В этом фрагменте сначала **+ 2** отправляется объекту **Число** **3**, что
даёт объект Число **5**, после чего этому числу отправляется **-1**.
Внимательные читатели справедливо заметят расхождение
этого протокола с общепринятым математическим порядком
операций. XOScript игнорирует математический порядок ради
единообразия своей системы сообщений. В результате выражение:

```
2 + 3 * 5 = 25
```

а не 17.

Так задумано. Порядок вычислений можно изменить с помощью скобок:

```
2 + (3 * 5) = 17
```

Большинство объектов в ответ на сообщение возвращают
самих себя. Это удобно, поскольку позволяет продолжить диалог с этим
объектом, отправив ему следующее сообщение:

```
Выход написать:
[' привет '] сократить верхний-регистр.
```

```
привет
```

Здесь объекту **Текст** отправляются два сообщения: **сократить**, а затем
**верхний-регистр**.

В следующем фрагменте запятая необходима, чтобы показать,
что поступает новое сообщение. Иначе XOScript запутается.

```
Выход написать: ['Hello!'], стоп.
```

Сначала символу карандаша отправляется сообщение **написать:**, а затем
**стоп**. Без запятой XOScript решил бы, что вы хотите отправить
**стоп** **строке** **Hello!**, что бессмысленно.

Сообщения обрабатываются в следующем порядке: слева направо;
сначала сообщения в скобках, затем унарные сообщения. Далее
бинарные сообщения и в конце сообщения с ключевыми словами. См. пример
ниже:

```
Выход написать: 0.5 округлить + (2 - 1), стоп.
```

XOScript всегда читает слева направо: сначала объекту Выход отправляется сообщение **написать:**,
а за ним следует сообщение **стоп**. Внутри
самого аргумента XOScript также читает слева направо, поэтому сначала **0.5 округлить**,
а затем **+**.

{{note}}
Сообщение стоп добавляет к строке символ новой строки.
Название этого сообщения навеяно телеграфом.
В телеграфных сообщениях
часто использовалось слово STOP (ТЧК) для обозначения конца предложения
(поскольку знаки препинания были ненадёжны или стоили дорого).
{{/note}}

Кроме того, **округлить** имеет приоритет над **+**, поскольку это
**унарное сообщение**. Из-за скобок сначала вычисляется **2 - 1**,
после чего **1** прибавляется к результату **0.5 округлить** (1).

Весь процесс даёт результат **2**, который и будет выведен
в качестве ответа. После запятой следует сообщение стоп, которое переводит курсор
на новую строку. Разумеется, лучший способ полностью освоить порядок
вычислений в программах на XOScript — практика.

Стоит отметить, что в XOScript, в отличие от многих других языков
программирования, пробельные символы являются важной частью синтаксиса.
Особенно в случае бинарных сообщений пробелы могут вызвать некоторую
путаницу. Всегда ставьте пробел после бинарного сообщения. Нельзя
присоединять число непосредственно к сообщению, например:

```
3 + 2
```

отличается от

```
3 +2
```

Первый пример (**3 + 2**) отправляет
сообщение **+** числу **3** с аргументом — числом **2**.
Результатом в этом случае будет **5**. Во втором примере (**3 +2**)
числу **3** отправляется унарное сообщение **+2**. В зависимости от
контекста результат может оказаться совсем другим.

```

Ошибки не будет. Программа просто выведет текст **Объект**.

## Интерполяция строк

Список *кДж/ккал* можно сделать более
наглядным. Желательно, чтобы он выглядел так:

```
100 kj ➞ 23.88 kcal

200 kj ➞ 47.76 kcal
```

Если превратить желаемый вывод в шаблон, его запись
может быть такой:

```
number1 kJ ➞ number2 kcal
```

Это означает, что **number1** обозначает значение в кДж, а **number2** — значение
в ккал. Так работает интерполяция строк в XOScript. Для неё
в XOScript не нужны отдельные грамматические правила. Просто отправьте
тексту слово, которое нужно заменить, а в качестве аргумента — текст для
подстановки:

```
>> text :=

['number1 kJ ➞ number2 kcal']

number1: 100,

number2: 23.9.
```

Результат:

```
100 kj ➞ 23.9 kcal
```

Это правило подстановки действует для любого неопределённого сообщения, полученного
объектом **строка**. Каждое сообщение, которое объект **строка** не распознаёт,
интерпретируется следующим образом: *заменить текст сообщения
текстом из аргумента сообщения.* Программу можно изменить

нумерации; в этом случае сначала понадобится объект счёта.

## Рекурсия

В предыдущем примере переопределяется **знак** плюс. Обратите внимание,
что в конце концов само сложение всё равно должно быть выполнено, и
фактически это происходит в следующей строке:

```
>> ответ := сам + (к-числу x коэффициент).
```

Как же XOScript понимает, что этот **знак** плюс относится к
исходной логике сложения? Ведь возможна и другая интерпретация:
XOScript будет снова и снова отправлять то же сообщение тому же
объекту, что, в свою очередь, приведёт к **бесконечному циклу**. Очевидно,
что это не то, что задумано. Как только вы отправляете объекту сообщение,
которое выполнило бы тот же самый код, XOScript поймёт,
что в этом случае имеется в виду нижележащее, переопределённое сообщение. Таким образом, ваша
программа автоматически защищена от такого рода бесконечных
циклов. Если же вы действительно хотите вызвать ту же функцию из
текущей функции, сначала нужно отправить сообщение
**рекурсия**. В этом случае результатом будет бесконечный
цикл. Однако у рекурсивных задач есть полезные применения;
предположим, например, что вы хотите вычислить факториал заданного
числа. В этом случае просто добавьте сообщение **factorial** к
Число:

@test609

Здесь требуется рекурсия. Ведь задача, связанная с
сообщением **factorial**, должна снова выполняться внутри этой функции.
Таким образом, функцию факториала нужно вызвать из самой
функции факториала. Как правило, XOScript предотвращает такой вызов
из-за риска попасть в бесконечный цикл. Поэтому
крайне важно предварить сообщение словом **рекурсия**. Это
делается для того, чтобы XOScript знал, что вы
намеренно выполняете ту же задачу и не ошиблись.

## Объекты, подобные классам

Хотя в xoscript нет классов, имитировать поведение,
подобное классам, тривиально. Просто переопределите сообщение новый.

```
>> Животное := Объект новый.
Животное в: ['новый'] сделать: {
	<- сам новый инициализировать.
}.

Животное в: ['инициализировать'] сделать: {
	мой звук := ['?'].
	мой ноги  := 4.
}.
```

В приведённом выше фрагменте кода мы создаём объект Animal.
Этот объект служит *чертежом* для всевозможных животных,
например собак и кошек. Родительский объект Animal пишется
с прописной буквы A, чтобы показать, что это объект, подобный классу.
Затем мы переопределяем сообщение новый, написав собственный метод новый.
В данном случае он отправляет сообщение новый самому себе (сам), а затем сообщение
инициализировать. Поскольку xoscript по умолчанию блокирует рекурсию, это не приведёт
к бесконечному циклу. Вместо этого сообщение новый будет отправлено родительскому
объекту (Объект), в результате чего получится новый экземпляр Animal. Итак, мы создаём
новый объект на основе того же объекта, для которого написали свой метод новый.
Это совершенно корректно. Кроме того, мы отправляем сообщение инициализировать, которое гарантирует,
что у объекта Animal будут значения свойств по умолчанию. По умолчанию
у животного 4 ноги, а звук неизвестен (отсюда вопросительный знак).
Чтобы создать новый экземпляр нашего Animal, достаточно написать:

```
>> a := Животное новый.
```

Теперь мы получаем новый экземпляр Animal с 4 ногами, неизвестным звуком и
методом инициализировать. Как и в других ООП-языках, мы также можем
расширить наш Animal:

```

# Объект Пустой

{{messages}}

Объект Пустой
представляет пустоту, а точнее — отсутствие информации.
Иногда вы будете получать этот объект в ответ на сообщение,
если результатом является **ничто**. Самый важный вопрос,
который можно задать объекту **Пустой**: **пустой?**.
Ответом всегда будет **Истина**.

```
Выход написать: Пустой пустой?.
```

результат:

```
Истина
```

Любой объект, кроме **Пустой**, ответит **Ложь**.
Приведённый выше фрагмент кода может показаться несколько философским, однако у объекта **Пустой**
безусловно есть вполне практические применения. Например, вы
получите объект Пустой в ответ, если запросите
несуществующий элемент списка. Объект Пустой можно также использовать,
если вы хотите объявить переменную, но пока не хотите задавать ей значение.
Вместо этого вы просто **присваиваете** ей специальное значение **Пустой**. В
XOScript нельзя объявить переменную без значения, например так:


```
>> величина.
```

Вместо этого нужно написать следующее:

```
>> величина := Пустой.
```

# Логические значения

{{messages}}

В отличие от большинства популярных на момент написания языков программирования,
в XOScript есть только один объект Истина и только один объект Ложь.
Иначе говоря, каждый раз, когда вы пишете **Истина**, это не означает,
что создаётся новый объект. Вместо этого вы всегда используете ссылку. Это
означает, что если написать следующее:

\>\> x := Истина.

то **x** ссылается на объект **Истина**. Условный код и циклы также
проверяют именно эту ссылку. В XOScript значение **Истина** и **Ложь**
не является фиксированным. Более того, программа на XOScript будет изрядно потрясена
таким выражением:

Истина := Ложь.

Результат подобных действий не определён, однако это остаётся допустимым
действием и потому формально разрешено. Кроме того, существует объект
Логический, который является корневым объектом как для **Истина**, так и для **Ложь**,
поскольку оба являются производными от этого корневого объекта. Однако сам объект Логический
не имеет практического применения.

## Подводные камни

Будьте осторожны при использовании **и:** и **или:**

```
Выход написать: (Ложь or: Истина or: Истина), стоп.
Выход написать: (Ложь или: Истина, или: Истина), стоп.
```

Даёт

```
Ложь
Истина
```
поскольку сообщение **или:** принимает только 1 аргумент. Первая строка
отправляет объекту Ложь сообщение **или:или:**, которого не существует, поэтому объект игнорирует
это сообщение и возвращает самого себя (Ложь). Вторая же строка
отправляет **или:**, а затем ещё одно **или:** (с помощью символа цепочки, то есть запятой: ,).

# Функции

{{messages}}

Код можно сгруппировать между { и }, и тогда он становится функцией.
В xoscript мы иногда также используем термин «задача» или просто
«блок кода».

Функцию можно запустить, отправив ей сообщение *запуск*.


```
{ Выход написать: 123, стоп. } запуск.
```

Если функция принимает аргументы, используйте **применить:**.

```
{ :a Выход написать: a, стоп. } применить: a.
```

См. также примеры ниже.
Из-за простоты архитектуры у функции может быть только
одна точка возврата. Чтобы избежать лишних накладных расходов или чрезмерной вложенности
условий, можно использовать процедуру (это то же самое, что
использовать знак умножения с аргументом 1):

```
{
  (a = 1) истина: { x := 1. }, разрыв.
  (a = 2) истина: { x := 2. }, разрыв.
} процедура.
```

Таким образом, (a = 2) не будет вычисляться, если a = 1.
Кроме того, так не нужны вложенные сообщения истина:.
Всякий раз, когда вы замечаете, что вкладываете условия друг в друга, вспомните
о сообщении процедура. Возможно, оно сделает ваш код
более читаемым.


Вот важный подводный камень:

```
{
	Ложь ложь: {
		Выход написать: ['Конец цикла.'].
	}, разрыв.
	
	Выход написать: ['Не показывай меня.'].

} процедура.

```

В этом случае текст 'Dont show me' будет показан,
потому что **разрыв** отправляется объекту Ложь. Если вы хотите выполнить
разрыв, его нужно отправить как сообщение объекту **Истина**.
 

```
{
	Ложь не истина: {
		Выход написать: ['Конец цикла.'].
	}, разрыв.
	
	Выход написать: ['Не показывай меня.'].

} процедура.

```

Будет работать так, как ожидается.

Исключения можно обрабатывать так:

```
{ Задача 1 } впоймать: { Задача 2 }, запуск.
```

Можно также намеренно вызвать ошибку в программе и
тем самым активировать блок-обработчик. Для этого текущей задаче отправляется
сообщение **ошибка:**, как показано в следующем
примере:

```
{

}, запуск.

## Внедрение значений

XOScript позволяет внедрять значения в задачи. Посмотрите
на задачу ниже:

```
>> отправка := {
	Рассылка кому: мой recipient.
}.
отправка задать: ['recipient']
значение: ['info@recipient.org'].
отправка запуск.
```


В этом примере показана воображаемая задача, которая отправляет рассылку
на адрес электронной почты, то есть **получателю** (recipient). Этого получателя можно внедрить
в задачу извне ещё до её запуска, отправив задаче
сообщение **задать:значение:**. Таким образом, значение
**recipient** заранее устанавливается в задаче. Это значение также можно изменить
и затем снова запустить задачу. Это полезный приём при работе с
объектами-задачами.

## Пустые функции

Пустые задачи не допускаются. Теоретически пустая задача выглядела бы
так: **{}**, однако XOScript считает это языковой ошибкой. Если
вы хотите объявить пустую задачу, можно использовать объект Пустой:

```
>> задача := Пустой.
```

Хотя это не настоящая задача, а объект Пустой, ему всё равно можно
отправить сообщение запуск:

```
>> ответ := задача запуск.
```

На самом деле это то же самое, что:

```
>> ответ := Пустой запуск.
```

Поскольку объект **Пустой** не распознаёт сообщение **запуск**, он
вернёт в ответ самого себя, и ответом снова будет **Пустой**.
Таким образом, пустая задача не нужна. Благодаря элегантному
устройству языка программирования XOScript для этого можно просто использовать объект
Пустой.

фибоначчи добавить-в-конец: 5.
фибоначчи добавить-в-конец: 8.
фибоначчи добавить-в-конец: 13.
```

Если вывести список на экран:

```
Выход написать: фибоначчи, стоп.
```

мы увидим:

```
Список ← 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13
```

Вместо добавить-в-конец: для добавления элементов в список можно также использовать ;:


```
>> фибоначчи := Список новый ; 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13.
```

Точки с запятой (;) — это бинарные сообщения, которые помещают
значение в список.

## Цепочки сообщений

Предположим, у вас есть такой список:

```
>> x := Список новый ; 1 ; 2 ; 3.
```

Если вы хотите удалить первый и последний элементы, ваше
сообщение будет выглядеть так:

```
x срез-слева срез-справа.
```

К сожалению, такая запись не будет работать правильно.
Сообщение **срез-слева** возвращает первый элемент списка, который,
в свою очередь, становится получателем сообщения **срез-справа**. Таким образом,
сообщение **срез-справа** отправляется не **x**, а 2.
Одним из возможных решений этой проблемы было бы написать два отдельных
предложения, например:

```
x срез-слева.
x срез-справа.
```

Однако это довольно неудобно, особенно когда нужно
удалить больше двух элементов. Поэтому XOScript предлагает
альтернативную структуру сообщений для подобных ситуаций. В
**альтернативной** структуре сообщений ответы объектов игнорируются,
и в ответ вы каждый раз получаете обратно объект-получатель.
**Альтернативная** структура сообщений начинается отправкой объекту
сообщения **сделать**, а завершается
отправкой сообщения **выполнить**. В
рассмотренном примере это можно применить так:

```
>> x := Список новый ; 1 ; 2 ; 3.
x сделать срез-слева срез-справа выполнить.
```

# Карты

{{messages}}

**И Список, и Карта** — это коллекции. Однако, в отличие от
списка, у карты **нет** порядка. Ещё одно различие между ними
в том, что карта состоит из пар объектов. Один объект служит ключом (или
ключевым словом) для поиска другого объекта. Хороший пример
такого списка — прейскурант, например:


```
>> меню := Карта новый
	разместить: ['£5'] в: ['яблочный пирог'],
	разместить: ['£6'] в: ['морковный торт'],
	разместить: ['£3'] в: ['fudge'].
```

Как и в случае списка, для добавления объекта используется сообщение разместить:в:.
Разница в том, что, в отличие от
списка, связываются два объекта. Первый объект, как и
в списке, — это объект, который вы сохраняете. Второй
объект — это не его позиция в коллекции, а **ключ**,
по которому предыдущий объект можно будет получить позже.
Короче говоря, карта работает примерно как словарь: по ключевому слову
можно найти значение. Например, чтобы получить из
приведённого выше списка цену помадки (fudge):

```
>> price := меню в: ['fudge'].
```

Можно также использовать краткую запись:

```
>> price := меню ? ['fudge'].
```

Если ключи, под которыми вы сохраняете объекты, не содержат пробелов
(и не совпадают с другими предопределёнными сообщениями),
можно использовать и следующую запись:

```
>> меню := Карта новый
	pie:   ['£5'],
	cake:  ['£6'],
	fudge: ['£3'].
```

Несомненно, такая запись читается более естественно.
Чтобы запросить цену
помадки, можно использовать следующую упрощённую запись:

```
>> price := меню fudge.
```

# Программа и стандартный вывод

{{messages}}

Объект Программа представляет текущее запущенное приложение. Этот объект
позволяет выполнять системные команды, подключать подпрограммы,
читать аргументы и многое другое — все функции, связанные с системой.

## Стандартный вывод

Выход — это объект стандартного вывода. У него по сути два метода:
**написать:** и **стоп**. Сообщение написать: используется для отправки строки
в stdout, а сообщение стоп выводит символ новой строки.
Вместо **стоп** можно также использовать \\n.

Пример:

```
Выход написать: ['Hello World'], стоп.
```

результат:

```
Hello World
```

## Модули и плагины

Мир XOScript можно расширить новыми системными объектами,
установив модули. Новый системный объект добавляется в мир
XOScript, если поместить файл модуля (обычно файл с суффиксом .so)
в папку mods.

Когда вы отправляете сообщение объекту, который предоставляется
модулем-плагином, XOScript загрузит его автоматически.

Плагины можно писать и самостоятельно. Плагины пишутся на
языке программирования C. Пример плагина можно найти в исходном
коде пакета в каталоге src/plugins/example.


## Рефлексия

Существуют различные способы
исследовать систему во время выполнения программы. В XOScript есть несколько методов,
позволяющих определить, какие объекты присутствуют и на какие сообщения эти объекты
отвечают. Во-первых, у каждого объекта можно спросить, какой у него **тип**,
однако типы в XOScript изменчивы и поэтому ненадёжны.

Можно также спросить у объекта Программа, присутствует ли
данный объект в программе:

```
Программа Инструмент истина: { ... }.
```

Если имя объекта
состоит из одного символа, во избежание путаницы лучше использовать
следующую запись:

```
Программа найти: ['X'], истина: { ... }.
```

Помимо объектов, у объекта Программа можно также спрашивать
о сообщениях. Например, можно спросить, знает ли
объект **Число** сообщение **между:и:**, так,
как показано ниже:

```
Программа Number: ['between:and:'], стоп.
```

Вот очень простая веб-программа, которую можно использовать со

```

## Запрос

Объект HTTP-запрос можно использовать для получения данных GET/POST/COOKIE и
UPLOAD:

```
>> http-запрос  := HTTP-запрос новый.
>> search   := http-запрос get: ['search']. # ?search=books
>> password := http-запрос post: ['password']. # из формы
>> выбранные := http-запрос get-список: ['sel[]']. #?sel[]=1&sel[]=2
>> выбранные := http-запрос post-список: ['sel[]'].
>> кука   := http-запрос cookie: ['session-id'].

```

## Ограничения POST и длины содержимого

По умолчанию максимальное число полей POST — 40, а максимальная длина
содержимого — 2MB. Чтобы задать другие значения для отдельного скрипта:

```
Программа конфигурация: ['max-soderzhimoe'] параметр: 1. 
Программа конфигурация: ['max-polya'] параметр: 1. 
```

{{note}}
Если длина содержимого превышает максимум,
процесс принудительно завершается, поскольку мы больше не можем быть уверены
в безопасности полезной нагрузки.
{{/note}}

Ограничение maxtime определяет максимальное время в мс
на чтение stdin/данных POST.

```
Программа конфигурация: ['max-time'] параметр: 5000. # 5sec
```

Оно применяется только к чтению данных POST при вводе-выводе и предотвращает
атаки типа slowloris. Если вы действительно хотите ограничить
время выполнения любой операции, используйте сообщение максимальное-время: объекта Программа.

## База данных

Объект базы данных можно использовать для запросов к MariaDB/MySQL.
Чтобы подключиться к базе данных:

```
>> бд := MariaDB новый хост: ['localhost'],
	пользователь: ['xo'],
	пароль: ['pass123'],
	имя-базы: ['xobase'],
	подключить.

```

Чтобы вставить запись, используйте:

```
>> параметры := бд запрос: ['
	INSERT INTO book (id, description, price, rating) 
	VALUES (NULL, ?, ?, ?)
'], параметры: ( Список новый ; ['abc'] ; 12.35 ; 6 ). # параметризованные запросы

{  параметры мутация. бд commit. }
впоймать: { :e бд rollback.  }, запуск.
```

Обратите внимание, что xoscript работает *только* с транзакциями и никогда не выполняет автоматическую фиксацию (autocommit).
Если autocommit невозможно отключить, вы получите ошибку подключения.
Всегда используйте привязку параметров в запросах и никогда не вставляйте пользовательский ввод
непосредственно в SQL.

Получить идентификатор вставленной записи можно так:

```
Выход написать: ['ВСТАВЛЕНО: '] + параметры insert-id, стоп. # id вставки
```

Чтобы получить записи:

```
>> параметры :=
бд
	запрос: ['SELECT * FROM book order by id desc limit 2'], 
	получить: { :ряд 
		Выход написать: ряд id + [' '] + ряд description + [': '] + ряд price, стоп.
	}. # получение строк

```

## Сессии

Для сохранения данных между запросами можно записывать данные в объект сессии и читать их оттуда.
Сначала создайте новый **Веб-документ**. Объект Веб-документ объединяет
запрос, заголовки, HTML и сессию. Дело в том, что, когда вы
посещаете веб-сайт в браузере, вы видите только HTML. Но
весь Веб-документ состоит также из **заголовков**. Например,
большинство HTTP-ответов содержат заголовок вроде Content-type:text/html, который
сообщает браузеру, что следующие за ним данные нужно отображать как HTML
(а не, например, скачивать как файл). Сессии — это способ
хранить данные пользователя между запросами. Чтобы отслеживать эти данные, нужно
установить cookie, и этот cookie также устанавливается через заголовок. Вот почему
всё сходится в объекте Веб-документ (ведь это полный
документ, содержащий и заголовки, и HTML или другие данные).


```
# Сначала создаём новый экземпляр Веб-документ
>> веб := Веб-документ новый.

# Теперь начинаем сессию; это создаст заголовок для cookie и
# файл для ваших данных, связанный с этим cookie
>> сеанс := веб начать-сессию.

# Теперь с сессией можно работать как с Картой
сеанс userid: 123.
```

Чтобы уничтожить сессию (при выходе из системы):

```
веб уничтожить-сессию.
```

## Заголовки

Веб-документ позволяет также задавать другие распространённые заголовки.
Например, если вы хотите перенаправить пользователя на другой URL:

```
веб перейти-к: ['/other.html'].
```

«Под капотом» эта команда также формирует HTTP-заголовок, который отправляется
вместе с остальными данными или HTML и указывает браузеру перейти
по заданному адресу.

Чтобы добавить собственный заголовок:

```
веб заголовок: ( 
	HTTP-Заголовок новый
	ключ: ['Content-Length']
	величина: 400
).
```

Чтобы показать страницу 404:

```
веб не-найдено: ['Упс..'].
```


## Шаблоны

Система шаблонов по умолчанию очень проста. Вам не нужно изучать
новый синтаксис шаблонов. Кроме того, шаблонизатор обеспечивает настоящее разделение
представления и бизнес-логики.

Чтобы создать шаблон из файла:

```
>> tpl := веб заготовка: ['templates/ux.tpl'].
```

Система шаблонов использует маркеры.
Есть три типа маркеров: маркеры вырезки (cut), маркеры вставки (paste) и
маркеры-слоты (slot). Основная идея очень проста: вы вырезаете
области, обозначенные маркерами вырезки, и можете вставлять их в
области, обозначенные маркерами вставки. В маркеры-слоты можно
подставлять строки.

Итак, например, возьмём следующий шаблон: положим
драгоценный камень в шкатулку и добавим ценник.

```
<!-- cut:gem -->
<img src="gem.gif">
<b>$<!-- slot:price --></b>
<!-- /cut:gem -->

<div id="box">
<!-- paste:jewels -->
</div>
```

Это можно сделать так:

```
>> gem := tpl вырезать: ['gem'], скопировать.
gem price: 99.
tpl вставить: gem в: ['jewels'].
веб вывести: tpl подчистить.
```

Последняя строка просто отправляет шаблон в виде строки клиенту
вместе с необходимыми HTTP-заголовками.

Результат:

```
<div id="box">
<img src="gem.gif">
<b>$99</b>
</div>
```


## Passthru

Для безопасной отдачи файлов, загруженных пользователями, можно использовать passthru:

```
>> загружено := ['smile.gif'].
Server передача: загружено префикс: ['/uploads/images/'].
Программа конец.
```

Так загруженное пользователем содержимое будет отдаваться с соответствующим
MIME-типом. Поддерживаются только MIME-типы из белого списка:
GIF, JPG, PNG, WEBP, MP4, WEBM, MP3, ZIP, GZIP, PDF и SVG.
Файлы SVG, ZIP и GZIP отправляются для скачивания, поскольку SVG
может содержать скрипты, которые иначе выполнялись бы на вашем домене.
Этот метод предотвращает TOCTOU-атаки, обход путей (path traversal),
выполнение вредоносного кода (внедрение), атаки через символические ссылки,
DDoS-атаки (ограничение размера файла = 50MB), атаки с перехватом (sniffing) и
различные другие проблемы безопасности.

Чтобы закодировать объект в JSON:

>> json := ( JSON jsonify: (

## Регулярные выражения

Регулярные выражения можно использовать, создав шаблон (Шаблон).
Например, чтобы найти атрибуты href и target гиперссылок:

```

```

	Выход написать: m, стоп.

	<- ['XXX'].

Выход написать: результат, стоп.
```

## Форматирование

Объект Формат позволяет форматировать данные, например дополнять их пробелами или
добавлять нули. Он использует синтаксис printf.

```
>> фмт := Формат новый: ['%06.0f'].
фмт применить: 56. # даёт 000056
```

Формат может содержать одно преобразование, и оно должно соответствовать значению,
иначе вы получите ошибку:

- `применить:` со строкой: `%s`
- `применить:` с числом: `%f`, `%e`, `%g` или `%a`
- `применить-int:` с числом: `%d`, `%i`, `%o`, `%u`, `%x` или `%c`

Значения из запроса являются строками. Чтобы отформатировать такое значение как число,
сначала преобразуйте его:

```
фмт применить: (http-запрос get: ['amount']) к-числу.
```

# ffi

{{messages}}

FFI предоставляется на уровне платформы или плагина, поскольку он
привязан к архитектуре нижележащей системы, а ядро этим
заниматься не должно.
Серверный плагин предлагает совместимую реализацию ffi/blob.
По умолчанию ядро взаимодействует с целевой платформой
через stdin/stdout, ограниченные средства файлового ввода-вывода и оболочку (Программа Системная-команда:).
Дополнительная интеграция обеспечивается с помощью ffi/blob через плагины,
ориентированные на приложения, такие как серверный плагин.

FFI расшифровывается как Foreign Function Interface (интерфейс внешних функций). Он позволяет использовать функциональность, написанную другими людьми на
других языках программирования и предоставляемую через файлы DLL, SO или Dylib. Это
могут быть самые разные функции, и таким способом доступен огромный спектр возможностей.
Начнём с примера:

```
Server связать: (
 Список новый ;
 ['/usr/lib/x86_64-linux-gnu/libc.so.6'] ;
 ['printf'] ;
 ( Список новый ; ['pointer'] ; ['int'] ) ;
 ['void'] ;
 ['Printf'] ;
 ['template:number:']
).
>> s := Blob utf8: ['FFI has %d letters.\n'].
Printf template: s number: 3.
s свободно.
```

В результате выполнения этого кода в командной строке вы увидите следующее:
FFI has 3 letters.
Наверное, вы сейчас думаете: «Слишком много кода для такой простой вещи».
В самом деле, разве нельзя было решить это командой Gui show? Ответ — безусловно, да!
Но это всего лишь наглядный пример.
Обычно FFI используется для более сложных задач, но из них не получаются хорошие
примеры, поэтому я выбрал что-то тривиальное.

Аргументы метода связывания:

- Аргумент №1: файл DLL или SO, который вы хотите использовать.
- Аргумент №2: функция в этом файле, которую вы хотите связать.
- Аргумент №3: список с именами типов данных аргументов функции.
- Аргумент №4: имя типа возвращаемого значения функции.
- Аргумент №5: имя объекта, с которым вы хотите связать эту функцию (если он не существует, он будет создан
автоматически).
- Аргумент №6: сообщение, с которым должна быть связана эта функция.

В приведённом выше примере мы хотим связать функцию printf из libc.so. Имена типов
данных можно найти в документации программного обеспечения, с которым вы связываетесь. Доступны следующие типы:
void, pointer, float, double, int, uint, char, uchar, intX и uintX,
где X может быть 8, 16, 32 или 64.

Эти типы обозначают количество байтов, необходимое для хранения данных. Для printf мы выполняем связывание с
новым объектом Printf и сообщением template:number:. Перед использованием вы переводите внешнюю
функцию на диалект XOScript. Сообщение template:number: ожидает в качестве первого параметра
буфер с текстом шаблона. Мы создаём этот буфер с помощью объекта Blob, который
позволяет вручную выделять память. Вы отвечаете за освобождение этой памяти впоследствии
с помощью сообщения свободно.

Заполнить блок памяти (blob) можно разными способами. В нашем примере мы заполняем его текстом, поэтому используем
сообщение utf8: (UTF-8 — это кодировка для преобразования текста в байты). Blob можно также заполнить
с помощью байта:, передав список значений байтов. Чтобы прочитать содержимое blob, используйте от:длина:.
Байты вы получите обратно в виде списка. С помощью Blob можно даже создать C-структуру, используя
сообщение структура: и передав последовательность типов C. Это может понадобиться при вызове функции C
во внешней программной библиотеке, которая ожидает указатель на структуру.

{warning}
Blob-объекты нужно освобождать самостоятельно.
Сборщик мусора не очищает blob-объекты.
{/warning}

Поскольку blob-объекты могут передаваться внешним функциям из библиотек, их
нельзя автоматически убирать сборщиком мусора (они могут по-прежнему использоваться
внешними функциями, или эти внешние функции могут захотеть освободить их
сами). Поэтому при необходимости blob-объекты нужно освобождать самостоятельно.

Чтобы освободить blob, используйте:

```
мойBlob свободно.
```

Чтобы освободить структуру, используйте:

```
мояСтрукт структура-свободно свободно.
```

Таким образом, для структуры нужно отправить два сообщения: структура-свободно и свободно, чтобы
освободить блок памяти.
