Добро пожаловать в XOScript
Проект XOScript ставит перед собой цель создать простой и легко поддающийся аудиту скриптовый язык.
Но простой не обязательно означает лёгкий.
Знакомый язык программирования вполне может оказаться удобнее XOScript.
Здесь под простотой мы понимаем несколько другое:
возможность сформировать целостное представление о языке и полностью понимать его поведение.

XOScript задуман так, чтобы разработчик мог целиком понять устройство языка.
Его грамматика и набор концепций намеренно сведены к минимуму.
В языке нет классов — объекты можно расширять напрямую.
Объекты передаются по ссылке, копирование выполняется явно,
а у функций есть только одна точка выхода.

Некоторые из этих решений заметно отличаются от подходов, принятых в большинстве популярных языков.
Например, в XOScript нет системы типов, а область видимости является динамической.
Сообщения, которые невозможно обработать, просто игнорируются, вместо того чтобы вызывать исключение.
У этих решений есть свои последствия, и они вовсе не призваны устранить ошибки.
Их задача — сохранить внутреннюю модель языка небольшой и последовательной.

XOScript также можно локализовать, что позволяет формулировать бизнес-
правила на естественном языке и при необходимости обсуждать их с нетехническими специалистами.

Тот же принцип распространяется и на реализацию.
Runtime написан на C и включает небольшие lexer, parser и механизм обхода синтаксического дерева,
реализованные вручную.
Стандартная библиотека и runtime во многом повторяют структуру самого языка,
поэтому связь между кодом XOScript и его реализацией остаётся достаточно прямой.

Тесты также тесно связаны с документацией.
Для каждого метода должен существовать соответствующий тест, который можно включить в руководство,
что помогает поддерживать документацию в актуальном состоянии и синхронизировать её с реализацией.

XOScript не предназначен для конкуренции с популярными языками
по количеству возможностей или привычности. Он преследует другую цель:
создать программную среду, устройство которой разработчик может понять целиком.

Мы надеемся, что небольшой язык и компактная
реализация позволят на практике разобраться в программном обеспечении
на всех уровнях — от байта до объекта, от синтаксиса до runtime — и писать код
уверенно, понимая как то, что происходит
в скрипте, так и то, что происходит внутри.

Архитектура серверной конфигурации xoscript
проста, но при этом достаточно гибка.

Чтобы использовать xoscript как серверный язык, необходимо установить
серверный плагин в папку /mods/server.

Это позволяет нам отделить ядро языка
от серверной функциональности — в отличие, например, от PHP или Python.
В противном случае нам пришлось бы поставлять всем пользователям
огромный набор функций, которые большинству из них попросту не понадобятся.
Это было бы бессмысленно.
При желании можно устанавливать и другие модули. Система достаточно гибкая.

Кроме того, некоторые возможности удобнее реализовывать непосредственно
на самом скриптовом языке — например, работу с шаблонами и сессиями.
Поэтому мы дополнительно поставляем библиотеки template.xo и webtools.xo.
Всё это сделано по одной простой причине: мы не знаем, как именно вы собираетесь
использовать xoscript. Это может быть серверный скриптовый язык,
но также GUI, встраиваемые устройства или обычная пакетная обработка.
Даже если вы используете его как серверный скриптовый язык (а сейчас это
один из основных сценариев использования), вам может понадобиться
другой шаблонизатор или другой обработчик сессий.
С какой стати мы должны решать за вас, какие инструменты вы обязаны использовать?

Одно из преимуществ собственного шаблонизатора заключается в том,
что вам не придётся изучать дополнительный синтаксис для создания шаблонов.
Стандартный шаблонизатор, поставляемый с xoscript, обеспечивает 100%-ное
разделение представления и логики. Вместо специального
синтаксиса шаблонов он использует очень гибкую систему маркеров слотов.
Подробнее об этом см. в главе Server.

Обратите внимание: если вы не хотите использовать стандартный шаблонизатор
или стандартные webtools, вам, разумеется, придётся предоставить
собственные решения.

Если веб-сервер работает внутри chroot, jail или другой песочницы,
вам также необходимо установить зависимости xo в этой среде.
Узнать, какие библиотеки вам нужны, можно с помощью ldd
(см. manpage для Linux или BSD).
Если вы хотите использовать shell-команды в своих xo-скриптах,
соответствующий shell (например, bash или ksh) также необходимо
скопировать в эту среду.

Отдельно хотим отметить, что к обратной совместимости мы относимся очень серьёзно.
В языке даже есть специальный механизм обратной совместимости под названием
'version'. В целом наша цель — сделать так, чтобы ваш код мог работать вечно.
Вам никогда не придётся обновлять его, чтобы сохранить совместимость с новыми версиями
xoscript. Наша цель проста: написал один раз — запускай вечно.

Остальная часть этого руководства посвящена подробному описанию
языка программирования xoscript. Серверный скриптинг рассматривается в главе
Server. Если вы опытный разработчик, некоторые главы можно
пропустить: отдельные разделы намеренно довольно подробны или
посвящены вещам, хорошо знакомым каждому, кто уже работал с программированием.
Поэтому если вы уже знакомы с несколькими языками программирования,
воспринимайте это руководство скорее как справочник.

## Установка в Linux

Скачайте apache2 и mariadb:
```
sudo apt-get install apache2 mariadb-server
sudo a2enmod cgi
```
Скачайте xoscript.
Замените X на соответствующий номер версии!
```
wget https://xoscript.com/downloads/xoserver-linux-1_5_X.tar.gz
tar xvf xoserver*.tar.gz
```
Скопируйте файлы в корневую директорию веб-сервера и в /bin:
```
sudo cp bin/xo /bin/xo
sudo cp -R bin/mods /var/www/html/
sudo cp *.xo /var/www/html/
```
Отредактируйте конфигурацию apache2:
```
sudo nano /etc/apache2/sites-enabled/000-default.conf
```
Замените VirtualHost на:
```
<VirtualHost *:80>
    <Directory /var/www/html>
        Options +ExecCGI
        AllowOverride All
        AddHandler cgi-script .xo
        Require all granted
    </Directory>
    DocumentRoot /var/www/html
</VirtualHost>
```
Создайте тестовую страницу:
```
sudo nano /var/www/html/test.xo
```
и напишите небольшую тестовую программу:
```
#!/bin/xo
Server init.
Program use: ['webtools.xo'].
>> web := Web-Document new.
web out: ['Hello World'].
```
Разрешите apache2 выполнять вашу программу через CGI:
```
sudo chmod uog+x /var/www/html/test.xo
```
Перезапустите apache2:
```
sudo systemctl restart apache2
```
Откройте тестовую страницу в браузере:
```
http://localhost/test.xo
```
Вы должны увидеть:
```
Hello World
```

## Установка в OpenBSD

Отредактируйте `/etc/httpd.conf` и добавьте:
```
server "mydomain.com" {
    listen on * port 80
    root "/htdocs/mydomain/"

    location "*.xo" {
        fastcgi
        fastcgi socket "/run/slowcgi.sock"   # inside chroot
    }
}
```
Добавьте бинарный файл xo и модули, а также все необходимые зависимости в chroot (список зависимостей можно определить с помощью ldd).

## Запуск примеров

Чтобы запустить одну из программ-примеров, входящих в пакет:
```
./example.sh <name> <Linux/OBSD> [clean]
```
Например, чтобы запустить пример FizzBuzz в Linux:
```
./example.sh fizzbuzz Linux
```
Чтобы запустить тот же пример в OpenBSD:
```
./example.sh fizzbuzz OBSD
```
Чтобы запустить пример после чистой сборки:
```
./example.sh fizzbuzz OBSD clean
```


```
./runtests.sh nobuild
```

## Hello world

После того как вы перенесли файл на свой компьютер, распакуйте его
и запустите xo следующей командой:
```
xo
```
Чтобы запустить XOScript, сохраните программу в файл, при желании добавив
суффикс -xo. Затем укажите имя файла программы после команды XOScript:
```
xo myprogram.xo
```
Когда вы запускаете команду XOScript, передавая в качестве параметра файл с программой,
xo прочитает этот файл и выполнит содержащуюся в нём программу.

>*Вы также можете запустить программу, просто перетащив её на значок xo.*

>*В некоторых системах необходимо заранее предоставить xo разрешение на загрузку динамических библиотек.*

По традиции первой программой на любом новом языке программирования
становится своего рода приветствие миру. В XOScript такая программа
**Hello world** выглядит следующим образом:

@test598

После сохранения этого текста в файл, например `hello.xo`, его можно выполнить
следующим образом: .
```
xo hello.xo

Hello world
```

Результат работы программы показан в расположенном выше чёрном окне.
В дальнейшем в этом руководстве мы будем использовать такое же визуальное
представление для вывода программы.


>*`Out` пишется с заглавной буквы `O`.
В целом имена объектов начинаются с заглавной буквы,
если только объект не используется как экземпляр (то есть не имеет
собственных методов, а содержит только данные).
Это соответствует соглашению, принятому в других языках программирования
для различения классов и их экземпляров.*

## Синтаксис

XOScript — *чистый* *объектно-ориентированный* язык программирования. Это означает,
что xoscript рассматривает всё как объект, поэтому других *типов данных* в языке нет.
В программе на XOScript есть три основных действия, которые постоянно выполняются:
*присваивание*, *отправка сообщений* и *ответ*. Обмен сообщениями между объектами —
ключевая часть программы на XOScript. Ниже показаны эти три основных действия:

| Действие | Пример |
|---|---|
| Присваивание | `>> x := 1.` |
| Унарное сообщение | `x even?.` |
| Бинарное сообщение | `1 + 2.` |
| Ключевое сообщение | `x from: 0 length: 10.` |
| Возвращаемое значение | `<- answer.` |

Эта глава даст вам общее представление о языке XOScript
и познакомит с его основными принципами. XOScript — небольшой язык,
построенный вокруг трёх действий (см. иллюстрацию), которые сводятся
примерно к шести правилам грамматики. Этого достаточно, чтобы освоить
язык.

Не беспокойтесь, если поначалу что-то покажется не совсем очевидным:
все основные элементы будут подробно разобраны в следующей главе (3),
а базовые правила ещё раз повторены. Однако основная задача этой главы —
дать общее представление о языке. Основные принципы будут кратко объяснены
и проиллюстрированы несколькими показательными примерами.
Недостающие детали мы рассмотрим позднее.

Комментарии в XOScript начинаются с символа `#`. Поэтому следующая строка
будет проигнорирована:
```
# это просто комментарий
```

## Переменные

Для присваивания переменной используется символ объявления переменной: `>>`.
Имя переменной может содержать любые символы, кроме ` <-`, `:=`, пробелов,
точек, запятых, двоеточий, кавычек `[' ']` и круглых скобок `()`.
Кроме того, имя переменной не может занимать несколько строк.
Обратите внимание, что имя переменной не может начинаться с цифры или знака минус.

Вот несколько примеров допустимых имён переменных:
```
>> password := ['Secret'].
>> ♡♡♡ := 3.
>> $ := ['dollar'].
>> +plus := True.
>> user-password := ['Pssst!'].
```
Например, недопустимыми именами переменных являются:
```
>> -123 := ['negative number'].
>> password of user := ['Classified'].
>> password.of:user := ['Classified'].
>> ,x := 10.
```
>*Не требуется экранировать никакие символы (включая одинарные и двойные кавычки, а также границы строкового литерала), если только их наличие не создаёт неоднозначности для lexer.*
После объявления переменную можно использовать без каких-либо ограничений. Это означает,
что символ объявления нужно использовать только при первом обращении к переменной
(то есть при её объявлении).

Иными словами, нельзя просто взять и присвоить значение переменной
*(x := 2)* — сначала её необходимо объявить *(\>\> x := 2)*.
Однако после объявления значение переменной можно изменять без символа объявления:
*(\>\> x := 2. x := 3.)*.

Обратите внимание, что при объявлении переменной ей обязательно должно быть присвоено значение.
В отличие от многих других языков программирования, нельзя объявить переменную,
не задав ей начальное значение. Каждая переменная должна быть явно связана
с некоторым начальным значением. При этом в качестве начального значения можно использовать
объект **None**. В таком случае переменную можно считать пустой
*(\>\> x := None.)*.

Иными словами, объявить переменную без начального значения нельзя. Поэтому,
```
>> x.
```
является недопустимым и приведёт к сообщению об ошибке.

> xoscript использует динамическую область видимости переменных.
> Подробнее см. в главе Functions.

## Литералы

XOScript рассматривает всё как объекты: числа, строки и фрагменты кода.
Числа, такие как 1, 2, 100, -999 и 1,234, являются объектами `Number`.
Любой текст, заключённый в одинарные кавычки, является объектом `String`.
Фрагменты кода, заключённые в фигурные скобки `{...}`, являются объектами `Function`.

| Литерал | Корневой объект | Пример |
|---|---|---|
| Числа | `Number` | `1, 2, 3...` |
| Строки | `String` | `['hello']` |
| Функция | `Function` | `{ 1 + 2. }` |

Такие объекты, как числа и строки, всегда происходят от некоторого
корневого объекта. Например, все числа являются производными объекта
**Number**. Все строки происходят от **String**, а все фрагменты кода —
от **Function**. В свою очередь, все эти объекты происходят от **Object**,
который фактически является корневым объектом для всех объектов.


## Сообщения

Программирование на XOScript в основном сводится к отправке сообщений
объектам. Общий синтаксис отправки сообщения объекту выглядит следующим образом:
```
<object> <message>
```
Чтобы, например, проверить, является ли число **2** чётным, объекту **2** отправляется
сообщение **even?**:
```
2 even?
```
Результатом будет **True** (опять же, объект). Неизвестные сообщения обычно
игнорируются объектами, поэтому ошибки не возникает. Некоторые объекты
(например, числа или строки) реагируют на неизвестное сообщение
определённым заранее образом (подробнее об этом позже).

Объект может получать сообщения трёх видов.

| Тип сообщения | Количество аргументов |
|---|---:|
| Унарное | 0 |
| Бинарное | 1 |
| Ключевое | 1+ |

Во-первых, существуют **унарные сообщения** — см. пример выше, — которые не имеют аргументов.
Во-вторых, существуют **ключевые сообщения**, которые принимают один или несколько аргументов,
например:
```
>> x := Number between: 1 and: 10.
```
В данном случае объекту **Number**, который является корневым объектом всех чисел,
отправляется сообщение **between:and:**. Результатом будет случайное число
от 1 до 10. Наконец, существуют **бинарные сообщения**, которые состоят
только из одного символа и принимают один аргумент:
```
2 + 3
```
Похоже на обычное математическое сложение, но на самом деле это всего лишь ещё одно сообщение.
Сообщение **+** отправляется объекту **2** с аргументом **3**, в результате чего возвращается
значение **5**. Бинарные сообщения можно записывать без двоеточия.

Бинарные сообщения можно объединять в цепочки:
```
>> x := 3 + 2 - 1.
```
В этом фрагменте сначала сообщение **+ 2** отправляется объекту **Number** со значением **3**,
в результате чего получается объект **Number** со значением **5**, после чего этому числу
отправляется сообщение **-1**.

Внимательные читатели справедливо заметят, что такой порядок выполнения не соответствует
привычному математическому порядку операторов. XOScript намеренно игнорирует математические
приоритеты в пользу единообразия своей системы сообщений. В результате сумма:
```
2 + 3 * 5 = 25
```
а не 17.

Это сделано намеренно. Чтобы изменить порядок выполнения, можно использовать скобки:
```
2 + (3 * 5) = 17
```
Большинство объектов в ответ на определённое сообщение возвращают сами себя.
Это удобно, поскольку позволяет продолжить взаимодействие с этим объектом,
отправив ему следующее сообщение:
```
Out write:
[' hello '] trim upper.
```
```
HELLO
```
Здесь объекту **String** последовательно отправляются два сообщения: **trim**, а затем **upper**.

В следующем фрагменте запятая необходима, чтобы обозначить начало нового сообщения.
Без неё XOScript не сможет однозначно определить, что именно вы хотите сделать.
```
Out write: ['Hello!'], stop.
```
Сначала символу карандаша отправляется сообщение **write:**, после которого следует
**stop**. Без запятой XOScript решил бы, что вы хотите отправить сообщение **stop**
объекту **String** **Hello!**, что было бы совершенно бессмысленно.

Последовательность обработки сообщений выглядит следующим образом: сообщения обрабатываются
слева направо; сначала выполняются сообщения в скобках, затем унарные сообщения.
После них идут бинарные сообщения, а в конце — ключевые сообщения. См. пример ниже:
```
Out write: 0.5 round + (2 - 1), stop.
```
XOScript всегда читает код слева направо: сначала объекту Out отправляется сообщение **write:**,
после чего следует сообщение **stop**. Внутри самого аргумента XOScript также читает код
слева направо, поэтому сначала выполняется **0.5 round**, а затем **+**.

> *Сообщение **stop** добавляет к строке символ перевода строки.*
> *Название этого сообщения связано с телеграфными системами.*
> *В телеграфных сообщениях слово STOP часто использовалось для обозначения*
> *конца предложения, поскольку знаки препинания были ненадёжными или дорогими.*

Кроме того, **round** имеет приоритет над **+**, поскольку является **унарным сообщением**.
Благодаря скобкам сначала вычисляется **2 - 1**, после чего результат **0.5 round** (1)
складывается с ним.

В результате получается **2**, что и является выводимым ответом. После запятой следует
сообщение **stop**, которое переводит курсор на новую строку. Разумеется, лучший способ
полностью понять порядок выполнения сообщений в программах XOScript — практика.

Стоит отметить, что в XOScript, в отличие от многих других языков программирования,
пробелы являются важной частью синтаксиса. Особенно это касается бинарных сообщений,
где пробелы могут вызвать некоторую путаницу. Всегда ставьте пробел после бинарного сообщения.
Например, нельзя непосредственно присоединять число к сообщению:
```
3 + 2
```
отличается от
```
3 +2
```
В первом примере (**3 + 2**) числу **3** отправляется сообщение **+** с аргументом
**2**. В данном случае результатом будет **5**. Во втором примере (**3 +2**)
числу **3** отправляется унарное сообщение **+2**. В зависимости от контекста
это может дать совершенно другой результат.

## Несуществующие методы

Отправка сообщения объекту вызывает функцию, которая связана с этим объектом
под именем данного сообщения. Если отправить сообщение, которое объект не понимает,
он просто проигнорирует его и вместо этого вернёт ссылку на самого себя,
чтобы можно было продолжить взаимодействие. Это называется **терпимой передачей сообщений**
(tolerant message passing).

Пример:
```
Out write: Object blah, stop.
```
Ошибки не возникнет. Программа просто выведет текст **Object**.


## Управление потоком выполнения

В XOScript нет необходимости в отдельных правилах грамматики для *циклов* и
*условных конструкций*. Условный оператор — это обычное сообщение **true:** или
**false:** объекту **True** или **False**:
```
2 even? true: {
	Out write: ['Two is an even number'], stop.
}.
```
В предыдущем примере объекту **True** отправляется сообщение **true:** (это ответ
на вопрос: является ли 2 чётным числом?). В качестве аргумента передаётся
дополнительный фрагмент кода — объект **Function**. Эта функция выводит на экран
сообщение о том, что 2 действительно является чётным числом.

Для *циклов* также не нужны отдельные правила записи. Чтобы выполнить фрагмент
кода три раза, достаточно отправить **\*** с аргументом **3** этой **Function**:
```
@test5
```
В этом фрагменте кода **i** — это индекс. Поэтому при первом выполнении Function
**i** равно 0, при следующем выполнении **i** = 1 и так далее.

Рассмотрим другой пример. Допустим, необходимо вывести таблицу преобразования
из *kJ* (килоджоулей) в *kcal* (килокалории) с шагом 100. Правильная запись
выглядит следующим образом:
```
@test599
```
Здесь номер текущей строки передаётся параметру **:line**. В начале функции
определяются её параметры. Неиспользуемые параметры остаются пустыми (**None**).
Параметры всегда располагаются в начале функции, сразу после открывающей
фигурной скобки, и обозначаются двоеточием.

Сообщение **while:** представляет собой комбинацию *цикла* и *условия*.
Две функции можно связать с помощью сообщения **while:**. Получающая сообщение
функция будет продолжать выполняться до тех пор, пока функция после двоеточия
не вернёт отрицательный результат. Например:
```
@test600
```
В приведённом выше фрагменте кода к **x** прибавляется 1 до тех пор, пока **x**
меньше **5**. Когда это условие перестаёт выполняться, вторая функция возвращает
**False**, и выполнение первой функции завершается. Обратите внимание, что **x**
определена за пределами функции и является глобальной переменной. Подробнее
о правилах области видимости см. в главе Functions.

## Интерполяция строк

Список *kJ/kcal* можно сделать более наглядным. В идеале он должен выглядеть
следующим образом:
```
100 kj ➞ 23.88 kcal
200 kj ➞ 47.76 kcal
```
Когда желаемый вывод преобразуется в шаблон, его запись может выглядеть так:
```
number1 kJ ➞ number2 kcal
```
Это означает, что number1 обозначает значение в kJ, а number2 — значение в kcal. Именно так в XOScript работает интерполяция строк. Для этого в XOScript не нужны отдельные правила грамматики. Достаточно отправить в текст слово, которое нужно заменить, передав в качестве аргумента текст для подстановки:
```
>> text :=
['number1 kJ ➞ number2 kcal']
number1: 100,
number2: 23.9.
```
Результат:
```
100 kj ➞ 23.9 kcal
```
Это правило подстановки работает для каждого неопределённого сообщения, полученного
объектом **String**. Любое сообщение, которое **String** не распознаёт, интерпретируется
следующим образом: текст сообщения заменяется текстом, переданным в качестве его аргумента.
Программу можно изменить следующим образом:

```
@test601
```

Чтобы не путаться в том, какие сообщения можно использовать для подстановки, а какие нельзя,
лучше ввести специальный маркер шаблона, например `<>`, для фрагментов текста,
которые должны быть заменены.

## Возвращаемые значения

Для возврата результата в ответ на сообщение используется стрелка возврата
(*<-*). Следующий пример показывает, как создать задачу для вычисления процента:
```
@test602
```
После того как задача определена и присвоена переменной **percentage**,
ей отправляется сообщение **apply:and:** с аргументами **100** и **7**.

Это выполняет задачу с аргументами **100** и **7**, то есть вычисляет 7% от 100.
С помощью стрелки возврата результат возвращается из задачи в основную программу.

## Расширение

Хотя этот код корректен, у него есть один недостаток: приходится помнить порядок аргументов.
Так почему бы не записать это так: *7 percent of: 100*? Это выглядело бы гораздо
*естественнее*. Чтобы сделать это возможным, нужно изменить родительский объект **7** —
объект **Number** — так, чтобы он понимал сообщение **percent of:**. Для этого объекту
**Number** можно отправить сообщение **on:do:** следующим образом:
```
@test603
```
Поскольку в данном случае процентом является само число, мы обращаемся к `self` —
ключевому слову *self*. Проще говоря, символ `self` означает:
*отправить это сообщение самому себе*.

# Объекты

{{messages}}

Помимо изменения и расширения существующих объектов, можно создавать и новые объекты,
просто отправив сообщение **new**. Допустим, вам нужно создать объект счёта-фактуры,
который обеспечивает последовательную нумерацию. В этом случае сначала понадобится
сам объект счёта-фактуры.

Мы знаем, что каждый объект происходит от другого объекта, который, в свою очередь,
в конечном счёте происходит от корневого объекта всех объектов — **Object**.
Поэтому необходимо решить, на основе какого из существующих объектов будет создан
новый объект.

Новый объект наследует все свойства объекта, на основе которого он создан, то есть
того объекта, которому изначально было отправлено сообщение **new**.

В данном примере предпочтителен достаточно нейтральный объект, не имеющий слишком
многих унаследованных свойств. Поэтому выбор очевиден: новый объект можно создать
непосредственно на основе корневого объекта **Object**. Тогда предполагаемая
система счетов-фактур будет выглядеть следующим образом:
```
@test604
```
Текущий номер счёта хранится непосредственно в объекте, поэтому перед ним используется
ключевое слово **own**. Это называется *свойством*; подробнее об этом далее.

Некоторые компании предпочитают включать год в номера счетов. В этом случае можно
создать новый объект счёта-фактуры на основе уже существующего объекта счёта-фактуры,
добавив возможность указать нужный год:
```
@test605
```
Нет необходимости заново реализовывать сообщение **number**, поскольку оно наследуется
от ранее созданного **invoice object**. Таким образом, уже написанный код можно повторно
использовать. В XOScript нет таких понятий, как классы и связанных с ними концепций.
Объекты могут наследовать свойства только от других объектов — это также называется
*прототипным наследованием*.

Теперь вернёмся к свойствам. Доступ к свойствам объекта возможен только *внутри иерархии
объектов*, поэтому другие объекты не могут видеть эти свойства.

В отличие от многих других языков программирования, все свойства объектов доступны
исключительно объекту, который создал это свойство, и объектам, производным от него.

Распространённый подход заключается в использовании объекта в качестве своего рода
*шаблона*. Именно так, например, устроены рассмотренные выше счета-фактуры.
Ещё один хороший пример — **Point**. Допустим, вы создаёте программу, которая выполняет
вычисления с точками на карте. Можно создать объект **Point**, содержащий свойства
x- и y-координат, а внешний доступ к ним организовать через сообщения:
```
@test606
```
Сообщение **=** сравнивает две точки с помощью сообщения **and:**. Первое сравнение
даёт объект **True** или **False**. Это логические объекты. Если отправить сообщение
**and:** объекту **True**, а переданный после двоеточия аргумент также будет **True**,
результатом снова будет **True**. Если хотя бы один из объектов равен **False**,
результатом будет **False**.

Обратите внимание, что одна точка не может напрямую прочитать координаты другой точки.
Для получения этих данных необходимо отправить другой точке соответствующее сообщение:
**x-coordinate** или **y-coordinate**. Ведь, как уже объяснялось выше, свойства можно
получить только внутри самого семейства объектов.

Обратите внимание, что здесь для сравнения точек используется сообщение **=**.
Разумеется, можно было бы использовать и другое сообщение, например **is:** или **equal:**,
однако в данном случае использование символа **=** показалось более уместным.

## Наследование

Уже написанный код можно повторно использовать для создания иерархии объектов.
Например:
```
>> Animal := Object new.
>> Dog := Animal new.
>> Poodle := Dog new.
```
В данном случае **Dog** наследует всё поведение и свойства **Animal**, а объект
**Animal**, в свою очередь, наследует всё поведение **Object** — корневого объекта
для всех объектов.

Обратите внимание, что второй элемент **red** не попадает в список.

В следующем примере создаётся объект **Size**. Этот объект возвращает число,

## Рекурсия

В предыдущем примере знак **плюс** переопределяется. Обратите внимание,
что в конечном итоге само сложение всё равно должно быть выполнено —
фактически оно происходит в следующей строке:
```
>> answer := self + (number x factor).
```
Как же XOScript понимает, что этот знак **плюс** должен обратиться к исходной
логике сложения? Например, можно было бы предположить, что XOScript будет снова
и снова отправлять то же сообщение тому же объекту, что в итоге привело бы к
**бесконечному циклу**. Очевидно, это не то, что здесь задумано.

Как только вы отправляете объекту сообщение, которое должно выполнить тот же самый
код, XOScript понимает, что в данном случае имеется в виду исходное,
переопределённое сообщение. Таким образом, программа автоматически защищена
от такого рода бесконечных циклов.

Однако если вы действительно хотите вызвать из текущей функции ту же самую функцию,
сначала необходимо отправить сообщение **recursive**. В этом случае результатом
будет бесконечный цикл.

При этом рекурсивные задачи могут быть весьма полезны. Например, предположим,
что вам нужно вычислить факториал заданного числа. Для этого достаточно добавить
сообщение **factorial** к объекту **Number**:

@test609

Здесь требуется рекурсия. Функция, связанная с сообщением **factorial**, должна
снова вызвать саму себя в процессе выполнения. То есть функцию `factorial`
необходимо вызвать непосредственно из самой функции `factorial`.

По умолчанию XOScript предотвращает такое поведение из-за риска получить
бесконечный цикл. Поэтому перед сообщением необходимо явно указать слово
**recursive**. Это сообщает XOScript, что повторный вызов той же функции
сделан намеренно, а не является ошибкой.

## Объекты, похожие на классы

Хотя в xoscript нет классов, имитировать поведение, похожее на классовое,
очень просто. Достаточно переопределить сообщение **new**.
```
>> Animal := Object new.
Animal on: ['new'] do: {
	<- self new init.
}.

Animal on: ['init'] do: {
	own sound := ['?'].
	own legs  := 4.
}.
```
В приведённом выше фрагменте мы создаём объект под названием Animal.
Этот объект служит *шаблоном* для различных животных, например собак и кошек.
Родительский объект Animal записывается с заглавной буквы A, чтобы показать,
что это объект, выполняющий роль класса.

Затем мы переопределяем сообщение new, написав собственный метод new.
В данном случае он отправляет сообщение new самому себе (`self`), а затем
сообщение init. Поскольку по умолчанию xoscript блокирует рекурсию,
это не приводит к бесконечному циклу. Вместо этого сообщение new отправляется
родительскому объекту (Object), в результате чего создаётся новый экземпляр Animal.

Таким образом, мы создаём новый объект на основе того же объекта, для которого
определили собственный метод new. Это вполне допустимо.

Затем мы также отправляем сообщение init, чтобы у объекта Animal были
значения по умолчанию для его свойств. По умолчанию у животного 4 ноги,
а звук неизвестен (отсюда вопросительный знак).

Чтобы создать новый экземпляр нашего Animal, достаточно написать:
```
>> a := Animal new.
```
Теперь у нас есть новый экземпляр Animal с 4 ногами, неизвестным звуком и
методом init. Как и в других объектно-ориентированных языках, мы также можем
расширить наш Animal:
```
>> Dog := Animal new.
Dog on: ['init'] do: {
	self init.
	own sound := ['barks'].
}.
```
Это легко проверить, добавив метод `string`:
```
Animal on: ['string'] do: {
	<- own legs string + own sound.
}.
```
Соберём всё вместе:
```
@test13
```

Создание объекта, которому необходимо задать определённое начальное состояние, —
довольно распространённая задача. Предположим, необходимо создать объект **Rectangle**
для вычисления периметра и площади. Возможная запись может выглядеть так:
```
>> Rectangle := Object new.

Rectangle on: ['area'] do: {
	<- own length * own width.
}.
```
Очевидно, что задание длины и ширины является необходимым условием. Для этого
можно добавить сообщения **length:** и **width:**:
```
Rectangle on: ['length:'] do: { :length
	own length := length.
}.

Rectangle on: ['width:'] do: { :width
	own width := width.
}.
```
Затем этот объект Rectangle можно использовать следующим образом:
```
>> rectangle := Rectangle new length: 2, width: 3.
Out write: rectangle area.
```
Однако если при создании объекта не задать начальные значения длины и ширины,
возникнет сообщение об ошибке:
```
>> rectangle := Rectangle new.
Out write: rectangle area.
```
приведёт к следующей ошибке:
```
Key not found: length
```

# Объект None

{{messages}}

Объект **None** обозначает пустоту или, точнее, отсутствие информации.
Иногда этот объект возвращается в ответ на сообщение, если результатом является
**ничего**. Самый простой вопрос, который можно задать объекту **None**:
**None?**. Ответ всегда будет **True**.
```
Out write: None None?.
```
результат:
```
True
```
Любой объект, кроме **None**, ответит **False**. Приведённый выше фрагмент кода
может показаться немного философским, однако объект **None** имеет множество
вполне практических применений. Например, объект **None** будет возвращён в
качестве ответа, если запросить несуществующий элемент списка. Объект **None**
также можно использовать, если нужно объявить переменную, но пока не задавать
ей конкретное значение. В этом случае достаточно **присвоить** ей специальное
значение **None**. В XOScript нельзя объявить переменную без значения, например:
```
>> value.
```
Вместо этого необходимо написать следующее:
```
>> value := None.
```

# Логические значения

{{messages}}

В отличие от большинства популярных языков программирования на момент написания
этого руководства, XOScript предоставляет только один объект **True** и один
объект **False**. Иными словами, каждый раз, когда вы пишете **True**, это не означает,
что создаётся новый объект. Вместо этого вы всегда получаете ссылку на уже существующий
объект. Например:
```
\>\> x := True.
```
Здесь **x** ссылается на объект **True**. Условные конструкции и циклы также проверяют
эту ссылку. В XOScript смысл **True** и **False** не является неизменным. Фактически
такая конструкция способна довольно сильно изменить поведение программы:
```
True := False.
```
Результат такого действия не определён, однако сама конструкция остаётся допустимой
и формально разрешена. Кроме того, существует объект **Boolean**, являющийся корневым
объектом для **True** и **False**, поскольку оба они являются его производными.
Сам объект **Boolean**, однако, не имеет практического применения.

## Подводные камни

Будьте осторожны при использовании **and:** и **or:**.
```
Out write: (False or: True or: True), stop.
Out write: (False or: True, or: True), stop.
```
даёт в результате
```
False
True
```
поскольку сообщение **or:** принимает только один аргумент. В первой строке объекту **False**
отправляется сообщение **or:or:**, которого не существует, поэтому объект игнорирует это
сообщение и возвращает самого себя (**False**). Во второй строке отправляется **or:**,
за которым следует ещё одно **or:** (с использованием символа цепочки, то есть запятой: `,`).


Каждый раз, когда вы записываете число, например 9, -10 или 3,12, XOScript

тогда как при использовании вторых изменяется сам объект. Это показано в следующем


# Строки

{{messages}}

Каждый раз, когда текст помещается между **блоками и кавычками** ['...'] ,
XOScript создаёт для вас новый строковый объект. Однако обязательно
используйте правильные кавычки. Кавычка в начале
текста отличается от той, что находится в конце (это позволяет вам
использовать одинарную кавычку без необходимости её экранировать).

## UTF8

Строки в xoscript обычно содержат текст в кодировке UTF-8. Хотя
технически в строке можно хранить двоичные или не являющиеся UTF-8 данные, для этого рекомендуется использовать blobs. Blobs
предоставляются серверным плагином (см. главу ffi).
В целом blobs/ffi предоставляются
на уровне плагина/платформы, поскольку они связаны с платформой
и архитектурой (ffi/blobs). Ядро языка сценариев старается
оставаться максимально независимым от платформы.

## Приведение типов

Вы можете создать копию каждого объекта
с другим типом, используя следующие сообщения:

| Сообщение | Результат |
|---|---|
| number | Преобразует в число |
| string | Преобразует в строку |
| bool | Преобразует в логическое значение |

Применяются следующие правила:

| Тип сообщения | `None` | `bool` | `number` | `text` | Другое |
|---|---|---|---|---|---|
| `bool` | `False` | Н/Д | `0` → `False`, иначе → `True` | `True` | В большинстве случаев `True` |
| `number` | `0` | `False` → `0`, `True` → `1` | Н/Д | `['n']` → `n` | В большинстве случаев `1` |
| `string` | `['None']` | `['False']` / `['True']` | `['n']` | Н/Д | Зависит от значения |

# Функции

{{messages}}

Вы можете сгруппировать код между `{` и `}` — тогда он станет функцией.
В XOScript мы также иногда используем термин «задача» или просто
«блок кода».

Вы можете запустить функцию, отправив ей сообщение *start*.
```
{ Out write: 123, stop. } start.
```
Если ваша функция принимает аргументы, используйте **apply:**.
```
{ :a Out write: a, stop. } apply: a.
```
Также смотрите примеры ниже.

Из-за упрощённой архитектуры функция может иметь только
одну точку возврата. Чтобы избежать накладных расходов или чрезмерной вложенности
условий, можно использовать процедуру (что равнозначно использованию
знака умножения с аргументом `1`):
```
{
  (a = 1) true: { x := 1. }, break.
  (a = 2) true: { x := 2. }, break.
} procedure.
```
Таким образом, `(a = 2)` не будет вычисляться, если `a = 1`.
Кроме того, при таком подходе вам не потребуются вложенные сообщения `true`.
Если вы обнаружили, что вкладываете условия друг в друга, вспомните
о сообщении `procedure`. Оно может сделать ваш код
более читаемым.

Вот важный нюанс:
```
{
	False false: {
		Out write: ['End the loop.'].
	}, break.
	
	Out write: ['Dont show me.'].

} procedure.
```
В этом случае будет показан текст `'Dont show me'`.
Это происходит потому, что **break** отправляется объекту `False`. Если вы хотите выполнить
прерывание, его нужно отправить как сообщение объекту **True**.
```
{
	False not true: {
		Out write: ['End the loop.'].
	}, break.
	Out write: ['Dont show me.'].
} procedure.
```
Будет работать ожидаемым образом.

## Исключения

Исключения можно обрабатывать следующим образом:
```
{ Task 1 } except: { Task 2 }, start.
```
Вы также можете намеренно вызвать ошибку в своей программе и тем самым
активировать блок обработчика. Для этого необходимо отправить
сообщение **error:** текущей задаче, как показано в следующем
примере:
```
{
this-task error: ['Whoops!'].
} except: { :mistake
Out write: mistake.
}, start.
```

## Внедрение значений

XOScript предоставляет задачам возможность внедрять значения. Теперь взгляните
на задачу ниже:
```
>> sending := {
	Newsletter to: own recipient.
}.
sending set: ['recipient']
value: ['info@recipient.org'].
sending start.
```
В этом примере показана воображаемая задача, которая отправляет рассылку
на адрес электронной почты получателя — **recipient**. Этого получателя можно внедрить
в задачу извне и до её запуска, отправив задаче
сообщение **set:value:**. При этом значение
**recipient** предварительно устанавливается в задаче. Это значение также можно изменить,
а затем снова запустить задачу. Такой подход удобен при использовании
объектов `Task`.

## Пустые функции

Пустые задачи не допускаются. Теоретически пустая задача выглядела бы
так: **{}**, однако XOScript воспринимает это как ошибку языка. Если вы
хотите объявить пустую задачу, можно использовать объект `None`:
```
>> task := None.
```
Хотя это не настоящая задача, а объект `None`, ему всё равно можно
отправить сообщение `start`:
```
>> answer := task start.
```
Фактически это то же самое, что:
```
>> answer := None start.
```
Поскольку объект **None** не распознаёт сообщение **start**, он
вернёт самого себя в качестве ответа, и результатом снова будет **None**.
Таким образом, необходимость в пустой задаче отсутствует. Благодаря элегантному
устройству языка программирования XOScript для этого можно просто использовать
объект `None`.

# Списки

{{messages}}

XOScript поддерживает два типа коллекций: *списки* и *словари*.
**Списки** представляют собой перечисления объектов в *фиксированном порядке*.
Словари не имеют порядка и, скорее, напоминают справочник, состоящий из ключа
(или термина) и соответствующего ему значения. Списки сопоставимы с массивами
в PHP, Java и C, а также со списками в Python. Словари сопоставимы
с ассоциативными массивами в PHP или словарями в Python. Чтобы создать
новый список, напишите:
```
>> fibonacci := List new.
```
Этот пустой список можно заполнить с помощью **append:**:
```
fibonacci append: 0.
fibonacci append: 1.
fibonacci append: 1.
fibonacci append: 2.
fibonacci append: 3.
fibonacci append: 5.
fibonacci append: 8.
fibonacci append: 13.
```
Если вывести список на экран:
```
Out write: fibonacci, stop.
```
мы увидим:
```
List ← 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13
```
Вместо `append` для добавления элементов в список также можно использовать `;`:
```
>> fibonacci := List new ; 0 ; 1 ; 1 ; 2 ; 3 ; 5 ; 8 ; 13.
```
Все точки с запятой (`;`) являются бинарными сообщениями, которые добавляют
значение в список.

## Цепочки

Предположим, у вас есть список вида:
```
>> x := List new ; 1 ; 2 ; 3.
```
Если вы хотите удалить первый и последний элементы, отправьте
следующее сообщение:
```
x shift pop.
```
К сожалению, предыдущая запись не будет работать правильно. Сообщение
**shift** возвращает первый элемент списка, который, в свою очередь,
становится получателем сообщения **pop**. Таким образом,
сообщение **pop** отправляется не объекту **x**, а объекту `2`.
Возможное решение этой проблемы — создать два отдельных
выражения, например:
```
x shift.
x pop.
```
Однако это довольно непрактично, особенно если нужно удалить
более двух элементов. Поэтому XOScript предлагает
альтернативную структуру сообщений для подобных ситуаций. В
**альтернативных** структурах сообщений ответы объектов игнорируются,
а в качестве результата снова и снова возвращается объект-получатель.
**Альтернативная** структура сообщений начинается с отправки объекту
сообщения **do** и завершается отправкой сообщения **done**. В
приведённом примере это можно применить следующим образом:
```
>> x := List new ; 1 ; 2 ; 3.
x do shift pop done.
```

# Словари

{{messages}}

**И `List`, и `Dict` являются коллекциями. Однако, в отличие от
списка, словарь **не имеет** порядка. Ещё одно различие между ними
заключается в том, что словарь состоит из пар объектов. Один объект выступает
в качестве записи (или ключевого слова), чтобы по нему найти другой объект.
Хорошим примером словаря является прайс-лист, например:
```
>> menu := Dict new
	put: ['£5'] at: ['apple pie'],
	put: ['£6'] at: ['carrot cake'],
	put: ['£3'] at: ['fudge'].
```
Как и для списка, для добавления объекта в словарь используется сообщение
**put:at:**. Разница заключается в том, что, в отличие от
списка, связываются два объекта. Первый объект, как и
в списке, — это объект, который будет сохранён в коллекции. Второй
объект — не его позиция в коллекции, а **ключ**,
который позволяет получить первый объект позднее. Короче говоря,
словарь работает примерно как обычный словарь: по ключевому слову
можно найти значение. Например, чтобы получить из
упомянутого выше словаря цену помадки:
```
>> price := menu at: ['fudge'].
```
Также можно использовать сокращённую запись:
```
>> price := menu ? ['fudge'].
```
Если ключи, которые вы используете для хранения объектов, не содержат пробелов
(и не конфликтуют с другими предопределёнными сообщениями),
можно также использовать следующую запись:
```
>> menu := Dict new
	pie:   ['£5'],
	cake:  ['£6'],
	fudge: ['£3'].
```
Несомненно, приведённая выше запись читается немного естественнее.
Чтобы запросить цену помадки, можно использовать следующую
упрощённую запись:
```
>> price := menu fudge.
```

# Программа/стандартный вывод

{{messages}}

Объект `Program` представляет запущенное в данный момент приложение. Этот объект
предоставляет возможности для выполнения системных команд, подключения
подпрограмм, чтения аргументов и многого другого — в общем, все функции,
связанные с системой.

## Стандартный вывод

`Out` — это объект стандартного вывода. В основном он имеет два метода:
**write:** и **stop**. Сообщение `write:` используется для отправки строки
в stdout, а сообщение `stop` выводит символ новой строки.
Вместо **stop** также можно использовать `\\n`.

Пример:
```
Out write: ['Hello World'], stop.
```
результат:
```
Hello World
```
## Модули/плагины

Мир XOScript можно расширять новыми системными объектами, устанавливая
модули. Новый системный объект можно добавить в среду
XOScript, поместив файл модуля (обычно файл с расширением `.so`)
в папку `mods`.

Когда вы отправляете сообщение объекту, который предоставляется
модулем-плагином, XOScript автоматически загружает этот модуль.

Вы также можете писать собственные плагины. Плагины пишутся на
языке программирования C. Пример плагина можно найти в пакете исходного
кода по пути `src/plugins/example`.

## Рефлексия

Существуют различные способы исследования системы
во время выполнения программы. XOScript предоставляет несколько методов,
позволяющих определить, какие объекты доступны и на какие сообщения эти объекты
отвечают. Прежде всего, у каждого объекта можно запросить его **type**,
однако типы в XOScript изменяемы и поэтому ненадёжны.

Также можно спросить объект `Program`, присутствует ли
указанный объект в программе:
```
Program Tool true: { ... }.
```
Если имя объекта состоит из одного символа, во избежание путаницы лучше использовать следующую запись:
```
Program find: ['X'], true: { ... }.
```
Помимо запроса об объектах, можно также задавать объекту `Program`
вопросы о сообщениях. Например, можно проверить, известно ли объекту
**Number** сообщение **between:and:**,
как показано ниже:
```
Program Number: ['between:and:'], stop.
```

Плагин `Server` в XOScript предоставляет возможности для

## Настройки сервера

Можно задать следующие настройки сервера:

```
	# default values are given

	Program 
	setting: ['max-postfields']
	value: 40.

	Program
```

## Hello World

Вот очень простая веб-программа, которую можно использовать со
стандартным CGI-сервером, таким как Apache2, NGINX, OpenHTTPD или любым другим
широко известным сервером.
```
#!/bin/xo

Server init.
Program use: ['webtools.xo'].

>> web-document := Web-Document new.

web-document out: ['
<html>
<body>
<b>Hello World!</b>
</body>
</html>'].
```
Если вы не хотите использовать объект `Web-Document`, это не проблема,
но тогда вам придётся самостоятельно записывать HTTP-заголовки:
```
#!/bin/xo
Out write: ['Content-type: text/html; charset=utf-8 \n\n'], stop.
Out write: ['hello world!'], stop.
``` 

## Запрос

Объект HTTP-запроса можно использовать для получения данных
GET, POST, COOKIE и UPLOAD:
```
>> request  := HTTP-Request new.
>> search   := request get: ['search']. # ?search=books
>> password := request post: ['password']. # from form
>> selected := request get-list: ['sel[]']. #?sel[]=1&sel[]=2
>> selected := request post-list: ['sel[]'].
>> cookie   := request cookie: ['session-id'].
>> upload   := request upload: ['file'].
>> temppath := upload ? 0.
>> filename := upload ? 1.
```

## Максимальное количество полей/длина

Максимальное количество полей POST по умолчанию — `40`, а максимальная
длина содержимого по умолчанию — `2 МБ`. Чтобы настроить эти параметры
отдельно для каждого скрипта:
```
Program setting: ['max-contentlength'] value: 1. 
Program setting: ['max-postfields'] value: 1. 
```

>*Если длина содержимого превышает максимальное значение,
процесс завершается, поскольку мы больше не можем быть уверены
в безопасности полезной нагрузки.*

Ограничение `maxtime` определяет максимальное время в миллисекундах
для чтения `stdin` или данных POST.
```
Program setting: ['max-time'] value: 5000. # 5sec
```
Это относится только к вводу-выводу при чтении данных POST и предотвращает
атаки типа Slowloris. Если вам действительно нужно ограничить
время выполнения любой операции, используйте `Program alarm`.

## База данных

Объект `Database` можно использовать для выполнения запросов к MariaDB/MySQL.
Чтобы подключиться к базе данных, выполните:
```
>> db := Maria-DB new host: ['localhost'],
	username: ['xo'],
	password: ['pass123'],
	dbname: ['xobase'],
	connect.
```
Чтобы вставить запись, используйте:
```
>> query := db query: ['
	INSERT INTO book (id, description, price, rating) 
	VALUES (NULL, ?, ?, ?)
'], parameters: ( List new ; ['abc'] ; 12.35 ; 6 ). # parameterized queries

{  query execute. db commit. }
except: { :e db rollback.  }, start.
```
Обратите внимание: XOScript *работает только* с транзакциями и никогда не выполняет
автоматическую фиксацию изменений. Если отключить автоматическую фиксацию невозможно,
вы получите ошибку подключения. Всегда используйте привязку параметров
для запросов и никогда не добавляйте пользовательский ввод непосредственно
в SQL.

Получить идентификатор вставленной записи можно так:
```
Out write: ['INSERTED: '] + query insert-id, stop. # insert id
```
Чтобы получить записи:
```
>> query :=
db
	query: ['SELECT * FROM book order by id desc limit 2'], 
	fetch: { :row 
		Out write: row id + [' '] + row description + [': '] + row price, stop.
	}. # fetching rows
```

## Сессии

Для постоянного хранения данных можно сохранять и получать данные из объекта
сессии. Сначала создайте новый **Web-Document**. Объект Web-Document объединяет
запрос, заголовки, HTML и сессию. Это связано с тем, что при посещении
веб-сайта в браузере вы видите только HTML. Однако весь документ Web-Document
также состоит из **заголовков**. Например, большинство HTTP-ответов
содержат заголовок вида `Content-type:text/html`, который сообщает
браузеру, что следующие данные должны быть отображены как HTML
(либо, например, загружены как файл). Сессии позволяют
хранить пользовательские данные между запросами. Чтобы отслеживать эти данные,
необходимо установить cookie; оно также устанавливается через заголовок. Поэтому
всё объединено в Web-Document: это полный документ, содержащий
как заголовки, так и HTML или другие данные.
```
# First we make a new Web Document instance
>> web := Web-Document new.

# Now we start a session, this will generate a Header for a cookie and
# create a file to store your data, associated with that cookie
>> session := web session-start.

# Now we can treat session like a dict
session userid: 123.
```
Чтобы уничтожить сессию (например, при выходе из системы):
```
web session-destroy.
```

## Заголовки

`Web-Document` также позволяет задавать другие распространённые HTTP-заголовки.
Например, если вы хотите перенаправить пользователя на другой URL:
```
web goto: ['/other.html'].
```
Внутренне эта команда также создаёт HTTP-заголовок, который отправляется
вместе с другими данными или HTML и указывает браузеру перейти
по заданному целевому адресу.

Чтобы добавить пользовательский заголовок:
```
web header: ( 
	HTTP-Header new
	key: ['Content-Length']
	value: 400
).
```
Чтобы показать страницу 404:
```
web not-found: ['OOps..'].
```
## Шаблоны

Стандартная система шаблонов очень проста. Вам не нужно изучать новый
синтаксис шаблонов. Кроме того, шаблонизатор обеспечивает реальное разделение
между представлением и бизнес-логикой.

Чтобы создать шаблон из файла:
```
>> tpl := web template: ['templates/ux.tpl'].
```
Система шаблонов использует маркеры.

Существует три типа маркеров: маркеры вырезания, маркеры вставки и
маркеры слотов. Основная идея очень проста: вы вырезаете области,
обозначенные маркерами вырезания, и можете вставлять их в области,
обозначенные маркерами вставки. В маркеры слотов можно подставлять строки.

Например, имея следующий шаблон, давайте поместим драгоценный камень
в шкатулку для украшений и добавим ценник.
```
<!-- cut:gem -->
<img src="gem.gif">
<b>$<!-- slot:price --></b>
<!-- /cut:gem -->

<div id="box">
<!-- paste:jewels -->
</div>
```
Это можно сделать следующим образом:
```
>> gem := tpl cut: ['gem'], copy.
gem price: 99.
tpl paste: gem at: ['jewels'].
web out: tpl clean.
```
Последняя строка просто отправляет шаблон клиенту в виде строки
вместе с необходимыми HTTP-заголовками.

Результат:
```
<div id="box">
<img src="gem.gif">
<b>$99</b>
</div>
```

## Passthru

Чтобы безопасно отдавать файлы, загруженные пользователями, можно
использовать `passthru`:
```
>> uploaded := ['smile.gif'].
Server passthru: uploaded prefix: ['/uploads/images/'].
Program end.
```
Этот метод отдаёт загруженное пользователем содержимое с соответствующим
MIME-типом. Поддерживаются только MIME-типы из белого списка:
GIF, JPG, PNG, WEBP, MP4, WEBM, MP3, ZIP, GZIP и PDF.

Этот метод предотвращает TOCTOU-атаки, обход путей, выполнение
вредоносного кода (инъекции), атаки через символические ссылки,
DDoS-атаки (ограничение размера файла — 50 МБ), атаки со sniffing
и ряд других проблем безопасности.

## Регулярные выражения

Вы можете использовать регулярные выражения, создав шаблон.
Например, чтобы сопоставить `href` и цели гиперссылок:
```
Pattern new: ['href="([^"]+)" target="([^"]+)"'].
```
Теперь примените шаблон к строке subject следующим образом:
```
pattern match: subject do: { :m :x .... }
```
Полный пример:
```
>> subject := ['<html>
	<a href="http://link1" target="_blank">
	<a href="http://link2" target="_blank">
</html>'].
>> pattern := Pattern new: ['href="([^"]+)" target="([^"]+)"'].
>> result  := pattern match: subject do: { :m :x
	Out write: m, stop.
	Out write: x, stop.
	<- ['XXX'].
}.
Out write: result, stop.
```

# ffi

{{messages}}

FFI предоставляется на уровне платформы или плагина, поскольку он
взаимодействует с базовой архитектурой системы — тем, чем ядро
заниматься не должно.

Плагин сервера предоставляет совместимую реализацию FFI и BLOB-объектов.
По умолчанию ядро взаимодействует с целевой платформой через stdin/stdout,
ограниченные службы файлового ввода-вывода и оболочку (`Program os`).
Дополнительная интеграция обеспечивается посредством FFI/BLOB-объектов
через плагины, ориентированные на приложения, такие как плагин сервера.

FFI означает *Foreign Function Interface* («интерфейс внешних функций»).
Он позволяет использовать функциональность, написанную другими людьми на
разных языках программирования и поставляемую в DLL-, SO- или Dylib-файлах.
Это могут быть самые разные функции; таким способом доступен огромный
спектр возможностей.

Начнём с примера:
```
Server link: (
 List new ;
 ['/usr/lib/x86_64-linux-gnu/libc.so.6'] ;
 ['printf'] ;
 ( List new ; ['pointer'] ; ['int'] ) ;
 ['void'] ;
 ['Printf'] ;
 ['template:number:']
).
>> s := Blob utf8: ['FFI has %d letters.\n'].
Printf template: s number: 3.
s free.
```
Результатом выполнения этого кода будет следующий вывод в командной строке:
```
FFI имеет 3 буквы.
```
Вероятно, вы сейчас думаете: «Это слишком много кода для такой простой задачи».
В конце концов, разве нельзя решить это простой командой `Gui show`? Ответ —
однозначно да! Но этот пример приведён лишь для иллюстрации.

Обычно FFI используется для более сложных задач, но такие задачи плохо подходят
для примеров, поэтому здесь выбран тривиальный случай.

Аргументы метода `link`:

- Аргумент №1: DLL- или SO-файл, который вы хотите использовать.
- Аргумент №2: Функция из этого файла, которую вы хотите подключить.
- Аргумент №3: Список имён типов данных аргументов функции.
- Аргумент №4: Имя возвращаемого типа функции.
- Аргумент №5: Имя объекта, к которому вы хотите подключить эту функцию; если его не существует, он будет создан автоматически.
- Аргумент №6: Сообщение, с которым должна быть связана эта функция.

В приведённом выше примере мы хотим подключить функцию `printf` из `libc.so`.
Имена типов данных можно найти в документации программного обеспечения,
к которому вы подключаетесь. Доступные типы:

`void`, `pointer`, `float`, `double`, `int`, `uint`, `char`, `uchar`, `intX`
и `uintX`, где `X` может быть равен 8, 16, 32 или 64.

Эти типы указывают количество байтов, необходимое для хранения данных. Для
`printf` мы подключаем функцию к новому объекту с именем `Printf` и сообщению
`template:number:`. Перед использованием внешнюю функцию необходимо
перевести на диалект XOScript.

Сообщение `template:number:` ожидает в качестве первого параметра буфер с
текстом шаблона. Мы создаём этот буфер с помощью объекта `Blob`, который
позволяет вручную выделять память. После этого вы обязаны освободить эту
память с помощью сообщения `free`.

Заполнить BLOB в памяти можно разными способами. В нашем примере он
заполняется текстом, поэтому используется сообщение `utf8:` (UTF-8 — это
кодировка для преобразования текста в байты). Также можно заполнить BLOB с
помощью `bytes:`, передав список значений байтов. Чтобы прочитать содержимое
BLOB, используйте `from:length:`. В результате вы получите байты в виде
списка.

С помощью BLOB можно даже создать C-структуру, используя сообщение `struct:`
и передавая последовательность C-типов. Это может понадобиться при вызове
C-функции из внешней программной библиотеки, если она ожидает указатель на
структуру.

>*BLOB-объекты необходимо освобождать вручную. Сборщик мусора не очищает BLOB-объекты.*

Поскольку BLOB-объекты могут передаваться внешним функциям из библиотек, их
нельзя автоматически очищать сборщиком мусора: они могут всё ещё использоваться
внешними функциями, либо эти функции могут захотеть освободить их самостоятельно.
Поэтому при необходимости BLOB-объекты нужно освобождать вручную.

Чтобы освободить BLOB, используйте:
```
myblob free.
```
Чтобы освободить структуру, используйте:
```
mystruct structfree free.
```
Таким образом, для структуры необходимо отправить два сообщения:
`structfree` и `free`, чтобы освободить блок памяти.
```
@api_Blob_fficonnect
```

## Серверный скрипт

Вот как может выглядеть типичный скрипт на сервере:
```
#!/bin/xo

# keep backward compat.
Program version: (
	Moment 
	zone: ['CEST'],
	from: ['2026-06-15 10:00:00']
).

Server init.

# I prefer a central loader that loads
# webtools.xo and template.xo
Program use: ['app/libs/loader.xo'].

# create a new document
>> web-document := Web-Document new.
>> tpl := Template new: ( 
	File new: ['app/templates/greeting.tpl'], read
).

# cut the message section
>> message := tpl cut: ['message'].

# add a message (will be encoded properly to avoid xss)
message greeting: ['hello world!'].

# paste the element at the designated slot
tpl paste: message at: ['messages'].

# output including http headers
web-document out: tpl.
```
Это отрендерит HTML-документ с сообщением hello world.
Как видите, здесь используется очень строгое разделение между HTML и
логикой представления (с помощью стандартного шаблонизатора), поэтому
разработчик шаблона может обновлять шаблон без необходимости
изменять какой-либо код.

Результат можно посмотреть здесь:

[https://xoscript.com/test.xo](https://xoscript.com/test.xo)

## Продвинутые шаблоны

Вот пример того, как создать `select` в форме:
```
>> htmlstr := ['
<html>
<body>
<form>
<!-- cut:products -->
<select name="products">
	<!-- cut:product -->
	<option value="<!-- slot:value -->">
		<!-- slot:name -->
	</option>
	<!-- /cut:product -->
	<!-- paste:product -->
</select>
<!-- /cut:products -->
<!-- paste:products -->
</form>
</body>
</html>
'].

>> tpl := Template new: htmlstr.
>> menu := List new ; ['pizza'] ; ['pasta'].
>> products := tpl cut: ['products'], copy.
>> product := products cut: ['product'], copy.

menu each: { :n :item
	products paste: (
		product copy
		value: n,
		name: item
	) at: ['product'].
}.

tpl paste: products at: ['products'].
```

## FizzBuzz

Это стандартный пример FizzBuzz:
```
{ :i
	(i = 0) continue.
	(i % 15 = 0) true: {
		Out write: ['FizzBuzz'], stop.
	}, continue.
	(i % 3 = 0) true: {
		Out write: ['Fizz'], stop.
	}, continue.
	(i % 5 = 0) true: {
		Out write: ['Buzz'], stop.
	}, continue.
	Out write: i, stop.
} * 101.
```
Вывод:
```
1
2
Fizz
4
Buzz
Fizz
7
8
Fizz
Buzz
11
Fizz
13
14
FizzBuzz
etc...
```

# Локализация

При желании вы можете использовать XOScript на своём родном языке.
Для этого соберите XOScript следующим образом:
```
make clean
PACKAGE="server" make plugin-clean
iso="xx" LDFLAGS='-shared' make
iso="xx" PACKAGE="server" NAME="libctrserver.so" make plugin
```
Замените `xx` на ISO-код нужного языка и добавьте словарь для этого языка,
если он ещё не предусмотрен.
